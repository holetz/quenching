# `quenching-management` method evolution — spine/index

> **Way back:** human entry point → [../README.md](../README.md) · system design →
> [../ARCHITECTURE.md](../docs/method/architecture.md) (section «Machine 2 — evolving the method
> itself»). This folder is the **home of the HISTORY** of the method (rounds/revisions);
> the active spec (SKILL.md/references/assets) describes only the present.

This is the **index** of the method's evolution log. The verbose detail of each
round/revision **does not** live here — it lives in [log/](log/), **one file
per context** (dimension or theme). This spine holds what is cheap and
always-read: the **anchor state**, the **exclusion index** (one line per
boundary), the **advance backlog** and the **review queue**.

Two agents evolve the method, reading the next action from here and writing the detail
to the correct context file:

- [`quenching-evolutionist`](../.claude/agents/quenching-evolutionist.md) —
  **advances the boundary**: one new evolution per round (`R*`), increments
  `current-round`, never re-attacks what has already been done.
- [`quenching-reviewer`](../.claude/agents/quenching-reviewer.md) — **critiques and
  refines what already exists**: one revision per invocation (`Rev*`), revisits an
  already-addressed definition, **does not** increment `current-round` (tracked by
  `last-revision`); sharpens, merges, prunes, or supersedes.

Layout, ID conventions (`R*` vs `Rev*`) and routing: [log/README.md](log/README.md).

## Invariant (applies to every round and every revision)

reintroduce coupling to a specific repo or to an external skill. Where an older
record says **"Owner: `<repo-skill>`"**, read **"Payload:
`assets/skills/knowledge-*`"** — the model became an *installer* (the package
carries its own artifacts in [assets/](../plugins/claude-quenching/skills/quenching-management/assets/) and installs them), not a
*delegation*.

  the context file and updates `last-revision` + the `revised-by` mark.

reviewer never advances the boundary.
