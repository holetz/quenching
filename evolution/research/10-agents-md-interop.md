# AGENTS.md and cross-tool interoperability

> This angle covers the open AGENTS.md standard — format, adoption, relationship with CLAUDE.md and other vendor-specific files, symlink/import strategies, and single source of truth — serving the "AGENTS.md / cross-tool interoperability" frontier and dimension 1 (CLAUDE.md as map) of the audit skill.

## Summary

The AGENTS.md standard emerged in August 2025 as an initiative by OpenAI, Google, Cursor, AmpCode, FactoryAI, and Roo Code to create a tool-neutral format that any coding agent could read natively. Its central proposal is to eliminate the fragmentation caused by the proliferation of vendor-specific files — CLAUDE.md, GEMINI.md, .cursorrules, .github/copilot-instructions.md, .windsurfrules — where the same project convention must be duplicated and manually kept in sync by each team. By mid-2026, the standard has native support in 28+ tools and over 60,000 open-source repositories on GitHub, and is stewarded by the Agentic AI Foundation under the Linux Foundation.

The format is intentionally minimalist: pure Markdown, no mandatory schema, no fixed fields, no hard size limit (the practical recommendation converges on fewer than 150–200 lines). Canonical content covers: project overview (stack, versions, non-obvious constraints), build/test commands with exact flags, code conventions that differ from ecosystem defaults, security instructions, Git workflow triggers, and — crucially — judgment boundaries (what the agent NEVER does, what it needs to ASK, what it can ALWAYS do). The hierarchy rule in monorepos is clear: the AGENTS.md closest to the file being edited takes precedence over its ancestors; explicit user prompts take precedence over everything.

Claude Code does not read AGENTS.md natively — it reads only CLAUDE.md. This gap is the central friction point for multi-tool teams and is the subject of the most-voted feature request in the official repository (anthropics/claude-code #6235 and #34235, open without a confirmed roadmap as of June 2026). Three practical solutions have converged in the community: (1) the import pattern — creating CLAUDE.md with only `@AGENTS.md` on the first line, making Claude Code expand the shared file into the session context; (2) the Unix symlink — `ln -s AGENTS.md CLAUDE.md`, which Claude Code follows byte for byte; (3) the division of responsibilities — AGENTS.md as the shared base (stack, conventions, boundaries) and a thin CLAUDE.md covering only Claude Code-exclusive features (permissions, MCP servers, @import of skills, path-scoped rules, CLAUDE.local.md for personal overrides).

CLAUDE.md has structural capabilities that AGENTS.md does not: a six-layer hierarchy (managed policy, user-global, project-root, .claude/rules/, subdirectory, path-scoped); `@import` syntax for file composition; rules scoped by file glob via YAML frontmatter; local overrides via CLAUDE.local.md excluded from git; and direct integration with skills and subagents. AGENTS.md, by contrast, is more portable and easier to maintain as a single source of truth when the team uses multiple tools simultaneously. Research from Princeton showed a 28.6% reduction in execution time and a 16.6% reduction in tokens with a well-written, manually authored AGENTS.md; files generated by LLMs increased cost by 23% — indicating that content quality, not volume, determines value.

For a skill that audits the knowledge surface of a repository, this landscape defines a precise frontier: dimension 1 (CLAUDE.md as map) must also be audited for the presence and state of AGENTS.md and the vendor-specific files. The auditor needs to detect whether there is duplication between CLAUDE.md and AGENTS.md, whether the import pattern or symlink is configured, and whether CLAUDE.md retains only what is Claude-exclusive or wastes space with content that could belong in the shared file. The boundary doctrine (dimension 12) applies directly: each instruction must have a single home — if it is in the shared AGENTS.md, it must not also appear inline in CLAUDE.md. The most frequent smell is CLAUDE.md growing with content that should be in AGENTS.md (portable) or in a skill (on-demand loading), degrading signal density and wasting context tokens in every session.

## How this feeds the method's evolution

- **Dimension 1 — new detectable smell**: CLAUDE.md containing content that should be in AGENTS.md (stack, build commands, portable conventions) is an auditable smell. The "good" criterion for CLAUDE.md becomes sharper: it must contain only what is exclusive to Claude Code (path-scoped rules, @import of skills, MCP permissions, CLAUDE.local.md); everything portable belongs in the shared AGENTS.md.

- **Dimension 1 — cross-tool audit checklist**: The skill must verify the presence and state of AGENTS.md, CLAUDE.md, GEMINI.md, .cursorrules, and .github/copilot-instructions.md; detect content duplication between them; confirm whether the import pattern (`@AGENTS.md` at the start of CLAUDE.md) or symlink is configured; and flag whether the team uses multiple tools without a single source of truth.

- **Dimension 12 — new boundary to audit**: "Each instruction has a single home" now applies to the cross-tool axis: the same content must not exist in both AGENTS.md AND CLAUDE.md. The skill can emit a "content duplicated between AGENTS.md and CLAUDE.md" smell as a failure criterion in the boundary audit.

- **Dimension 13 — refinable content convention**: The Pink Elephant Problem rule (ASDLC) is actionable as a quality criterion: constraints formulated as negatives ("do not use X") must be converted into structural restrictions or removed — never left as warnings in AGENTS.md/CLAUDE.md. The skill can flag negative bullets as refactoring candidates.

- **Dimension 14 — automatic generation guardrail**: The quantitative evidence (23% cost increase with LLM-generated AGENTS.md vs. +4% with manual) is a behavioral guardrail: the skill must not offer to generate AGENTS.md automatically; it must guide manual authorship using the five canonical sections as a scaffold.

- **AGENTS.md frontier — new workflow step**: When the skill detects that the repository uses multiple tools (presence of .cursorrules, GEMINI.md, copilot-instructions.md) but has neither AGENTS.md nor the import pattern configured, it must propose the migration one-liner (`mv CLAUDE.md AGENTS.md && ln -s AGENTS.md CLAUDE.md`) and the list of required symlinks — with the guardrail of not symlinking entire directories (.claude/).
