# Skill taxonomy and naming

Every skill in `.claude/skills/` is classified on **one axis**:

- **Domain-bound** — serves ONE folder subtree of this repo. Named as the flattened
  folder path plus a verb (`communications/teams/` + create →
  `communications-teams-create`), and mirrored by a thin command wrapper at
  `.claude/commands/<folder-path>/<verb>.md`, invocable as `/<folder>:<subfolder>:<verb>`.
- **Generic** — serves the repo as a whole. Named verb-object (`release-notes`), never
  mirrored under a folder path: a flat command or none.

The classification test: name the one folder the skill acts on — exactly one answer means
domain-bound to that folder; "the repo" means generic; several unrelated folders means the
skill is kept as-is and reported, never forced onto the axis.

Directory-scoped skills (`<folder>/.claude/skills/`) are an **accepted variation** for
expressing domain-binding; new skills are minted with the mirrored-wrapper mechanism above.

The surface is listed in the registry at
[/docs/documentation/reference/automation.md](/docs/documentation/reference/automation.md):
its GENERATED zone is regenerated by `skills.py registry reindex`, which owns its format, and
is invoked only by the owning skills (`quenching-skill-new`, `quenching-skill-align`) — hand
edits inside the markers are overwritten on their next run, not merged.

## Invocation and permission

Chosen at mint, never defaulted into:

- `user-invocable: false` **hides the `/` menu entry**; it does **not** block programmatic
  invocation. It is the normal setting for a skill reached through a command wrapper.
- `disable-model-invocation: true` is the **only** field that blocks programmatic invocation.
  Use it when a skill's cost or blast radius means a human must choose it.
- Both at once leaves **no caller** — reported as `sk-unreachable`, an error.
- `context: fork` is forbidden on any skill that gates on a mid-flow confirmation: a forked
  context cannot present the plan whose OK the run depends on.

## `allowed-tools` is always scoped

Grant the narrowest set the workflow needs, and scope every tool that takes a scope —
`Bash(python3:*)`, `Bash(git status:*)` — never a bare `Bash`, which grants the whole shell for
the turn (`sk-unscoped-bash`). The one exception is a skill running **this repo's own
toolchain** (its build, tests, linters), which cannot enumerate those commands in advance; such
a skill may hold an unscoped grant **provided its body states the reason**.

## The verifier

`skills.py` decides everything mechanical on this surface: `lint` (the caps, trigger position,
the `Not for:` boundary, body length, a `**Done when:**` per step, tool scoping, invocation
coherence), `doctor` (the bijection, names, mirroring), `registry reindex`, and `budget` (what
the surface costs before anything fires). Uniform `--json`; exit **0** ok · **1** findings ·
**2** refusal, with errors setting the exit code and warnings never doing so. Findings are named
by their `sk-*` code.

The surface is aligned when `doctor` and `lint` exit 0 — or every surviving finding is named in
the report by its code — and `registry reindex` reports `changed: false`.

What the tool does **not** decide: the axis above, and whether a skill's prose earns its place.
Those stay a human read.
