# `vision/` — direction, segmented by area

Where the platform is heading (target state, "the what and why"), **without a
schedule**. The vision is **segmented by area**: one shell per pillar/area
(`<area>.md`), not a single `VISION.md`. Each new area uses the method's area mold
(applied by the `quenching-docs` skill).

Boundary: direction **carries no deadline, milestone, or order**. What **is missing**
to get there lives in `backlog/`; what **has already become reality** distills into
`standards/`. An open decision about how to get there lives in `decisions/`.
