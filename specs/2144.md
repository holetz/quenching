## Problem

`plugins/quenching/assets/references/specs-develop/specs-surface.md` owns the `cq specs` tool
surface, one table row per verb, and a command body that must choose a verb reads it. Two verbs have
no row: `cq specs push`, which predates spec 2138 and was never documented there, and
`cq specs artifact list|read|write|rm`, which spec 2138 introduced. The gap is not cosmetic — the
session that looks for the door to the artifacts tree finds no row and invents a path under `/tmp`
instead, which is the failure 2138 exists to remove.

## Proposal

- Add a `cq specs artifact …` row beside `cq specs show`: the four verbs, the tree
  (`specs/artifacts/<id>/<name>` on the specs branch, `specs/artifacts/_handoffs/<name>` when
  `--spec` is omitted), one path segment, UTF-8 text only, the 1 MiB cap, the body from stdin or
  `--from`, and `sp-artifact-unsupported` when the backend declares no such capability.
- Add a `cq specs push …` row beside `cq specs export`: every pending write of the clone in one
  push that leaves the store branch a single parentless commit, `--drop <id>` to discard one spec's
  pending writes first, and `sp-push-no-store` (exit 2) when the repository declares no git store.
- Keep the same two-cell shape as the neighbouring rows and add no prose section: the table is the
  owner, and a second explanation drifts from it.
- Deploy the reference into `.agents/quenching/assets/references/` and read the copy back.

## Impact

- `plugins/quenching/assets/references/specs-develop/specs-surface.md`: two rows.
- `.agents/quenching/assets/references/specs-develop/specs-surface.md`: the deployed copy of the
  same file.
- No command body, no code and no payload mirror: the reference is loaded through
  `cq components read`, not generated into a plugin listing.

## Validation

- The reference carries exactly one `cq specs artifact` row and one `cq specs push` row, both inside
  §The `cq specs` tool surface.
- `cq components read .agents/quenching/assets/references/specs-develop/specs-surface.md --sections
  "§The \`cq specs\` tool surface"` prints both rows after the deploy, and its output carries no
  `sp-*` code other than the two the rows name.
- `bash scripts/verify_repo.sh` prints `Repository verification passed.`
