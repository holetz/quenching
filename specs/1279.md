## Problem

A 1266 (#1271) deu ao git-steward `Bash(cq specs:*)` e `Bash(cq components:*)` para o passo de PR (`plugins/quenching/agents/git-steward.md:4`), mas esses padrões cobrem escritas fora do papel dele: `cq specs record <id> approved --set by=human` (forja a aprovação que `agents/orchestrator.md:28-29` e `commands/specs/develop.md:356-358` reservam), `promote --force`, `section --write`, `export --out <qualquer caminho>`, `release` e `components translate --write --target <qualquer caminho>`. O `pr:create` só precisa de `config`, `status`, `section`, `record … pr` e `components read`. A proibição de `--admin`, `--delete-branch` e `--auto` (`git-steward.md:28-29`) só existe na prosa, porque `Bash(gh:*)` aceita as três. E `git-steward.md:21-22` manda usar a worktree "as `--root` for `cq`", mas `create.md:29,32` roda `cq git conventions`/`cq git base`, e `cq --root <x> git …` sai com `git declares no --root` (exit 3, reproduzido; a 1267 documentou `cd <wt> && cq git …` em `execute.md`/`branch.md`, não no steward). Achados da re-revisão de 2026-10-08.

Consequência: o steward pode forjar `approved by=human`, arquivar à força ou escrever em qualquer caminho pelo próprio grant; e um steward que siga a regra do `--root` à letra volta `blocked` no passo de PR.
