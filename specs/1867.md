## Problem

**O git-steward disparou duas chamadas de merge do mesmo PR em paralelo, três vezes em 2026-10-17:** nos merges da 1734 (#1845) e da 1677 (#1847) (relatório do orchestrator do épico 1843) e da 1856 (#1861, épico 1852). A segunda chamada foi recusada porque o PR já estava mergeado; `gh` confirma um merge só. `plugins/quenching/agents/git-steward.md:48-54` descreve um comando de merge, mas não proíbe chamadas paralelas nem trata "already merged" como sucesso idempotente.

**Consequência.** Hoje sem dano, mas é corrida no passo que escreve na `main`; um `cq git pr merge` concorrente com head movido entre as duas leituras pode reportar erro falso ou mascarar estado.

**Validação.** O steward faz uma chamada de merge por vez (texto do agente) e `cq git pr merge` trata PR já mergeado no mesmo head como `ok` idempotente (teste com `gh` falso). Gate exit 0.

## Proposal

- O texto do git-steward manda fazer uma única chamada de `cq git pr merge` por vez para um PR, nunca duas em paralelo.
- `cq git pr merge` sobre um PR já mergeado devolve `ok` idempotente (exit 0, `alreadyMerged: true`) sem chamar `gh pr merge`.
- Um teste com `gh` falso prova o caminho idempotente e que o merge normal segue igual.

## Out of Scope

- Novo grant ou nova ferramenta para o steward: o comando e as permissões ficam como estão.
- Afrouxar qualquer checagem: PR aberto segue exigindo checks verdes, estado limpo e `--match-head-commit`.
- Tratar o "already merged" de uma corrida em que `gh pr merge` já foi disparado: só o PR visto como `MERGED` antes do merge é idempotente.

## Design

**Regra durável.** `cq git pr merge` lê `state` junto com `headRefOid` e `mergeStateStatus` na primeira leitura do PR; `state == MERGED` encerra com `ok: true`, `alreadyMerged: true`, antes de ler checks. Um PR mergeado não tem mais o que certificar, então a segunda chamada de uma corrida vira sucesso em vez de erro falso. O texto do steward proíbe a segunda chamada em paralelo; a idempotência cobre o que escapar.

## Alternatives Considered

- Só o texto do agente: não cobre a corrida que escapar da instrução.
- Só a idempotência no verbo: deixa o steward livre para disparar chamadas duplicadas.

## Open Decisions

- none — o efeito de `alreadyMerged` no fluxo do steward é o `ok` já existente; nada a decidir.

## Risks

- Um PR mergeado por outra via, não pelo steward, também devolve `ok`: ACCEPTED — o estado final pedido (PR mergeado) é verdadeiro.
- `state` ausente na leitura do `gh`: tratado como não mergeado, caminho atual preservado.
