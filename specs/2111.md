## Problem

Os corpos dos comandos chamam o `cq` por blocos bash, e cada distribuição (Codex, OpenCode, Omnigent) reescreve esses blocos com um wrapper próprio. Com o `quenching-mcp`, a mesma prosa pode chamar ferramentas MCP e servir os quatro harnesses sem tradução de bash. Esta é a primeira de três fatias: os comandos de specs e de git, que formam o fluxo de desenvolvimento, e os agentes do fluxo (orchestrator, spec-runner, verifier, git-steward, reviewer, scout, spec-architect).

## Proposal

Reescrever na fonte `plugins/quenching/` os blocos `cq specs …` e `cq git …` desses comandos e agentes como chamadas às ferramentas do `quenching-mcp`, mantendo o mesmo contrato de saída (os campos JSON que os corpos leem). O bash continua só onde o passo é de shell de verdade (testes, build do projeto-alvo). Os geradores deixam de emitir wrappers `cq` para esses corpos. Os evals existentes desses comandos precisam continuar verdes.
