## Problem

`cq specs show`, `status` e `parallel` exigem `--spec <id>`, enquanto `cq specs section <id>` e `promote <spec>` recebem o id posicional; o placeholder `<id>` serve tanto para spec quanto para task em `plugins/quenching/commands/specs/execute.md:267` e `plugins/quenching/assets/references/specs-execute/execution.md:174,228`.

Medido nos logs de sessão dos últimos 14 dias: 7 de 23 runs de spec-runner e 2 de 4 do orquestrador bateram num erro de uso do `cq`; 11 chamadas a `show`/`status`/`parallel` falharam com `required: --spec`; 4 de 18 runs que marcam tasks passaram o id da spec como id da task (`no task 'NNNN'`), e um run repetiu o erro determinístico 4 vezes com sleeps de 0 a 60 s. 17 de 20 respostas com texto de argparse ficaram mascaradas por pipe.

Consequência: turnos e tokens desperdiçados em todo run orquestrado, e erros que passam despercebidos.

## Proposal

Aceitar o id posicional também em `show`, `status` e `parallel`, mantendo `--spec`; desambiguar nos corpos e references o placeholder (`<spec-id>` contra `<task-id>`).

## Out of Scope

Renomear verbos ou mudar o formato de saída.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/specs/commands/cli.py` — `show`, `status` and `parallel` take the id positionally too
- `plugins/quenching/tests/test_specs_cli_positional.py` — new CLI test
- `plugins/quenching/commands/specs/execute.md` and `plugins/quenching/assets/references/specs-execute/execution.md` — `<spec-id>` against `<task-id>`
- `plugins/quenching-codex/**` and `plugins/quenching-specs-reader/**` — generated copies, regenerated by `cq components translate --write`

## Validation

`cq specs show 1192`, `cq specs status 1192` e `cq specs parallel <id>` funcionam como com `--spec`; os trechos citados não têm `<id>` ambíguo; testes de CLI; `bash scripts/verify_repo.sh` sai 0.

## Design

- **Both forms, one meaning.** `show`, `status` and `parallel` declare an optional positional `ID` beside `--spec`; `main` folds the positional into `args.spec` before dispatch, so no verb body changes. Giving both with different values refuses; `show` and `parallel` with neither refuse as before (`status` keeps its `--epic` alternative). `--spec` is never removed, so every existing call keeps working.
- **One placeholder per kind.** In the bodies a spec id is `<spec-id>` and a task id is `<task-id>`; `<id>` alone is no longer used where both appear in one command line.
- Alternative weighed per decision: a shared helper `add_spec` in `cli.py` (chosen) against editing three parsers by hand (drifts).

## Alternatives Considered

- Make every verb positional-only: rejected, it breaks every body and log that passes `--spec`.
- Only fix the prose: rejected, the measured failures are 11 calls that bounced off `required: --spec`; the tool should accept what the sibling verbs already accept.

## Open Decisions

- none — the 17 masked argparse responses are a separate concern (pipes in callers), parked in Discoveries and not decided here.

## Risks

Um posicional novo não pode colidir com subcomandos ou com `--epic` em `status`.
