## Problem

`cq components session cost` (1311) escolhe a sessão por mtime (`plugins/quenching/assets/bin/quenching/session/transcript.py:64`) e o orchestrator não passa sessão (`orchestrator.md:83`): `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review10/cost/root` reportou a sessão concorrente; uma linha JSON que não é objeto dá `AttributeError` (`cost.py:54`).

Origem: item R8 da fila da rodada 2 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round2-queue.md`), da revisão de correção opus do épico 1306.

## Proposal

O orchestrator passa a própria sessão ao `cq components session cost` (o verbo já aceita id de sessão ou caminho), e o verbo deixa de escolher por mtime em silêncio quando há mais de uma sessão candidata; uma linha JSON que não é objeto é ignorada ou contada como ilegível, nunca `AttributeError`.

## Out of Scope

- Making `resolve_transcript` (shared with `digest` and `read`) refuse on ambiguity: those verbs keep "most recent" as documented; only `cost`, whose total is attributed to one run, must not guess.
- Discovering the orchestrator's own session id from the environment: the id is passed in the prompt/context; no new env contract is minted.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/session/commands/cost.py` — session choice and record parsing
- `plugins/quenching/tests/test_session_cost.py` — one test per vector
- `plugins/quenching/agents/orchestrator.md` — step 8 passes the session id
- `plugins/quenching-codex/**` — generated mirror (`.generated-files.json`, `agents/orchestrator.md`, `scripts/bin/quenching/session/commands/cost.py`)

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p "test_*cost*.py"` exits 0.
- Before the fix, `cq components session cost <dir with a line "[1]">` dies with `AttributeError`; after, it exits 1 with an anomaly `record is not a JSON object`.
- Before the fix, two sessions with subagents under one project dir and no argument report the mtime-newest one; after, exit 2 `se-ambiguous-session` listing both ids.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- **Rule: a cost attributed to one run is never chosen by mtime among several candidates.** With no argument, `cost` looks at the sessions in the project dir that have a `subagents/` directory: more than one refuses (exit 2, `se-ambiguous-session`, ids listed); exactly one is used; none falls back to the old path and its existing refusals. An explicit id or path is unchanged.
- **Rule: a transcript record that is not a JSON object is an anomaly, never an exception.** Same for a non-string `agentType` or `model` (read as `unknown`) and a meta file that is not an object.
- The orchestrator passes its own session id, the verb's existing argument; the verb's refusal is the backstop when it does not.
- Assumption: the orchestrator learns its session id from its launching context; if it cannot, it gets the refusal and the id list rather than a wrong number.

## Alternatives Considered

- Keep mtime but print a warning: rejected, a total that looks right but belongs to another session is the failure.
- Change `resolve_transcript` for all verbs: rejected, widens the blast radius to `digest` and `read`.

## Open Decisions

- none — the session-id source for the orchestrator is its launching context; revisit if a runtime env var for it appears.

## Risks

- A parallel session that has not spawned subagents yet is not a candidate, so it cannot cause a refusal; ACCEPTED — it also cannot be mis-costed, having no subagents.
- A project dir with two sessions now refuses where it used to answer; the message names the ids so the fix is one argument.
