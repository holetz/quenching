## Problem

Escopo e executores restantes do audit: `diff --name-only` com detecção de rename esconde a origem (`git mv protected/gate.sh allowed/gate.sh` → `changed: ['allowed/gate.sh']`; `audit.py:157`; usar `--no-renames`); a busca preguiçosa ainda alcançável em `cq git worktree`/`push` via `audit._commit`; falha silenciosa de `remote get-url` e leitura de config de filtro ignorada em `_inert_env` (1341). `audit.py` é `plugins/quenching/assets/bin/quenching/git/audit.py`.

Origem: item T6 da fila da rodada 3 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round3-queue.md`), da revisão de correção opus da rodada 2 (épico 1337).

## Proposal

Direção: usar `--no-renames` no `diff --name-only` do escopo; fechar a busca preguiçosa alcançável por `audit._commit` em `cq git worktree`/`push`; falhar fechado quando `remote get-url` ou a leitura da config de filtro em `_inert_env` falham. Depois do T5 (mesmo arquivo).

## Out of Scope

- A fechar a busca preguiçosa dentro de `fetch` em `cq git worktree add/retire`: o fetch precisa de transporte e continua usando `_git_run` direto. Fecha-se só o que lê (`_run`, `_commit`).
- Reescrever `specs/config.py`, `common/config.py` e os backends de specs, que também chamam `remote get-url`: leem config própria, fora do audit.

## Design

- **`--no-renames`** no `diff --name-only` do escopo: o rename aparece como delete da origem mais add do destino, então o escopo vê o caminho protegido. Decisão durável: a lista de escopo nunca depende de detecção de rename.
- **Busca preguiçosa**: `_run` passa a usar `{**os.environ, **NO_FETCH}` quando não recebe `env`; `_commit` herda por usar `_run`. Assim todo chamador (worktree, push, pull) lê sem transporte. Alternativa rejeitada: exigir `env` em cada chamador, que repete o esquecimento.
- **`remote get-url`**: o git sai 2 para remote inexistente (fato legítimo) e outro código para falha real. Só 0 é "existe" e só 2 é "não existe"; qualquer outro código recusa (push/worktree) ou entra em `errors` (state).
- **`_inert_env`**: aceita `errors`; `config --get-regexp` sai 0 (achou) ou 1 (nenhuma chave, fato). Qualquer outro código é anexado a `errors`, tornando `complete: false`. Assunção: o audit e o state já propagam `errors` para o payload.
- Verbos que usam `_run` para `remote get-url` de `--remote` do usuário: o `NO_FETCH` não afeta get-url, apenas torna o env uniforme.

## Alternatives Considered

- Tratar o rename só na leitura (`-M0`): equivalente, mas `--no-renames` é explícito e cobre config `diff.renames`.
- Bloquear o audit inteiro quando a config de filtro falha: rejeitado, o contrato é relatório com `errors`/`complete`, não recusa.

## Open Decisions

- Why now / custo de esperar: o épico 1337 deixou o escopo cego à origem de rename; decidido pela fila do autopilot (T6), sem pergunta humana.

## Risks

- `_run` com NO_FETCH pode quebrar chamador que dependia de transporte via `_run`: mitigado por varrer os chamadores (nenhum busca via `_run`; fetch usa `_git_run`) e pelos testes existentes.
- Recusar em código inesperado de `get-url` pode bloquear um fluxo antes tolerado: ACCEPTED — é o fail-closed pedido.
