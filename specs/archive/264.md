## Problem

Sub-spec da 262 (gate local verde no Windows), fundação das outras: o gate e os helpers de teste que todas as famílias usam. Medido em 2026-11-23 no slot 3 (main `efd26cfe2`, Windows 11, Python 3.12 do `.venv`, `pytest -n auto`): **276 failed, 12 errors, 2909 passed** em 11 min; cada sintoma se reproduz com `python -m pytest quenching/tests/<módulo>`.

**Causas medidas, todas fora dos testes de produto:**
- **Fim de linha.** O Git for Windows vem com `core.autocrlf=true` no gitconfig do sistema e o repositório não tem `.gitattributes`: 1643 arquivos ficam `w/crlf` com o índice `i/lf` (o próprio `scripts/verify_repo.sh`, o `citation-check.sh`, os `.md`). Só `.agents/quenching/bin/cq.cmd` é `i/crlf` no índice. O `citation-check.sh` junta parágrafos de arquivos CRLF e devolve **27 achados falsos** de seção (`FAIL cited sections: 27 distinct, over 760 checked`); fixtures copiadas do checkout quebram o `git` com `fatal: bad config line 10 in file .git/config` (test_run_evals/test_git `Containment`).
- **`citation-check.sh` no Git Bash:** compara `git rev-parse --show-toplevel` (`C:/Projetos/...`) com `$PWD` (`/c/Projetos/...`) e sai 2 (`is not the repository root`); o probe de seções em Python lê o heredoc e escreve no console em cp1252 (`UnicodeEncodeError: '\u2192'`, e `§` não casa), contando `0 sections checked`.
- **`python3` do gate** resolve para o alias da Microsoft Store (Python 3.13 sem as dependências), não para o `.venv`; o `bash` do PATH do PowerShell é o lançador do WSL (`C:\Windows\System32\bash.exe`), e `subprocess.run(["bash", …])` no Windows sempre acha o do System32 antes do PATH (`<3>WSL … execvpe(/bin/bash) failed`).
- **`scripts/toolchain/tmproot.py:134`**: com `PYTHONUTF8=1` a saída do `fsutil devdrv query` (OEM) não decodifica e o gate morre antes da suíte.
- **Leitura sem `encoding=`** de arquivo UTF-8: `test_portal_ui.py:24` (`(ROOT / "app.js").read_text()`) nem é coletado (12 errors) e derruba `test_suite.py::SuiteIntegrity::test_discovery_is_not_empty`; `test_knowledge_projection` (`'utf-8' codec can't decode byte 0x97`).
- **Helpers de teste que não existem para o Windows**, usados pelas sub-specs irmãs: um `bash` resolvido para o Git Bash (nunca o lançador do WSL), uma ferramenta falsa executável (no Windows um script com shebang sem extensão não roda — `[WinError 193]` — e `shutil.which` não o acha), e pôr uma ferramenta real no PATH isolado sem `os.symlink` (`[WinError 1314]` sem privilégio de administrador: 23 falhas).

**Pronto quando** o `.gitattributes` fixa LF (CRLF só para `*.cmd`/`*.bat`), o gate resolve `python` e `bash` do próprio ambiente, `citation-check.sh` passa no Git Bash com 0 achados, `tmproot` sobrevive a `PYTHONUTF8=1`, `test_portal_ui`/`test_suite`/`test_knowledge_projection` passam, e existe um módulo de helpers de teste (`quenching/tests/_tools.py`, sem `test` no nome) com testes próprios, que as sub-specs irmãs consomem. Regra do humano: corrigir teste e código, nunca esconder falha; `skipIf(os.name == "nt")` só quando o comportamento não existe no Windows, com o motivo escrito.

## Proposal

Consertar a fundação do gate no Windows, sem esconder falha, em cinco frentes:

1. **Fim de linha:** um `.gitattributes` na raiz fixa `* text=auto eol=lf`, com `*.cmd` e `*.bat` em `eol=crlf`, num commit só dele. A cópia de trabalho do slot é reescrita em LF (CRLF→LF só onde o índice já é LF), sem checkout. Com a árvore limpa, `git add --renormalize .` prova que o índice não muda: ele já é LF, e `cq.cmd` já é CRLF. Por isso a renormalização não deixa commit nenhum, e essa ausência é a prova.
2. **Gate:** `scripts/verify_repo.sh` resolve o `python3` para o `.venv` do projeto (`.venv/bin/python` ou `.venv/Scripts/python.exe`) e cai no `python3`/`python` do PATH só quando não há `.venv`. A função `python3` é exportada para os scripts bash filhos, e o citation-check roda com `"$BASH"`, nunca com um `bash` solto.
3. **`citation-check.sh`:** no Git Bash, compara o toplevel do git com a grafia do próprio shell (`cd "$TOPLEVEL" && pwd`). Fixa `PYTHONIOENCODING=utf-8` para os probes em heredoc. O probe de seções passa a normalizar caminhos com `posixpath`, porque `os.path.normpath` troca `/` por `\` no Windows, e essa é a causa medida dos 27 achados falsos.
4. **`tmproot`:** decodifica a saída do `fsutil devdrv query` com `errors="replace"`.
5. **Testes e helpers:** `test_portal_ui.py` e `test_knowledge_projection.py` passam a ler e escrever com `encoding="utf-8"`. Um módulo novo, `quenching/tests/_tools.py`, traz `bash()` (Git Bash, nunca o lançador do WSL), `fake_tool()` (corpo Python atrás de um `.cmd` no Windows, ou script com shebang no POSIX) e `link_tool()` (um `.cmd` que repassa ao binário real em vez de `os.symlink`), com testes próprios em `test_tools_helpers.py`.

## Design

- **A causa dos 27 achados não era CRLF.** Medido no slot: com a cópia de trabalho ainda em CRLF, o citation-check passa a 0 achados só com o `posixpath`. Todo arquivo é lido com newline universal, e o que quebrava era a chave do índice de headings (`quenching\references\…` contra `quenching/references/…`). O `.gitattributes` continua necessário por outro motivo: o orçamento de bytes do `app.css` (`test_portal_ui` Budget: 49.865 bytes com CRLF, contra o teto de 49.152) e as fixtures copiadas do checkout.
- **O `python3` do gate é uma função de shell**, não um `sed` em 30 linhas. `export -f` leva a função aos bash filhos (o citation-check chama `python3 -` nos heredocs). O `.venv` é o mesmo ambiente que `uv run` usa, então o CI, que roda `uv sync`, também ganha consistência.
- **Os helpers retornam o caminho escrito.** Um `.cmd` é achado por `shutil.which` (PATHEXT) e executável por `subprocess.run([path])`. A limitação fica documentada no módulo: no Windows, `subprocess.run([name], env={"PATH": …})` não procura no PATH do filho.
- 2026-11-23 (decisão do condutor, check 10 do spec-verifier): os três `gate-shrunk` são reescrita, não rebaixamento da régua. Nenhum check saiu do gate. O citation-check roda pelo `$BASH` do gate, os caminhos alvo usam `posixpath` porque são pathspecs do git, a raiz é comparada no formato do próprio shell e o encoding fica fixo. O `python3` do gate resolve para o `.venv` do projeto, com fallback para o do PATH. O `tmproot.py` mantém o `timeout=5` e ganha `errors="replace"`. Evidência: o diff de `scripts/verify_repo.sh`, `citation-check.sh` e `tmproot.py` contra origin/main, lido pelo condutor; o commit de renormalização `477f701` sai vazio em `git show --ignore-cr-at-eol --stat`. Mesmo tratamento da 2253.

### Assumptions

- O `.venv` do projeto, quando existe, tem o grupo dev. É o que `uv sync --all-groups` produz e o que o CI faz (Proposal §2).
## Alternatives Considered

- **Tornar o citation-check tolerante a CRLF em vez do `.gitattributes`:** descartada, porque a leitura já é universal e o CRLF não era a causa. O `.gitattributes` resolve os orçamentos de bytes e as fixtures.
- **`os.link`/cópia do binário em vez do `.cmd` no `link_tool`:** descartada. O `git.exe` de `cmd/` localiza a instalação pelo próprio caminho, e um hardlink fora dela não acha o mingw.
- **Trocar cada `python3` do gate por `"$GATE_PYTHON"`:** funciona, mas não alcança o `python3` dentro do citation-check, que é distribuído aos alvos e não deve conhecer o `.venv` deste repositório.

## Risks

- **Renormalização que mudasse blobs:** mitigada pela prova em commit separado (`git diff --cached` vazio depois do `--renormalize`).

- **`.cmd` com caracteres especiais (`%`, `^`) no caminho:** os caminhos dos testes vêm do temp root e do `sys.executable`. O risco foi aceito e fica documentado.
