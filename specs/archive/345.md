## Problem

Reproduzido em 2026-11-24 pelo condutor do autopilot (épico 306): com os 12 slots ocupados, a 331 ficou esperando vaga; `cq git worktree release --path <slot> --json` recusou os 9 slots de specs já mergeadas com "holds ignored files no shared.regenerablePaths entry covers: .quenching/git-base-cache.json; the slot stays held" (o slot 4 também com `.quenching/git-ci-cache.json`), e `--discard-ignored` não muda isso. Os arquivos vieram da 311 (cache de `isDefault` do `git base` e do resultado do `ci` do preflight) e são puro cache (`{"<url>|main": {"isDefault": true, "at": …}}`). O condutor apagou os dois arquivos à mão nos 9 slots e o release passou.

**Consequência:** toda worktree onde `cq git base` ou `preflight` rodou fica presa depois do merge; com o teto de slots, os workers seguintes esperam até 30 min por vaga ou o autopilot para.

Proposta: os caches de git saem da worktree (para o git common dir, compartilhado entre slots, que é também onde o cache rende mais) ou entram nos `regenerablePaths` padrão do quenching; teste: acquire → `cq git base` → release passa sem intervenção.

## Proposal

- Os dois caches de git da 311 (`.quenching/git-base-cache.json`, `.quenching/git-ci-cache.json`) contam como regeneráveis por padrão: o `release` de um slot que só os carrega passa sem `--discard-ignored` e sem entrada em `shared.regenerablePaths`.
- O contrato (`docs/standards/workflows/plugin-configuration.md` e a reference de config) lista os dois caminhos na lista embutida.

## Out of Scope

- Mover os caches para o git common dir: rende mais cache entre slots, mas muda o contrato de `git/base.py` e `git/preflight.py` e a invalidação; fica como follow-up se o hit rate pedir.
- Mudar o ignore das worktrees dos alvos: cada alvo continua declarando o que mais for regenerável.

## Impact

### Standards this spec will write into docs/standards/

- `docs/standards/workflows/plugin-configuration.md` — a lista embutida de regeneráveis ganha os dois caches de git

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/git/ignored.py` — `DEFAULT_REGENERABLE`
- `quenching/tests/test_git_ignored.py` — a lista padrão e a cobertura dos dois caminhos

### Process surface this spec expects to touch

Os espelhos (`.agents/`, `.claude/`, `.opencode/`, `.agents/.quenching-deploy.json`) são regenerados por `python3 quenching/assets/bin/cq deploy --target . --write`.

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_git_ignored.py` — a lista padrão inclui os dois caminhos e `is_regenerable` os aceita ancorados na raiz.
- `python3 -m unittest discover -s quenching/tests -p test_git.py` — o release/retire de um slot com os dois caches passa.
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` — gate verde.

## Design

- **Decisão: entram na lista embutida (`DEFAULT_REGENERABLE`), como entradas ancoradas com barra.** Um caminho com barra só casa na raiz, então `pkg/.quenching/...` continua não regenerável. Evidência: `is_regenerable` em `git/ignored.py` e o `Problem` (os arquivos são `{"<url>|main": {"isDefault": true, "at": …}}`, puro cache). Alternativa: git common dir; ver Out of Scope.
- Binding: `docs/standards/workflows/plugin-configuration.md` — a chave só soma à lista embutida, nunca remove.

### Mapa de dependências

- `git/slots.py` (`release`) e `git/worktree.py` (`retire`) e `git stale` consomem `declared_regenerable`; nenhum muda.
- `tests/test_git_ignored.py` asserta a tupla literal; `tests/test_git.py` só usa a lista pelo nome.

## Alternatives Considered

- Caches no git common dir: rejeitada por ora, muda o contrato dos dois módulos e a invalidação; o ganho é cache compartilhado, não o desbloqueio do slot.
- Cada alvo declarar os dois caminhos em `regenerablePaths`: rejeitada, todo alvo que roda `cq git base` teria o mesmo defeito.

## Outcome

Os dois caches da 311, `.quenching/git-base-cache.json` e `.quenching/git-ci-cache.json`, entram em `DEFAULT_REGENERABLE` (`quenching/assets/bin/quenching/git/ignored.py`), ancorados na raiz. Um slot que só guarda esses arquivos é liberado sem intervenção. `test_git_ignored.py` cobre a lista e o ancoramento. O padrão embutido está documentado em `docs/standards/workflows/plugin-configuration.md` e na reference `specs-align/plugin-configuration.md`; o espelho implantado foi regenerado.

Ficou de fora: mover os caches para o git common dir (contrato de `git/base.py` e `preflight.py` intacto, decisão registrada em `## Discoveries`). A entrada com barra final em `regenerablePaths` segue como outra spec.

Aceite no alvo: acquire de um slot livre → `cq git base` (criou `.quenching/git-base-cache.json`) → `cq git worktree release` saiu com `released: true`, sem `--discard-ignored`.
