## Problem

`load_config()` em `plugins/quenching/assets/bin/specs.py` ignora o root que recebe como argumento e
resolve a configuração a partir do cwd real do processo, subindo diretórios até achar um
`.claude/quenching.json` de verdade.

O sintoma mede-se com o próprio selftest da ferramenta, e o resultado depende de onde ele é rodado:

```bash
cd /tmp && python3 <repo>/plugins/quenching/assets/bin/specs.py selftest   # 0 error(s)
cd <repo>/plugins/quenching && python3 assets/bin/specs.py selftest        # 2 error(s)
```

Os dois erros são `sp-config-default-drift`: o check (linha ~6704) chama
`load_config(os.path.join(os.sep, 'nonexistent-specs-root', 'specs'))` esperando os defaults
documentados (`backend='files'`, `present=False`), e o comentário do próprio check diz que ele
"stays self-contained and never depends on this checkout's own config". Ele depende: o resultado
real é `backend='github'`, `present=True` — a configuração **deste** repositório.

**Por que agora.** O selftest é gate declarado de duas tarefas da spec `rework-specs-isolate-flow`
(3.1 e 3.5) e do bloco `## Validation` dela, e naquele checkout ele não pode voltar limpo — a spec
teve de carregar uma exceção nomeada de "sem regressão nova" para poder fechar. Enquanto isso valer,
qualquer repositório que declare um backend diferente de `files` herda dois erros falsos, e o
selftest deixa de distinguir "falhou" de "não pôde ser medido".

Confirmado pré-existente por `git stash`: os mesmos dois erros aparecem antes de qualquer mudança de
`rework-specs-isolate-flow`. Promovido a partir de `## Discoveries` daquela spec.

## Outcome

Abandonada em 2026-08-11 — o defeito já não reproduz, pelo mesmo padrão já registrado pela spec
irmã `corrigir-load-config-resolvendo-repo-pelo-cwd` (abandonada em 2026-08-06) para o mesmo
defeito por outro ângulo.

`find_repo_root(specs_root)` (`quenching/specs/config.py:123`) hoje recebe e usa o argumento
explicitamente: guarda com `os.path.isdir(specs_root)` antes de chamar git, e cai para
`os.path.dirname(os.path.abspath(specs_root))` sem nunca subir a partir do cwd real do processo. A
docstring cita literalmente o cenário do bug ("load_config's own selftest fixture") como o caso que
motivou o guard — a correção já sabe do problema que esta spec descreve.

Nada foi construído por esta spec: sem tarefas, sem `branch` record, sem merge. Colheita de
distilação: vazia.
