## Problem

Na execução da spec 527 (2026-11-25, develop passo 7), `specs_validate(spec=527)` foi recusado pelo schema MCP com `spec: Expected string`, enquanto `specs_status`, `specs_section_write` e `specs_record` aceitaram o mesmo `spec=527` numérico na mesma chamada de Code Mode; `specs_parallel` também exige string. O mesmo argumento tem tipos diferentes entre verbos irmãos, e um lote de escritas para no meio (as anteriores já gravadas, as seguintes não), o que o passo 7 do develop pede que seja uma única operação.

Minimal fix proposed: declarar `spec` como `string | number` em todos os verbos `specs_*` do servidor MCP, como `specs_status` já faz.

**Insumos**

- servidor MCP `quenching`: schemas de `specs_validate` e `specs_parallel` (`spec: string`) contra `specs_status` (`spec: string | number`)
- saída: `Invalid arguments for tool "quenching_specs_validate": - spec: Expected string`
- spec 527, develop passo 7 (lote de escrita)
