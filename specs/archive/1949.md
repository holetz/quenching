## Problem

Achados da revisão do épico 1945 (main 17270600), todos reproduzidos. A guarda do `cq codex review` (`plugins/quenching/assets/bin/quenching/codex/guard.py`) promete provar que o review "changed nothing at all", mas deixa passar quatro classes de mudança:

1. **Índice** (`guard.py:73`, Codex): `tree()` faz hash dos bytes da worktree e do código XY, nunca do índice. Reprodução: `a.txt` com status `MM`, troca do blob staged via `git update-index --cacheinfo` com os mesmos bytes na worktree; resultado `F1 index changed: True | tree equal: True`.
2. **`git status` que falha** (`guard.py:27`, Codex): `git()` devolve `""` quando o comando falha, e `tree()` vira `{}` nos dois lados. Reprodução: `chmod 0 .git/index`, depois um arquivo novo; resultado `F2 tree before/after: {} {} | head still read: True`. A guarda tem de falhar fechada.
3. **Arquivos ignorados** (`guard.py:33`, revisor, segurança): sem `--ignored`, o review pode escrever `.claude/settings.local.json` ou `hooks-config.local.json` (`.gitignore:15-16`, lido em `knowledge/config.py:36`) e ainda sair com exit 0.
4. **Refs fora do HEAD** (`guard.py:59`, revisor, segurança): só são lidos o nome do ref do HEAD, o reflog do HEAD, `refs/stash` e o HEAD de cada worktree. `git branch x` ou `git tag y` passam, embora a regra do prompt (`review.py:36`) proíba branch.

Consequência: um Codex sob bypass pode alterar estado que a guarda declara provado, inclusive a configuração local de permissões do Claude.

**Decisão do dono delegado:** vigiar `git for-each-ref` (todas as refs), o hash do índice (`git ls-files -s` ou equivalente) e os arquivos ignorados sob `.claude/` e `**/*.local.json`; qualquer comando git da guarda que falhe vira recusa ou exit 2, nunca uma árvore vazia. Não se vigiam todos os ignorados (caches de teste dariam falso positivo). Atualizar `codex-pillar.md` §The git guard e o README.

## Proposal

A guarda do `cq codex review` passa a ler, antes e depois, todas as refs (`git for-each-ref`), o hash do índice (`git ls-files -s`) e os arquivos ignorados de configuração local (`.claude/**` e `*.local.json`); um comando git da guarda que falhe vira recusa (antes da execução) ou exit 2 `codex-git-guard` (depois), nunca uma árvore vazia.
## Out of Scope

- Vigiar todos os ignorados: caches de teste dariam falso positivo (decisão do dono delegado).
- A guarda do executor (`implement.py`): continua com `refs`/`touched` lenientes; o escopo é o review.
- Mudar o argv, o prompt ou a regra `RULE` do review.

## Design

`guard.py` ganha `GuardError` e `git_strict` (levanta em exit != 0). `status(strict=True)` e `tree()` usam a leitura estrita; `strict_refs()` devolve `allRefs` (saída de `for-each-ref`) e `index` (sha256 de `ls-files -s -z`). `tree()` acrescenta `!! <sha>` para cada ignorado de `ls-files --others --ignored --exclude-standard` sob `.claude/` ou terminado em `.local.json`. `review.snapshot` junta `refs`, `strict_refs` e `tree`; falha antes da execução recusa (e remove o diretório do run, sem chamar o codex); falha depois devolve exit 2. `git()` lenient e `touched()` ficam para o executor.

## Alternatives Considered

- Tornar `git()` estrito para todos: quebraria o executor e os `rev-parse` de sondagem do review. Rejeitado.
- Vigiar todos os ignorados: falso positivo com caches. Rejeitado pelo dono.

## Risks

- Um repositório com muitos ignorados sob `.claude/` encarece o hash; aceito (poucos arquivos pequenos).
- `for-each-ref` inclui refs que um fetch concorrente move; aceito, o review roda em worktree isolada.

## Outcome
