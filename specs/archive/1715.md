## Problem

Ops crashes when a registry has two generated zones or invalid UTF-8. Independent verification in `../resume-map-verify.json`, item 5, at 719ca3e5 used a target with `ops.opsRoot=scripts` and router `pyproject.toml`; registry write and a clean doctor initially exited 0. Duplicating the generated zone in `scripts/README.md` caused doctor, registry check and status to raise `ValueError: registry document has more than one generated zone` (exit 1). Invalid UTF-8 also caused `registry --check` to raise `UnicodeDecodeError` (exit 1); doctor already handles that encoding case.

Cause: `plugins/quenching/assets/bin/quenching/ops/registry.py:68` raises without callers catching it; `ops/cli.py:116` only catches `FileNotFoundError`, while `checks.py:71` handles encoding. Consequence: the command violates the refusal=2 contract in `common/output.py:5`; exit 1 is confused with findings and doctor loses unrelated diagnostics after a realistic merge conflict. This repository does not adopt ops (`scripts/verify_repo.sh:51-56`); consumer targets are affected.

Scope: return typed refusal via `refuse(...)` (exit 2) from registry verbs and a dedicated `op-registry-*` finding from doctor/status for malformed zones, preserving other findings. Files: `plugins/quenching/assets/bin/quenching/ops/cli.py`, `checks.py`, `registry.py`, and `plugins/quenching/tests/test_ops.py`. Do not change registry lifecycle (1621), grants or execution surfaces.

Acceptance: neither duplicate zones nor invalid UTF-8 produces a traceback; registry check exits 2 with a message; doctor/status retain the appropriate finding and unrelated findings. Behavioral regressions fail on the base. `python3 -m unittest discover -s plugins/quenching/tests -p test_ops.py` and `bash scripts/verify_repo.sh` exit 0.

## Proposal

- A registry document with more than one generated zone makes `cq ops registry` (check and write) refuse with exit 2 and a typed code, never a traceback.
- A registry document that is not valid UTF-8 makes `cq ops registry` refuse with exit 2 and a typed code, never a traceback.
- `doctor` and `status` report a malformed registry zone as a dedicated `op-registry-malformed` finding and keep every unrelated finding.
- Regression tests fail on the base and pass after the change.

## Out of Scope

- Registry lifecycle parsing (1621), grants and execution surfaces: untouched.
- Changing how doctor already treats invalid UTF-8 (registry read as absent, `op-undocumented`): kept.

## Design

- Rule: `registry.py` raises `RegistryError(ValueError)` for a duplicated zone, and exposes `read_registry(path)` that returns `""` when absent and raises `RegistryError` on invalid UTF-8. Callers translate the typed error; nothing catches bare `ValueError`.
- Rule: the registry verb refuses through `refuse({"code": "op-registry-malformed", ...})` (exit 2, per `common/output.py`), for both check and write.
- Rule: `check_registry_stale` catches `RegistryError` from rendering and returns an `op-registry-malformed` finding in place of `op-registry-stale`; `_registry_text` keeps returning None on decode errors so existing doctor behaviour is preserved.
- Alternative weighed: reuse `op-registry-stale` for the malformed case; rejected because stale means "regenerate", which would then crash.

## Alternatives Considered

- Catch `ValueError` broadly in `main`: rejected, it would mask unrelated bugs as refusals.
- Auto-merge duplicate zones on write: rejected, it silently rewrites authored content after a merge conflict.

## Open Decisions
