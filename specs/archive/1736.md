## Problem

Since PR #1735 (spec 1733, merge 1c00c6e3), `check_registry_stale` in `plugins/quenching/assets/bin/quenching/ops/checks.py:110-117` only tests `is_file()` and then calls `registry.read_registry` (`ops/registry.py:67-74`), which handles only `FileNotFoundError` and `UnicodeDecodeError`; the `except` at `checks.py:116` catches only `RegistryError`. Any other `OSError` (permission denied, EISDIR through a symlink, I/O error) now escapes as a traceback. Before, `_registry_text` caught `OSError` and returned `[]`.

Reproduction: the `MalformedRegistry._target` fixture with `scripts/README.md` set to `chmod 000`, then `python3 plugins/quenching/assets/bin/cq ops doctor --json` → `PermissionError: [Errno 13] Permission denied: '.../scripts/README.md'`, exit 1. On d32cf79b the same fixture returns JSON with `"ok": false`, no exception.

Consequence: violates the contract in `tests/test_ops.py:782` ("a typed refusal or a finding, never a traceback"); doctor crashes instead of reporting. Expected: an unreadable registry maps to `op-registry-malformed` (or the pre-1733 behavior), with a test covering it.

## Proposal

- `ops doctor` reports an existing registry that cannot be read (any `OSError` other than absence) as one `op-registry-malformed` finding, never a traceback.
- `cq ops registry` and `registry --write` refuse the same unreadable registry with a typed exit 2.
- A regression test covers the unreadable case.

## Out of Scope

- Changing the finding codes or the invalid-UTF-8 message: spec 1733 settled them.
- Other readers of `scripts/README.md`: not part of this regression.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/ops/registry.py` — `read_registry` maps `OSError` to `RegistryError`
- `plugins/quenching/tests/test_ops.py` — regression test in `MalformedRegistry`

## Validation

- `python3 -m unittest plugins/quenching/tests/test_ops.py` exits 0, including the new unreadable-registry test.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Rule: `read_registry` is the single boundary where reading failures become `RegistryError`; callers (`check_registry_stale`, the registry command) already map that type to a finding or exit 2. Catch `OSError` after `FileNotFoundError` there, rather than widening each caller's `except`.
- Assumption: the message names the path and the OS reason.

## Alternatives Considered

- Widen `except` in `check_registry_stale` to `OSError`: rejected, it would leave `registry`/`--write` with the same traceback.

## Open Decisions

- none — the finding code is the existing `op-registry-malformed`, as the Problem expects.

## Risks

- A permission-based test cannot fail when run as root: the test skips under root. ACCEPTED — the gate runs unprivileged.
