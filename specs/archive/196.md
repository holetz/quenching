## Design

- 2026-11-21 — Política de autonomia: o humano invocou `/quenching-specs autopilot --until-dry` (sem teto). A invocação autoriza a execução forçada (develop com `approved` `orchestrator-forced`, execute, conclude), o push, o PR e o merge de cada membro depois de um PASS do spec-verifier com CI verde. No máximo 3 workers simultâneos (limite rígido); nenhum parâmetro de modelo nos sub-agentes; git só leitura fora dos worktrees dos workers.
- 2026-11-21 — Checkout sujo: 0 caminhos. O checkout principal fica na branch do humano (plan/1037500-merge-sem-checks) e nunca é trocado; todo worktree é cortado de origin/main.
- 2026-11-21 — Mãos fora: PR #170 e as specs 2249, 2253, 2254–2257, 2271 e 2272 são do humano. Também ficam de fora git/azure_pull.py, git/pr*, git/pull.py e git/merge* (a branch do humano).
- 2026-11-21 — Ondas: 191, 192 e 193 tocam codex/implement.py e por isso rodam em série (191 → 192 → 193). 190 (mcp/), 194 (codex/probe.py) e 195 (delivery/inventory.py) são disjuntos. Os quatro falsos erros do delivery viraram uma spec só, porque são o mesmo arquivo e a mesma classe de erro.
- 2026-11-21 — 191: a correção falha fechado (recusa quando git status falha). Isso só estreita a guarda e não muda o flag do executor nem nenhuma grant.
- 2026-11-21 — 195: o escopo é a inventory e o check do delivery (assumir o trigger padrão da plataforma quando a chave falta, aceitar `"on":` entre aspas, contar `container:` do GitHub como setup). Nenhum workflow de CI deste repositório muda.
- 2026-11-21 — Mandada ao épico do humano 2206 (S22): 189 (o conclude commita sem tarefa × check 4 do verifier). Escolher entre o verifier reconhecer o conclude como declarante e o conclude declarar uma tarefa [conclude] muda o contrato de aceitação do fluxo autônomo, logo nunca é forçada.
