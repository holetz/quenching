## Problem

Em 2026-10-25, num run do orchestrator no forge lançado a partir da sessão do quenching, o verifier deu um FAIL inconclusivo. Os verbos `cq git` (`audit`, `history`, `state`) usam o diretório onde o shell começa, e esse diretório era o checkout do quenching. Diferente de `cq specs`, eles não aceitam `--root`. Prefixar `cd <repo> && ` resolveu, mas os agentes `verifier` e `reviewer` têm grants escopados como `Bash(cq git audit:*)`. Um prefixo `cd` fica fora desse grant e só funciona porque a sessão está em bypass.

Proposta: dar `--root PATH` a todo verbo `cq git` que lê um repositório, com o mesmo contrato de `cq specs --root`. O orchestrator passa a repassar `--root` ao verifier e ao reviewer quando o repositório alvo não é o da sessão.

Done when: os verbos aceitam `--root`, com teste que roda contra um repositório temporário a partir de outro cwd; os corpos do verifier, do reviewer e do orchestrator citam `--root` para runs entre repositórios; os espelhos foram regenerados; o gate passa. Nenhum grant muda: `Bash(cq git audit:*)` já cobre `cq git audit --root …`.

## Proposal

- Os verbos `cq git` que leem um repositório (`base`, `stale`, `conventions`, `state`, `history`, `preflight`, `audit`) aceitam `--root PATH` e leem esse repositório a partir de qualquer cwd.
- Um `--root` que não é diretório é recusa (exit 2), sem ler nada.
- Os corpos do `verifier`, do `reviewer` e do `orchestrator` citam `--root` para runs entre repositórios, no lugar do prefixo `cd <repo> &&`.
- Um teste roda os verbos contra um repositório temporário a partir de outro cwd; os espelhos estão regenerados e o gate passa.

## Out of Scope

- `--root` nos verbos que escrevem (`commit`, `worktree`, `push`, `prune`, `pr`, `specs`): continuam sempre no cwd do worktree, porque uma escrita no repositório errado é pior que uma leitura nele. Os corpos de `git/branch.md` e `specs/execute.md` ganham só a precisão "nos verbos de escrita".
- Qualquer mudança de grant, `tools:`, hook ou CI: `Bash(cq git audit:*)` já cobre `cq git audit --root …`.

## Design

- **Decisão:** `--root` é opção de cada verbo de leitura, e `main` faz `os.chdir(root)` antes do despacho. Os verbos já derivam tudo de `os.getcwd()`, então um único ponto cobre todos sem mexer em cada módulo. Regra durável: um caminho relativo em outra opção resolve contra o `--root`.
- **Alternativa pesada:** `--root` global no pilar `git` (via `takes_root` no `cq`) também liberaria os verbos de escrita; rejeitada, ver Out of Scope.
- **Contrato:** o grant escopado `Bash(cq git <verbo>:*)` casa por prefixo, então `--root` depois do verbo continua coberto.

## Alternatives Considered

- `--root` global no pilar `git`, repassado pelo `cq --root`: perdeu por liberar os verbos de escrita.
- Manter o prefixo `cd <repo> &&`: perdeu porque fica fora do grant escopado e só funciona em bypass.
