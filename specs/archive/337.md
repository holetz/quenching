## Problem

Medido em 2026-11-24 por um scout do autopilot (clone em scratchpad, nice 19, 12 núcleos, com outros gates rodando: 2m48s real, 3m59s user, 1m41s sys; na máquina livre o gate mede 1m42s). A mesma suíte sem `--cov` levou 43,5 s (pytest) / 58 s (parede) contra 104,6 s com coverage; a coleta leva 2,1 s. `quenching/assets/checks/citation-check.sh:192-194` roda `git grep` duas vezes por padrão morto (`-c` e depois `-o`) em 10 padrões (14,4 s no passo de citação).

**Consequência:** ~35 s de coverage por gate completo e alguns segundos de grep duplicado em todo gate.

Proposta: `COVERAGE_CORE=sysmon` quando o interpretador é ≥ 3.12 (medir; manter o piso de coverage idêntico), conferir que o combine não relê `.quenching/coverage/.coverage.*` velhos, e um único `git grep -o` por padrão no citation-check. Provar com a medição antes/depois no mesmo host.

## Proposal

- `scripts/verify_repo.sh` selects `COVERAGE_CORE=sysmon` for the measured pytest run when the interpreter is >= 3.12, unless the operator already set `COVERAGE_CORE`; the coverage totals and the floor stay identical.
- The measured run drops stale `.quenching/coverage/.coverage*` data before it starts, so the combine never reads a killed run's leftovers.
- `citation-check.sh` runs one `git grep -o` per dead pattern and derives both the file count and the occurrence count from it, with the same output as before.

## Out of Scope

- Lowering or bypassing the coverage floor, or dropping coverage from the full gate: epic 335 keeps the CI/release gate whole.
- Branch coverage or dynamic contexts (not supported by sysmon on older interpreters; the repo measures statement coverage only).

## Impact

### Product code this spec expects to touch

- `scripts/verify_repo.sh` — coverage core and stale-data cleanup
- `quenching/assets/checks/citation-check.sh` — one grep per dead pattern

### Process surface this spec expects to touch

- `quenching/assets/checks/citation-check.sh` — shipped check; its deployed mirror under `.agents/quenching/` is regenerated by the deploy

## Validation

- `bash scripts/verify_repo.sh` under `QUENCHING_TEST_SCOPE=affected` exits 0.
- `bash quenching/assets/checks/citation-check.sh .` exits 0 with output byte-identical to the previous version.
- Coverage `totals` of a run with `COVERAGE_CORE=sysmon` equal those of the default core (measured: 24141/28342 covered statements, both).

## Design

- Decision: the core is chosen by the gate, not by `pyproject.toml`, because `requires-python` stays >= 3.11 where sysmon does not exist. Rule: an operator-set `COVERAGE_CORE` always wins.
- Decision: stale coverage data is removed in the gate before the measured run, the only place that owns `COVERAGE_FILE`.
- Binding: epic 335 Design — the full CI/release gate (coverage floor included) is never weakened.
- Measurement (2026-11-24, this host, Python 3.14.4, coverage 7.17.3, seed 1, `-n 6`, other gates running): pytest 49.9 s with `ctrace`, ~45 s default/`sysmon` (3.14 already defaults near sysmon), 40.7 s without coverage. The ~35 s overhead measured by the scout belongs to older interpreters; the explicit choice protects 3.12/3.13 hosts and CI.

## Alternatives Considered

- Drop the JSON/combine step by running coverage serially: rejected, loses xdist parallelism.
- Cache the dead-pattern sweep across runs: rejected, a stale cache would hide a regression the check exists to catch.

## Open Decisions

- none — every decision is settled by the measurement above.

## Risks

- sysmon on Python 3.12/3.13 reports differently for some constructs: mitigated by the identical totals on 3.14 and by the floor check in CI, which fails loudly on a drop. ACCEPTED — the operator override `COVERAGE_CORE=ctrace` restores the old core.
