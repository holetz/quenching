## Problem

Não há semente real: o único criador do arquivo é `cq doctor --setup` (`common/config.py:259-297`), que ninguém chama, grava `backend: github|azure-boards` (deprecado; o padrão é `git`) e só `profiles`, de modo que um projeto novo nasce sem nenhuma chave visível. Decisão do humano em 2026-10-17 (C1 A): `cq config init` grava todos os defaults ajustáveis por extenso (codex, executor, orçamentos, teto de lançamentos, chat, autonomia), `/quenching-align:align` o chama, e o `doctor` acusa chaves faltando em vez de deixá-las invisíveis. Mapa: `~/Projetos/quenching/.quenching/autopilot/2026-10-17/config-map.md`.

## Proposal

- `cq config init` previews, and with `--write` creates, `.claude/quenching.json` carrying every adjustable default spelled out: `shared.codex` (including `executor`), `shared.autonomy`, `shared.workHost` (the leaves that have a non-null default), `shared.contextBudgets`, `shared.okfValidate`, `specs.chat`, plus `backend: git` and the detected `shared.profiles.installed`.
- `cq config check` and the top-level `cq doctor` name the seeded keys the file lacks (exit 1 from `check`; `doctor` only reports), so a key added in a later release stops being invisible.
- `/quenching-align:align` calls `init` when the file is absent and reports the missing keys when it is present, under the authorization it already asks for.
- The configuration standard and the product manual describe the seed and the check.

## Out of Scope

- Rewriting or merging into an existing file: `init` refuses when the file exists (exit 2), the same posture as `doctor --setup`. Filling missing keys into a file the human edited is a separate decision (see Open Decisions).
- Removing `cq doctor --setup` or its deprecated `backend: github|azure-boards` write: left in place; both write the same file, and only one can create it.
- Keys spec 1661 (model policy) may add later: the seed reads the code defaults, so a new block joins by adding its defaults to the seed module.
- The config-map inconsistencies 1-8 beyond the table of keys this change touches.
- A `workHost.target`, `dockerContext` or `runner` entry: their default is null and the loader warns on a null, so they stay out of the seed and are documented as optional.

## Design

**One module owns the seed.** `config/seed.py` builds the document from the owning modules' own constants, so the seed cannot drift from the code: `codex.config.DEFAULTS`, `config.autonomy.DEFAULTS`, `config.host.DEFAULTS` (minus null leaves), `session.commands.context.BUDGETS`, and `specs.chat` constants. Two defaults live where the `quenching-specs` module cannot import them (`knowledge.config.DEFAULTS` — the specs module has no `knowledge` tree; the chat model `"sonnet"` — hardcoded in `specs/portal.py`). Those are restated in the seed and pinned by a test that compares them with the owners, so a change on either side fails the gate.

**The seed spells every leaf.** Nested blocks (`codex.maxUsedPercent`, `codex.executor`) are written whole. `check` flattens both the seed and the repository file to dotted leaves and reports seed leaves the file lacks; it never reports extra keys (unknown keys are the loaders' business) and it reads only the repository file, not the user or branch layer, because `init` and the file are what the human edits.

**`init` shape:** preview by default, `--write` creates, an existing file is exit 2 (`cq-config-present`) with a remedy pointing at `check`. `backend` is written as `git`, the documented default; the deprecated provider backends stay with `doctor --setup`. `profiles.installed` reuses `detect_profile(root, "git")`.

**`doctor` reports in `run()` only.** `inspect_environment` stays side-effect free and byte-stable for its many tests; the human and JSON output gain a `config` block (`present`, `missing`). The import of the seed module is guarded, because some generated modules ship no `config` tree... they all ship it after regeneration for `quenching`, `quenching-specs` and `quenching-codex`; the other plugins ship `common` only, so the guard returns "not checked" there.

**Align calls `init`, under the authorization it already holds.** The conductor's Applicability section gains a configuration probe (`cq config check --json`): file absent -> the plan lists "seed .claude/quenching.json" and the OK covers `cq config init --write`; file present with missing keys -> reported, not rewritten.

## Alternatives Considered

- **Seed from a static JSON file shipped in the plugin.** Rejected: a second copy of the defaults that drifts from the code the first time a block changes; building from the owners' constants is the same cost with no drift.
- **`cq doctor --setup` grows the full seed.** Rejected: it writes a deprecated backend and lives in the top-level prerequisite check; a configuration verb belongs in the `config` pillar, which already owns `show --effective`.
- **`check --fix` merges missing keys into an existing file.** Deferred: a rewrite of a human-edited file needs an opinion on key order and comments (the file is plain JSON), so the first version only reports.

## Open Decisions

- Whether a later `config init --fill` should merge missing keys into an existing file: decided when the first release adds a key and the report shows how often humans hit it.
- Whether the seed should also carry the `specs` provider keys (`artifactLanguage`, `card`): not now, they have no code default to spell out; decided when one is given.

## Risks

- A generated mirror lacking `config` raises on import in `doctor`: mitigated by the guarded import and a test that runs the doctor with the import failing.
- Spec 1661 adds a block after this lands and the seed misses it: ACCEPTED — `check` against a seed that lacks the block cannot see it, and the fix is one line in `seed.py`; the spec-1661 branch rebases onto the seed module's list.
- A seeded value freezes today's default in user files, so a later default change does not reach them: ACCEPTED — that is the explicit-default trade the human chose (C1 A); `check` makes it visible, not automatic.
