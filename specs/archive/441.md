## Problem

Reproduzido pelo condutor em 2026-11-24 (épico 415): com o servidor `quenching` carregado antes do merge da 435, `specs_show(spec=415, full=true)` devolveu `ok: true` e o **índice** da spec (`"view": "index"`, só títulos de seção, 912 bytes) — o `full` não existe no `inputSchema` daquele servidor (`spec`, `tasks`) e foi descartado sem aviso. O spec-verifier da 418 leu esse índice como se fosse o documento e deu FAIL no check 9 por "não achar" um bullet que estava lá; custou dois verifiers e um relançamento.

**Consequência:** uma ferramenta que ignora argumento desconhecido falha **aberta**: o modelo acredita ter pedido uma coisa e recebe outra com `ok: true`. Com o MCP como porta única (épico 415), todo descompasso entre o corpo que cita um parâmetro e o servidor que está rodando (servidor não recarregado, versão anterior, typo) vira resultado errado silencioso em vez de recusa.

## Proposal

O servidor valida os argumentos contra o `inputSchema` de cada ferramenta (`additionalProperties: false` e checagem no despacho) e recusa argumento desconhecido com erro tipado (exit 2 / `isError`), nomeando o parâmetro e a versão do servidor — a mensagem diz "recarregue o servidor" quando a fonte do repositório declara o parâmetro e o processo carregado não. Teste por ferramenta: argumento extra é recusado, nunca ignorado.

## Out of Scope

- A superfície `catalog.py` (`argv()`) — já recusa argumento desconhecido; este spec só fecha o caminho das ferramentas `specs_*`.
- Validar tipos e valores aninhados — já é feito pelos construtores de argv de cada ferramenta.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/specs/mcp.py` — despacho das ferramentas `specs_*`
- `quenching/tests/test_specs_mcp.py` — prova por ferramenta

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_specs_mcp.py` sai 0; cada ferramenta de `TOOLS` e `WRITES` recusa um argumento extra com `mcp-bad-arguments`.
- `bash scripts/verify_repo.sh` verde no fechamento.

## Design

Causa: `catalog.argv()` recusa o desconhecido, mas as ferramentas `specs_*` são servidas por `specs/mcp.py` (`call_tool`/`call_write`), cujos construtores de argv leem só as chaves que conhecem e descartam o resto — o `inputSchema` com `additionalProperties: false` só era anunciado, nunca imposto.

Decisão: uma checagem única, `_reject_unknown(schema, args)`, no início de ambos os despachos, contra `properties` do `inputSchema` (`root` está no schema via `_schema`). Mensagem: nomeia os desconhecidos, a versão do servidor e diz para recarregar o servidor se a fonte do repositório declara o parâmetro.

### Assumptions

- A versão vem de `quenching.common.version.VERSION`, a mesma do `serverInfo` (Validation).

## Alternatives Considered

- Validar com uma biblioteca de JSON Schema — rejeitada: dependência nova para checar só as chaves de topo.
- Comparar a fonte do repositório com o processo carregado para só então dizer "recarregue" — rejeitada: o servidor não conhece a fonte do repositório; a mensagem condicional cobre o caso.

## Open Decisions

- none — a forma da recusa segue o código `mcp-bad-arguments` já existente.

## Risks

- Um cliente que mandava argumento extra passa a ser recusado — é o comportamento pedido. ACCEPTED — falhar fechado é o objetivo.

## Outcome
