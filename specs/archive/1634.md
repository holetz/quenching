## Problem

Eight plugin modules approved by ADR 0013 need explicit ownership for resources that the current single plugin shares implicitly: `assets/bin/quenching/common`, the `cq` router, and reference closures addressed through each plugin's own root. The current specs-reader generator hard-codes one consumer, while release hard-codes seven version surfaces. Adding consumers separately would duplicate both contracts and permit silent payload or version drift.

The approved form A requires one declarative distribution contract before production extraction. The specs reader is the first real consumer: preserve its read-only behavior and existing payload while proving general generation and lockstep. This unlocks spec 1635 without extracting production modules here.
## Proposal

- Declare current published plugins, generated versus authored payload ownership, eight planned principal modules, their source ownership and generated support closures in one manifest.
- Generate the reader through one manifest-driven `--write`/`--check` tool; preserve its authored command, read-only shim and README and reject unsafe manifests before writing.
- Derive the published release surface list from that manifest and enforce published version agreement and one active PATH `cq` owner in the repository gate.
- Keep the existing reader sync invocation as a compatibility wrapper over the same generator, with no independent generation rules.

## Out of Scope

- Production extraction, namespace rewriting, optional-front loaders and activation of eight modules belong to spec 1635; planned records must not create directories or marketplace entries here.
- A shared dependency-only base is rejected by ADR 0013; no host-dependent cross-plugin citation locator is introduced.
- Version bumps, publication, native residency measurements and changes to the reader's permission/write-block policy are not part of this foundation.

## Design

Use `plugins/quenching/assets/modules.json` as the sole declarative source, loaded by a stdlib helper under `common`. Current `quenching`, `quenching-specs-reader` and `quenching-hud` records are published. Eight principal records are planned, not published: specs owns specs/git/session and the future PATH shim; alignment owns knowledge/components/root align; design, ops, proof, toolchain, delivery and security own their respective fronts. Specs includes generated components support; alignment includes generated session support; proof includes generated ops support. Shared references use the explicit transitive closure S and per-module additions in ADR 0013. This is a declaration, not a claim that extraction is already shipped.

The editable common/router/reference source remains `plugins/quenching`. The reader declares its four copy trees and generated metadata, and its three authored paths. The generic tool derives source/version/author/license and preserves file bytes and executable bits. It preflights all records, rejects absolute/traversing/symlink paths and authored/generated overlaps before mutation, deletes stale files only below declared generated trees, and ignores Python caches. Generated provenance names the manifest and general generator. Missing source roots are refusals, not empty copies. `--check` compares without mutation and audits every published version surface, marketplace membership and the current single cq PATH owner. Inactive module records are validated but never materialized.

Release derives VERSION/plugin metadata surfaces from published records, plus marketplace and the source shared VERSION constant. Retain `RELEASE_ARTIFACTS` as a derived compatibility export for existing callers/tests, but load the target repository's manifest for a real bump. All artifact existence, changelog and version checks remain before any writes. Generated asset refresh remains a separate general-generator step after bump, as the existing contract requires; this spec does not widen release commits to silently include regenerated assets.

Keep `scripts/sync_specs_reader_plugin.py` as a thin compatibility entry point so conclude's executable recipe and existing automation do not become orphaned. The repository gate itself calls the general tool.

## Risks

- Deleting authored payload during stale cleanup: preflight disjoint generated/authored roots, restrict stale discovery to generated trees, and fixture-test preservation.
- Missing sources silently producing empty consumers: validate all copy roots and reject before writes.
- Version or marketplace drift escaping a copied-payload check: audit published surfaces separately in the same `--check` call; retain refusal-before-write in release.
- Planned modules becoming accidentally published: explicit published flag and no directory creation for inactive records, proved by fixtures.
- ACCEPTED — temporary legacy quenching ownership of cq remains until spec 1635 activates specs ownership; the manifest records both states explicitly.
