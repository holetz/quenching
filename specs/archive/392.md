## Problem

Achado de segurança reproduzido pela revisão da rodada 4 do autopilot de 2026-11-24 (PR #391, spec 389): `git init -q --separate-git-dir "$S/p/gd/.git" sep && python3 quenching/assets/bin/cq doctor --antivirus --root sep --json` lista `paths ['$S/p/gd', '$S/p/gd-slot-*', …]`, enquanto `git -C sep rev-parse --show-toplevel` é `$S/p/sep`, que nunca aparece. Causa: `quenching/assets/bin/quenching/common/doctor.py:222-224` (`_primary_root`) devolve `dirname(common)` quando o basename do git common dir é `.git`, sem comparar com `--show-toplevel`; `_too_broad` (`:231-241`) só barra raiz, home, temp e ancestrais.

**Consequência:** com um git dir em `/opt/.git` ou `~/work/.git`, o doctor manda excluir `/opt` ou `~/work` (mais o curinga `-slot-*`) e deixa a worktree real fora da lista — uma exclusão larga demais e no lugar errado.

Proposta: a raiz primária é a worktree principal (`git worktree list --porcelain`, primeira entrada, ou `--show-toplevel` quando o common dir não é `<toplevel>/.git`); a pasta do git dir só entra se estiver dentro da worktree; teste com `--separate-git-dir` e com um slot.

## Proposal

`_primary_root` (`quenching/assets/bin/quenching/common/doctor.py`) passa a devolver a worktree principal provada, nunca a pasta-mãe do git dir por dedução de nome:

- na worktree principal (`--absolute-git-dir` == `--git-common-dir`), a raiz é `--show-toplevel` — vale para o repositório comum e para o `--separate-git-dir`;
- numa worktree ligada (slot), a raiz é o primeiro candidato que prova ser dono do common dir: o irmão sem o sufixo `-slot-<n>` cujo `.git` (arquivo `gitdir:` ou diretório) resolve ao common dir, depois `dirname(common)` quando o common dir se chama `.git` e a pasta tem ao menos um caminho rastreado no índice principal presente nela; nenhum provado → `--show-toplevel` da própria worktree (mais estreito, nunca mais largo).

O git dir fora da worktree não vira exclusão: entra em "Not listed" com o motivo. Dentro do repositório comum a saída não muda (byte a byte).

## Out of Scope

- `git worktree list` como fonte: com `--separate-git-dir` o próprio git responde a pasta-mãe do git dir (reproduzido), então não prova nada.
- Repositório `--bare` e `core.worktree` explícito: não são forma de checkout que o quenching cria; seguem o caminho do `--show-toplevel`.
- Mudar `_too_broad`, a recusa fora de repositório (spec 389) ou o restante da lista (cache, `.venv`, `uv`, processos).
