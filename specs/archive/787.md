## Overview

O README do plugin é o primeiro arquivo que alguém lê antes de instalar quenching, e hoje ele
descreve uma arquitetura que o plugin abandonou: trinta skills, uma árvore `skills/` que não existe
e doze seções cabeçadas por nomes retirados. `## Problem` mostra que "prosa obsoleta" é o sintoma —
a causa é o README manter uma segunda cópia, escrita à mão e sem nenhuma checagem, da description de
cada command; e mostra o que isso já custa, medido: quatro links que não resolvem, quatro commands
sem entrada nenhuma, e um changelog parado duas releases atrás do `VERSION`.

`## Proposal` lista o que passa a ser verdade, e `## Alternatives Considered` compara as quatro
formas que o manual poderia ter tomado, incluindo a de gerar a lista por código — rejeitada por um
motivo concreto que `## Design` desenvolve: a `description` de um command é material de routing, não
prosa de manual, então a lista continua escrita à mão e ganha uma checagem em vez de um gerador.
`## Design` também fixa o que **não** pode se mover — o heading `## Cost model`, porque quatro
citações vivas apontam para aquela âncora e duas delas embarcam dentro do plugin — o que sai do
arquivo por pertencer aos standards deste repo e não ao produto, e onde a checagem passa a morar
para que ela realmente rode depois deste spec. Essa última decisão é o que `## Impact` declara como
o único standard que este spec escreve.

`## Validation` é onde a promessa fica exigível: oito asserções, todas rodadas contra o arquivo atual
durante o develop, então cada uma já se sabe verde ou vermelha e por quê. Vale ler junto com
`## Risks`: dos nove riscos listados, cinco são fechados por uma asserção nominal, e o mais caro
deles — uma âncora quebrada que embarca para quem já adotou o plugin — é o único cujo conserto não é
um revert, o que é por que ele roda antes do merge.

`## Tasks` põe a checagem antes da reescrita, de propósito, para a autoria ter sinal desde a primeira
linha. `## Out of Scope` desenha a fronteira com três specs que reescreveriam este mesmo arquivo,
`## Risks` nomeia cada um deles, e `## Open Decisions` guarda as duas perguntas que a autoria resolve
melhor do que a antecipação.
## Problem

`plugins/quenching/README.md` ainda documenta a arquitetura de dois arquivos que o spec
`collapse-skills-into-commands` apagou. A task 5.3 daquele spec tinha escopo só em §Cost model, que
foi reescrita; **as outras ~131 linhas não foram** — os blocos `###` cabeçados por nome de skill, o
layout `.claude/skills/` como se fosse casa do plugin, e toda a prosa de wrapper descrevem uma forma
que o plugin não tem mais.

Um rename cego sobre o arquivo inteiro foi **tentado e revertido** durante aquele spec: mastigou 28
caminhos de link em formas como `skills//docs:add/references/homes.md`. Essa é a evidência de que
aqui é autoria, e não substituição — e a razão de o trabalho ter ficado fora de uma migração cujo
diff tinha de continuar revisável.

### A causa, não o sintoma

Ler o arquivo mostra que "prosa obsoleta" é o sintoma. O defeito causal é que o README mantém uma
**segunda cópia, escrita à mão, da description de cada command** — blocos `###` cuja única fonte é
alguém redigitando o que o frontmatter de `commands/**/*.md` já diz. Essa cópia não tem nenhuma
checagem, então ela deriva a cada mudança de surface; o collapse apenas tornou a deriva visível em
escala.

## Proposal

- O manual descreve **todas** as commands que existem em `commands/**`, uma linha por command, e
  nenhuma entrada nomeia um artefato que o plugin não tem mais. A contagem é uma propriedade das
  linhas da tabela, não uma afirmação em prosa — ela aparece escrita só onde é inevitável, e ali é
  comparada com `cq --root . components doctor --json`.
- Nenhum heading do arquivo carrega nome de skill retirado (`quenching-knowledge-*`,
  `quenching-components-*`, `quenching-handoff`, `quenching-align-all`): a identidade de cada command
  é o caminho invocável, como `/.knowledge/standards/naming/command-surface.md` §The path IS the
  identity (`authority: current`) exige. São **13** headings hoje.
- **Todo link do arquivo resolve, e nenhum é absoluto de raiz.** Os dois `ABS-ROOT` restantes
  passam a ser relativos.
- `## Upgrade` alcança o `VERSION`: as sete releases com tag que faltam — **4.13.0, 5.0.0, 6.0.0,
  6.0.1, 6.1.0, 6.2.0, 6.3.0** — entram, então o log para de terminar sete releases atrás.
- O heading `## Cost model` e a tabela de model policy dentro dele continuam existindo e continuam
  alcançáveis pela âncora `#cost-model`, que **cinco** citadores resolvem — dois deles em runtime, na
  sessão de quem adotou o plugin, e dois na tradução Codex.
- Nenhuma doutrina de operação **deste** repo permanece restatement no README: o que sobrar de
  procedimento de release e de how-to de checks vira ponteiro para os donos em `/.knowledge/standards/`.
- Uma **checagem mecânica** compara a lista de commands do README com `commands/**` e falha quando
  as duas divergem. Ela mora em `plugins/quenching/tests/`, que o bloco de verificação de CLAUDE.md
  já roda por `python3 -m unittest discover -s tests` — então ela roda dali para frente **sem
  CLAUDE.md ganhar nenhuma linha**.
- O arquivo fica **menor** do que as 793 linhas atuais.

- **Os quatro links relativos quebrados, os caminhos `skills/quenching-*` e a afirmação corrente da

## Design

### Quatro tabelas por família, não um bloco de prosa por command

O manual passa a ser **quatro tabelas mais duas linhas de raiz** — treze `/quenching:knowledge:*`,
nove `/quenching:specs:*`, sete `/quenching:components:*`, sete `/quenching:git:*`, mais
`/quenching:align` e `/quenching:handoff` — com uma linha por command: nome invocável e uma frase
dizendo o que ele faz. É a forma que §The `specs` flow já prova dentro do próprio arquivo: foi o
único front reescrito no fold, é o único que não obsoletou, e é o único cuja contagem é
**estrutural** (linhas se contam) em vez de prosa.

**A regra durável:** um inventário escrito à mão de uma surface montada em session start só se
justifica quando a contagem é uma propriedade da estrutura e não uma afirmação em prosa.

Isso derruba treze blocos `###` e, com eles, a fonte estrutural dos caminhos de citação reescritos à
mão — que só existem porque cada bloco redigitava um caminho que o body do command já cita
corretamente por `${CLAUDE_PLUGIN_ROOT}`.

### A coluna de papel é prosa autoral, não paráfrase da description

A suposição que sustentaria "só aponte para o frontmatter" é que a `description` de um command serve
como manual. **Ela é falsa**, e vale testar em vez de assumir: a `description` de
`commands/components/command/retro.md` são onze linhas de trigger phrases e de fronteiras
`Not for:`. É material de routing, escrito para o roteador, não para um leitor humano.

Logo a coluna de papel carrega a carga explicativa inteira e é **escrita**, uma frase por command,
como as linhas de `/quenching:specs:*` já são. Uma paráfrase da description reproduziria o defeito
em prosa mais curta.

### A tabela de model policy sobrevive; a âncora que a alcança tem de voltar a resolver

A seção que carrega a tabela de model policy **não pode ser cortada**: cinco citações vivas apontam
para ela, duas delas resolvendo em runtime na sessão de quem adotou o plugin, e duas na tradução
Codex.

O spec original escreveu que o heading `## Cost model` "não pode ser renomeado nem cortado". **Ele já
foi renomeado** — o commit `618a2bb` (`extensible-surface-and-budget-retirement`, task 2.4) tirou o
§Cost model junto com o orçamento total e deixou `## Model policy` no lugar, sem varrer os cinco
citadores. Uma âncora markdown quebrada falha em silêncio, e é exatamente por isso que a checagem
delas é a asserção V2 e não uma lembrança de quem escreve.

**A decisão é varrer os citadores, não restaurar o nome antigo.** `## Model policy` é o nome
verdadeiro do que a seção carrega hoje; ressuscitar `## Cost model` para satisfazer links seria
manter vivo um segundo nome para a mesma coisa — o defeito que
`/.knowledge/standards/naming/command-surface.md` §The path IS the identity nomeia.

### O que sai: doutrina de operação do repo, não do produto

CLAUDE.md diz que o README é a documentação **do produto** e que os standards deste repo não são
restated ali. O que cruzar essa linha sai e vira ponteiro: procedimento de release tem dono em
`/.knowledge/standards/ci-cd/versioning-release.md`, e how-to de checks tem dono em CLAUDE.md
§Operating e em `/.knowledge/standards/quality/surface-verification.md`. Ficam as frases voltadas ao
adotante — o que Claude Code lê para detectar um upgrade, e o que o `--version` do tool responde.

**Duas coisas que parecem candidatas e ficam.** As "two rules that must survive any future
optimization" ficam: aparecem também em CLAUDE.md, mas ali como regra de refactor deste repo, e aqui
como política que embarca para o adotante que está lendo justamente a tabela de política. E os
"OKF-strict rules the plugin enforces" ficam: é o contrato que o plugin impõe no repo de terceiro,
ou seja, produto.

### Autoria, nunca substituição

O `## Problem` guarda a evidência: um rename cego mastigou 28 caminhos e foi revertido. Portanto
nenhuma passada de `sed`, `perl -pi` ou replace-all sobre este arquivo, em nenhuma task. Cada linha
que muda é lida antes. Custa mais tempo de autoria e é exatamente o que a evidência arquivada compra.

A régua de vocabulário retirado tem de discriminar pelo mesmo motivo: `grep 'skills/'` casa sete
ocorrências corretas de `.claude/skills/`, a superfície do adotante. A que discrimina é
`grep '^### \`quenching-'`.

### A tabela derivada do tool, nunca da memória

A forma como o número errado entra é sempre a mesma: alguém escreve a contagem de cabeça. A task que
escreve as tabelas parte da saída de
`find commands -name '*.md' | sed 's#^commands/##; s#\.md$##; s#/#:#g; s#^#/quenching:#' | sort`, e
de `cq --root . components doctor --json` para a contagem.

**Corolário:** a contagem literal é evitada onde é evitável. A surface saltou de 26 para 38 commands
entre a escrita deste spec e a sua execução — a melhor prova possível de que um número escrito em
prosa tem prazo de validade curto. O texto diz "as commands" e deixa as linhas da tabela carregarem
o número; onde ele é inevitável, V1 o compara com `doctor --json`.

### A casa da checagem mudou de endereço

Trinta e oito linhas de tabela em lockstep manual com `commands/**` é o defeito deste spec
reintroduzido a um décimo do tamanho. Isso só se aceita se o lockstep for verificado por máquina — e
uma asserção que vive **só** em `## Validation` roda uma vez, no conclude deste spec, e nunca mais.
Foi assim que a lista chegou ao estado atual.

O spec original punha a checagem no bloco de verificação de CLAUDE.md. **Essa escolha é de
2026-07-27, quando `plugins/quenching/tests/` não existia.** Hoje existe, e o próprio bloco de
CLAUDE.md já a roda por `python3 -m unittest discover -s tests`. Então a checagem vira um teste na
suíte, e o resultado é estritamente melhor em três eixos:

- **CLAUDE.md não ganha nenhuma linha**, num arquivo que este repo trata declaradamente como ponteiro
  fino e cuja largura é medida.
- **A falha é nomeada.** Um `assertEqual` entre dois conjuntos diz qual command sobrou e qual faltou;
  um `diff` de duas substituições de shell diz que houve diferença.
- **Roda em mais lugares.** Todo caminho que executa a suíte passa a cobrir a lista, não só quem
  segue o bloco de CLAUDE.md à mão.

Duas alternativas seguem descartadas: uma regra de finding no `cq components lint` — o tool roda em
repo de terceiro, e nenhum adotante tem o README do plugin — e `## Validation` sozinha, que é a forma
que não roda.

### Mapa de dependências

Varrido em 2026-08-27. `plugins/quenching/README.md` é folha na árvore de execução — nenhum código o
lê — e nó de citação para cinco arquivos, todos pela mesma âncora:

### Contratos que este design não pode contradizer

- `/.knowledge/standards/naming/command-surface.md` §The path IS the identity (`authority: current`)
  — "There is **no second name**". O README atual viola isso treze vezes; a reescrita é enforcement,
  não preferência, e é também o que decide a âncora a favor de varrer os citadores.
- `/.knowledge/standards/ci-cd/versioning-release.md` §When the bump happens — nenhuma task de bump.
  Escrever entradas de changelog de releases **já tagueadas** é registrar história publicada, não
  bumpar.
- CLAUDE.md — o README é doc do produto; standards deste repo não são restated ali, e CLAUDE.md é
  ponteiro fino.
- CLAUDE.md §Safety that must stay visible — nada aqui toca `context: fork` nem tier de modelo.
## Alternatives Considered

Quatro formas inteiras para o manual, comparadas antes de escrever qualquer linha.

| Forma | Custo | O que compra | O que impede |
| --- | --- | --- | --- |
| **A. Uma tabela por front, uma linha por command** (escolhida) | autoria de 26 linhas mais três cortes | contagem estrutural, ~230 linhas a menos, os quatro links quebrados desaparecem com os blocos, rename barato | nada relevante — a description de cada command continua sendo a fonte longa |
| B. Manter os treze blocos `###` e reescrever cada um | autoria de 26 blocos de prosa | fidelidade à estrutura atual | é a forma que produziu esta bagunça: 26 blocos em lockstep manual com 26 descriptions |
| C. Apagar o manual e apontar para o frontmatter | quase zero | nunca deriva | um adotante no GitHub não lê frontmatter, e §Problem diz que o adotante é o público inteiro do arquivo |
| D. Zona `<!-- GENERATED -->` renderizada por `skills.py` | código novo no tool mais uma checagem | deriva zero por construção | ou cola descriptions de ~1.000 caracteres, ilegíveis, ou exige uma segunda linha curta escrita à mão — a deriva de volta, agora com um gerador para manter |

**B perdeu** porque duplica por design: treze cópias escritas à mão de um texto que já embarca dentro
do arquivo do command. Um bloco por command é o shape skill+wrapper que o collapse acabou de
remover, aplicado a prosa.

**C perdeu** no público, não no custo. É a alternativa mais barata e a mais tentadora, e um README
sem lista de commands falha o único leitor que `## Problem` nomeia. A disciplina dela foi adotada
mesmo assim: uma linha por command, não um parágrafo.

**D perdeu** por legibilidade e por preço. É a forma anti-drift que este repo já usa em
`plans/index.md` e no registry de automation, e teria sido a resposta certa se a description fosse
prosa de manual. Ela não é (ver `## Design` §A coluna de papel). Uma zona gerada a partir de
descriptions de routing seria ilegível; uma gerada a partir de resumos escritos à mão seria a mesma
deriva com um gerador em cima. A parte boa de D — a verificação mecânica — foi extraída sem o
gerador, e virou `## Validation` V1.

**Não fazer nada** foi considerado e perdeu no arquivo: o README já carrega, nas linhas 64–66, um
aviso admitindo que a prosa está obsoleta e prometendo esta reescrita. Um aviso de obsolescência
permanente é pior do que a obsolescência, porque ensina o leitor a não confiar no resto do arquivo.

## Open Decisions

- **A âncora morta `#cost-model`: restaurar o heading, ou varrer os citadores?** V2 mede o defeito;
  este spec o conserta varrendo os cinco citadores para `#model-policy`. *Como se decide*: já
  decidido, e o motivo é a doutrina do próprio repo. `## Model policy` é o nome verdadeiro do que a
  seção carrega desde que o orçamento total saiu; restaurar `## Cost model` só para satisfazer
  citadores seria manter um segundo nome vivo, exatamente o que
  `/.knowledge/standards/naming/command-surface.md` §The path IS the identity proíbe em espírito.
  A varredura toca dois arquivos sob `commands/**` e a tradução Codex, o que `## Out of Scope`
  excluía por outro motivo (o `description` de frontmatter) — consertar um link morto num body não é
  editar a description dele, e a exclusão foi reescrita para dizer isso.
- **A checagem da lista graduaria para dentro de `cq components lint`?** Este spec a instala como um
  teste em `plugins/quenching/tests/`, e não como código no tool. Motivo: `cq` roda em repo de
  terceiro, e o README do plugin não existe em nenhum repo adotante, então uma regra de finding
  cobraria de todo adotante uma checagem que só o repo do plugin pode rodar. **Decidido por:**
  aparecer um segundo consumidor, isto é, algum repo adotante mantendo à mão um inventário da sua
  própria surface. Até lá, o teste na suíte é a casa correta.
- **A prosa por command fica com uma frase por command, ou com um parágrafo para as poucas que
  carregam contrato próprio?** Candidatas a parágrafo: `/quenching:knowledge:align` (a regra de
  refresh de `QUENCHING.md`), `/quenching:components:align` (a fronteira do audit read-only),
  `/quenching:specs:conclude` (a ordem em que o merge é a última ação) e `/quenching:align` (a
  autorização que aninha um nível). **Decidido por:** escrever as trinta e oito linhas primeiro. Se a
  linha de uma dessas quatro só fizer sentido citando o body, ela ganha um parágrafo curto abaixo da
  tabela do seu front; se ela se sustentar sozinha, a tabela basta. É uma decisão que a autoria
  resolve, não uma que a antecede — e resolvê-la antes é o que produziu os treze blocos atuais.
