## Problem

Regressão reproduzida pela revisão de correção do épico 1534 (2026-10-11), introduzida pela #1535 (spec 1530).
`plugins/quenching/assets/bin/quenching/git/audit.py:668` e `:675-676` ignoram um teste apagado sempre que algum
arquivo adicionado (`A`) em qualquer lugar do diff tem o mesmo nome. O conteúdo não é comparado, e o arquivo novo
nem precisa estar sob `tests/`. Probes com a fixture `Audit` de `test_git.py`:
- A: apagar `tests/test_a.py` (com `assert`) e adicionar um `docs/examples/test_a.py` sem relação → `lowered: []`;
- B: mover `tests/test_m.py` para `tests/unit/test_m.py`, trocando o `assert` por `pass` → `lowered: []`. O arquivo
  novo nunca passa por `test-lost-asserts`, porque `show(base, path)` vem vazio para um arquivo adicionado;
- C: apagar `tests/checks.py` (com `assert`) e adicionar um `src/checks.py` qualquer → `lowered: []`;
- controle D, só apagar → `test-deleted` (ok).
Em `10263dd9`, antes da #1535, A, B e C davam `test-deleted`/`fail`.

Consequência: o check 10 do verifier deixa passar teste removido ou esvaziado, e um worker autônomo rebaixa a régua
só movendo o arquivo. A correção estreita a regra: só conta como movido o par cujo destino é um teste e que preserva
os `assert`, com o destino avaliado como `test-lost-asserts` contra a origem.

## Proposal

- A deleted test counts as moved only when an added file with the same basename is itself a test (matches `TEST_PATH`) and keeps an `assert` whenever the origin had one.
- An unrelated added file of the same name (`docs/examples/test_a.py`, `src/checks.py`) no longer hides the deletion: it reads `test-deleted` again.
- A move whose destination lost every `assert` the origin had reads `test-lost-asserts` (fail) on the destination path.
- A genuine move that preserves the `assert`s stays silent.

## Out of Scope

- Matching the move by content similarity or enabling git rename detection: the audit keeps `--no-renames` and pairs by basename, as the #1535 fix did. Ruled out because it widens the rule's surface.
- Gate-file moves (`GATE_PATH`) and the suppression warn: untouched.

Rule: a deletion is exempt only when a same-basename added path is a test and the test keeps its `assert`s; a destination that dropped them is reported on the destination as `test-lost-asserts`. Per epic 1546 `## Design`, 1540 only tightens: no new exemption, no new kind, no payload shape change.

## Alternatives Considered

- Compare file content between origin and destination: rejected, heavier and still needs a basename pairing.
- Remove the exemption altogether: rejected, it would regress the legitimate move that #1535 fixed.

## Open Decisions

- none — the epic's Design fixed the rule.

## Risks

- A test legitimately moved to a path outside `tests/` with a non-test name is now reported `test-deleted`: ACCEPTED — failing closed is the point, the conductor settles it.
- Several added files share the basename: any one that keeps asserts exempts the deletion. ACCEPTED — pairing is by basename, as before.
