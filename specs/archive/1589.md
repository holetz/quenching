## Problem

Encontrado pelo mapa da rodada 11 do autopilot (2026-10-12) e reproduzido pelo condutor em `main` 0fac8801. Num repo
descartável com `pyproject.toml` só com `[project]`, `pytest.ini` com `addopts = --strict-markers --maxfail=1`, `src/`
e um `node_modules/x/index.js` não rastreado, `cq proof doctor --json` emite:
1. `pf-unmarked` ("pytest strict markers are not enabled"), embora o `pytest.ini` os habilite.
   `proof/inventory.py:177-187` toma o `pyproject.toml` sempre que ele existe, mesmo sem
   `[tool.pytest.ini_options]`. O pytest, porém, lê o `pytest.ini` primeiro, e o `pf-stop-first` também se perde.
2. `pf-unmeasured-surface` com o caminho `node_modules`. `_SKIP_DIRS` (`proof/inventory.py:29-32`) não tem
   `node_modules`, `vendor`, `build`, `dist` nem `.eggs`, e a varredura lê o disco, não os arquivos rastreados.

Consequência: erros falsos na régua de prova, que só somem com uma `proofExclusions` sem sentido, e checagens de
config feitas sobre o arquivo errado. A correção segue a ordem de descoberta do pytest (o `pyproject` só quando tem
`tool.pytest.ini_options`) e conta como superfície só o que o git rastreia, ou ao menos pula os diretórios de
dependências e de build.

## Proposal

- `cq proof doctor` reads the gate config in pytest's own discovery order: `pytest.ini` first, then `pyproject.toml` only when it carries `[tool.pytest.ini_options]`, then `tox.ini` with a `[pytest]` section.
- A `pyproject.toml` with only `[project]` no longer hides the `addopts` of `pytest.ini`, so `pf-unmarked` and `pf-stop-first` follow the file pytest really reads.
- `pf-unmeasured-surface` no longer lists dependency or build directories (`node_modules`, `vendor`, `build`, `dist`, `.eggs`). It does not read `.gitignore` and runs no subprocess: a path git ignores outside that set still counts.
## Out of Scope

- Reading `setup.cfg` (`[tool:pytest]`): not part of the reported defect; the current code never read it either.
- Changing how the ratchet or the coverage floor are computed: only which file is the gate config changes.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/proof/inventory.py` — `_gate`, `_SKIP_DIRS`, `_source_surfaces`
- `plugins/quenching/tests/test_proof.py` — regression tests

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p 'test_proof.py'` exits 0, with the new tests red on the base.
- In a throwaway repo with a `[project]`-only `pyproject.toml`, a `pytest.ini` with `--strict-markers --maxfail=1`, `src/` and an untracked `node_modules/x/index.js`, `cq proof doctor --json` emits neither `pf-unmarked`, `pf-stop-first` nor a `pf-unmeasured-surface` for `node_modules`.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Rule: the gate file is the one pytest would pick. `pytest.ini` wins whenever it exists; otherwise `pyproject.toml` only when `tool.pytest.ini_options` is a table; otherwise `tox.ini` with `[pytest]`. Coverage settings (`tool.coverage`) are still read from `pyproject.toml` when present, since they do not belong to pytest's discovery.
- Rule: a surface is a top-level directory with a source-like file that is not under a skipped directory. `_SKIP_DIRS` gains `node_modules`, `vendor`, `build`, `dist`, `.eggs`; a top-level directory in that set is itself skipped. The scan stays a disk walk.
- Alternatives: asking git (`git ls-files`) was rejected because the proof front forbids any subprocess (`test_all_five_commands_refuse_to_execute_the_target_suite`). A pure-Python `.gitignore` reader (task 1.2) was built and reverted: it was partial (root file and `info/exclude` only), so it would report a coverage it does not have.
## Alternatives Considered

- Only extending `_SKIP_DIRS`: rejected, it leaves other ignored directories (any name) counted.
- Only using git: rejected, the doctor must work in a directory that is not a repo.

## Open Decisions

- none — the epic's Design fixed both decisions (discovery order; git-aware with skip fallback).

## Risks

- A repo whose `pyproject.toml` has no `ini_options` and no `pytest.ini` changes gate path to `None` or `tox.ini`: intended, since pytest ignores that pyproject. Mitigated by a test.
- `git` missing or failing: falls back to the disk walk. ACCEPTED — same result as today minus the skipped names.
