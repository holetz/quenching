## Problem

`quenching/agents/spec-orchestrator.md:53` manda rodar os verbos de publicação "from inside the worktree, after a `cd <worktree> &&` (the git verbs take no `--root`)" e `cd <base checkout> && cq specs reconcile --write --json` após cada merge. O `tools:` do orquestrador (`.claude/agents/quenching-spec-orchestrator.md:4`) só concede `Bash(.agents/quenching/bin/cq <verbo>:*)`, sem `cd`. O próprio harness afirma o contrário: `quenching/agents/spec-verifier.md:35` ("never `git`, `bash` or `cd <wt> && …`, which no grant matches") e `spec-reviewer.md:26` ("never a `cd <repo> &&` prefix"). O `cd` é evitável: `cq git push --branch BRANCH` funciona de qualquer checkout, `pr create` recebe `--head`, `pr merge` recebe `--url`; o reconcile já roda no checkout base.

Consequência: duas referências do mesmo harness prescrevem formas opostas; num host que avalia o comando composto contra a allowlist (Claude Code), a publicação autônoma e o arquivamento pós-merge pedem permissão ou são negados, e o spec sai `blocked` com PASS e CI verdes. [unverified no runtime: no OpenCode, rodadas 1–2 publicaram 14 PRs por esse caminho.] Mudança só de prosa; não alarga nenhum grant (estreita a forma do comando).

## Proposal

- `quenching/agents/spec-orchestrator.md` prescribes the publish verbs without any `cd <worktree> &&` prefix: `cq git push --branch <branch>`, `cq git pr create --head <branch> --spec <id>`, `cq git pr merge --url <url> …`.
- The post-merge `cq specs reconcile --write --json` runs with no `cd <base checkout> &&` either.
- The orchestrator no longer contradicts `spec-verifier.md` and `spec-reviewer.md` on the shape of the command; no grant and no `tools:` list is widened.
- The deployed mirrors match the source.

## Out of Scope

- Changing any `tools:` list or grant: the fix narrows the command form, so none is needed.
- Changing `cq git` verbs: they already take `--branch`, `--head` and `--url`.
- Touching Azure merge/pull code.

## Impact

### Process surface this spec expects to touch

- `quenching/agents/spec-orchestrator.md` — drop the `cd` prefixes from the publish and reconcile instructions
- `.agents/quenching/agents/spec-orchestrator.md`, `.claude/agents/quenching-spec-orchestrator.md`, `.opencode/agents/quenching-spec-orchestrator.md`, `.agents/.quenching-deploy.json` — generated mirrors

## Validation

- `grep -n 'cd <' quenching/agents/spec-orchestrator.md` returns no `cd <worktree>` nor `cd <base checkout>` instruction.
- `bash scripts/verify_repo.sh` exits 0 (deployed surface lockstep included).

## Design

Decision (epic 2223 Design, 2026-11-21): prose only. `cq git push --branch` works from any checkout, `pr create --head` names the branch, `pr merge --url` names the PR, and reconcile runs from the checkout the orchestrator already stands in (the base). The audit line already forbids `cd <repo> &&`; this aligns the publish line with it. If a verb turns out to need the worktree cwd, stop with needs-human rather than add a grant.

## Alternatives Considered

- Granting `Bash(cd:*)`: rejected, widens the grant and contradicts the verifier/reviewer doctrine.

## Open Decisions

## Risks

- A verb that silently reads the cwd instead of its flag: mitigated by `--head`/`--branch`/`--url` being explicit; a failure surfaces as `blocked` with the verb's message.
