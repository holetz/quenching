## Problem

Resíduo reproduzido pela revisão de correção do épico 1534 (2026-10-11). A #1537 (spec 1528) corrigiu o README do
HUD e a `description` do `marketplace.json`, que agora admitem fetch, escrita de ref e cache. Duas superfícies ainda
dizem o contrário: `plugins/quenching-hud/.claude-plugin/plugin.json:4` ("Read-only band above the prompt…") e
`docs/project/layout.md:28` ("read-only band above the prompt"). Consequência: o manifesto que o host mostra ao
instalar contradiz o README e o marketplace. A correção é só de prosa.

## Proposal

- `plugins/quenching-hud/.claude-plugin/plugin.json` `description` no longer says "Read-only"; it carries the same admission as the marketplace entry (cq specs status may fetch origin, update a ref and a cache, or call the GitHub API).
- `docs/project/layout.md` row for `plugins/quenching-hud/` no longer calls the band "read-only".

## Out of Scope

- The README of the HUD and the `marketplace.json` description: already corrected by #1537.
- Any version bump or changelog: owned by the merge/release, not this spec.
- Any behavior change in the HUD or in `cq specs status`.

## Impact

### Standards this spec will write into docs/standards/

- none — prose fix in a project doc, no standard is written.

### Product code this spec expects to touch

- `plugins/quenching-hud/.claude-plugin/plugin.json` — the `description` string only
- `docs/project/layout.md` — the HUD row of the layout table

## Validation

- `grep -rni "read-only band" plugins docs` returns nothing.
- `python3 -c "import json;json.load(open('plugins/quenching-hud/.claude-plugin/plugin.json'))"` exits 0.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- The manifest description is what the host shows at install, so it must agree with the README and the marketplace entry. Rule: the HUD is described as a band that writes no spec or branch, never as read-only, while `cq specs status` can fetch and cache.
- The manifest wording mirrors the marketplace entry, shortened to fit a one-line description.
- Epic 1546 policy: a verifier check-9 flag on prose or `description` in `plugin.json` alone is pre-cleared by the conductor. No grant, hook or CI is touched.

## Alternatives Considered

- Leave the manifest vague (drop "Read-only" without the admission): rejected, the manifest would still understate the fetch and cache effects the README admits.

## Open Decisions

- none — the wording is fixed by the marketplace entry.

## Risks

- A mirror test could pin the old description: mitigated by running the full gate.
- Manifest versions are in lockstep; only the description changes, no version moves.
