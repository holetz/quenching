## Problem

Evidência (scout ses_de7f04b5, 2026-11-26): `tools/call git_stale {}` deu `truncated:true, chars:152486, kept:60000`; na CLI `manifest` tem 90.870 chars, `worktrees` 43.102, `heldSlots` 14.351, enquanto `staleBranches` (o que importa) veio vazio. `cq git stale --help` só tem --remote. Consequência: ~17k tokens por chamada e JSON cortado (possivelmente inválido). Proposta: saída padrão com o resultado (staleBranches, contagens) e --full para manifest/worktrees completos; mesmo padrão no MCP. Arquivos: quenching/assets/bin/quenching/git/stale.py, schema MCP do git, testes.

## Proposal

- `cq git stale --json` (e o `git_stale` do MCP, que herda o parser) devolve por padrão só o resultado: `base`, `remote`, `prLookup`, `staleBranches`, `keptBranches`, `remoteBranches`, `orphanWorktrees`, `unregisteredWorktrees`, mais `counts` (`manifest`, `worktrees`, `heldSlots`, `groups`) e `full: false`.
- `--full` (parâmetro `full` no MCP) devolve a forma completa de hoje (`worktrees`, `heldSlots`, `manifest`, `groups`) com `full: true`.
- `/quenching-git cleanup` passa a pedir `--full`, porque seu passo 2 depende do `manifest`.

## Out of Scope

- Mudar `stale_report`, `cq git prune` ou o formato do texto humano: o prune relê o relatório completo por conta própria.
- Paginar `remoteBranches` ou `keptBranches`: com o resultado útil cabendo em poucos milhares de caracteres, não há o que paginar.

## Impact

### Standards this spec will write into docs/standards/

- `docs/standards/workflows/plan-git-record.md` — o relatório do `cq git stale` é enxuto por padrão e o `manifest` completo exige `--full`

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/git/stale.py` — a flag `--full` e o recorte do JSON em `cmd_stale`
- `quenching/assets/bin/quenching/git/__init__.py` — o argumento `--full` do parser
- `quenching/tests/test_git.py` — a prova do padrão enxuto e do `--full`

### Process surface this spec expects to touch

- `quenching/skills/quenching-git/references/cleanup.md` — chamar `git_stale(remote=<remote>, full=true)`

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_git.py` sai 0, com casos novos: sem `--full` o JSON não traz `manifest`, `worktrees`, `heldSlots` nem `groups` e traz `counts` e `full: false`; com `--full` traz tudo e `full: true`.
- `cq git stale --json` neste repositório devolve bem menos que os 152 mil caracteres medidos (alvo: abaixo de 20 mil).
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` fecha verde no conclude.

## Design

- **O recorte mora em `cmd_stale`, não em `stale_report`.** `cq git prune` e os testes de cleanup leem o relatório completo por `stale_report`; só a saída de `cmd_stale` encolhe, então nenhum chamador interno muda.
- **O MCP herda o parser.** O catálogo publica `git stale` como verbo de leitura e deriva os parâmetros do argparse; `--full` vira o parâmetro booleano `full` sem tocar o catálogo.
- **Padrão enxuto, forma completa por flag** (decisão do épico 594, 2026-11-26). `counts` deixa o leitor saber o que o `--full` traria.
- **Texto humano intacto**: já é um resumo, não o despejo de 150 mil caracteres.

### Assumptions

- O consumidor do `manifest` é só o `cleanup` (grep em `quenching/skills` e `quenching/references`); depende de: `## Tasks` 1.2.

## Alternatives Considered

- Truncar a saída no MCP: deixa a CLI com o mesmo despejo e corta JSON no meio.
- Dois verbos (`stale` e `stale-manifest`): duplica o catálogo e os grants por uma flag.

## Open Decisions

- none — a forma (lean por padrão, `--full` para o resto) está decidida no `## Design` do épico 594.

## Risks

- Um chamador externo que lia `manifest` sem flag passa a recebê-lo ausente. ACCEPTED — o único consumidor no repositório é o `cleanup`, que passa a pedir `--full`, e `counts` denuncia a ausência.

## Outcome

`cq git stale --json` (e o `git_stale` do MCP) devolve por padrão o resultado — `staleBranches`, `keptBranches`, `remoteBranches`, `orphanWorktrees`, `unregisteredWorktrees` — mais `counts` e `full: false`; `--full` (`full=true` no MCP) traz de volta `worktrees`, `heldSlots`, `manifest` e `groups`. Neste repositório a saída caiu de ~152 mil para ~10 mil caracteres. O recorte mora em `cmd_stale`; `stale_report`, `cq git prune` e o texto humano ficaram intactos. `/quenching-git cleanup` passa a pedir `full=true`, e `plan-git-record.md` documenta a forma enxuta. Ficou de fora: paginar `remoteBranches`/`keptBranches`. Nenhum release obligation nem destilação adicional; a varredura do fluxo não achou defeito evidenciado.
