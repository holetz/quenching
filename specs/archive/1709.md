## Problem

Correctness review of PR #1708 (range 03e24c1b..719ca3e5) reproduced a RED cleanup failure in targets using checkout conversions. plugins/quenching/agents/spec-runner.md:50 and plugins/quenching/assets/references/specs-execute/execution.md:146 restore tracked test files with `git -C .quenching/red show HEAD:<file> > .quenching/red/<file>`. This emits repository bytes instead of checkout bytes.

Reproduction in an isolated fixture with a committed tests/test_x.py and `.gitattributes` containing `*.py text eol=crlf`:

```bash
git worktree add -q --detach .quenching/red "$BASE"
cp tests/test_x.py .quenching/red/tests/test_x.py
git -C .quenching/red show HEAD:tests/test_x.py > .quenching/red/tests/test_x.py
git -C .quenching/red status --short
git worktree remove .quenching/red
```

Actual output: ` M tests/test_x.py`, then `fatal: ... contains modified or untracked files, use --force to delete it`, exit 128. The reviewer independently reproduced the same failure with core.autocrlf=true. Plain LF targets clean up successfully. Git 2.43.0 on Linux. No LFS reproduction was performed.

Consequence: the documented restoration leaves the RED worktree dirty, so its safe removal is refused, the runner blocks, and the nested RED worktree prevents retiring the spec worktree. Fix the restoration contract and protect this case with a meaningful regression check. Preserve unrelated files and existing prohibitions on force removal; do not widen grants, hooks, scripts, CI, or agent tools. Any solution requiring such widening must be deferred to the human epic. The reviewer verified that cat-file --filters restores the expected bytes, but solution selection must also account for existing tool grants and filter execution boundaries.

## Proposal

Replace tracked-file restoration in `plugins/quenching/agents/spec-runner.md:50` and `plugins/quenching/assets/references/specs-execute/execution.md:146` with `git -C .quenching/red cat-file --filters HEAD:<file> > .quenching/red/<file>`. The filters apply the same checkout conversions (`eol`, `autocrlf`, configured smudge filters) used by worktree creation. Add a behavioral regression that executes the documented restoration against converted checkout bytes.
## Out of Scope

- Grants, agent tools, allowed-tools, hooks, scripts, CI and settings.
- Existing prohibitions remain: no checkout, restore, stash, reverse git apply or force removal; restoration stays confined to `.quenching/red`.
- LFS behavior is not reproduced or claimed as validated.
- Tests overwriting `.gitattributes` itself.
- RED lifecycle or autonomous protocol redesign.
## Impact

Consumers using `eol=crlf`, `core.autocrlf=true` or checkout filters can currently block RED cleanup and prevent retiring the parent spec worktree. Plain LF targets should retain their existing behavior. The change touches two executable prose carriers and one test file.

## Design

Change only the restoration verb in both carriers, with a brief explanation of checkout bytes. Preserve deletion of newly copied tests, worktree removal without force, optional parent-directory removal, and blocked state when safe cleanup refuses.

Update the existing restoration contract test and add a temporary Git fixture with CRLF attributes, autocrlf and plain LF cases. Extract the documented command from each carrier and substitute the test path; invoke the Git argv without shell=True, directing stdout into the restoration file. Assert clean status and successful safe removal, so reverting either carrier to show makes the behavior test fail.

Permission boundary: spec-runner already has Bash, and the same configured checkout filters already ran during worktree add for this base. No grant or execution boundary is widened. If implementation evidence contradicts this boundary, stop and route the requirement to human epic 1690.
## Alternatives Considered

- Checkout/restore: rejected by the existing RED safety contract.
- Forced removal: explicitly prohibited and hides unrelated work.
- Backup/copy-back: viable without filters, but introduces extra runner state; filtered blob output uses the existing base directly.
- Manual EOL conversion after show: incomplete for configured filters and autocrlf.
- New cleanup hooks/scripts/grants: outside the authorized scope and unnecessary for the reproduced case.
