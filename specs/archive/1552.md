## Problem

Reproduzido pela revisão de correção do épico 1546 (2026-10-11), em `main` 06d9ef79, na #1550 (spec 1543):

1. **(média) No backend github, `--no-fetch` ainda usa a rede e grava cache antes de recusar.** Num repo com origin no
   github.com, sem config de backend e com `gh`/`git` falsos que registram as chamadas, `cq specs status 1 --no-fetch
   --json` sai com `sp-no-local-read` (exit 2). Antes disso, porém, o log mostra `gh repo view --json
   nameWithOwner,issues`, e aparece `$XDG_CACHE_HOME/quenching/github/<hash>.json`. A causa é que `read.py:123` chama
   `open_backend` → `open_github_backend` → `resolve_github_repo` (`github.py:476`) antes da checagem em `read.py:126`.
   Consequência: o HUD chama a API do GitHub e grava cache (no máximo a cada 5 min, `GH_CACHE_TTL_S = 300`) em repos
   com backend github, o que desmente `plugins/quenching-hud/README.md:25` ("sem chamar a API do GitHub").
2. **(baixa) Sem ref local, o erro engana.** Sem `refs/remotes/origin/quenching`, `cq specs status --spec 1527
   --no-fetch --json` responde `sp-unknown-id` ("no spec with id '1527'"), exit 1, porque `_snapshot(None)` devolve
   uma árvore vazia (`backends/git.py:237`). O correto seria dizer que falta o ref do store.

## Proposal

- `cq specs status --spec <id> --no-fetch` on a repo whose store is not the git branch refuses with `sp-no-local-read` (exit 2) before any remote is resolved: no `gh` call, no GitHub API request, no file under `$XDG_CACHE_HOME/quenching/github/`.
- On the git store, `--no-fetch` with no local `refs/remotes/origin/quenching` refuses with a code that says the store ref is missing, instead of `sp-unknown-id`.
- The HUD README claim "sem chamar a API do GitHub" is true on both backends.

## Out of Scope

- Making `--no-fetch` read a local copy of the github or azure store: those backends have none, so refusing is the contract (spec 1543).
- Changing the fetch policy of the git store when `--no-fetch` is absent.

## Design

Per epic 1554: `--no-fetch` resolves no remote, calls no API and writes no cache on either backend, and a missing local ref is reported as such.

- Decide the backend from `load_config` (local data: `.claude/quenching.json`, the remote URL string) before `open_backend`. Only an explicit `backend: git` reaches the store; a github or azure provider refuses first. Declared-unknown or unrecognised provider falls through to `open_backend`, whose refusals touch no network.
- The missing-ref probe is a method on `GitBackend` (`has_local_ref`), reusing `_local_tip`; `cmd_status` refuses with `sp-no-local-ref` after opening the git store and before `read_one`.
- The mirror under `plugins/quenching-specs-reader` is regenerated by `scripts/sync_specs_reader_plugin.py`, never hand-edited.

## Alternatives Considered

- Making `open_github_backend` lazy so the refusal stays where it is: rejected, it touches every github caller to fix one flag.

## Open Decisions

- none — the epic's Design settled the behaviour.

## Risks

- A repo with `backend: git` declared only on the branch config (not in `.claude/quenching.json`) is read through `load_config`, which may read the local ref only; ACCEPTED — with `--no-fetch` the env var already makes that read local.
- The mirror drifts if not regenerated; mitigated by the repo gate.
