## Problem

O renderer embutido é tudo-ou-nada e não permite que um gênero use um pipeline externo sem manter estrutura paralela fora da frente de design. O gênero deve declarar builtin ou um comando externo que receba dados e template e devolva o artefato.

## Proposal

- Add an explicit `engine` declaration to genre contracts, defaulting to `builtin`.
- Invoke a declared external command with a stable JSON request containing data, template, medium, root, and output metadata, and write its stdout artifact to the requested output.
- Surface non-zero exit status and empty output deterministically, and list the engine in generated `MEDIUM.md`.

## Out of Scope

- Implementing Pandoc, LaTeX, Typst, browser automation, or any named external document engine.
- Allowing shell interpolation, arbitrary environment mutation, network orchestration, or engine discovery.
- Changing builtin substitution or making external engines responsible for design-source validation.

## Impact

- `plugins/quenching/assets/bin/quenching/design/genre.py` — engine declaration and process orchestration.
- `plugins/quenching/assets/bin/quenching/design/build.py` — engine visibility in MEDIUM projection.
- `plugins/quenching/assets/bin/quenching/design/cli.py` — optional engine argument when minting a genre.
- `plugins/quenching/tests/test_design.py` — fake external engine and builtin regression coverage.
- `docs/standards/automation/extension-points.md` — declared extension boundary and no hidden execution.
- `docs/standards/quality/unproven-capability-warning.md` — external execution must have a proving fixture.

## Validation

- A genre created with `engine: builtin` retains current HTML/Typst/PDF behavior byte-for-byte.
- A genre with a command string invokes it without a shell, sends the documented JSON request on stdin, writes stdout bytes to the output, and appears with its engine in `MEDIUM.md`.
- Non-zero exit and empty stdout produce stable `DesignError` refusals containing the engine result.
- The test engine cannot escape the declared root through input metadata; existing design tests remain green.

## Design

- Frontmatter stores `engine: builtin` or a non-empty command string. `genre new --engine` accepts the same value and defaults to builtin.
- The external process receives UTF-8 JSON on stdin: `{\"data\": object, \"template\": string, \"medium\": string, \"root\": absolute string, \"output\": absolute string}`. It writes the artifact bytes to stdout and diagnostics to stderr; the plugin never interpolates input into a shell command.
- `render_genre` performs source/build drift checks and field validation before dispatch. Builtin follows its current path; external engines receive the raw template and data, so they own only template semantics.
- An external engine returning non-zero or empty stdout is a refusal. PDF output may be binary; stdout is captured as bytes and written without decoding.
- MEDIUM.md adds an Engine column with `builtin` or the declared command string, while preserving current rows and generated provenance.
- Dependency map (2026-08-30): `cli.py` captures the declaration → `genre.py` validates and invokes it → `build.py` exposes it in the generated listing → `test_design.py` proves success and failure without a real external engine.

## Alternatives Considered

- Passing data and template as shell arguments: rejected because quoting, size, and injection behavior are unsafe.
- Requiring a fixed plugin-owned engine registry: rejected because it prevents generic external pipelines from being declared by projects.
- Making the external engine write directly to the output path: rejected because the plugin could not distinguish an empty/partial artifact and would widen file permissions.

## Open Decisions

- none — command transport, error behavior, builtin default, and MEDIUM representation are fixed.

## Risks

- A declared engine can be slow or resource-intensive; the plugin intentionally orchestrates only and leaves resource policy to the calling environment.
- External commands may emit untrusted bytes; the output is an artifact, not executed by the plugin.
- A command string resolved through PATH can vary by host; the contract reports the declared command and tests the no-shell invocation, while environment pinning remains project policy.
