## Problem

During git cleanup, existing worktrees are excluded from assessment and branch/worktree inventories lack reference dates. Repeating exact deletion commands for every choice makes long inventories (such as two local and 92 remote merged branches) difficult to review. Users need evidence-based advice, concise explicit selections, and preservation of ongoing work.

## Proposal

Extend the read-only stale report with assessed registered worktrees and a complete cleanup manifest: stable identity IDs, observed tips, date provenance, exact actions, reasons and recommended subsets. Offer concise grouped local and remote decisions referencing that manifest. Revalidate approved identity/tip and eligibility at execution; preserve all existing deletion safeguards and require explicit confirmation that selected worktrees are inactive.

## Out of Scope

- Executing any cleanup against this repository or the originally reported branches/worktrees.
- Automatic deletion, implicit fetch/prune, force removal, age thresholds, inferred last-use dates, or changing spec lifecycle records.
- Detecting every external process using a checkout; unknown activity is disclosed and inactivity must be confirmed by the owner.

## Validation

Run `python3 -m unittest discover -s plugins/quenching/tests -p test_git_cleanup.py` and the existing `test_git.py` suite against disposable repositories only. Prove snapshot drift refusal and preservation of modified, untracked, ignored, locked, current/main, open-PR and unmerged worktrees. Prove date origin, stable IDs, exact actions and grouping at 2 local/92 remote scale. Run `bash scripts/verify_repo.sh` with zero errors. Never perform cleanup against real repository branches.

## Design

Use additive report keys to preserve legacy stale/kept/remote/orphan/unregistered list shapes. Dates describe the observed tip's committer timestamp (`git show -s --format=%cI`), never creation, last checkout use or file activity. Unknown metadata stays null with a named source. Stable IDs derive from kind and exact remote/ref or canonical worktree identity; a separate observed tip guards approval drift.

Existing linked worktrees are removable candidates only with successful inspection, fully merged HEAD, no tracked/untracked/ignored content, no lock, and no current/main checkout, base branch, open PR or unavailable PR lookup. Detached HEAD is assessed by ancestry. Candidate status is eligibility, not evidence of inactivity. Worktrees require the owner's explicit inactivity confirmation. Missing registered directories retain their separate orphan class; unregistered directories remain information only.

A complete manifest includes candidates and preserved entries, exact argv and guarded cq invocation, observations and recommendations. Summarize homogeneous groups by kind/reason/date provenance, keeping local and remote decisions distinct. Recommend the evidenced subset when available, or none when uncertainty remains; recommendation never grants execution. Groups resolve to the displayed immutable IDs, never newly discovered targets. Fresh execution compares approved tip and identity, then rechecks all protections. Remote deletion retains the exact-tip lease.

## Alternatives Considered

- Prose-only cleanup change: insufficient because the current tool cannot authorize existing worktrees or provide dates.
- Show every action in the decision: complete but unreadable for 92 remotes; keep completeness in the manifest instead.
- Delete all merged items: confuses ancestry with current intent/activity and ignores PR uncertainty.

## Open Decisions

- Why now and appetite cutoff: the problem records current review burden; no additional product threshold is assumed. The owner may reprioritize before delivery.
- Per-worktree activity cannot be proved by git; the cleanup decision explicitly requires owner confirmation of inactivity and leaves uncertain items untouched.

## Risks

- Concurrent change after inspection: revalidate the approved tip and eligibility, retain Git refusal and remote lease; disclose residual filesystem races rather than claiming zero risk.
- Ignored files can be destroyed by ordinary Git removal: include ignored files in successful status inspection and refuse their removal.
- Unavailable host lookup: preserve worktrees and recommend no uncertain branch subset; do not interpret unavailable as no PRs.
- Long lists hide targets: expose a complete manifest with stable IDs and exact argv before the concise selection; bind groups to that snapshot.
