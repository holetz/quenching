## Problem

O épico 2148 mudou o desenvolvimento para confiança no intent, mas as três trajetórias (simples, complexa e autônoma) não foram medidas em specs reais: perguntas feitas, refinos aplicados, paradas durante a execução e quedas de cache por espera. Sem isso, o ganho de comportamento do épico é só declarado.

## Proposal

Nas próximas specs reais, registrar por trajetória o número de perguntas, os refinos escolhidos, as paradas na execução e, por `cq components session cache`, as quedas de cache depois de cada espera humana; comparar com a linha de base `baseline-2026-11-02.json` da 2149 e escrever o resultado em `docs/standards/automation/context-discipline.md`.

## Out of Scope

- The `simple` and `complex` trajectories: they need a human answering questions and choosing refinements in a live session, which no autonomous run produces. Recorded as an explicit gap, never estimated.
- The comparison with `baseline-2026-11-02.json` (spec 2149): the artifact is not in the repository or on the `quenching` branch, so there is no "before" to compare against. Recorded as an explicit gap; the section only states the gap and the autonomous numbers on their own.
- Any new tool, counter or instrumentation: only what `cq components session cache` and `session cost` already read is used (guidance: no layers that add token cost with little return).

## Design

### Decisions
- **Narrowed to the autonomous trajectory (conductor, 2026-11-25).** The simple and complex trajectories and the 2149 baseline are explicit gaps, not estimates. Evidence: `baseline-2026-11-02.json` exists neither in the tree nor on the `quenching` branch, and a human-in-the-loop run cannot be produced inside an orchestrated spawn.
- **What is measured.** `cq components session cache --since 2026-11-25T00:00:00 --json` over this repository (Claude Code and OpenCode stores): requests, hit rate, median first request, median peak, reads after a gap over 5 minutes and the tokens missed after a 5–60 minute gap, per model and role. `session cost` reads one session's subagents; it is cited for what it covers, never summed across models.
- **Counted by construction, not by instrument.** An autonomous run asks zero questions and runs no refine (develop.md: autonomous never asks, never refines); stops are the `blocked` returns of the runners.
- **Where it lands.** One paragraph block in the existing rationale of §The prompt cache is a per-harness measurement, beside the 2157 comparison, which already says the three real specs stay unmeasured. No new file, no new section.

### Assumptions
- `--since 2026-11-25` is a proxy for epic 483's runs: the epic ran that day, but other sessions on the same day are inside the count (§Risks).

## Alternatives Considered

- Block the spec until a human supplies the baseline and the other two trajectories: rejected by the conductor, option (b); the gap is cheaper to declare than to wait for.
- Add a trajectory counter to `cq components session`: rejected, a new layer of tooling for one measurement with little return.

## Open Decisions

- none — the narrowing and the gap wording were decided by the conductor; the figures come from the command's output at build time.

## Risks

- The day-wide window includes sessions that are not epic 483's: ACCEPTED — the figures are stated as indicative, same as 2157's, never a cost claim.
- A reader takes the autonomous numbers for the three-trajectory result: mitigated by writing the three gaps in the same block and in `## Outcome`.
