## Problem

Reproduzido pela revisão de correção do épico 1534 (2026-10-11). A #1537 (spec 1528) só documentou o fetch do HUD
e deixou em aberto uma leitura sem fetch. `plugins/quenching-hud/hooks/register.tsx:21` roda
`cq specs status --spec <id> --json` a cada `turn.complete`, e `cq specs status --help` só oferece `--json`, `--spec`
e `--epic`. Mesmo com `QUENCHING_SPECS_READ_ONLY=1` e um `XDG_CACHE_HOME` vazio, o comando gravou o cache, e esse
cache só é escrito por `_touch_cache` dentro de `_fetch` (`specs/backends/git.py:180-194`). Logo, o fetch aconteceu.
A variável só barra as escritas do transporte, e o modo mirror também busca da `remote_url`.

Consequência: ssh e rede a cada turno (timeout de 120s), escrita de `refs/remotes/origin/quenching` no `.git`
compartilhado, e chamadas à API do GitHub no backend github. A correção estreita: um modo de leitura local
(ref ou cache já presente, sem fetch) em `cq specs status`, usado pelo HUD, com o README e as descrições alinhados.

## Proposal

- `cq specs status --spec <id> --no-fetch [--json]` answers from the local remote-tracking ref (`refs/remotes/origin/quenching`) already present, and never fetches, whatever the 30s cache says.
- The same flag on a backend that has no local copy (github, azure) refuses with exit 2 and a named code instead of calling the network.
- The `quenching-hud` hook passes `--no-fetch`, so a turn no longer costs ssh, network or a ref write.
- The HUD README, `docs/project/layout.md` and both HUD descriptions state what the HUD now does, and `cq specs status --help` names the flag.

## Out of Scope

- A fetch scheduled by the HUD (a background refresh): deferred; the band reads whatever the last explicit `cq` command fetched, and says nothing about staleness.
- `--no-fetch` on other verbs (`list`, `show`, `next`): no consumer asks for it; add it when one does.
- Any new network, hook, write or grant: this only removes a fetch.
- Fail-closed rule for check 9: spec 1545, with the human.

## Design

### Mapa de dependências (2026-10-11)

| File | Relation | What breaks if it changes |
| --- | --- | --- |
| `specs/backends/git.py` `_tip` | single place every git read gets its tip (`list_specs`, `read_spec`, `read_config`) | a read that bypasses `_tip` would still fetch; `_local_tip()` callers at git.py:514 already do not fetch |
| `specs/commands/cli.py` `main` | runs before `load_config`, which reads the branch config through the same backend instance | setting the env after dispatch would let the config read fetch |
| `quenching-specs-reader/assets/**` | copy of the above | drifts unless the sync script is rerun |
| `hooks/register.tsx` | only caller of the flag | none |

### Decisions

- The switch is an environment variable, `QUENCHING_SPECS_NO_FETCH`, that `main` sets from `--no-fetch` before dispatch. Durable rule: a read that must not fetch is decided once at the transport (`_tip`), never per verb, because the config load shares the backend instance and would otherwise fetch behind the verb's back.
- The flag lives on `status` only, the one verb the HUD runs.
- Under the flag, a missing local ref reads as an empty store and the usual unknown-id refusal follows; the HUD shows nothing. No fallback to a fetch, since a fallback is the bug.
- A backend that is not `git` refuses (`sp-no-local-read`, exit 2): it has no local copy, so the only way to answer is the network the flag promises not to use.

## Alternatives Considered

- Reuse `QUENCHING_SPECS_READ_ONLY`: rejected, it guards writes of the transport and the mirror mode still fetches; changing its meaning widens a documented contract.
- Raise `FETCH_TTL_S`: rejected, it still fetches once per window and gives the HUD no guarantee.
- Have the HUD read the ref with `git cat-file` itself: rejected, it would duplicate the parser in TypeScript and add executed commands.

## Open Decisions

- none — every choice above is settled by the epic 1546 policy ("only narrows") and the code read.

## Risks

- The band can show a stale stage until something else fetches. ACCEPTED — freshness is the cost of removing a network call per turn; the first explicit `cq specs` command refreshes it.
- A worktree that never fetched shows no band. ACCEPTED — same reason; before it, the band cost a 120s timeout.
- Description change in `plugin.json`/`marketplace.json` may trip verifier check 9. ACCEPTED — pre-cleared by epic 1546 for prose-only changes.
