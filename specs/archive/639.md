## Problem

`specs_read(verb="validate")` sem `spec` devolve o achado de cada spec do store — no alvo, 885 specs e ~89 mil caracteres. Com algum achado `error`, a tool lança a exceção com o relatório inteiro no texto, então o chamador não consegue filtrar: aconteceu duas vezes ao abrir o épico 1041918 no alvo, em 26/11/2026.

**Origem**

- Ensaio da vertical de specs no alvo riscos-plataforma (spec 1041893 lá; rodada de 2026-11-27T00:36Z; sessões de 20 a 27/11/2026; quenching 7.18.3). Épico 636.

## Proposal

- Por padrão, um resumo por código e severidade, com as specs afetadas sob demanda.
- A exceção carrega o resumo, não o relatório.

## Out of Scope

- none to widen — paginating the `--full` output and changing `--by-code` itself are ruled out; `--full` keeps today's payload for callers that want it.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/specs/commands/validate.py` — default summary when no `--spec`
- `quenching/assets/bin/quenching/specs/commands/cli.py` — `--full` and `--with-specs` flags

### Process surface this spec expects to touch

- `quenching/references/specs-develop/specs-surface.md` — the verb's documented flags

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_specs_validate_summary.py` exits 0.
- `python3 -m unittest discover -s quenching/tests -p test_specs_links.py` still exits 0 (callers building their own namespace keep the full payload).

## Design

- Without `--spec`, and without `--full`, `cmd_validate` emits the by-code summary. The JSON rows drop the spec lists unless `--with-specs`; an explicit `--by-code` keeps its historical shape. Because the exception the MCP tool raises carries stdout, the summary is what it carries.
- Alternative weighed: truncating inside the MCP server. Rejected: the CLI has the same flaw and the grouping already exists.
- Namespaces built without a `full` attribute (internal callers, existing tests) keep the full payload.

## Alternatives Considered

- Truncate the payload in the MCP layer — rejected, leaves the CLI and the cause intact.

## Open Decisions

- none — the flag names are settled here.

## Risks

- A caller that parsed `findings` from the whole-store sweep now needs `--full`. ACCEPTED — the whole-store payload is the defect; `--spec` and `--full` remain.
