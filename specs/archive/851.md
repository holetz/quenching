## Overview

Defeito já corrigido (verificado 2026-08-06, commit 263222b de 2026-08-04) — `load_config` já honra
o `root` recebido, e `specs.py selftest` já sai limpo dentro e fora do repo. Mantido como registro,
não como trabalho a construir. Duplicado por `fix-load-config-root-argument` e
`specs-py-selftest-nao-e-checkout-independente-e-sai-1-na-main-pristina`, que descrevem o mesmo
defeito. Próximo passo: `/quenching:specs:conclude` nas três.

## Problem

**Corrigido — verificado em 2026-08-06, esta passada de `/quenching:specs:develop`.** O guard que
faltava já está em `find_repo_root` (`plugins/quenching/assets/bin/specs.py:1165`):
`_git(specs_root, ...) if os.path.isdir(specs_root) else ""` — a chamada de git é pulada quando
`specs_root` não existe, em vez de deixar `_git` cair para `cwd="."`. O guard chegou no commit
`263222b` ("plan/configurable-branch-strategy: 2.1", 2026-08-04), de passagem numa tarefa não
relacionada a este defeito.

Reproduzido hoje e **não reproduz mais**: `specs.py selftest` sai `exit 0` tanto de dentro do repo
quanto de `/tmp`, e `load_config(os.path.join(os.sep, "nonexistent-specs-root", ".specs"))` chamado
diretamente devolve `backend: files, present: False` — os defaults documentados — mesmo executado de
dentro deste checkout, cujo `.claude/quenching.json` declara `backend: github`.

Este spec, `fix-load-config-root-argument` e
`specs-py-selftest-nao-e-checkout-independente-e-sai-1-na-main-pristina` descrevem o mesmo defeito
por três ângulos; nenhuma das três tem mais o que construir. O registro fica porque a lição é
durável — um selftest cujo fixture confunde "path ausente" com "cwd do processo" é um modo de falha
que pode voltar — mas as três ficam para fechar via `/quenching:specs:conclude`, apontando aqui.

---

O texto abaixo é o `## Problem` original, preservado porque é ele que registra o defeito medido
antes do conserto.

`load_config(root)` resolve o repositório via `find_repo_root` a partir do **CWD**, e não a partir do
`root` que recebeu. O caso `config-default` do `selftest` — que existe para provar que um
`.claude/quenching.json` ausente devolve os defaults documentados — acaba lendo o `backend: github`
declarado *deste* checkout.

Consequência: `specs.py selftest` sai **exit 1 de dentro do repo e exit 0 de fora dele**, com dois
`sp-config-default-drift`. O veredito depende do diretório de onde se chama, que é exatamente o que
um selftest não pode fazer.

Isso trava todo `verify:` de tarefa escrito como `specs.py selftest exit 0` — na spec
`evaluate-spec-creation-flow` foram as tarefas 1.3, 2.1 e 2.4, que tiveram de ser verificadas por
outro caminho. É pré-existente e foi confirmado idêntico em `main` durante a revisão de branch
daquela spec, em 2026-08-03.
