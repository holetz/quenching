## Problem

`git/worktree.py:24-30` abre o JSON cru e lê `sharedPaths` na raiz, sem passar por `load_config`; a raiz é chave legada que o envelope recusa com `sp-config-unscoped` (`common/config.py:22-27`), então um repositório que declara `shared.sharedPaths`, a única forma aceita, tem os links silenciosamente não criados enquanto `git:branch` reporta sucesso; `tests/test_git.py:268` cimenta o formato legado. `sync.md:47` faz `git rebase --update-refs` e `push.md:41,71` recusa branch divergente mandando de volta ao `sync`, sem caminho `--force-with-lease` confirmado: abrir PR, sincronizar e republicar é um beco. `pr/create.md:92,123` impõe `--delete-source-branch true` no Azure, exatamente o que a reference `git/merge.md:63-66` alerta que destrói a resolução dos `subject:` da spec, enquanto na rota GitHub a deleção é uma oferta. `revert.md:52,80` proíbe tocar checkboxes: a task revertida continua `[x]` com `subject:` apontando para um commit anulado. `pr/create.md:87`, `cleanup.md:99-104` e `git/stale.py:33` fixam `origin`; só `push` aceita `--remote`. `tests/test_git.py:456-612` testa os corpos por substring de prosa, sem executar git.

## Proposal

- `worktree.py` lê `shared.sharedPaths` via `load_config`; teste com o formato namespaced e recusa do legado.
- `push`: quando a divergência é o rebase local dos mesmos commits (upstream contido no reflog do branch), oferecer `--force-with-lease` com uma confirmação que mostra o que será sobrescrito; caso contrário, uma recusa que nomeia a saída.
- Azure: deleção do branch de origem como oferta, com o mesmo alerta da rota GitHub.
- `revert` de uma task: desmarcar o checkbox com razão (`cq specs task --uncheck --reason`) e registrar em `## Discoveries`.
- Parametrizar o remote em cleanup, pr:create e `cq git stale`.
- Testes de comportamento em repositório git temporário para worktree, sync→push e revert.

## Out of Scope

- Não reescrever toda a camada git nem alterar provedores de PR fora dos caminhos nomeados.
- Não usar force push sem confirmação que mostre ref e lease; nem apagar branch automaticamente.
- Não modificar histórico de tasks já commitadas.

## Validation

- shared.sharedPaths cria links e config flat retorna sp-config-unscoped.
- Rebase local oferece force-with-lease com lease explícito e o upstream termina no commit esperado.
- Revert reabre task com razão; cleanup/PR mostram remote e efeitos destrutivos separadamente.
## Design

worktree.py passará pelo envelope de configuração e lerá shared.sharedPaths; uma configuração legada será recusada pelo loader. push receberá um caminho explícito para a divergência causada por rebase e exigirá confirmação antes de force-with-lease. A rota que não puder provar a origem da divergência recusará.

PR Azure oferecerá delete-source-branch separadamente, e GitHub manterá oferta equivalente; nenhum caminho apagará a branch cuja resolução de records ainda é necessária. Revert usará task --uncheck --reason e discovery para deixar o estado legível.

Todos os comandos que hoje fixam origin aceitarão o remote resolvido/fornecido e exibirão o alvo antes de escrever.

### Mapa de dependências

Atualizado em 2026-09-02. git/worktree.py depende de common/config e das records de branch; push/sync compartilham refs e upstream; pr/create e cleanup usam remote e branch lifecycle. specs task/promote guardam estado das tasks; referências git/isolation/merge/pr definem efeitos de deleção e records. test_git é a prova comportamental.

## Alternatives Considered

| Forma | Custo | Benefício | O que fecha | Decisão |
| --- | --- | --- | --- | --- |
| Manter atalhos fixos e corrigir só prosa | baixo | nenhum conflito de código | becos continuam operáveis só por acidente | rejeitada |
| Sempre permitir force push/delete | baixo | fluxo curto | destruição sem confirmação e records órfãos | rejeitada |
| Parametrizar alvos e gatear operações destrutivas | moderado | previsibilidade e recuperação | mais prompts e testes git reais | escolhida |

## Open Decisions

- A detecção de rebase local usará apenas fatos do reflog/upstream que o git fornece; sem prova, a saída será recusa, nunca fallback para force.
- Quando um revert não encontrar task correspondente, registrará discovery e não inventará checkbox.

## Risks

- Force-with-lease ainda pode sobrescrever trabalho remoto desde que o lease esteja errado; mitigação: mostrar remote/ref/expected hash e confirmar.
- Deletar branch cedo pode retirar âncoras de records; mitigação: manter oferta separada e default preservar.
- Namespaced config pode expor fixtures legados; mitigação: teste positivo namespaced e recusa para flat.

## Handoff

## Outcome

- Entregue: o pilar Git agora lê `shared.sharedPaths`, oferece `force-with-lease` somente para rebase comprovado, trata deleção de branch Azure como escolha explícita, reabre tasks revertidas com motivo em `## Discoveries` e parametriza o remote em stale, cleanup e PR create.
- Evidência: 71 testes de comportamento em repositórios Git temporários passaram, além dos testes direcionados de specs; o fluxo rebase → lease push substituiu somente o tip esperado e o revert preservou o commit original no histórico.
- Escopo: nenhuma mudança de provider, remote ou branch foi publicada por esta execução; PR e merge permanecem como a próxima etapa de entrega.
- Próximo leitor: use o remote selecionado explicitamente quando não for `origin`; consulte o status da spec e os commits ancorados nas tasks para rastrear cada correção.
