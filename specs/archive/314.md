## Problem

Pedido do humano (2026-11-24): depois do deploy, OpenCode, Claude Code e GitHub Copilot usam o MCP do quenching e recebem a configuração que dá a eficiência esperada sem atrapalhar o fluxo de worktrees; o OpenCode recebe, pelo projeto, os N níveis de subagente que autopilot e orquestração precisam.

Mapa de 2026-11-24: o OpenCode só recebe `.opencode/agents/*` e o bloco `mcp` (`deploy/tree.py:405-411`, `mcpfiles.py:143-145`); nada de `experimental.subagent_depth` (padrão 1, que derrubou o orchestrator do épico 230 em 2026-11-22, ver spec 234) nem de `permission.external_directory` — os slots são irmãos do repositório (`git/slots.py:250`, store irmão `git/worktree.py:50-59`) e caem em `ask` (opencode.ai/docs/permissions). Um bloco `experimental` de projeto substitui o global em vez de mesclar (anomalyco/opencode#60410, a confirmar). Claude Code: `.mcp.json` de projeto pede aprovação (`enabledMcpjsonServers`, a confirmar); o deploy não escreve. Copilot lê `.claude/settings.json` e `.mcp.json` (docs.github.com hooks-reference e add-mcp-servers).

**Consequência:** no OpenCode o fluxo orquestrado falha ou para em prompt; no Claude Code o servidor pode nem ligar sem aprovação manual.

Proposta: o deploy escreve no `opencode.json` `experimental.subagent_depth` ≥ 4 (com a mescla segura do bloco global decidida no develop) e `permission.external_directory` só para os padrões dos slots e do store irmão; no `.claude/settings.json` `enabledMcpjsonServers: ["quenching"]`; sem `WorktreeCreate` e sem arquivo próprio do Copilot (hooks dobrariam); README e `docs/standards/automation/hooks.md` atualizados.

## Proposal

- Com o harness `opencode`, `cq deploy` mescla no `opencode.json` do alvo `experimental.subagent_depth` igual a 4 (um valor maior que o projeto já tenha fica) e `permission.external_directory` com `allow` só para dois padrões: os slots irmãos (`<pai>/<repo>-slot-*`) e o store irmão (`<pai>/<repo>.*`), derivados do diretório git comum, de modo que o mesmo deploy rodado num slot escreve os mesmos padrões.
- Quando o bloco `experimental` global do usuário traz chaves que o do projeto não traz, o deploy não escreve a profundidade (o bloco de projeto esconderia as globais, anomalyco/opencode#60410) e avisa nomeando as chaves e a linha a acrescentar à mão.
- Com o harness `claude` e o MCP registrado, o deploy mescla `"quenching"` em `enabledMcpjsonServers` do `.claude/settings.json`, preservando os outros nomes; um `disabledMcpjsonServers` que nomeia `quenching` fica como o usuário escreveu e vira aviso.
- O que o deploy escreveu nesses dois arquivos fica registrado no manifesto e sai com `--remove` ou quando o harness deixa de ser selecionado; `--check` acusa a diferença como drift.
- O deploy não escreve hook `WorktreeCreate` nem arquivo próprio do Copilot; `deploy-mode.md`, `hooks.md` e o README dizem o contrato novo.
- Este repositório roda o deploy de novo e passa a carregar essas chaves no seu `opencode.json` e no seu `.claude/settings.json`.

## Out of Scope

- `read`/`edit` ou qualquer outra permissão do OpenCode além de `external_directory`, e qualquer padrão fora dos slots e do store irmão: a autorização do humano (épico 306) é só essa.
- Copiar o bloco `experimental` global para o projeto: gravaria configuração pessoal num arquivo versionado e o faria mudar de máquina para máquina.
- `enableAllProjectMcpServers` e aprovar outros servidores: só o `quenching` é do deploy.
- O formato V2 `permissions` (array) do OpenCode: o V1 continua suportado (opencode.ai/docs/migrate-v1) e é o que os agentes gerados já usam; migrar é outra decisão.
- Reescrever o aviso de MCP não registrado da spec 234: pertence a ela.
- Hook `WorktreeCreate` e `.github/hooks/`: o worktree é do fluxo do quenching, e um arquivo do Copilot dobraria cada hook.

### Decisões

- **A profundidade é 4, constante, e nunca baixa o que o projeto já tem.** Condutor → orchestrator → runner → filho (épico 306). O valor não lê a máquina: o arquivo é versionado e não deve mudar de máquina para máquina.
- **O global só decide escrever ou avisar.** OpenCode 1.19.5 (máquina do humano) troca o bloco `experimental` do projeto pelo global em vez de mesclar campo a campo — anomalyco/opencode#60410, "a project experimental block hides every global experimental option (fields are not merged)", título e trecho lidos pela busca em 2026-11-24; o corpo não pôde ser aberto (webfetch negado). Sem verificação completa, a regra do épico manda não esconder: o global com chave que o bloco do projeto não tem → não escreve, avisa. O global é lido de `$OPENCODE_CONFIG`, depois `$XDG_CONFIG_HOME/opencode/` (padrão `~/.config/opencode/`), arquivos `opencode.json`, `opencode.jsonc`, `config.json`, como JSONC (comentários e vírgula final); ilegível → trata como sem chaves e não bloqueia.
- **Padrões absolutos, `~/` sob o HOME.** OpenCode casa `external_directory` contra `<dir>/*` absoluto e expande `~/` (opencode.ai/docs/permissions; anomalyco/opencode#20045). `*` casa qualquer sequência, `/` incluída, então `<pai>/<repo>-slot-*` cobre cada arquivo dentro de cada slot. A raiz primária vem de `git rev-parse --path-format=absolute --git-common-dir`; fora de um repositório git não há slots e nada é escrito.
- **Formato V1 `permission` (objeto).** "The V1 config format remains supported" (opencode.ai/docs/migrate-v1); é o formato dos agentes gerados (`deploy/translate.py:227`). As regras de projeto vêm depois das globais e são só `allow`, sem catch-all, então não mudam o resto da política do usuário.
- **`enabledMcpjsonServers` no `.claude/settings.json` versionado.** Claude Code honra a aprovação de projeto numa pasta confiável e a ignora numa não confiável (code.claude.com/docs/en/mcp §Project server approvals and workspace trust); é o efeito pedido sem tocar o arquivo do usuário em `~`.
- **Propriedade pelo manifesto.** O manifesto registra `opencodeConfig: {subagentDepth, externalDirectory: [...]}` e `claudeSettings.mcpjson: true`; a remoção tira só o valor ainda igual ao registrado.

### Assumptions

- O V1 `permission.external_directory` de projeto soma às regras V2 `permissions` globais em vez de substituí-las — sustenta `## Design` (formato V1); verificável abrindo o OpenCode neste repositório depois do redeploy.

## Open Decisions

- Se o OpenCode corrigir #60410 (mesclar campo a campo), o aviso de conflito vira ruído — decide-se quando a issue fechar com a correção, removendo o aviso numa spec nova.
- Se padrões com `~/` num arquivo versionado precisam de outra forma para times com layouts diferentes — decide-se no primeiro alvo versionado por mais de uma pessoa que acusar o drift no `--check`.

## Risks

- **`opencode.json` versionado com caminhos da máquina.** Outro layout de diretório faz o `--check` acusar drift. ACCEPTED — os slots e o store são irmãos do repositório por contrato e `~/` cobre o caso comum; a decisão aberta acima registra o gatilho.
- **Baixar uma profundidade global maior.** Nesta máquina o global tem 5; o projeto com 4 a sobrepõe. ACCEPTED — 4 é o mínimo que o fluxo precisa e o arquivo não lê a máquina.
- **O `*` do OpenCode casa demais.** `<repo>.*` também casa outro irmão chamado `<repo>.<algo>` que não é store. ACCEPTED — o épico autorizou o store irmão, e esse prefixo é dele.
- **Global JSONC malformado.** Tratado como sem chaves: pode esconder uma chave global. Mitigação: o aviso só some quando o global é legível; ilegível gera um aviso próprio.
