## Problem

Spec 1480 (#1491) made `plugins/quenching/assets/references/components-command-new/capabilities.md` cite an official
source for each fact. The worker found that the `spawned-agents` field is listed on none of the official pages it
cited, and left it untouched. Consequence: the reference passes off as a Claude Code capability a field with no
source. It goes stale silently, the exact failure 1480 set out to close. Decide by evidence (official docs, the
installed version): either correct it, or mark it as this repository's convention.

## Proposal

- `capabilities.md` §Subagents no longer presents `spawned-agents` as a Claude Code frontmatter field.
- The same sentence states the sourced mechanism: a subagent spawns subagents only when `Agent` is listed in its `tools`, and any type list in parentheses is ignored in a subagent definition.
- The `**Fonte:**` line of that section stays accurate (page, version, check date).

## Out of Scope

- The same field cited in `docs/standards/automation/agents.md`, `assets/templates/automation/agent.md`, `assets/templates/automation/agents-standard.md` and `commands/components/agent/new.md`: parked as a discovery; each is a different surface with its own contract.
- Any change to a grant, hook, CI, allowed-tools or an agent's `tools:` — this is prose only.

## Impact

- `plugins/quenching/assets/references/components-command-new/capabilities.md` — the one sentence in §Subagents.

### Standards this spec will write into docs/standards/

- none — a reference sentence is corrected; no standard is written.

### Product code this spec expects to touch

- `plugins/quenching/assets/references/components-command-new/capabilities.md`

## Validation

- `grep -c "spawned-agents" plugins/quenching/assets/references/components-command-new/capabilities.md` prints 0 after, and 1 before.
- `bash scripts/verify_repo.sh` exits 0.

## Design

Evidence (code.claude.com/docs/en/sub-agents, read against Claude Code 2.1.296): the frontmatter fields table has no `spawned-agents`; the documented mechanism is `Agent` in `tools`, and "in a subagent definition ... any type list inside the parentheses is ignored". Decision: correct it rather than relabel it as a repository convention, because the repository convention would be a field the runtime ignores. Durable rule: a capability cited in a reference carries an official source or is not cited as a capability.

## Alternatives Considered

- Mark `spawned-agents` as this repository's convention: rejected, the runtime does not read the field, so it would document a control that controls nothing.

## Open Decisions

- Whether the four other surfaces citing `spawned-agents` get their own spec: decided by the human reading the discovery line.

## Risks

- A reader of the templates still sees the field while the reference says otherwise — ACCEPTED, parked as a discovery for a follow-up spec.
