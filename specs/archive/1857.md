## Problem

Reproduzido na revisão de correção opus dos merges 8f845ea6..3152e241 (2026-10-17; Codex indisponível: cota primária 83% ≥ 80%).
**O specs-reader roteia para um id que não existe mais.** `plugins/quenching-specs-reader/commands/read.md:6` diz `→ the full \`quenching\` plugin's /quenching:specs:* commands`; depois da 1635 o plugin `quenching` é `published: false` e fora do marketplace; o destino certo é `/quenching-specs:specs:*`. `closure_findings` (`scripts/generate_plugin_modules.py:111-133`) só varre os módulos principais (`owned`) e não pega arquivo autoral do specs-reader.

**Validação.** Texto corrigido; o closure check (ou teste) cobre os arquivos autorais dos consumidores e falha com o id antigo. Gate exit 0.

## Proposal

- O `description` de `plugins/quenching-specs-reader/commands/read.md` aponta para `/quenching-specs:specs:*`, id publicado.
- `closure_findings` em `scripts/generate_plugin_modules.py` também varre os arquivos autorais `.md` dos consumidores (`authored` do manifesto) e acusa o id `/quenching:` não publicado.
- Um teste prova que um arquivo autoral com o id antigo falha o `--check`.

## Out of Scope

- Corrigir outras menções textuais do README do specs-reader (ex.: referência ao script de sync antigo): não faz parte do defeito reportado.
- Varrer arquivos autorais não `.md`: o id de comando só aparece em prosa.

## Impact

### Standards this spec will write into docs/standards/

- none — correção de texto e de checagem; nenhuma regra nova.

### Product code this spec expects to touch

- `plugins/quenching-specs-reader/commands/read.md` — o texto autoral.
- `scripts/generate_plugin_modules.py` — o closure check.
- `plugins/quenching/tests/test_plugin_modules.py` — o teste.

## Validation

- `python3 -m unittest plugins/quenching/tests/test_plugin_modules.py` sai 0, com o novo teste cobrindo o arquivo autoral.
- `python3 scripts/generate_plugin_modules.py --check` sai 0 depois da correção e sai 1 com `/quenching:` num arquivo autoral.
- `bash scripts/verify_repo.sh` sai 0.

## Design

- Regra durável: o closure check cobre todo texto que o consumidor publica, gerado ou autoral. Os autorais vêm da lista `authored` do manifesto, lidos do disco do módulo, não da árvore gerada.
- Alternativa pesada: incluir os autorais em `generated_tree`. Perdeu: a árvore gerada é o que o `--write` sobrescreve, e autoral nunca é sobrescrito.
- Atribuição datada (2026-10-17): o plugin `quenching` é `published: false`; `/quenching-specs:specs:*` é o destino publicado.

## Alternatives Considered

- Só corrigir o texto, sem estender o check: o defeito voltaria sem alarme.

## Open Decisions

- none — a lista `authored` do manifesto decide o que se varre.

## Risks

- Falso positivo em prosa autoral que cite `/quenching:` como exemplo histórico: o check já tem esse custo nos módulos principais; ACCEPTED — o gate mostra a linha e o texto se reescreve.
