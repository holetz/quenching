## Problem

Achado reproduzido pela revisão de correção do épico 515 (2026-11-25), sobre a 491. O predicado de `strengthened` em `quenching/assets/bin/quenching/git/audit.py:1157` compara conjuntos de palavras separadas por espaço: uma linha `plus` cujo conjunto é superconjunto estrito de uma linha `minus` absolve a remoção. O filtro de `#` (`audit.py:1154`) só vale para `minus`, não para `plus`; a ordem das palavras é ignorada; uma linha `plus` absolve várias `minus`. `quenching/agents/spec-verifier.md:150` diz que `strengthened` (severity info) "never blocks".

Reprodução (predicado exato contra as listas que `_lowered` monta em `audit.py:1148-1149`):

```
['# unset A B'] -> strengthened: ['unset A B']
['true || run one'] -> strengthened: ['run one']
['run one || true'] -> strengthened: ['run one']
```

Consequência: comentar uma linha do gate, ou torná-la incapaz de falhar (`|| true`, `true ||`), passa no check 10 como reforço em vez de `gate-shrunk`. O teste novo (`quenching/tests/test_git.py`, `test_lowered_reads_a_superset_rewrite_as_strengthened_and_a_dropped_token_as_shrunk`) só cobre `unset A B` → `unset A B C`.

Minimal fix proposed: `strengthened` só quando a linha nova é a antiga com tokens acrescentados ao FIM (prefixo preservado, mesma ordem), nunca com `plus` comentada, e nunca com `||`, `true`, `:` ou `exit 0` entre os tokens acrescentados; cada `plus` absolve no máximo uma `minus`; testes para os três casos acima.

## Proposal

- O check 10 só lê uma linha do gate reescrita como `strengthened` quando a linha nova é a antiga com tokens acrescentados ao FIM, na mesma ordem.
- Uma linha nova comentada (`#`), ou cujos tokens acrescentados incluem `||`, `true`, `:` ou `exit 0`, nunca absolve a remoção: a linha antiga sai como `gate-shrunk`.
- Cada linha acrescentada absolve no máximo uma linha removida.
- Os três casos reproduzidos em `## Problem` têm teste.

## Out of Scope

- Reconhecer toda forma de neutralizar um comando de shell (`&`, redirecionamentos, `set +e`) — o ruler é um predicado textual barato; a lista cobre os casos reproduzidos, e o resto continua sob o `spec-verifier`.
- Mudar a severidade ou o formato do achado `strengthened` — o contrato `info` não bloqueia continua.

## Design

- O predicado vira uma função `_strengthens(old, new)` em `audit.py`: verdadeira só quando `new` não começa com `#`, os tokens de `old` são o prefixo dos de `new` e os tokens acrescentados não contêm `||` (inclusive colado), `true`, `:` ou a sequência `exit 0`. Prefixo preservado é o que exclui `true || run one` e `# unset A B` sem lista de prefixos proibidos.
- A absolvição consome a linha `plus` usada (um conjunto de índices), então uma `plus` absolve no máximo uma `minus`.
- Estreitar o check 10 não pede autorização de grant (epic 550 `## Design`, 2026-11-25).

### Assumptions

- O spec-verifier é a segunda linha para neutralizações fora da lista (`## Out of Scope`).

## Alternatives Considered

- Remover a leitura `strengthened` e reprovar toda reescrita — perdeu: a 491 introduziu a leitura para não reprovar reforços legítimos (`unset A B` → `unset A B C`).
- Parsear a linha como shell (`shlex`) — perdeu: custo e falsos negativos maiores que o predicado textual para o mesmo conjunto de casos.
