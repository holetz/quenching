## Problem

A revisão de correção do épico 1616 (rodada 18) achou que o leitor de lifecycle do registry de ops ainda perde formas documentadas: estado em code span ou com ênfase, `archived 2026-08-30` sem separador e a declaração com maiúscula viram `op-orphan`.
Este épico agrupa a correção desse achado (spec 1618) como rodada 19 do autopilot de 2026-10-12.

## Design

### Autonomy policy

Authorized on 2026-10-11 by the human's invocation of `/quenching:specs:autopilot until dry`, the same one that
authorized epics 1522 through 1616. After a verifier PASS, the run may execute 1618 forced, push, open the PR and
merge it into `main` with no further confirmation: the conductor sends the leaf to `git-steward` for the merge.
Nothing widens a grant, a hook, CI, or a surface that executes code.

### Conductor decisions (as the delegated owner)

- Relevance: the opus review of epic 1616 reproduced it against a963e946. The form in a code span is the one the
  `lifecycle.md:18` table uses.
- 1618 fixes the root cause instead of adding one more case. Before reading the state, it normalizes the cell or the
  declaration: it strips backticks and `*`/`_` emphasis and ignores case. It takes the state as the first word
  followed by any text, and the path from the first cell that holds a code span ending in a script extension.
  Purpose free text is never read as a lifecycle. The tests cover every form from 1612, 1615 and 1618 in one table
  of cases.
- The ops lifecycle reader has now taken three rounds (1612, 1615, 1618). If the next review finds another regression
  in this reader, the conductor sends the reading contract (which declaration formats are accepted) to the human
  epic instead of opening a fourth spec.
