## Problem

**Human's request (2026-11-01):** "adjust so quenching uses its own git branch to store spec artifacts, instead of dropping them into loose folders", and so that "handoffs happen with a direction output for other sessions (with an example prompt, indicating where to find the handoff, which may or may not be attached to a spec)".

**The handoff dies with the machine.** `plugins/quenching/commands/handoff.md` (`:19-28`) composes the document into a `mktemp -t` file under `/tmp`: it does not survive a reboot, does not exist in another clone, and breaks the ephemeral-writes contract (`docs/standards/agents/ephemeral-writes.md`). The last step reports a path and stops; nothing in the report tells the next session what to do with it. Spec 1872 already recorded the near-loss of a handoff that survived only because the conductor copied it into the store by hand.

**A spec artifact has no home.** The `quenching` branch of this repository carries 851 paths today, all `specs/**` plus the root `quenching.json` — not one artifact. Each session invents its folder: this session left `tmp/1020934-handoff/handoff-1020934-2026-10-31.md` in the consuming repository; 1872 proposed `.quenching/handoff/`; that repository's own standard sends evidence to `analysis/specs/<id>-<subject>/`. Three destinations for the same object, and none of them findable by whoever opens the spec.

**Why now.** The store already has what the handoff lacks — per-spec identity, a pending ref shared by every worktree of the clone, and a sync point (`cq specs push`). The cost is one tree and one verb family, not new infrastructure; without it, every session boundary keeps paying the risk of losing the map.
## Proposal

- An artifact of a spec lives at `specs/artifacts/<id>/<name>` on the `quenching` branch; an artifact with no spec lives at `specs/artifacts/_handoffs/<name>`.
- `cq specs artifact list|read|write|rm` is the only door to that tree; no command writes a loose file to keep a spec artifact.
- An artifact is UTF-8 text up to 1 MiB, passes the same leak guard as the document, and is refused before any write when binary, too large, or named outside the grammar.
- An artifact write is a store write: it shows up in the next read, enters the pending commit, is carried by a concurrent sync, and reaches the remote on `cq specs push`.
- `/quenching-specs:handoff` stops using `mktemp`: it resolves the spec (explicit id, `cq specs find` over the current branch, or none), writes through the door, pushes the store, and reads back what it wrote.
- Every handoff closes with the same direction block — locator, read command, and an example prompt ready to paste into the next session — with or without a spec attached.
- The branch tree, the store standard and the glossary declare the destination and the new sync point.
## Out of Scope

- **Binary artifacts** (screenshot, PDF, parquet): the read path decodes UTF-8 and the leak guard is textual; opening bytes now would duplicate the read without a real consumer.
- **Migration of what is already loose** (`tmp/`, `.quenching/handoff/`, the targets' `analysis/specs/`): the store gains the destination; nothing is swept.
- **MCP tools for artifacts**: `cq specs mcp` truncates at 60,000 characters and a 1 MiB artifact would arrive cut; the CLI is this slice's door.
- **`cq specs export --artifacts` and `scrub` over a stored artifact**: export is the mitigation for losing a backend, not a backup; scrub keeps judging documents.
- **Retention and pruning of `_handoffs`**: the first number that justifies it is the branch size after N handoffs.
- **Stamping the artifact's pointer into the spec's `## Handoff`**: section and artifact have different readers; gluing one into the other duplicates the source.
- **1872's scope** ("land in-flight work before writing"): this spec changes the handoff's destination and report, not the inventory of worktrees, branches and PRs.
- **A card for an artifact**: a card is a projection of the document; an artifact has no tracker number.

## Design

**1. The tree sits under `specs/`, not at the root.** `_snapshot()` reads everything under `specs/` in one `ls-tree` (`git.py:342-358`); a root `artifacts/` would cost a second listing per read and a second conflict model. The branch keeps meaning "specs and what belongs to them", never code.

**2. A spec owns two paths and one prefix.** `specs/<id>.md`, `specs/archive/<id>.md` and everything under `specs/artifacts/<id>/`. That predicate is the only authority: `_replay`, `_store_local`, `_store_sync`, `_close` and `_late` judge the union of owned paths present in base, local and remote. Today `_spec_paths` returns only the two documents (`git.py:112-113`), which is why an artifact-only write (a) never enters `replay["changes"]` (`:368-410`), (b) vanishes in `_store_local`'s merge (`:745`), (c) is retired without a push by `_store_sync` (`:842-844`), and (d) is not rescued by `_late` (`:953-957`).

**3. A name is one segment; `_handoffs` is reserved.** `^[A-Za-z0-9][A-Za-z0-9._-]{0,119}$`, no `/` and no `..`; the owner is a numeric id or `_handoffs`, which never collides because an id is digits. Writing the same name replaces it — the same day and focus supersedes the previous handoff — and `rm` is the other side.

**4. Reading never decodes artifacts in bulk.** `preload()` (`:452-453`) decodes every blob in the snapshot for `list --lean`, the portal header and MCP; with artifacts in the tree, each listing would load every handoff. `preload` loads only the documents `_index` recognises.

**5. Text, a 1 MiB cap, refusal before the write.** `_texts` decodes UTF-8 (`:423`) and the guard is textual; `sp-artifact-binary` and `sp-artifact-too-large` refuse before any byte enters the commit. The cap is measured in bytes of the text, before hashing.

**6. A capability, not a sixth primitive.** The standard says the backend implements five primitives of the document (`base.py:12-31`). `write_artifact`/`read_artifact`/`list_artifacts`/`remove_artifact` sit on the base refusing `sp-artifact-unsupported`, and only the git store implements them; a tracker backend grows no tree.

**7. Archive does not move artifacts.** The id is the identity and a locator printed in a handoff must resolve after the archive; `specs/artifacts/<id>/` stays where it is when `specs/<id>.md` becomes `specs/archive/<id>.md`.

**8. The handoff resolves the spec without guessing.** An explicit id in the argument; otherwise `cq specs find` over the current branch (the `plan/<id>-<handle>` convention already resolves); otherwise none, stated in the report. An invented id is worse than a standalone handoff.

**9. The handoff pushes the store.** It is the session's last act: leaving it in the pending ref is losing it on a reboot or on another machine. `cq specs push` becomes a sync point; if it fails (offline, lease), the artifact stays pending and the block says `not sent — cq specs push`.

**10. The direction block is literal and single.** One structure for both cases, three fields: locator, read command, prompt. **What is literal is the structure and the field order; the labels and the prompt follow the target's conversation tag** (`docs/standards/agents/communication.md` §The language — a report a command prints is conversation). This repository's tag is `pt-BR`, so its printed form is:

```
## Handoff

quenching:specs/artifacts/2138/handoff-2026-11-01-destination.md

Cole numa sessão nova:

    Leia o handoff em
    quenching:specs/artifacts/2138/handoff-2026-11-01-destination.md antes de agir:
    `cq specs artifact read --spec 2138 --name handoff-2026-11-01-destination.md`.
    Ele pertence à spec 2138; siga com `/quenching-specs:specs:execute 2138`.
```

With no spec, the third sentence becomes "nenhuma spec está atrelada; pergunte o que fazer". With no push, one line says `não enviado — cq specs push`. In the fallback, the locator becomes `.quenching/handoff/<name>` and the line says `só local — este repositório não tem store git de specs`.

**11. `## Handoff` and the artifact do not replace each other.** The section is the small, event-bound context an executor reads (`artifacts.md` §`## Handoff`); the artifact is the session-to-session compaction. The command does not write into the section.

**12. With no store, it falls back to `.quenching/handoff/`.** The plugin's own fixed path, sanctioned by `ephemeral-writes.md`; the block declares `só local` and the handoff is not lost.

**13. 1872 is superseded on the destination.** 1872 is `captured` and fixes the destination at `.quenching/handoff/` (step 5). If it is built first, its step 5 falls; if this one is, 1872 inherits the door. Neither may write `mktemp`.

## Alternatives Considered

| Shape | Cost | Buys | Forecloses |
| --- | --- | --- | --- |
| `specs/artifacts/` on the store (chosen) | one tree in the already-read snapshot; an ownership predicate in five functions | one destination per repo, findable by id, that travels with the clone | nothing the spec asks for |
| Root `artifacts/` | a second listing per read and a second conflict model | an honest name for standalone handoffs | the cheap read; the tree stops being "specs and what belongs to them" |
| A second branch, `quenching-artifacts` | another ref, another lease, another fetch, another close | isolates artifacts from the specs branch's single-commit rewrite | the pending ref's atomicity: handoff and spec update no longer land in one commit |
| `.quenching/handoff/` (1872's step 5) | zero change to the store | fixes `/tmp` today, with no backend deploy | portability: it dies with the machine and the worktree, which is the original failure |
| The whole handoff inside `## Handoff` | no new storage | one source | the section's economy: it is sent to every executor and is small by construction |
| Leave each repo to invent its folder | no code | nothing new to maintain | finding a spec's handoff without asking whoever wrote it |

The first one wins, and the human confirmed the destination on 2026-11-01. The second branch was the only serious alternative: it loses because the gain it buys — not paying the single-commit rewrite — is unmeasured, and the plumbing cost is immediate.
## Open Decisions

- **A pointer in `## Handoff`.** If the first real session opens the spec without the prompt and misses the artifact, one line with the latest locator enters there through `cq specs section --scope global`; until then, no.
- **Retention of `_handoffs`.** Decided by the branch size after 20 handoffs: while the push stays under network noise, there is no pruning.
- **Artifacts over MCP.** Decided when the 60,000-character cap stops existing (streaming read) or when a consumer asks; today the CLI is enough.
## Risks

- **Silent loss of a pending artifact.** It is the failure mode the spec exists to prevent: without the ownership predicate, four paths drop the write with exit 0. Mitigation: the predicate is the only authority, and each of the four points gets its own test.
- **Listing cost.** A large artifact decoded on every `list --lean` would degrade the portal and MCP. Mitigation: `preload` decodes documents only, with a test that counts decodes.
- **Conflict with 1872.** Both touch `handoff.md` and disagree on the destination. Mitigation: 1872 is declared superseded at step 5; whoever builds second rebases the body.
- **Branch growth.** Every sync rewrites the single commit; artifacts add up. ACCEPTED — text and the 1 MiB cap bound it, and the proof measures the size after one handoff.
- **Leak through an artifact.** A handoff carries paths and names the document does not. Mitigation: the leak guard runs on the artifact write, with a test where a CPF is refused.
- **Store unavailable.** Without a network the push fails and the handoff stays in the local pending ref. ACCEPTED — the block says `not sent` and prints the command.
- **A name colliding across sessions.** Two sessions with the same focus on the same day write the same name and the second replaces the first. ACCEPTED — the name is date+focus, replacement is deliberate, and `rm` exists.

## Outcome

The spec store keeps spec artifacts. `specs/artifacts/<id>/<name>` — and `specs/artifacts/_handoffs/<name>`
for one attached to no spec — holds a text a spec carries beside its document, the handoff first, through
four backend verbs that are a capability and never a sixth primitive: the base refuses
`sp-artifact-unsupported` and only the git store implements them. A spec ID owns its whole prefix in the
replay, the pending merge, the sync, the late-write rescue and the close; an artifact-only pending is
reported (`artifacts`, beside `specs`) and pushed instead of retired silently; `preload` decodes documents
only, so `list --lean`, the portal header and MCP never read a handoff. `cq specs artifact list|read|write|rm`
is the door — text only, 1 MiB, one path segment, the body from stdin or `--from` — and the read-only reader
admits `list|read` while refusing `write|rm`.

`/handoff` closes a session through that door: it resolves the spec (`cq specs find` over the current
branch, never an invented id), writes the draft to `.quenching/handoff/<name>`, stores it on the branch,
pushes, reads it back, and prints one literal direction block — locator, read command, prompt — with labels
in the conversation's language. With no store it says the draft stayed local; with a failed push it says
`not sent`. The Codex citation guard stopped reading the `quenching:specs/…` locator as an agent citation.

Left out: MCP and the portal expose no artifact read (the 60,000-character MCP truncation would cut a
handoff without saying so); `cq specs export` does not carry artifacts; nothing prunes a handoff, so a
spec's artifact directory grows one file per session until someone removes one.

What the next reader needs: the conflict unit is the spec, not the path, so a document and an artifact of
one spec changed in two clones conflict together; `cq specs push` sends every pending write of the clone,
so a handoff never travels alone; one handoff costs the branch its own bytes and no history, because the
sync replaces the parentless commit.
