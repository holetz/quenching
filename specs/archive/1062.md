## Problem

The repository's current-facing documentation and proof surface have split from the live plugin surface. `plugins/quenching/commands/` contains 47 command files, and `docs/standards/architecture/align-surface.md` defines five aligned local fronts (`knowledge`, `design`, `components`, `ops`, `proof`), the provider-owned `specs` front without a local tree, and the alignless `git` pillar. Yet `install-profiles.md` and its copied index rows still describe four fronts, carry dead fifth/sixth-pillar anchors, and say the `ops` contract is tooling to come later even though its route, verifier and command bodies ship. Current-facing pages also retain 41-command and four-front claims, while the manual test hard-codes `EXPECTED_COMMAND_COUNT = 47`.

This is actionable now because umbrella spec 1057 measured these seams after the `ops` and `proof` fronts had landed, and the bundle's computed-fact fan-out standard says prose copies are invisible to ordinary validation. If the split remains, the suite can stay green while a new command or front changes the structural set and leaves readers, copied descriptions and numeric assertions stale. Historical mentions must remain true; only current claims and brittle lockstep checks need repair.
## Proposal

- The install-profile contract and its two index projections describe the seven installed entries consistently: five aligned local fronts, provider-owned `specs`, and the alignless `git` pillar; the dead pillar anchors resolve to the existing seventh-pillar section.
- The ops-front standard is marked and written as an implemented current contract, with its shipped route, verifier and command bodies represented rather than deferred by the "Contract first, tooling later" section.
- The explanation index and every current-facing count site found by the fan-out sweep use the live named sets or a deliberately retained count; obsolete 41-command and four-front claims are removed or corrected, while historical release and measurement prose remains historical.
- The canonical plugin manual has one explicit count decision recorded below. The recommended outcome is to retain a useful count only in that manual, make its test read the displayed value, and compare it with the independently derived `commands/**` set; all copied catalog prose should avoid owning another numeric source.
- `test_readme_surface.py` no longer contains a fixed expected count. Its lockstep proof remains discriminating because the manually listed command set and the on-disk command set are independently collected, and its synthetic failure test still demonstrates both missing and invented commands can turn the check red.
- The Codex README projection and the documentation indexes agree with the Claude source after the source update, without a second hand-maintained command catalog.
## Out of Scope

- New `toolchain`, `delivery` or `security` axes, their standards, routes, conductor order and implementation. Those are later children of umbrella 1057 and are not needed to repair the current set.
- The shared configuration-key arbiter, the extracted configuration loader, or any change to the profiles parser. Those belong to A4/A5 and are parked as discoveries below.
- Reworking the conductor ordering proof or its ordinal-based test. That is B2; this spec may cite the current aligned-front contract but does not re-derive its workflow assertions.
- Changes to `docs/standards/architecture/align-surface.md`, which is the authoritative current-set evidence for this repair, or to product/runtime behavior. The implementation task may change the surface test only.
- New automatic prose classification or a generated include system. Current-versus-historical mention/use judgment remains an execution-time review under the existing fan-out standard.
- Changelog, release/version metadata, glossary entries, concept docs, and any write to `/docs/` during this definition pass. Execution owns the declared documentation edits; emergent knowledge remains the close-out path.

## Design

### Current facts and authority

The live structural facts are measured, not inferred from a heading: `rg --files plugins/quenching/commands | wc -l` returns 47, and the mirrored Codex skill surface also contains 47 files. The authoritative front taxonomy is the aligned-front column in `docs/standards/architecture/align-surface.md`: five local aligned fronts, provider-owned `specs` without an align, and `git` as the seventh alignless pillar. `docs/standards/architecture/install-profiles.md` must therefore enumerate `knowledge`, `specs`, `design`, `components`, `ops`, `proof`, and `git`; its absent-profile explanation must describe all seven entries rather than the former five.

`docs/standards/architecture/ops-front.md` is no longer a proposal-only contract: the umbrella records the shipped `cq ops` route, inventory/doctor/status surface and command bodies. Its `authority: background` and the section that says tooling comes later contradict that evidence. The repair changes that state and preserves the standard's contract and vocabulary instead of rewriting implementation behavior.

### Count and prose rule

Use two independent measurements for a command count:

1. The manual is the human-maintained side: its command rows are parsed from the canonical plugin README (and projected to Codex).
2. The command surface is the structural side: command identities are derived from `plugins/quenching/commands/**/*.md`.

The test may compare the manual's displayed number with the structural set size and compare both sets for exact membership. It must not define an `EXPECTED_COMMAND_COUNT` from the same directory it is checking, and it must not derive both sides from `commands/**`. If the open decision removes the displayed number, the set comparison and synthetic can-fail proof remain the required assertion.

The prose sweep follows `computed-fact-prose-fanout.md`: first search the spelled-out numeric forms and exact command/front enumerations, then search the prose names and source-heading references that a numeric grep misses. Classify each hit as current-facing, copied/generated, or historical. Current-facing pages use the live named sets or the chosen canonical count; copied pages do not become new count authorities; changelogs, source histories and measured past facts remain unchanged except that a retired command path must not be left as a live citation.

### Repair boundaries

The install-profile table, profile example, dead anchors, ops implementation-status section, explanation index row, and two standards index projections are direct A2 repairs. The root README, bundle front door, project catalog/index, automation registry, how-to index, operating-model page, getting-started tutorial and adopt-how-to are the current-facing count/terminology fan-out class; each is reviewed per site and updated only where it asserts the present surface. `align-surface.md` remains the source of the named front set. `plugins/quenching-codex/README.md` is refreshed from the Claude README by the repository's translation path, not hand-edited.

## Alternatives Considered

| Approach | Cost | Benefit | What it forecloses | Decision |
| --- | --- | --- | --- | --- |
| Keep the hard-coded expected count and update it when the surface changes | Lowest immediate diff | Preserves the current test shape | It keeps a second remembered fact and future drift remains a manual discovery | Rejected: the umbrella and current test design show the failure mode. |
| Derive both expected and observed counts from `commands/**` | Small code change | Always reports the directory's current size | The assertion becomes tautological and cannot detect a stale manual or count | Rejected: it violates the computed-fact and surface-verification contracts. |
| Build a new generator/checker for every prose count | High new mechanism and maintenance cost | Could rewrite many copies mechanically | It cannot distinguish current use from historical mention and would create another source of truth | Rejected: the quality standard explicitly keeps this a human mention/use judgment. |
| Remove every visible numeric count | Smallest long-term fan-out | Eliminates stale numeric prose | Loses a potentially useful total in the canonical command manual | Available for the open decision; safe if the independent set assertion remains. |
| Retain one canonical manual count, validate it against the independent command set, and remove numeric copies elsewhere | Bounded test/doc work | Keeps useful reader information while leaving one checked source | Requires the execution owner to decide which current-facing copies are worth retaining | Recommended: it follows the manual's role and preserves a discriminating assertion. |
## Open Decisions

- Decide whether the canonical plugin manual should retain its displayed command total (and therefore the generated Codex heading) or use a count-free heading. Recommended: retain one total because the manual is the reader's complete surface map, but make the test parse it and compare it to the independently derived `commands/**` set; decide during execution by reviewing the manual's reader value and confirming the comparison can fail.
- Decide per secondary current-facing site whether an exact total is useful or should be removed in favor of a named set/catalog link. Decide during the fan-out task by checking whether the site is a navigation aid or a canonical manual and whether an independent assertion owns the number; historical statements are not candidates for rewriting.
## Risks

- The count check can become tautological if both sides are computed from `commands/**`. Mitigation: keep the manual rows and displayed number as the independent side, retain set difference assertions, and preserve the synthetic manual that proves a missing and invented command are observable.
- A prose sweep can damage an accurate changelog or measurement. Mitigation: classify current use separately from historical mention, keep past tense and source/history text, and use the retired-command spelling rule when a dead citation would otherwise fail the citation check.
- A generated Codex README can drift from the Claude source. Mitigation: regenerate it from the source and require the translation check to report `in-sync`.
- A copied index row can be updated while its source standard remains contradictory. Mitigation: update source standards first, then both index projections, and run the OKF validator plus a fresh source/index comparison.
- The broad current-facing fan-out may miss a non-numeric formulation. Mitigation: use the two-pass search (spelled-out forms, then prose names/source anchors), record every disposition, and keep the review bounded to the dependency map.
- Marking `ops-front.md` current without proving the shipped implementation would overstate the contract. Mitigation: tie the wording to the existing `cq ops` route, tests and command bodies, and let the full plugin suite and citation check expose missing surfaces.
- Removing secondary totals can make a reader lose orientation. Mitigation: replace them with stable named sets and links to the canonical command catalog; retain the canonical total only if the open decision selects it.
