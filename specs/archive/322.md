## Problem

No conclude autônomo da spec 308 (2026-11-24, passo 7, branch 11 commits atrás de origin/main), `git merge --no-edit origin/main` conflitou em dois arquivos: `.agents/.quenching-deploy.json` (coberto pela receita) e `quenching/README.md`, só na linha `<!-- quenching-proof-readme-sha256 ... -->` do bloco gerado `quenching-proof-readme-start`. A receita de `quenching/skills/quenching-specs/references/conclude.md` §7 (e a tabela §Under `autonomous`, linha "Step 7 — branch behind its base") só trata como mecânico o deployed surface (`.agents/quenching/**`, `.claude/skills/**`, `.agents/.quenching-deploy.json`); qualquer outro caminho manda `git merge --abort` e `needs-human`. Seguida à letra, a spec pararia por um conflito puramente gerado — que acontece sempre que duas specs paralelas acrescentam um módulo de teste. A resolução correta foi tomar qualquer lado e rodar `cq proof readme --write` antes de `cq deploy --target . --write`, e o gate ficou verde; o run só a fez porque o prompt do orquestrador disse "resolve generated blocks by regenerating them".

O conserto tem de tornar impossível parar em needs-human por um conflito restrito a blocos gerados que um verbo `cq` regenera.

Minimal fix proposed: estender a receita do passo 7 (e a linha da tabela) para os blocos gerados com verbo de regeneração conhecido — no mínimo o bloco `quenching-proof-readme` via `cq proof readme --write` — exigindo que o conflito esteja inteiramente dentro do bloco.

## Proposal

- O conclude autônomo (passo 7 e a linha "Step 7 — branch behind its base" da tabela) trata como mecânico um conflito de merge restrito ao interior de uma zona gerada enumerada em `docs/standards/architecture/generated-listings.md` §Enumerated generated zones, e o resolve com o verbo de regeneração dono da zona (`cq proof readme --write`, `cq ops registry --write`).
- O conflito só é mecânico quando todo marcador de conflito do arquivo está entre os delimitadores `-start`/`-end` da zona; qualquer marcador fora delas mantém `git merge --abort` + `needs-human` com os caminhos.
- Um teste de contrato falha se o corpo do conclude voltar a mandar abortar por um conflito só no bloco gerado.

## Out of Scope

- Zonas sem verbo de regeneração (a zona `standards/index.md` do `cq knowledge listing` entra só se o verbo for citado na tabela; sem hash, a receita é a mesma, mas não foi observada): ficam como estão, em `needs-human`.
- Mudar o mecanismo do deploy ou do merge: só a receita em prosa muda.
- Resolver conflitos de conteúdo autoral dentro ou fora das zonas.

## Design

- **Regra durável**: um conflito de merge é mecânico quando cada marcador (`<<<<<<<`, `=======`, `>>>>>>>`) do arquivo cai entre os delimitadores de uma zona gerada enumerada; a regeneração pelo verbo dono produz os bytes que valem, então o lado escolhido dentro da zona é irrelevante.
- **Receita**: para cada arquivo em conflito fora do deployed surface, conferir que os marcadores estão dentro da zona; resolver só os trechos conflitantes tomando o lado da base (`git show :1:/:2:/:3:` para arquivos temporários e `git merge-file --theirs`, que preserva o que já mesclou limpo fora da zona), rodar o verbo dono `--write`, `git add`, e fechar o merge. Tomar o arquivo inteiro da base perderia edições autorais da branch fora da zona.
- A ordem importa: o verbo `cq proof readme --write` antes de `cq deploy --target . --write`, porque o deploy espelha o README; depois `cq deploy --target . --check` sai 0 e o verbo dono em modo `--check` também.
- A lista de zonas não é repetida no conclude: ele cita a tabela de generated-listings.md, que é a fonte, para não criar uma segunda lista.
- Evidência: spec 308, passo 7 (merge 591476bf3) — conflito só na linha `quenching-proof-readme-sha256`, resolvido assim com gate verde.

### Assumptions

- `git merge-file --theirs` aceita os três arquivos de estágio e resolve só os trechos conflitantes (seção `## Design`, receita).

## Alternatives Considered

- Tomar o arquivo inteiro da base (`checkout-index --stage=3`) para qualquer zona: rejeitada, descarta edições autorais da branch no mesmo arquivo.
- Listar só o `proof readme` na receita: rejeitada, deixa o próximo bloco gerado (ops registry) cair no mesmo needs-human.

## Open Decisions

## Risks

- Um marcador de conflito literal dentro de uma zona gerada poderia mascarar um conflito fora: mitigado exigindo a verificação posicional contra os delimitadores e `--check` do dono depois da regeneração.
- ACCEPTED — a receita é prosa seguida pelo modelo, sem executor; o teste de contrato guarda o texto, não o comportamento.
