## Problem

`scripts/verify_repo.sh` and the CI job run the suite with whatever timezone and locale the host has; a test that formats a date or sorts by locale passes on one machine and fails on another, and agent and CI sessions differ from a laptop here.

## Proposal

Export `TZ=UTC` in `scripts/verify_repo.sh`, next to the temporary-directory export, so every tier of the gate (affected, full, CI) renders dates against one timezone; a test holds the export in place.
## Out of Scope

- Pinning the clock.
- Pinning the locale: `C.UTF-8` is not a macOS locale, so a portable value does not exist for every host the gate runs on.
- Changing tests that currently pass.
## Impact

### Product code this spec expects to touch

- `scripts/verify_repo.sh` — the export
- `quenching/tests/test_toolchain_gate_env.py` (new) — the export stays present and precedes every check
## Validation

`python3 -m unittest discover -s quenching/tests -p test_toolchain_gate_env.py` passes and fails when the export is removed; `bash scripts/verify_repo.sh` shows no new failure.
## Design

- The export sits before any test or doctor runs, so xdist workers and `git` children inherit it.
- The test is named `test_toolchain_*` so the affected selector's `scripts/` rule and the Windows toolchain job both pick it up; it only reads the script.
- Precedent: equin pins locale `en-US`, timezone `UTC` and a fixed clock for its jsdom runner and guards the pins with a check (`plugins/framework/plugins/tooling/plugins/test-layout/CLAUDE.md`).
## Alternatives Considered

- Pin in the CI workflow `env:` only: local and affected tiers would still float. Rejected.

## Open Decisions

- none — `UTC` is valid on every supported host; the locale was dropped for lack of a portable value.
## Risks

- A test that silently depended on a host locale starts failing; that is the hidden dependency the pin exists to expose.
