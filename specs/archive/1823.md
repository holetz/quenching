## Problem

O passo 2 do conclude revisa só com Claude; com cota disponível, a revisão independente do Codex deveria rodar por padrão.

Decisão do humano em 2026-10-16: D8 A (Codex como revisor independente, em paralelo à revisão Claude) e "por padrão quando houver cota". Análise: `.quenching/autopilot/2026-10-16/codex-revisao-cruzada.md`.

Evidência: `plugins/quenching/commands/specs/conclude.md:137-155` (passo 2); Bash irrestrito em `:5`, então `cq codex` não exige grant novo.

Esperado: o passo 2 roda `cq codex probe --json` e, com exit 0 ou 2, `cq codex review` sobre o diff da PR em paralelo à revisão Claude; consolida por `path:line`; achado só do Codex só conta se reproduzido; exit 1, timeout ou falha viram fallback reportado. Linhas de resume e de modo autônomo cobertas. Regenerar o surface Codex do comando. Coordenar com a task 2.1 da spec 1660, que propõe outro caminho (`cq components codex-review`) para o mesmo passo.

Esta spec não alarga `allowed-tools` nem `tools:`.

## Proposal

O passo 2 do conclude ganha uma revisão Codex independente, em paralelo à revisão Claude, por padrão quando houver cota:

1. `cq codex probe --json`: exit 0 ou 2 (cota livre ou desconhecida) segue; exit 1 vira fallback reportado.
2. Segue: grava o prompt (diff `origin/<base>...HEAD` por referência, pedido de achados `path:line`) em `.quenching/codex/<run>/prompt.md` e roda `cq codex review --worktree <worktree> --prompt <arquivo> --run <run> --base origin/<base>` em paralelo ao que o Claude lê.
3. Consolida por `path:line`. Achado só do Codex só conta se reproduzido (pelo Claude ou com comando e saída); achado dos dois conta direto.
4. Exit 1 do probe, timeout ou falha do review: a revisão Claude segue sozinha e o relatório diz `Codex: fallback (<motivo>)`. Nunca é erro do conclude.
5. Resume: a linha `review` da tabela de retomada já cobre (`reviewed:` setado pula a revisão inteira, Codex incluída). Autônomo: linha nova na tabela, sem pergunta — roda igual; achado só do Codex não reproduzido vai para o relatório, nunca vira correção.
6. O surface Codex do comando é regenerado; a regra de adaptação marca a chamada como indisponível dentro de um run Codex (sem Codex aninhado).

## Design

Mudança só em prosa executável do conclude, no passo 2, mais um teste de texto no padrão dos testes de comando existentes. Sem código novo: `cq codex probe|review` já existem (`python3 plugins/quenching/assets/bin/cq codex --help`; o `cq` instalado 6.4.0 não tem o pilar, então o texto do comando usa `cq codex` e a validação usa o caminho do repositório).

Fluxo do passo 2:

```
probe ──0/2──> review Codex (bg, timeout do cq) ─┐
  └──1──> fallback reportado                     ├─> consolida por path:line
leitura Claude do diff ──────────────────────────┘
```

Invocação (da análise de 2026-10-16): sempre `-s read-only --ignore-user-config` (embutido no `cq codex review`), sem `--ephemeral`, tokens do último `total_token_usage` ou `not measured`. O diff vai por `--base`; o Codex lê o worktree.

Regras de consolidação: chave `path:line`; dois revisores = achado; só Codex = candidato, reproduzir antes de contar; falha do Codex nunca bloqueia o `reviewed`.
