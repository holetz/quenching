## Problem

/quenching:specs:execute delega cada commit a `Skill("quenching:git:commit")` (decisão do #1131), e cada invocação recarrega o corpo inteiro do comando para commitar um índice já preparado com um subject já conhecido; numa spec de 22 tarefas (holetz/eclume#57) são 22 cargas do mesmo corpo. Falta a medida de quanto isso custa em tokens por tarefa contra um `git commit` com o mesmo contrato (índice existente, sem `--no-verify`, subject conferido), para decidir se a delegação fica, vira uma chamada `cq git commit` ou carrega o corpo uma vez por execução.

## Proposal

- A dated decision, `docs/decisions/0010-custo-de-delegar-o-commit-ao-git-commit.md`, states the measured cost in characters and estimated tokens of one `Skill("quenching:git:commit")` delegation, and the same cost for a bare `git commit -m` with the same contract.
- The decision projects that cost over a 22-task spec (the holetz/eclume#57 case) for each of the three options the Problem names: keep the delegation, a `cq git commit` call, or load the body once per execution.
- The decision names a recommended option and the evidence it rests on; `docs/decisions/index.md` lists it.

## Out of Scope

- Changing `execute.md`, `execution.md` or `git/commit.md`: this is a spike, the measurement decides whether a follow-up spec exists. Building `cq git commit` is deferred to that follow-up.
- A real tokenizer run on a live execution: the host exposes no per-skill token count, so the measure is the loaded characters (the same unit earlier decisions used), converted at a stated ratio.

## Design

Per delegation, the Skill loads: the `git/commit.md` body (4898 chars), the `§The declared-directive layer` plus `§The read-if-present rule` sections (4220 chars), `§Commit messages` (1057 chars) and the `cq git conventions --json` output (1125 chars): about 11.3k chars, roughly 2.8k tokens at 4 chars per token. Over 22 tasks that is about 62k tokens of context, each carried by every later turn. A bare `git commit -m "<subject>" && git log -1 --format=%s` is about 0.1k tokens per task. The measurement is read from the tree at spec time; the task re-measures before writing the decision.

The contract the bare call must keep: existing index only, no `--no-verify`, subject conferred with the declared-directive layer. The subject for an execution already comes from the task (`subject:` metadata), so the resolution steps of git:commit are largely redundant inside execute.

## Alternatives Considered

- Keep the delegation as is: single commit boundary, but about 62k tokens over 22 tasks.
- `cq git commit` deterministic call: cheapest per task and keeps one boundary, but costs a new tool; deferred to a follow-up spec if the decision recommends it.
- Load the body once per execution: saves later loads, but the body stays in context for the whole run, so the saving is only on the repeated loads.

## Open Decisions

- Which option to adopt: decided by the human reading decision 0010 and its numbers; a follow-up spec implements it.

## Risks

- The token figure is an estimate from characters, not a tokenizer count. Mitigation: the decision states the ratio and the raw characters.
- Section bodies may change between spec time and execution. Mitigation: task 1.1 re-measures against the tree.

## Outcome

Measured on the tree: one `Skill("quenching:git:commit")` delegation loads 11300 characters (about 2.8k tokens); a 22-task spec pays about 62k tokens, against about 2k for a deterministic call and about 5k for loading the body once.
