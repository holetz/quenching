## Problem

The quenching Settings page (7.8.0) reads its project from `ctx.sessions.current()`, but opening OpenCode's Settings leaves the session tab, so the page shows "Abra uma sessão num projeto" and hides every key — the configuration is unreachable from where it is supposed to be edited. Reported by the user on 2026-11-13, right after the release. There is also no path from the Specs panel to the page: the user has to find Settings › quenching by hand.

## Proposal

The page stops depending on a session being on screen. The Specs panel records the directory of the session it shows in window-local plugin memory (`ctx.storage.memory`), together with a short list of recent projects. The page resolves its project as the current session's directory, else that remembered one, and a **Projeto** selector switches between the remembered projects. The Specs panel header gains a settings button, and the command palette a `quenching: configurações` command, that remember the current session's directory and open the page directly (`ctx.layout.settings("quenching")`).

## Outcome

Shipped: the quenching Settings page no longer needs a session on screen. The Specs panel remembers its session's project in window memory (`ctx.storage.memory`, with up to eight recent projects). The page reads that, or the current session when there is one, and a **Project** selector switches between the remembered projects. Two shortcuts open the page on the current project: a settings button in the Specs panel header and a **quenching: configurações** palette command, both through `ctx.layout.settings("quenching")`. Both register only where the host has `SettingsLayout`. A project that was never opened in the window is not listed; open its Specs panel once. `tsc` and the build pass; the round-trip in Desktop 2.3 is still a check by hand.
