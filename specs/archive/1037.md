## Problem

O doctor valida identidade, assets órfãos e literais não-web, mas não mede os pares de primeiro plano e fundo que a própria fonte DTCG declara. Pares abaixo do limiar WCAG podem chegar às peças sem finding e sem depender de detector externo.

## Proposal

- Measure every same-group `X`/ `on-X` color pair declared by the DTCG source.
- Apply a deterministic WCAG contrast ratio with default AA thresholds for normal and large text, and allow the source to declare the applicable text size and level.
- Return stable severity, code, path, ratio, threshold, and pair names in doctor findings without using Impeccable.

## Out of Scope

- Pixel sampling, browser rendering, color management for arbitrary display profiles, or replacing the external web detector.
- Automatically changing tokens to make a pair pass.
- Expanding the component property projection schema.

## Impact

- `plugins/quenching/assets/bin/quenching/design/model.py` — color normalization and contrast policy helpers.
- `plugins/quenching/assets/bin/quenching/design/doctor.py` — pair enumeration and findings.
- `plugins/quenching/tests/test_design.py` — passing/failing threshold fixtures.
- `docs/standards/architecture/design-front.md` — source/projection verification split.
- `docs/standards/quality/surface-verification.md` — an inconclusive external check is not a green result; this check is self-contained.

## Validation

- A known passing pair produces no contrast finding; a known failing pair produces one error with a ratio rounded to two decimals and the configured threshold.
- Pairs are discovered by terminal names in the same color group, are checked once, and are ordered deterministically.
- Default policy is WCAG AA normal text (4.5:1); a large-text or AAA declaration changes only the threshold and is visible in JSON.
- The full design test module and existing SAFRA-compatible fixture behavior remain green.

## Design

- A pair is terminal token `on-X` with sibling terminal token `X` under the same group. Non-color tokens and unmatched colors are ignored.
- Relative luminance uses the WCAG sRGB transfer function. DTCG sRGB component values are clamped to 0–1; color values already carrying an opaque hex are normalized through the same path.
- Policy is optional under `$extensions.org.quenching.accessibility.contrast`: `level` is `AA|AAA`, `textSize` is `normal|large`; defaults are AA/normal. Thresholds are AA normal 4.5, AA large 3, AAA normal 7, AAA large 4.5.
- Doctor emits `design-contrast-failure` as an error at `.design/tokens.json#<group>.<on-X>`, including `ratio`, `threshold`, `level`, `textSize`, and `pair` in payload fields while keeping message text concise.
- Colors in unsupported color spaces do not produce a false pass: doctor emits a warning `design-contrast-unmeasurable` naming the pair and reason. This distinguishes no pair from no verdict.
- Dependency map (2026-08-30): `model.py` converts canonical color values and policy → `doctor.py` enumerates pairs and classifies measured/unmeasurable → `test_design.py` asserts both; no external detector is involved.

## Alternatives Considered

- Relying on Impeccable's web detector: rejected because it is optional and frequently absent.
- Checking only hard-coded token names: rejected because the source's X/on-X convention is the portable contract.
- Treating unsupported color spaces as passing: rejected because absence of a measurement is not evidence of accessibility.

## Open Decisions

- none — pair matching, policy defaults, thresholds, and unsupported-color handling are fixed.

## Risks

- Contrast ratios for wide-gamut colors require conversion not present in the current model; they are surfaced as unmeasurable warnings until a conversion is added.
- A token pair can be mathematically compliant but visually unsuitable in a particular context; the doctor is a floor, not a design approval.
- Threshold metadata may be malformed; source validation will refuse invalid enum/value combinations rather than silently using defaults.
