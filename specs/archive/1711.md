## Problem

`cq delivery doctor` treats valid four-space GitHub Actions YAML as a workflow without triggers or jobs. Independent verification in `../resume-map-verify.json`, item 1, at 719ca3e5 compared equivalent fixtures parsed identically by PyYAML. `cq delivery --root <fixture> doctor --json` with two-space indentation returned `triggers:["push"]`, `jobs:["test"]`, and `delivery-setup-missing` (exit 1). Four-space indentation returned empty `triggers`, `jobs`, and `jobDetails`, with `delivery-trigger-unreachable` (exit 1).

Cause: `plugins/quenching/assets/bin/quenching/delivery/inventory.py:13` fixes `_CHILD` to exactly two spaces, with consumers at lines 51, 63 and 306; `delivery/checks.py:69` emits the false finding. `docs/standards/architecture/delivery-front.md` does not constrain indentation. Consequence: the false unreachable-workflow finding hides the real setup finding and prevents checks for each job.

Scope: derive the indentation of children within `on:` and `jobs:` instead of fixing it to two spaces. Files: `plugins/quenching/assets/bin/quenching/delivery/inventory.py` and `plugins/quenching/tests/test_delivery.py`. Preserve finding codes, severities and workflow semantics; do not widen grants or alter CI.

Acceptance: equivalent two- and four-space workflows yield identical triggers, jobs and findings, without treating nested steps as jobs. A behavioral regression fails on 719ca3e5. `python3 -m unittest discover -s plugins/quenching/tests -p test_delivery.py` and `bash scripts/verify_repo.sh` exit 0.

## Proposal

- Equivalent GitHub Actions workflows using two or four spaces expose identical triggers, jobs, job details and delivery findings.
- Nested trigger filters and job properties remain inside their parent; genuine checkout/setup findings remain visible.

## Out of Scope

- Full YAML parsing, new dependencies and unsupported YAML forms: this defect concerns immediate mapping indentation in the existing bounded inventory.
- Finding codes/severities, permission grants, CI configuration and provider discovery: preserve the existing delivery contract.

## Design

Derive immediate mapping children separately inside each top-level block from the smallest mapping indentation present. Return only mappings at that level, preserving source indexes so job slices end at the next sibling. Reuse that discovery for `_mapping_names`, `_job_blocks` and `_trigger_names`; retain inline/list triggers and provider-specific branches. Comments and blank lines contribute no mapping indentation. This is bounded static inventory extraction, consistent with the existing architecture rather than a general YAML parser.
