## Problem

A tool MCP `quenching.specs_record` recusa o registro `buildCost` com `measurements` vazio, que é exatamente a forma que `/quenching-specs conclude` passo 4 manda gravar para evidência indisponível ("an empty scalar is absence, not zero"). A shell aceita o mesmo registro.

Em 2026-11-23, no conclude da spec 246, `tools.quenching.specs_record({spec:246, name:"buildCost", fields:{status:"unavailable", ..., measurements:""}})` devolveu `{"ok":false,"code":"mcp-bad-arguments","message":"field `measurements` is not a valid value"}`; o mesmo registro por `cq specs record 246 buildCost --set status=unavailable ... --set "measurements="` saiu com exit 0. Como `align/tool-resolution.md` agora manda preferir a tool MCP, o caminho preferido falha onde o reference exige um escalar vazio. A melhoria tem de tornar impossível a tool MCP recusar um valor que a shell e o reference aceitam.
