## Problem

The plugin's coverage of a target repository's meta-work surfaces is incomplete in a way that is
**closed, not open-ended**. Framed as the questions a gold-standard repository must answer
verifiably, seven have an owner and three do not:

| # | Question the repo must answer | Answered by |
| --- | --- | --- |
| 1 | What do we know? | `knowledge` |
| 2 | What will we do, and what counts as done? | `specs` |
| 3 | What does it look like? | `design` |
| 4 | How does an agent act here? | `components` |
| 5 | How is it run? | `ops` |
| 6 | How is it proven? | `proof` |
| 7 | How is it versioned and integrated? | `git` (pillar) |
| 8 | **What is it built with?** | **nobody** |
| 9 | **How does it reach production?** | **nobody** |
| 10 | **What must not leak, and who may touch what?** | **nobody** |
| 11 | How is the product's own code organized? | deliberately out of scope |

Each gap is already enumerated by the bundle's own candidate lists with no front converging the
tree. `docs/standards/code/index.md` reserves `format-lint` / `typing` / `dependencies-pins`;
`docs/standards/ci-cd/index.md` reserves `build` / `deploy` / `manifest-generation` /
`pipeline-stages`; `docs/standards/platform/index.md` reserves `deploy-targets` /
`permissions-governance` / `external-services` / `secrets` and holds not one standard.

**The second half of the problem is the one that reorders the work.** Three more axes would convert
several strained seams into structural problems — except that, measured on `main` at `0caec597`,
six of those seams are **already broken at seven pillars**, before a single new front exists:

- `docs/standards/architecture/install-profiles.md:24` still says the plugin installs "four fronts
  plus one pillar" and its table omits `ops` and `proof` entirely; `:36`, `:87` and `:91` repeat
  the stale count, and `:96` links `align-surface.md` §The **fifth** pillar has no align — a
  heading that does not exist.
- `docs/standards/architecture/ops-front.md:135` links §The **sixth** pillar has no align — also
  dead, from a standard four days old — and the file is still `authority: background`, still
  carrying §Contract first, tooling later, which declares that spec 1043 "does not ship the
  `cq ops` route, a verifier, or command bodies". All three shipped.
- `docs/standards/workflows/plugin-configuration.md` §The recognised keys names none of the seven
  keys `ops` and `proof` shipped (`opsRoot`, `router`, `proofRoot`, `layers`, `measuredRoots`,
  `proofExclusions`, `ratchetPath`), whose validation lives inside the **specs** loader at
  `plugins/quenching/assets/bin/quenching/specs/config.py:72-73`.
- `plugins/quenching/tests/test_readme_surface.py:31` hard-codes `EXPECTED_COMMAND_COUNT = 47`, and
  `plugins/quenching/tests/test_align_contract.py:48-58` asserts the literal
  `["ops", "ops", "proof", "proof"]` plus the section ordinals `### 6. Front 4` and
  `### 7. Front 5`.
- `pyproject.toml` is read by two fronts with no arbiter — `ops/inventory.py:32,140` takes
  `[project.scripts]`, `proof/inventory.py:177-180` takes the gate.
- The front mold (`doctor` / `inventory` / `bands` / `align` / `status`) has stabilized three times
  — `design`, `ops`, `proof` — at a measured **44 versioned files per front** and has never been
  extracted.

Adding fronts on top of that is building on a foundation that has already moved.

## Proposal

One umbrella that does four things, in the order their dependencies require:

1. **Close the set explicitly** — publish a standard declaring what a front never converges **and
   the front-versus-pillar distinction that decides which of the two an admitted axis becomes**, so
   the wrong shape is never proposed for the right gap.
2. **Repair the five seams that are already broken**, none of which depends on a new axis existing.
3. **Extract the front mold** before writing it a fourth and fifth time.
4. **Mint three axes: two fronts and one pillar.** `toolchain` and `delivery` become **fronts** —
   they converge a tree and repair it. `security` becomes a **pillar** — it audits and reports and
   never writes, the same shape `git` already has.

**The front-versus-pillar split is the plan's central correction.** The plugin has two kinds of
axis, and only one of them is governed by the admission test:

| Kind | What it does | Existing instance |
| --- | --- | --- |
| **Front** | Converges a tree toward a canonical shape and repairs the drift. Requires a tree a probe can find drifted and a verifier that decides statically. | `knowledge`, `design`, `components`, `ops`, `proof` |
| **Pillar** | Answers live questions about the target's own state. Converges nothing, so it needs no tree of its own. | `git` |

`security` fails the admission test as a front — every candidate tree is a key inside another
front's tree (§The admission test) — and passes trivially as a pillar, because a pillar is not
asked for a tree. Its findings are exactly the live answers a pillar gives: which workflow grants
which permission, which secret classes the ignore rules cover, whether the lock has an advisory
configuration, who may touch what.

**A pillar is also roughly an eighth the cost of a front.** Measured: the `git` pillar is 5 modules
and 345 lines of `cq`; the `ops` and `proof` fronts are 1,153 and 1,403 lines across roughly 44
versioned files each.

The conductor order becomes seven local fronts, with the pillar outside it, exactly as `git` is:

```text
knowledge -> design -> components -> toolchain -> ops -> proof -> delivery
```

`toolchain` comes **before** `ops` and `proof`: the router lives in the manifest, and the gate runs
on the toolchain. `delivery` comes **after** `proof`: it publishes the evidence proof produces.
`security` earns no row — a pillar has no align for a conductor to invoke.

The work decomposes into thirteen sibling specs across three phases (§Decomposition, under Design).
Phase A is independently valuable and blocks nothing on the new axes; the `security` pillar depends
only on Phase A's closing standard and on neither new front.
## Out of Scope

**Product code stays out of the axis set, permanently.** `docs/standards/architecture/`'s reserved
`layers` / `module-boundaries` / `dependency-direction` do not become an eighth front: the plugin
converges *meta-work* surfaces, not the product, and the existing invariant "blast radius reaching
product code confirms on its own" is exactly that line. Nearly every architecture finding would
land in the judgement band, and an align whose majority is judgement is a `status` wearing an
align's name. **The pillar route does not rescue it either**: a pillar answers a live question, and
"are these layers right?" is not a live fact about the repository, it is an opinion about its
design.

**Domain-specific trees stay out.** `data-modeling`, `naming`, `mlops` and the data half of
`quality` (`row-checks`, `data-drift`, `model-monitoring`) describe surfaces a repository without
data does not have. They belong to the bundle as standards, which `knowledge` already hosts.
Documenting is not converging.

**`security` does not become a front.** It is minted as a pillar instead. The refusal is about the
*shape*, never about the subject, and A1 records that distinction so the front version is not
re-proposed later by analogy.

**This umbrella does not absorb the plugin's own release path.** `.claude/commands/release.md` and
`cq specs release` stay what they are. `delivery` converges a *target* repository's pipeline;
absorbing the plugin's own publication act would make the plugin's release depend on a front the
plugin ships, a circularity nothing in the align surface currently has.

**The thirteen child specs are not created by this spec.** Capturing them is
`/quenching:specs:develop`'s pass, deliberately serial: the GitHub backend returns an empty front
with `ok:true` under concurrent batch writes.

## Design

### The admission test

`docs/standards/architecture/align-surface.md` is the governing standard: **a front exists when
there is a local tree a probe can find drifted, and a verifier that decides conformance
statically.** That standard already records why `specs` lost its align (its local tree went to the
provider) and why `git` never had one (it converges nothing, it only answers).

**The test governs fronts, and only fronts.** An axis that fails it is not thereby rejected — it
may still be a pillar, which is what the `git` precedent proves. Reading the test as a gate on the
whole surface is the error A1 exists to prevent, and it is the error this plan itself made before
the human corrected it.

#### `toolchain` — admit as a front

**The tree.** The manifest set (`pyproject.toml`, `setup.cfg`, `package.json`, `Cargo.toml`), the
lock (`uv.lock`, `poetry.lock`, `package-lock.json`), the language pin (`.python-version`,
`.nvmrc`), and the tool configuration blocks those manifests carry.

**The verifier decides statically, and the proof is this repository.** Measured on `main`:

| Finding | Evidence |
| --- | --- |
| language version disagrees across manifest and CI | `pyproject.toml:5` says `requires-python = ">=3.11"`; `.github/workflows/sync-codex-plugin.yml:25` and `plugins/quenching/assets/zensical/ci-github-pages.yml:23` both say `python-version: '3.x'`; there is no `.python-version`; the local `.venv` is `python3.14` |
| a declared dev tool the gate never runs | `pyproject.toml` declares `[dependency-groups] dev = ["pytest>=8.0"]` while `CLAUDE.md:20` runs `python3 -m unittest discover -s tests` |
| a manifest key with two readers and no arbiter | `pyproject.toml`, read by `ops/inventory.py:32,140` and `proof/inventory.py:177-180` |

Three structural findings, zero judgement, on the plugin's own repository, before a line of the
front is written. That is the band test passing on live evidence rather than by analogy.

**Bands.**

| Band | Findings |
| --- | --- |
| Mechanical | lock desynchronized from the manifest; the same key declared in two configuration homes; a generated tool-config block stale against its source |
| Structural | language version disagreeing across manifest / CI / pin file / container; an unpinned dev tool; a missing build backend; a manifest key with no declared arbiter |
| Judgement | which formatter, which ruleset, the upgrade policy, whether to adopt a lock at all |

**The name is `toolchain`, not `config`.** "Configuration" is already taken by
`.claude/quenching.json` and its key contract; colliding the two makes every search for the word in
this repository return two unrelated subjects. `toolchain` also passes the one-axis naming test in
`docs/standards/naming/command-surface.md`: it names what the surface produces — the reproducible
build environment — not the files it happens to live in.

#### `delivery` — admit as a front, on a narrower tree than first assumed

**The tree.** `.github/workflows/**`, or the provider's equivalent, plus the release
configuration. Nothing else.

**The boundary risk is real and it is a hard sequencing constraint.** `proof` already reads CI, as
gate evidence (`pf-no-ci`). `ops` already names `deploy` as a canonical entry point. `delivery`
converges the pipeline's own shape, and the `security` pillar reads its `permissions:` blocks as a
live answer. Four axes, one directory — the `pyproject.toml` failure repeated on `.github/`, with
one extra reader. **`delivery` therefore cannot be minted before the arbiter-by-key rule exists.**

**Its own candidate list is already stale, and the staleness is evidence.**
`docs/standards/ci-cd/index.md` defers `pipeline-stages` with the reason "there is no CI pipeline
for the plugin itself" — false since the Codex sync workflow landed. A deferral ledger that has
gone wrong about its own repository is precisely the unowned surface a front exists to converge.

**Bands.**

| Band | Findings |
| --- | --- |
| Mechanical | a generated pipeline manifest or job matrix stale against its source — the mirror of `op-registry-stale` |
| Structural | a declared stage unreachable from any trigger; a job runtime disagreeing with the toolchain declaration; a release path not reachable from the declared pipeline; a pipeline with no checkout or setup provenance |
| Judgement | which provider, which environments, the promotion policy, what a release may publish |

#### `security` — refuse as a front, admit as a pillar

**Why it fails the front test.** Every candidate tree is a **key inside another front's tree**:

| Candidate tree | Who owns it as a tree |
| --- | --- |
| workflow `permissions:` blocks (`.github/workflows/sync-codex-plugin.yml:16-17` — `contents: read`) | `delivery` |
| dependency advisory configuration (`dependabot.yml`, `renovate.json`) — a statement about the lock | `toolchain` |
| secret and ignore patterns (`.gitignore:20-21` — `hooks-config.local.json`, `settings.local.json`) | nobody, and it is one file |
| "never ingest a secret" | already a hygiene rule in `commands/knowledge/import.md:37,113` and `references/components-harness-align/harness-routing.md:66` |

A **front** whose entire tree is borrowed is the `pyproject.toml` failure minted deliberately: two
partial readers, zero contract. That refusal stands.

**Why it passes as a pillar.** A pillar is not asked for a tree, because it converges nothing. It
answers live questions about the target's own state, which is exactly the shape these findings
have: *which workflow grants which permission · which secret classes the ignore rules cover ·
whether the lock has an advisory configuration · who may touch what*. None of them is a drifted
artifact to repair; every one of them is an answer. `cq git stale` reads branches without a
"branches front" existing, and `cq security` reads workflow permissions the same way.

**The pillar consequently ships no align, no `doctor`, no `bands.md`.** That is the same restraint
`align-surface.md` already records for `git`: inventing a verifier for an axis that converges
nothing would be filling a table for a front that does not exist. `security` earns no row in the
aligned-front column and no stage in the conductor.

**Cost, measured.** The `git` pillar is 5 modules and 345 lines of `cq`; the `ops` and `proof`
fronts are 1,153 and 1,403 lines across roughly 44 versioned files each. The pillar route delivers
the audit at close to an eighth of the front route's cost — and it is the shape that actually
matches what the findings are.

**It also removes a dependency error.** As a cross-cutting property distributed into other fronts,
`security` could not ship before `toolchain` and `delivery` existed. As a pillar it reads the
target directly and depends on neither.

**Seam 1's repair has a shipped precedent.** The ops registry's generated zone with its delimiter
plus `sha256` is the same mechanism applied to a file rather than to keys. Declare an arbiter per
key: `[project.scripts]` to `ops`; pytest and coverage configuration to `proof`; dependencies,
lock, language version, lint and build backend to `toolchain`; workflow triggers, jobs and stages
to `delivery`; CI as gate evidence to `proof`. **A pillar reads without owning**, so `security`
reading `permissions:` takes no arbiter row — the rule is about who may *write* a key, and a pillar
never writes.

**Seam 5's extraction also has a precedent.** `docs/standards/architecture/report-mold.md` did
exactly this for the report shape — "a format rewritten in eight bodies goes stale in seven" — and
`shared-mold-keys.md` gives the binding membership rule for what a shared mold may contain: a key
only one writer may legitimately set stays out of it.

**Seam 4 is named but not solved by an existing standard.**
`docs/standards/quality/computed-fact-prose-fanout.md` describes this failure and prescribes the
grep; what it does not say is *stop asserting the number*. It is also explicit that a checker
cannot be written here, because distinguishing a live claim from a historical one is invisible to a
regex — so the repair is per site, never a sweep.

## Alternatives Considered

**Mint `security` as a third front.** Rejected on the measurement in §The admission test: its whole
candidate tree is other fronts' keys, so a front there would deliberately reproduce the
unowned-surface failure Phase A exists to repair, at roughly 44 versioned files. The subject is not
rejected — only that shape. It ships as a pillar instead.

**Ship `security` as a cross-cutting property with no command at all**, its findings distributed
into the fronts that own the trees. **Proposed by an earlier draft of this spec and overturned
during refine.** Three faults: it could not ship before `toolchain` and `delivery` existed, so it
inherited the whole of Phase C's risk for none of its value; it gave the human no way to *ask* the
question, which is the actual ask; and it mistook "not a front" for "not an axis", when the `git`
pillar is the counter-example already shipped in this repository.

**Name the first front `config` rather than `toolchain`.** Rejected: "configuration" already names
`.claude/quenching.json` and its key contract, and colliding the two breaks search across the whole
repository.

**Make `delivery` a pillar too, auditing the pipeline without converging it.** Rejected: unlike
`security`, `delivery` has a tree of its own that a probe can find drifted — a stage unreachable
from any trigger, a job runtime disagreeing with the manifest, a release path not reachable from
the pipeline are all repairable artifacts, not live answers. An axis with a repairable tree that
only reports is a front that declined to do its job.

**Fold `.claude/commands/release.md` or `cq specs release` into `delivery`.** Rejected: it would
make the plugin's own publication depend on a front the plugin ships. `delivery` may name
`/release` as the closing command for a judgement finding in this repository; it does not absorb
it.

**Write the front mold a fourth and fifth time and extract later.** Rejected on the measurement: at
roughly 44 versioned files per front, two more fronts written before the extraction is roughly 88
files of duplication to unwind afterwards, against extracting from three existing instances now.

**Patch the ordering test rather than re-derive it.** Rejected: the assertion transcribes one
rendering of the conductor — a literal front list plus two section ordinals — instead of stating
the contract. Patching it preserves the property that any future axis breaks it again.

**Do the three new axes as three unrelated specs, with no synergy review.** Rejected: the
measurement in §The seams overturned it. Five seams are already broken at seven axes, so the repair
is not preparation for the new ones — it is the work, and it stands on its own.

## Risks

- **The load-bearing assumption: that a target wants its toolchain converged at all.** `ops` and
  `proof` converge surfaces where the plugin has a defensible opinion — an entry-point contract, a
  test-layer taxonomy. A toolchain already has a strong owner in its language ecosystem (`uv`,
  `poetry`, `cargo`) and a pipeline has one in its CI provider. A repository already governed by
  `uv` plus a dependency bot may find `toolchain` converging what it already has. **Named, not
  resolved.** The mitigation available is evidence: C2 measures the front against a second
  repository, not only this one, before `delivery` is written on the same assumption.
- **A5 breaks an installed target silently.** A target that declared a flat `opsRoot` would, under
  a naive namespaced loader, have `cq ops doctor` return `op-config-missing` and its align report
  "not applicable" — the front vanishes and nobody is told. This is the same failure class as a
  front returning empty with `ok:true`. **Mitigated by the deliverable itself**: A5 refuses loudly
  rather than reading a flat configuration as absent.
- **A3 rewrites a sentence that was true about the past.** A changelog line correctly naming a
  former count is not drift. `computed-fact-prose-fanout.md` §Historical mentions stay is explicit
  that no checker can tell the two apart. **Mitigated**: A3 decides per site under the mention/use
  judgment and never sweeps.
- **A3's derived assertion becomes tautological.** Replacing the hard-coded count with a value
  derived from the same directory the test already compares makes an assertion that can no longer
  fail. **Mitigated**: A3 keeps a discriminating assertion or removes the count outright; a green
  that could not go red is not evidence.
- **The mold generalizes from three accidental instances.** `design`, `ops` and `proof` may share a
  shape that is incidental rather than essential, and a mold extracted too eagerly becomes a
  constraint the fourth axis fights — a lock file is not an "inventory". **Mitigated**: B1's
  success criterion is a measured file-count reduction on C1 and C2, so the mold is validated by
  its first consumer before `delivery` is written to it.
- **Minting an axis is close to irreversible.** `computed-fact-prose-fanout.md` §Retiring a named
  thing measures the cost of retiring **one** command: a single grep found 18 files and missed four
  more. Two fronts and a pillar are not cheaply undone. Accepted, with the reason: the axis set is
  declared closed by A1 in the same work, so the irreversible act is bounded rather than open-ended.
- **Seven fronts make the conductor expensive to run.** The cross-front pass cap is 3, and seven
  fronts times three passes is a long run on a repository that installs all of them. **Mitigated**:
  applicability becomes a conductor stage in B2, and the probe-before-inventory rule already makes
  a conformant front nearly free.
- **The GitHub backend drops concurrent batch writes.** Decomposing this umbrella creates thirteen
  specs; a batch returns an empty front with `ok:true`. **Mitigated**: write them serially, with
  retry, verifying each landed.
- **The surface moves faster than the plan.** `ops` and `proof` were declared days apart, and a
  standard four days old already carries a dead anchor. Every child spec proves its relevance
  against the live tree before executing rather than trusting this document.
