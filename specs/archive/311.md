## Problem

Medido em 2026-11-24 (strace -tt): `cq git preflight --json` leva 4,8 s com as cinco checagens em série (`quenching/assets/bin/quenching/git/preflight.py:188-189`): `resolve_base` chama `gh repo view` 0,50 s (`git/base.py:42`, chamado em `preflight.py:186`, que descarta o `_default`), `ls-remote` 0,55 s (`:95`), `push --dry-run` 0,66 s (`:78,:124`), `gh auth status` 0,42 s (`:143`), `gh run list` + `gh run view` 2,37 s (`:154-166`). `cq git base` sozinho leva 0,61 s, quase todo no `gh repo view`, e os corpos o chamam 12 vezes.

**Consequência:** cada rodada do autopilot e cada conclude pagam segundos de rede que não informam nada novo.

Proposta: checagens independentes em paralelo (threads; só subprocessos); sem `gh repo view` no preflight; `ghAuth` derivado do `gh run list` quando ele passa; `isDefault` do `git base` em cache por URL do remote em `.quenching/`; resultado do `ci` em cache por SHA do último run concluído (TTL curto). Meta medida: preflight ≤ 2,5 s frio, < 1 s com cache.

## Proposal

- `cq git preflight` runs its independent checks concurrently and no longer calls `gh repo view`.
- `ghAuth` is derived from the `gh run list` the `ci` check already issues when that call succeeds; `gh auth status` runs only as the fallback.
- `cq git base` caches `isDefault` per remote URL and base under `.quenching/`, so repeated calls skip `gh repo view`.
- The `ci` result is cached per `databaseId` of the latest completed run, so `gh run view` is skipped on a hit.
- Measured goal: preflight ≤ 2.5 s cold, < 1 s warm.

## Out of Scope

- Changing the five check ids, statuses, messages or the exit-code contract: the autopilot reads them by name.
- Caching `push`, `store` or the Azure DevOps `az` calls: they probe live write access.
- Reducing the 12 `cq git base` calls the bodies make: those are body edits, separate.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/git/base.py` — opt-out of the host-default lookup, per-remote cache
- `quenching/assets/bin/quenching/git/preflight.py` — parallel checks, derived ghAuth, ci cache
- `quenching/assets/bin/quenching/git/stale.py` — pass the opt-out (result discarded)
- `quenching/assets/bin/quenching/git/refresh.py` — pass the opt-out (result discarded)
- `quenching/tests/test_git.py`, `quenching/tests/test_git_preflight.py` — tests

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_git_preflight.py` and `-p test_git.py` pass.
- `cq git preflight --json` returns the same five check ids; measured wall time cold ≤ 2.5 s and warm < 1 s on this repo.

## Design

- **`resolve_base(cwd, host_default=True)`.** The default keeps today's pair; stale, refresh and preflight pass `host_default=False` and get `(base, None)` without any network call.
- **Cache of `isDefault`.** `.quenching/git-base-cache.json` (already gitignored scratch), key `"<remote url>|<base>"`; only a definite True/False is stored, `None` is never cached. A branch's default status changes only by a host admin action, accepted as a stale window of the cache's TTL (24 h).
- **Parallel checks.** `concurrent.futures.ThreadPoolExecutor` over `_store`, `_push`, `_ci` (and `_gh_auth` on Azure); only subprocesses run inside threads, no shared mutable state. Result order is fixed regardless of completion order.
- **Derived `ghAuth`.** `_ci` returns the check plus whether `gh run list` exited 0; success → `ghAuth` ok ("gh is authenticated"); otherwise the old `gh auth status` runs, so a fail keeps its message. On Azure `ghAuth` still probes `az` in parallel.
- **CI cache.** `.quenching/git-ci-cache.json` keyed by `databaseId` of the latest completed run holds the `run view` verdict (`ok`/`unavailable`); a completed run is immutable, so the key needs no TTL beyond a 24 h cap. `unknown` is never cached.

### Assumptions

- `gh run list` succeeding implies authentication — Validation / ghAuth task.

## Alternatives Considered

- Cache the whole preflight result: rejected, the `push` probe must be live.
- `asyncio`: rejected, the code is subprocess-only and threads are the smaller change.

## Open Decisions

- none — every item is decided above.

## Risks

- A stale `isDefault` after the host changes its default: ACCEPTED — the 24 h TTL bounds it and the value feeds only a link-read hint.
- Thread interleaving of `.quenching/` writes: mitigated by writing the cache after the pool joins, atomically via replace.

## Outcome

Shipped: `cq git preflight` and `cq git base` no longer make redundant network calls and run their checks concurrently. `resolve_base` gained a `host_default` opt-out and a per-remote `isDefault` cache; preflight runs its checks in parallel, derives `ghAuth` from the `run list` result and caches `ci` by run id. The five check ids are unchanged. Tests added in `test_git.py` and `test_git_preflight.py`; both pass.

Measured: preflight wall time fell from 4.8s to about 0.9-1.0s warm. The cold target of ≤2.5s was only partly met: cold runs measured 2.2-3.0s. The warm target (<1s) was met.

Left out: no change to the check set, to `gh` usage outside these two verbs, or to caching across processes.
