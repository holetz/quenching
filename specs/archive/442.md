## Problem

Achado reproduzido pela revisão do épico 431 (2026-11-24), merge 3bed06f76 (#434, spec 2257). `integrations/opencode-cache/src/track.ts:50` chama `ttlFromUsage(s.ttlMinutes, ephemeralOf(step.native), prev?.ttlMin)`, e `integrations/opencode-cache/src/core/logic.ts:101` (cópia gerada de `integrations/claude-cache/hooks/logic.ts`) faz `if (setting !== 'auto') return Number(setting)` **antes** de ler os valores `ephemeral_5m`/`ephemeral_1h`. O Design da 2257 (linha 18), a decisão (2) do Design do épico 431 e `integrations/opencode-cache/NOTICE.md:20` dizem o contrário: o TTL vem de cada escrita em `native` e só cai em `shared.cache.ttlMinutes` quando `native` não traz a divisão. O teste `tests/track.check.mjs:34` ("shared.cache.ttlMinutes forces it") não passa `native` e não pega o caso.

**Consequência:** com `ttlMinutes: "5"` e uma escrita `ephemeral_1h` (o caso da rota `claude-agent`), a faixa diz "cache expirado" 55 min antes da hora e empurra handoffs desnecessários.

## Proposal

No OpenCode, o TTL de `native` vence quando existe; `ttlMinutes` só vale sem ele. A semântica do Claude Code (`ttlMinutes` 5/60 força, documentada no README do `claude-cache`) não muda: a correção fica no chamador do OpenCode (ou num parâmetro de precedência do núcleo, gerado igual para os dois). Teste com `native` `ephemeral_1h` e `ttlMinutes: "5"` → 60.

## Out of Scope

- none — a mudança fica no chamador do OpenCode; o núcleo compartilhado e a semântica do Claude Code não mudam.

## Impact

### Product code this spec expects to touch

- `integrations/opencode-cache/src/track.ts` — `applyStep` passa a ler o TTL da escrita em `native` antes de `shared.cache.ttlMinutes`
- `integrations/opencode-cache/tests/track.check.mjs` — casos com `native` 1h/5m contra `ttlMinutes` forçado

## Validation

- `cd integrations/opencode-cache && npm test` sai 0, com `ttlMinutes: "5"` e `ephemeral_1h` dando 60.
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` verde.

## Design

Decisão (2) do Design do épico 431: o TTL vem de cada escrita em `native`; `ttlMinutes` só vale quando `native` não traz a divisão. `ttlFromUsage` (núcleo gerado de `integrations/claude-cache/hooks/logic.ts`) mantém a precedência do Claude Code, onde `ttlMinutes` 5/60 força. O chamador `ttlOf` em `track.ts` passa `'auto'` ao núcleo quando `native` mostra uma escrita (`ephemeral_1h` ou `ephemeral_5m` > 0) e o `ttlMinutes` configurado caso contrário. O núcleo não é tocado, então `cache_plugin_sync.py` não precisa rodar.

### Assumptions

- `native` sem escrita (ambos 0 ou ausente) é "sem divisão" — `## Validation` depende disto.

## Alternatives Considered

- Parâmetro de precedência no núcleo: rejeitado, alarga a superfície compartilhada com o Claude Code sem ganho; o chamador resolve.

## Open Decisions

- none — a regra está decidida no Design do épico 431.

## Risks

- Uma escrita 5m vinda de `native` com `ttlMinutes: "60"` agora dá 5; é o comportamento pedido pela decisão (2).
