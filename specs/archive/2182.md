## Problem

The proof front is what a target repository converges its verification surface toward: measured roots and floors, layers and derived markers, order independence and CI parity. `cq proof align` repairs what is structural and reports what belongs to the owner. None of it says what a test run costs.

Spec 2181 cut that cost inside this repository — one RAM-backed temp root per run, a per-run git configuration, a worker budget shared by concurrent gates, and three scopes (a task runs the diff's tests, a close runs the same selection inside the whole gate, CI and release run everything). Of all of it, only the no-orphan-loop rule reached a target, as the shipped twin of `agents/ephemeral-writes.md`. The rest lives in `scripts/toolchain/` and `quenching/tests/_paths.py`, which `cq deploy` never ships.

The gap is measurable in a target: its suite can grow to thousands of cases and minutes of wall time, a one-line change can pay the whole suite locally, and every run can write the machine's disk — while `cq proof doctor` reports a surface perfectly conformant, because the contract never asked. This repository is the proof: 5,632 cases and 133 s, and a conformant report that says nothing about either.

## Proposal

One contract, six pieces:

1. **A sixth gate rule** in `quenching/skills/quenching-proof/references/proof-align/gate-contract.md`: *the gate is cheap without being narrower*. It states the four cost facts a target declares — where the run's temp lives, how many workers it takes, the git configuration it inherits, and the scope of each tier — and the rule that a narrower local scope never replaces CI. Like every other rule it carries its codes.
2. **A declaration**, `.agents/quenching.json` → `proof.cost`:

   ```json
   {"proof": {"cost": {
     "tempRoot": "isolated",
     "workers": "auto",
     "scopes": {"task": "...", "close": "...", "ci": "..."}}}}
   ```

   `tempRoot` is `isolated` (outside the repository, removed when the run ends) or `system`; `workers` is `auto` or a positive integer; `scopes` names the three tiers' commands. Every key is optional; an absent or malformed declaration is reported, never defaulted into a pass. A malformed shape is refused by the loader's existing `pf-config-invalid` path.
3. **Three finding codes**, all judgement, raised by `cq proof doctor`:
   - `pf-cost-undeclared` — the target declares layers and does not declare the cost contract, whole or in part; the message names the missing keys.
   - `pf-temp-shared` — `cost.tempRoot` is `system`: every run writes the machine's disk.
   - `pf-scope-wide` — the close scope is the CI scope, so every local run pays the whole suite.
4. **The generated proof README** gains a declared-cost block inside its generated zone, so temp root, workers and the three commands are visible where a target reads its proof surface, and `pf-readme-stale` keeps them current.
5. **A shipped standard**, `assets/knowledge/standards/ci-cd/test-cost.md`, with this repository's own copy at `docs/standards/ci-cd/test-cost.md` as its provenance: the rules, the measured evidence from 2181, and how a target adopts them without the plugin's helper modules. The two inline sections of the repo's `ci-cd/index.md` move into that file, and both homes gain their listing entry.
6. **Align and bands**: the three codes enter `bands.md`'s judgement table with the evidence to report and the closing command, and `align.md`'s band table names them.

## Out of Scope

- Shipping `tmproot`, `slots`, `affected` or `check_tmp` into a target: they are this repository's Python helpers, and a target's runner is the target's own code. The front teaches the contract and checks the declaration; it never installs a runner.
- A measurement command: the proof front stays static and never executes the target's suite.
- Bumping the plugin version: a release is cut deliberately by `/release`, never at a spec's close.

- `test_proof.py`: one fixture tree per new code, and the minimal correction that retires it.

## Design

The front grades declarations and structure only (`proof/checks.py`: "the suite itself remains outside this pillar's execution boundary"), so cost enters the same way every other rule does: the target declares, the doctor grades the declaration, the align reports the evidence and the owner's closing command. The declaration is not a promise the verifier can test — but it is reviewable, it is rendered into the generated README so it cannot rot silently, and it gives the align a concrete sentence to report instead of an unverifiable suggestion.

`proof.cost` lives under `proof` because the front owns the verification inventory; the shared loader's ownership table gains the key. The loader resolves it into the same frozen config dictionary the inventory already carries, so `checks.py` never re-reads the file and the model stays the only read path.

The three codes are judgement, not structural: moving a temp root, adding a diff selector and choosing a narrower close scope are all changes to the target's own runner, and the align never edits a runner. `pf-temp-shared` and `pf-scope-wide` grade what the declaration says; `pf-cost-undeclared` is conditional on declared layers, like `pf-readme-stale`, so a repository with no proof front is never asked about the cost of a suite it did not declare.

The README block joins the digest, which is what makes the declaration visible in review: a target that changes its temp root or its close scope sees `pf-readme-stale` until it regenerates the file, exactly as a layer change already does.

## Alternatives Considered

- **A heuristic scan of the gate script.** Read the script and infer isolation from `TMPDIR`/`trap` tokens. Rejected: it grades a shell the front does not own, and every wrapper idiom would need its own rule; the declaration plus the rendered README is honest about being a declaration.
- **Running the target's gate to measure it.** Rejected: the front is static by contract, and a doctor that runs the suite is a doctor a target stops running.
- **Shipping the helpers.** Rejected in Out of Scope: `cq deploy` ships the surface, not a target's test runner.
- **A standard without codes.** Rejected: a rule the verifier never raises is prose, and the align would never report it.
- **Folding the cost rules into the existing five gate rules.** Rejected: each rule owns its codes and its disposition band; folding a sixth concern into the floor or the CI rule would make one finding mean two things.

## Open Decisions

- none — the split (declaration + judgement codes + shipped standard) follows the front's existing separation between structure and owner decisions.

## Risks

- Three new findings make an already-noisy doctor noisier; all three are judgement and the align reports them once with the closing command. `pf-cost-undeclared` stays conditional on declared layers.
- The README digest changes for every target that has a proof README, so `pf-readme-stale` fires once until the file is regenerated — the same wave a new layer already causes.
- A target can satisfy the declaration without changing its runner. That risk is why the standard carries the measured evidence and the align names the concrete tiers, instead of accepting the word "isolated" as proof.

## Handoff

- This repository's own gate is the three tiers in `AGENTS.md`; a change to `quenching/assets/bin/quenching/` is global for the selector, so the close runs at least `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` and the final validation runs the full gate.
- After editing the shipped payload, `python3 quenching/assets/bin/cq deploy --target . --write` refreshes `.agents/`; the gate's deployed-surface lockstep check refuses a stale install.
- The golden proof payloads are captured from a fixture tree; a new key in the inventory changes `proof-inventory.json` and `proof-doctor.json`.

## Discoveries

- The generated proof README lives at quenching/README.md; quenching/tests/README.md still carries a generated proof zone from spec 2170 that no command rewrites.
- Running the gate from inside an OpenCode session fails test_session_context: the ambient OPENCODE_SESSION_ID outranks the test's CLAUDE_CODE_SESSION_ID patch. The gate is green with OPENCODE_SESSION_ID, OPENCODE and AI_AGENT unset.
- The task list did not declare two outputs the work necessarily writes: the generated README (committed with 2.1) and this repository's own proof.cost declaration in .agents/quenching.json (committed with 4.1).
- Zensical's nav must list every published Markdown document, so the new standard needed a zensical.toml entry in the same commit.

## Outcome

The proof front now grades what a run costs, as a declaration the target makes.

- `proof.cost` resolves in `proof/config.py` — absent stays `None`, a wrong shape is a
  `pf-config-invalid` refusal (exit 2) — reaches the read model as `CostContract` plus the config
  path, and is graded by three judgement checks: `pf-cost-undeclared` (conditional on declared
  layers, the message names the missing keys), `pf-temp-shared` and `pf-scope-wide`.
- The generated README renders a "Declared cost contract" block inside the digest, so changing the
  temp root, the workers or a scope makes `pf-readme-stale` fire until `cq proof readme --write`.
- The gate contract carries a sixth rule, *the gate is cheap without being narrower*; the three
  codes appear once in its table, `bands.md` gives each a closing command, and `align.md` lists them
  as judgement.
- `docs/standards/ci-cd/test-cost.md` states the rules and the measured evidence from spec 2181,
  with its shipped twin at `quenching/assets/knowledge/standards/ci-cd/test-cost.md`; the two
  inline sections left `ci-cd/index.md`.
- This repository declares its own cost (`isolated`, `auto`, three scopes) and the deployed surface
  follows the source.

Verified on a throwaway target: absent cost gives `pf-cost-undeclared`; `tempRoot: system` with a
close scope equal to CI gives `pf-temp-shared` and `pf-scope-wide`; the corrected declaration plus
`readme --write` gives none. `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` and the
full `bash scripts/verify_repo.sh` both pass, the coverage floor enforced.

Left out: nothing the spec asked for, and no version bump — a release cuts that. Two outputs the
task list did not declare (the generated README, and this repository's own declaration) sit in the
Discoveries section, as does the `test_session_context` failure that makes the gate red only when it
runs from inside an OpenCode session.
