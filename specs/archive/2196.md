## Problem

`warn-git-add-all.py` matches its regex against the raw hook payload, so it warns on any shell call whose text merely contains `git add .` — an `echo`, a quoted commit message, a heredoc — not only on a staging command that will run; and its `git +add` pattern misses a real `git -C <dir> add -A`.
## Proposal

Keep the regex as the fast path for the no-match case (widened to allow git's global options before `add`) and confirm a hit on the parsed command: tokenize `tool_input.command` with `shlex` (punctuation-aware), walk each simple command between control operators, and warn only when the command word `git` (after optional `VAR=value` assignments and `-C <dir>`/`-c <k=v>` options) is followed by `add` with `-A`, `--all` or `.` among its arguments. Quoted text is one token, so it never matches. Input that is not JSON or does not tokenize keeps the regex's verdict.
## Out of Scope

- Changing the warning's text, level, event or matcher.
- Porting a full shell parser; heredoc bodies are only skipped when their lines do not start with `git`.
- `deny-claude-coauthor.py`.

## Validation

## Design

- `stages_everything(raw)`: regex miss → silent; JSON or tokenizer error → the regex verdict (warn); otherwise the parsed walk decides.
- Lines are tokenized one by one when each parses alone (a newline ends a command), else the whole command is one stream (a quote spans lines).
- Control tokens are those made only of `;&|()`; redirections stay words, so `cat <<'EOF' > f` is one `cat` command.
- Precedent: equin's guards resolve verbs and paths through a shell parser rather than regex after measuring 56 of 60 denials of one guard as false positives (`plugins/framework/plugins/tooling/plugins/guards/CLAUDE.md`).

### Assumptions

- The PowerShell tool carries its command in `tool_input.command`, like Bash; its quoting is close enough to POSIX for `shlex` to keep a quoted mention one token — Design.
## Alternatives Considered

- A tighter regex anchored after control operators: still matches inside quotes and heredocs. Rejected.
- A shared tokenizer under `quenching.common`: the hook runs from the deployed `.agents/quenching/assets/hooks/` through a polyglot `python -c` line without the package on `sys.path`. Rejected for now.
## Open Decisions

- none — the fallback preserves today's verdict wherever parsing fails.

## Risks

- A heredoc body line that itself starts with `git add .` still warns; that errs toward the warning, which never blocks.
