## Problem

Hoje um repositório-alvo só consegue governar como o pilar `git` escreve seus textos — subject de
commit, nome de branch, título e corpo de PR, subject de merge — publicando um standard inteiro em
`docs/standards/git/**`; sem esse standard, valem os defaults do plugin e não há como declarar uma
diretriz curta. O `.claude/quenching.json` já é a casa única de configuração que o alvo dirige ao
plugin, mas não reconhece nenhuma chave para essas diretrizes, então quem quer apenas dizer "o
subject do commit leva o prefixo do ticket" precisa escrever um documento normativo que também
passa a governar humanos.

## Proposal

O `.claude/quenching.json` passa a reconhecer uma chave `gitConventions`: um objeto de cinco
sub-chaves, cada uma uma diretriz em prosa que o alvo dirige ao pilar `git` do plugin.

```json
{
  "gitConventions": {
    "commitSubject": "Prefixe o subject com o ticket entre colchetes; imperativo, sem ponto final.",
    "branchName": "feat/<ticket>-<handle-kebab>; nunca o nome de quem escreve.",
    "prTitle": "O mesmo subject do primeiro commit, sem o prefixo do ticket.",
    "prBody": "Três blocos: o que muda, como provar, o que fica de fora. Sem screenshots.",
    "mergeSubject": "Merge <branch> (<strategy>) — nunca o texto default do git."
  }
}
```

Os valores são **material de prompt**, exatamente como `subjects.<key>.description` e os valores de
`tagCatalog` já são: um agente os lê para construir o texto e um humano confirma. O núcleo valida a
forma e nunca interpreta o conteúdo — não interpola placeholder, não expande template, não valida o
texto que saiu.

A resolução é **por artefato e independente para cada um**:

1. um valor explícito que o chamador passou (`$ARGUMENTS`) — inalterado;
2. `gitConventions.<artefato>`, quando declarado;
3. `docs/standards/git/**`, no que aquele documento cobrir;
4. o default do plugin (`git/commit.md` §Commit messages, `git/isolation.md` §Branch and worktree
   names).

A configuração vence o standard do alvo porque é dirigida **ao plugin pelo nome**, é mais estreita
(um artefato por sub-chave, não um documento inteiro) e porque uma chave que perdesse para qualquer
`docs/standards/git/**` seria letra morta exatamente nos repositórios com mais chance de declarar as
duas coisas. O standard continua governando tudo que a configuração não nomeia, e continua
governando humanos.

`cq git conventions` vira o leitor único das duas camadas declaradas: continua reportando `governs`
e `declared` sobre a camada de docs — o campo não muda de significado — e ganha `config` com as
diretrizes reconhecidas e `configUnknown` com as sub-chaves que nada lê. Ele segue reportando
**fatos apenas**: se um documento parcial do alvo cobre commit mas não merge continua sendo uma
leitura que o corpo do comando (ou o humano) faz sobre os arquivos listados.

## Out of Scope

- **Templates interpolados.** `"{ticket}: {taskTitle}"` transformaria a configuração em uma
  linguagem que o núcleo precisa avaliar, com escape, campos ausentes e erro de sintaxe. A prosa
  diretiva é lida por um agente que já sabe o que é um id de task.
- **Migrar um `docs/standards/git/**` existente para a chave.** Nenhum align e nenhum comando
  reescreve o standard do alvo para dentro da configuração; o que existe continua sendo lido.
- **Instalar `docs/standards/git/**` no alvo.** A proibição de `git/conventions.md` §What is never
  done permanece intacta e agora vale também para a chave: nada escreve `gitConventions` no
  `quenching.json` de um alvo por conta própria.
- **Variantes por branch, por provedor ou por tipo de spec.** Uma diretriz por artefato, global ao
  repositório.
- **Um artefato para o texto de review de PR.** `/quenching:git:pr:review` responde a threads, não
  constrói título nem descrição.

## Design

A cadeia de resolução, por artefato:

```text
  $ARGUMENTS explícito ──► vence sempre
          │ ausente
          ▼
  gitConventions.<artefato>  (.claude/quenching.json)  ──► vence, quando declarado
          │ ausente
          ▼
  docs/standards/git/**      (no que o documento cobrir) ──► vence, quando cobre
          │ não cobre / não existe
          ▼
  default do plugin          (git/commit.md, git/isolation.md)
```

`cq git conventions --json` responde as duas camadas do meio em uma chamada:

```json
{
  "ok": true,
  "governs": "target",
  "declared": [{"path": "docs/standards/git/branching.md", "authority": "current"}],
  "config": {"commitSubject": "...", "prBody": "..."},
  "configUnknown": ["prDescription"]
}
```

`governs` e `declared` mantêm o significado que já têm — a camada de docs, e nada mais — porque
`tests/test_git.py::Conventions` já os assere e porque um resumo em uma palavra sobre três camadas
mentiria no caso normal, em que a configuração nomeia alguns artefatos e o standard cobre o resto.
Os dois campos novos são aditivos.

## Alternatives Considered

| Forma | Custa | Compra | O que fecha |
| --- | --- | --- | --- |
| **`gitConventions` com prosa por artefato** (recomendada) | uma chave, cinco sub-chaves, dois campos no payload de `cq git conventions` | declarar uma diretriz curta sem publicar um documento normativo que também governa humanos | nada — o standard do alvo continua lido para o que a chave não nomeia |
| `gitConventionsPath` apontando para um arquivo | uma chave só | mantém o texto longo fora do JSON | reintroduz um segundo lugar para procurar a mesma verdade, que é o que `docs/standards/git/**` já é |
| Templates interpolados (`"{ticket}: {taskTitle}"`) | um avaliador, escape, erro de sintaxe, campos ausentes | determinismo no texto gerado | fecha a diretriz em prosa, que é o que um alvo real escreve; e transforma o núcleo em intérprete |
| Nada — só `docs/standards/git/**` | zero | nada | mantém o custo de entrada em um documento inteiro para dizer uma frase |

O ponteiro para arquivo perde pelo mesmo argumento que `plugin-configuration.md` §Absence and
malformed values já usa contra a configuração legada: duas fontes competindo pela mesma verdade não
têm regra de precedência segura. Aqui a segunda fonte já existe e é o standard do alvo; uma terceira
seria uma a mais do que este contrato consegue ordenar.

## Open Decisions

- **Por que agora.** Nenhuma evidência na árvore responde qual é o custo de esperar; a lacuna existe
  desde que o pilar `git` foi escrito. Decidida por quem instalar o plugin em um alvo com convenção
  de commit própria e sem `docs/standards/git/**` — o primeiro relato disso é o gatilho.
- **O que tornaria isto não valer a pena.** Se todo alvo real já publicar `docs/standards/git/**`, a
  chave é peso morto. Decidida medindo `cq git conventions --json` em três alvos instalados antes de
  qualquer extensão futura da chave.
- **Se `prBody` deve aceitar uma lista de blocos em vez de uma frase.** Nenhum alvo instalado pediu;
  decidida no primeiro alvo que declarar `prBody` e reclamar que uma string não basta.

## Risks

| Risco | Aceito porque |
| --- | --- |
| A precedência inverte a expectativa de quem já publicou `docs/standards/git/**` e depois declara a chave sem notar | `cq git conventions` reporta as duas camadas no mesmo payload e os corpos nomeiam qual governou cada artefato no relatório, que é o contrato que `git/conventions.md` já exige ("State in the report which one governed") |

## Outcome

Entregue e pronto para merge. O `.claude/quenching.json` do repositório-alvo agora reconhece
`gitConventions`, um objeto de cinco sub-chaves — `commitSubject`, `branchName`, `prTitle`,
`prBody`, `mergeSubject` — em que cada valor é uma diretriz em prosa que um agente segue para
construir o texto correspondente da camada git. O núcleo nunca interpola placeholder, expande
template nem julga o texto que saiu; a chave é material de prompt, como `tagCatalog` já era.

A resolução é por artefato e independente para cada um: valor explícito do chamador → a chave →
`docs/standards/git/**` no que cobrir → o default do plugin. A configuração vence o standard do
alvo porque é dirigida ao plugin pelo nome e é mais estreita; o standard continua governando tudo
que a chave não nomeia, e continua governando humanos. `cq git conventions` virou o leitor único
das duas camadas declaradas: `config` e `configUnknown` são campos novos, e `governs`/`declared`
seguem respondendo só a camada de docs — um resumo em uma palavra sobre três camadas mentiria no
caso ordinário. Duas findings `warn` no `cq specs doctor` impedem que uma diretriz que nunca se
aplica fique em silêncio.
