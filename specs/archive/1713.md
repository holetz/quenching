## Problem

The orchestrator and orchestrate command read `complexity` and `approved` from `show`, which omits them. Independent verification in `../resume-map-prose-verify.json`, item 3, at 719ca3e5: `cq specs show --spec 1518 --json` has only `folder,id,ok,path,phase,sections,stage,strays,tasks,title,view`; `cq specs status --spec 1518 --json` includes `records.priority.complexity` and `records.approved`. The existing grant includes `Bash(cq specs status:*)`. `show --full` only exposes the fields by dumping the document, contrary to the context contract.

Locations: `plugins/quenching/agents/orchestrator.md:30` and `plugins/quenching/commands/specs/orchestrate.md:24-25`. Consequence: the `needs-approval` fail-fast decision and the runs-alone/human routing rely on absent fields.

Scope: read those two fields from `cq specs status --spec <id> --json`, retaining the existence check via show and the existing fail-fast policy. Files: both carriers and `plugins/quenching/tests/test_specs_execute.py`. No grants or autonomous protocol decisions change. Dependency: S1 (1709) serializes the shared test file.

Acceptance: a prose check requires status and the correct field paths in both carriers and rejects the instruction to obtain these fields from show. `python3 -m unittest discover -s plugins/quenching/tests -p test_specs_execute.py`, the equivalent discovery for `test_git.py`, and `bash scripts/verify_repo.sh` exit 0.

## Proposal

- Read orchestration complexity and approval from `cq specs status --spec <id> --json` using `records.priority.complexity` and `records.approved` in both carriers.
- Preserve the existence check via `show` and the existing approval, autonomous and worker-routing policies.
- Guard both prose contracts against reading these records from `show`.
