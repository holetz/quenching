## Problem

O manual do plugin não diz que a revisão Codex roda por padrão quando há cota, quanto custa, onde fica a saída nem como é o fallback.

Decisão do humano em 2026-10-16: D8 A (Codex como revisor independente, em paralelo à revisão Claude) e "por padrão quando houver cota". Análise: `.quenching/autopilot/2026-10-16/codex-revisao-cruzada.md`.

Evidência: `plugins/quenching/README.md` (catálogo, modelo de custo e §Model policy); custo do autopilot em `plugins/quenching/commands/specs/autopilot.md:44-46`; a configuração no namespace `codex` de `.claude/quenching.json` (`crossReview`, `maxUsedPercent`, `timeoutSeconds`, `model`).

Esperado: o README descreve `cq codex probe`/`review`, o padrão "quando houver cota", o custo na cota ChatGPT/Codex, os tokens ou `not measured`, a saída em `.quenching/codex/<run>/`, o fallback reportado e que o surface Codex não tem a etapa. O README é copiado para `plugins/quenching-codex/README.md`: regenerar.

Esta spec não alarga `allowed-tools` nem `tools:`.

## Proposal

- O README do plugin ganha uma subseção `### A revisão Codex independente` na seção do fluxo `specs`, que descreve `cq codex probe` e `cq codex review`.
- O README diz que a revisão roda por padrão quando há cota (`shared.codex.crossReview: "auto"`) e que `"off"` é a recusa explícita.
- O README declara o custo: uma chamada por épico, na cota ChatGPT/Codex e não na do Claude, com os tokens reportados ou `not measured`.
- O README diz onde fica a saída (`.quenching/codex/<run>/`: `review.md`, `events.jsonl`, `prompt.md` no modo `prompt-only`) e os três modos `sandboxed`, `prompt-only` e `unavailable`.
- O README descreve o fallback: cota indisponível (`probe` exit 1), timeout ou exit 1 da revisão seguem só com a revisão Claude, e o relatório final nomeia o motivo.
- O README diz que um achado só do Codex vira spec apenas depois de reproduzido, e que o surface Codex (`quenching-codex`) não tem a etapa.
- O README gerado do módulo `quenching-codex` e os demais espelhos de módulo ficam regenerados.

## Out of Scope

- Alterar `allowed-tools` ou `tools:` de qualquer comando ou agente: o Problem proíbe, e o conductor já é o único que chama `cq codex`.
- Alterar o código do pilar `codex` ou o padrão `docs/standards/architecture/codex-pillar.md`: a documentação descreve o que existe, não muda o comportamento.
- Declarar o hook `after_specs_execute_task` de revisão Codex por tarefa: é decisão do humano, já registrada no padrão.
- Reescrever o corpo de `autopilot.md`: ele já descreve o passo; o README só o torna descobrível.

### Decisões

- Os fatos vêm do padrão `codex-pillar.md` e do passo 6 do `autopilot.md`, nunca de memória: o namespace da configuração é `shared.codex` (o Problem diz "namespace `codex`"; o padrão e `config.py` fixam `shared.codex`, e o README segue o código).
- A subseção fica no fluxo `specs`, porque a revisão por padrão é um passo do `autopilot`; é lá que o leitor do catálogo procura. Em linha com o idioma da seção, o texto é em inglês como o resto do README.
- Os valores padrão (`80`/`90`, `900`, `gpt-6-astra`) entram na tabela de configuração porque o Problem os lista; se o padrão mudar, o README muda junto.

## Alternatives Considered

- Documentar só em `autopilot.md`: perdida, porque o Problem pede o manual do plugin e o `autopilot.md` não é lido por quem consulta o catálogo.
- Uma página nova em `docs/`: rejeitada, porque o README é a fonte copiada ao surface Codex e é onde o Problem aponta.

## Open Decisions
