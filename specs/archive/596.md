## Problem

Evidência (scout ses_de7f04b5, 2026-11-26): `cq specs list --json | wc -c` = 1.557.583; só --phase e --lean; `--phase plans` já dá 49 KB. No MCP, specs_list pagina (limit 50) e devolve 14.845 chars. Consequência: o fallback de CLI que os agentes recebem quando o MCP falta estoura o contexto. Proposta: --limit/--offset na CLI com o mesmo padrão do MCP e lean por padrão no --json (o completo atrás de flag). Arquivos: specs/commands/read.py, commands/cli.py, testes.

## Proposal

- `cq specs list --json` is lean by default (the shape `--lean` already gives and the MCP `specs_list` serves), so the fallback a client gets without the MCP no longer dumps ~1.5 MB.
- `cq specs list --full --json` keeps the complete document-derived shape (stage, tasks, sections), reachable only by that explicit flag.
- `cq specs list` takes `--limit N` and `--offset N` with the MCP's semantics (default page 50 and maximum 200 when `--limit` is given; payload adds `returned`, `offset`, `nextOffset`); without either flag the JSON lists every row, as the CLI does today.
- The references that name the CLI fallback say so.

## Out of Scope

- Changing the MCP `specs_list` tool: it already pages and is lean — ruled out, it is the model being copied.
- Paging `cq specs next` or other verbs — a separate measurement would be needed.
- Changing the human (non-JSON) rendering — it stays as is.

## Design

Decisions, each a durable rule:

- **`--json` is lean unless `--full`.** Lean is already the provider-neutral index (`list_specs(lean=True)`, the MCP's own call); the full shape derives from every document and is the cost. Alternative rejected: keep full default and add only paging — the fallback the agents receive would still carry the heavy shape per page.
- **Paging copies the MCP's semantics** (`limit` 1–200, `offset` ≥ 0, `returned`, `offset`, `nextOffset`) instead of inventing new ones (epic 594 decision). Slicing happens before the full shape's batched read, so a page costs only its own rows.
- **Paging is opt-in on the CLI**: `--limit` absent means every row (compatible with callers that sum the whole front); `--offset` alone pages from there with the default page size.
- The human rendering (no `--json`) is unchanged.

### Assumptions

- No in-repo caller parses `stage`/`tasks` from `list --json` (grep of quenching/, scripts/, integrations/); the two eval `inspect.sh` only print it. Depends on: Proposal bullet 1.

## Alternatives Considered

- Full by default, lean behind a flag (status quo) — lost: the stated problem is the default size.
- A new `cq specs index` verb — lost: a second verb for what `list` already is.

## Open Decisions

- none — every choice is settled by the MCP's existing semantics and the epic's decision.

## Risks

- A consumer that read `stage`/`tasks` from `list --json` now sees them absent. Mitigation: grep found none in the repo; the payload's own `unavailable` list and `lean: true` name the omission and `--full` restores it. ACCEPTED for external callers — it is the requested change.
