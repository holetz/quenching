## Problem

Visto em 2026-11-24 no épico 306: no conclude da 311 (PR #317) o corpo do PR saiu vazio e o worker o preencheu com `gh pr edit` cru, fora dos verbos `cq` que o grant e o protocolo preveem (relato do orchestrator). O código está em `quenching/assets/bin/quenching/git/` (verbo `pr create`).

**Consequência:** PR sem descrição para o revisor humano, e um worker que sai do grant para compensar — o tipo de alargamento que o verifier e o reviewer caçam.

Proposta: reproduzir com `cq git pr create --spec <id>` numa branch de spec; o verbo monta o corpo (Problem/Outcome da spec, tasks, link) ou recusa com exit 2 sem corpo; o conclude nunca precisa de `gh pr edit`.

## Proposal

- `cq git pr create` never opens a PR with an empty body: with `--spec` and no body it builds the body from the spec (Problem, Proposal, Impact, Validation, Tasks count); with neither it refuses with exit 2 (`git-pr-body-empty`).

## Out of Scope

- The Azure comment/truncation path and `pr-create.md` wording beyond one line.

## Impact

### Process surface this spec expects to touch

- `quenching/assets/bin/quenching/git/pull.py` - `_create` and a new `_spec_body`
- `quenching/tests/test_git.py` - the two new tests and two bodies made explicit

## Validation

- `python3 -m pytest quenching/tests/test_git.py` passes, including the empty-body refusal and the spec-built body.
- `bash scripts/verify_repo.sh` (affected scope) is green.

## Design

The builder mirrors the default builder of `pr-create.md` step 2. A caller body wins; `-` reads stdin as before. The refusal fires before any provider call, so no PR is opened.

## Alternatives Considered

- Only refuse on empty body: rejected, a spec-bound runner would then compose the body itself.

## Open Decisions

- none - the spec Proposal fixes the behaviour.

## Risks

- A caller that relied on an empty body now gets exit 2. Mitigation: two existing tests updated; no shipped flow opens a PR without a body.
