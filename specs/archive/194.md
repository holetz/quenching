## Problem

quenching/assets/bin/quenching/codex/probe.py:78 faz message['error'].get(...), e o except de :118 não inclui AttributeError. Reprodução: com um codex falso que responde {"id":1,"error":"boom"}, cq codex probe --json dá AttributeError: 'str' object has no attribute 'get', exit 1. Consequência: pelo contrato, exit 1 significa unavailable (um fato conhecido proíbe), mas o caso é unknown (2), que deveria cair no fallback de sessions; a cota é lida errado e eligible quebra em vez de recusar com reason.

## Proposal

Tornar `_rpc` em `quenching/assets/bin/quenching/codex/probe.py` tolerante ao formato da resposta
JSON-RPC: um `error` que não é objeto vira `RuntimeError` com o próprio valor (`str(error)`) como
mensagem, e um `result` que não é objeto (string, lista, número) também vira `RuntimeError`. Os dois
caem no `except` que já existe em `read_app_server`, que devolve `(None, appServerError)` — o
fallback de sessions roda e, sem snapshot, o estado é `unknown` (exit 2), como o contrato manda.

## Out of Scope

- Mudar a tabela de estados/exits de `docs/standards/architecture/codex-pillar.md` — o contrato já diz que doubt é `unknown`; o bug é o código não cumpri-lo.
- Tratar respostas malformadas de `cq codex implement` ou de `eligible` além do que herdam de `probe` — eles chamam `probe()` e passam a receber `unknown` sem mudança própria.
- Endurecer `read_sessions` (o fallback já captura `AttributeError` na leitura do jsonl).

## Design

O defeito está em `probe.py:78`: `message['error'].get('message')` assume objeto. Uma string dá
`AttributeError`, que não está na tupla do `except` em `probe.py:118`, escapa de `probe()` e o
`main` de `cq codex` sai 1 — o código de `unavailable`, um fato conhecido que proíbe a chamada.
O mesmo vale para `result` não-objeto: `message.get("result") or {}` devolve a string, e
`from_app_server` quebra em `result.get`.

Correção local em `_rpc`:

```
error = message["error"]
detail = error.get("message") if isinstance(error, dict) else error
raise RuntimeError(f"{method}: {detail}")
result = message.get("result")
if result is None: return {}
if not isinstance(result, dict): raise RuntimeError(f"{method}: result is not an object")
```

Não se alarga a tupla do `except` para `AttributeError`: isso esconderia erros de programação em
qualquer ponto do bloco. A resposta malformada é tratada onde é lida.

## Outcome
