## Problem

Achado pelo autopilot 2026-11-21 rodada 8 (scout read-only sobre origin/main 0574813c1), reproduzido em repositório descartável.

`quenching/assets/bin/quenching/knowledge/nav.py:196-201` (`replace_nav`) conta `[` e `]` também dentro de strings TOML; se a profundidade nunca volta a 0 devolve o texto intacto. Reprodução: `how-to/index.md` = `# Intervalos [0, 1)`; primeiro `nav --write` grava `{ "Intervalos [0, 1)" = [`; cria-se `how-to/new.md`; `nav b --root . --config zensical.toml --check` → `current`, rc 0; `--write` → `already current`; `grep -c new.md` → 0.

Consequência: nenhuma página nova entra no nav e `site-nav-stale` dá verde falso. Sem teste de `replace_nav`/`kept_titles`.

Arquivos prováveis: `knowledge/nav.py`, novo `quenching/tests/test_knowledge_nav.py`.

## Proposal

Trocar a contagem de colchetes por linha de `replace_nav` (`quenching/assets/bin/quenching/knowledge/nav.py:194-203`) por uma varredura caractere a caractere que só conta `[` e `]` fora de strings TOML básicas (`"..."`, com escapes `\"` e `\\`), fora de strings literais (`'...'`) e fora de comentários (`#` até o fim da linha). Com isso um título de seção como `Intervalos [0, 1)` deixa de desequilibrar a profundidade, o bloco `nav = [ ... ]` é encontrado inteiro, `--write` reescreve o nav com a página nova e `--check` responde `STALE` quando falta página.

Junto, o primeiro teste de unidade de `replace_nav` e `kept_titles`, em `quenching/tests/test_knowledge_nav.py`: a reprodução do `## Problem` (título com colchete desbalanceado + página nova → o nav gerado contém a página nova) e a preservação do título humano com colchete pelo `kept_titles`.

```
hoje:   linha `{ "Intervalos [0, 1)" = [`  → +2 -0 ... depth nunca volta a 0 → texto intacto → "current"
depois: só colchetes fora de "..."/'...'/# contam → depth fecha no `]` do nav → bloco trocado
```

## Out of Scope

- Recusar em voz alta um `nav = [` cujo array nunca fecha (TOML malformado escrito à mão): hoje `replace_nav` devolve o texto intacto e o `--check` diz `current`. Mudar isso altera o contrato de `generate`/`cli.py` (um erro em vez de uma tupla) e fica como descoberta, não nesta spec.
- Strings multilinha TOML (`"""`/`'''`) dentro do array `nav`: `render_nav` nunca as emite e um nav à mão com elas não é caso observado.
- Qualquer mudança em `kept_titles`, `render_nav`, `build_nav` ou no predicado de caminho privado que a 2262 já levou.

## Design

- O varredor é uma função privada pequena em `nav.py` (`_bracket_delta(line, state)` ou equivalente) que percorre a linha mantendo se está dentro de string básica ou literal; `#` fora de string encerra a linha. Strings básicas e literais TOML não atravessam linha, então o estado de string recomeça a cada linha; isso mantém a varredura por linhas e o resto de `replace_nav` (achar o `start`, recortar `lines[:start]` e `lines[end+1:]`) intacto.
- O comportamento de "nunca fechou → texto intacto" fica como está (ver `## Out of Scope`).
- `pattern:` do teste: `quenching/tests/test_knowledge_site_source.py` (importa `_paths`, usa `tempfile` e `generate`).

## Outcome

**Done — reviewed, distilled, ready for merge.**

- `replace_nav` (`quenching/assets/bin/quenching/knowledge/nav.py`) now counts `[`/`]` through `_bracket_delta`, which skips TOML basic and literal strings (honouring `\"` escapes) and stops at a `#` comment. A section title like `Intervalos [0, 1)` no longer leaves the nav array "open forever", so a new page under it reaches the nav and `nav --check` stops answering `current` over a stale nav.
- `quenching/tests/test_knowledge_nav.py` (new) covers brackets in strings and comments, literal strings with escaped quotes, `kept_titles` with a bracketed title, and the generate → write → check round trip with a page added under that title.
- The deployed copy and the deploy manifest were regenerated; the `quenching/README.md` proof block was regenerated for the new test file (task 1.2).

Left out: a hand-written `nav = [` that never closes still makes `replace_nav` return the text untouched and `nav --check` answer `current`. Refusing loudly changes the `generate`/CLI contract, so it was captured as its own spec instead of widened here.

Next reader: the scanner is per line by design — TOML single-line strings never cross a line; multi-line strings (`"""`/`'''`) inside a nav array are not handled and were not seen in any generated nav.
