## Problem

Build size becomes visible only after execution is expensive. The configurable-spec-backend plan
had 29 tasks in seven sections and sessions peaking at 292k and 332k; context-discipline records
13 tasks naming the same roughly 37k-token file. Complexity selects a definition/worker gear,
not a build-context prediction. Develop has no size signal before approval.

Task files, task sections, Impact standards and on-disk sizes already provide a bounded reading
estimate. Develop should compare that estimate to the measured-policy worker budget and recommend
epic decomposition before approval when declared reading alone exceeds it. Conclude should retain
observed build cost with provenance, or explicitly report unavailable measurement, for calibration.

## Proposal

Add a read-only `cq specs estimate <id> --json` declared-reading heuristic by task section, compare
its known loading estimate against the 100000-token worker policy at develop's approval close,
and preserve scoped observed costs in a conclude-owned `buildCost` record. An estimate below the
budget is never evidence that the full build fits.

## Out of Scope

- Native Codex telemetry, transcript budget enforcement, automatic monetary pricing and adaptive calibration.
- Automatic decomposition, approval of generated children, execution or mutation of complexity.
- Predicting generated code size, tool output, test iterations or complete runtime context.

### Declared reading heuristic

Use UTF-8 byte size divided by four, rounded upward, explicitly labeled estimated. Group the
existing parsed tasks by section. Resolve only declared files and markdown standards paths in
Impact, with repository-relative paths and symlink containment. Each section loads its unique
union of files/standards once plus the execute command body and spec build-section text. A repeated
file in another section is counted there again. Report per-section bytes/tokens, task counts,
unique files, unresolved entries, maxSectionTokens and totalReadTokens. Compare maxSectionTokens
to workerBudgetTokens (default 100000, explicit positive override allowed). `overBudget` is a
warning about known reading, never a runtime prediction. `complete` describes coverage of the
declared inputs only. New/missing files and tasks without files remain unresolved, never silently
free. No sections means an incomplete estimate.

Always report exclusions: host/system/harness overhead, conditional execute references, tool/test
output, iteration count, growing history and generated code. No success field may assert fits;
unknown inputs and excluded overhead remain visible below the budget. File paths outside the
checkout are not read. Preamble source is the shipped execute body; unresolved preamble is explicit.

### Approval and decomposition

After develop's ready gate, call estimate before low/human approval. Above the worker budget,
recommend decomposition via spec-architect using the source spec, section estimates, unresolved
inputs and worker budget. Proposal mode returns independent slices and dependencies without writes.
Do not approve the unsplit source automatically at low/autonomous; return needs-human with the
budget evidence. Human may choose decomposition or explicitly accept the estimate's risk. Capturing
children and converting the source to an epic requires explicit authorization, preserves the
original problem and never silently rewrites approved tasks or starts execution. Below the budget,
report the known estimate and uncertainty; it is not a fits verdict.

### Measured build cost

Add optional conclude-owned `buildCost` with status measured/unavailable, date, source, measurements
and reason. Measurements is a compact JSON scalar holding scoped per-model usage totals, request
count and maximum reported request exposure. Do not call aggregated request exposure context peak.
Use existing `cq session cost` only for an explicitly identified Claude Code subagent build scope;
missing source, wrong runtime, refusal or incomplete attribution records unavailable with reason.
Never infer scope from the latest session, never mix model tiers, never turn estimates into measured
values and never write zero as missing telemetry. Conclude writes before archive and reports provenance.

## Risks

- Bytes/4 is a heuristic and excluded overhead can dominate. Labels, exclusions and unavailable
  coverage prevent a below-budget estimate from certifying a complete build.
- Existing session cost only covers Claude Code subagents and reported request exposure. Exact
  scope/provenance and per-model records prevent invented Codex or context-peak claims.
- New record/method must preserve generic record and generated-reader contracts.
