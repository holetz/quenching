## Problem

**`cq components session cost --latest-orchestrator` mede a janela errada com dois orchestrators em paralelo.** Em 2026-10-17 o orchestrator do épico 1627 (workers em opus) recebeu do comando só linhas sonnet, inclusive de spec-runner — eram do orchestrator paralelo do épico 1852, iniciado depois. Duas vezes o relatório saiu "custo não medido" e a auditoria de tipos lançados não rodou. O comando escolhe "o orchestrator mais recente" da sessão.

**Consequência.** Com paralelismo (até 3 workers, épicos simultâneos), o custo por épico e a auditoria de tipos ficam errados ou ausentes, justamente o que a spec 1632 (orçamento medido) precisa.

**Proposta mínima.** O orchestrator mede pela própria identidade (seu agentId/transcript, que ele conhece) em vez de "mais recente": por exemplo `--agent <id>` ou `--self` como em `session context --self` (1632). Teste com duas árvores de orchestrator intercaladas. Gate exit 0.

## Proposal

- `cq components session cost` gains `--self MARKER`: it scopes to the descendants of the orchestrator whose own latest `session cost … --self MARKER` call is the newest, found the way `session context --self MARKER` finds its caller.
- With two orchestrators interleaved in one session, each caller receives its own window: its own rows, its own `agents` peaks and its own `overBudget`.
- `--self` is in the same mutually exclusive scope group as `--descendants-of`, `--nested` and `--latest-orchestrator`; `--latest-orchestrator` keeps working unchanged.
- `agents/orchestrator.md` measures its cost with `--self orchestrator-<epic id, or the first spec id>`, the marker it already uses for `session context --self`, instead of `--latest-orchestrator`.
- A marker no subagent transcript carries, or carried identically by two, refuses (exit 2) with a code, never falling back to "most recent".

## Out of Scope

- Removing `--latest-orchestrator`: other callers and the conductor may still use it when only one orchestrator runs; deferred, not forgotten.
- Changing `session context --self` behavior or its marker contract.
- Any change to the budgets, to `overBudget` semantics or to the audit of launched types.
- Pushing, opening the PR or any grant change.

## Design

- **Identity by the caller's own command, not by clock.** The orchestrator knows its marker and the transcript records the Bash call in flight before it runs, so the tool finds the caller by searching the session's subagent transcripts for the newest `session cost … --self MARKER` call. This is the mechanism `session context --self` (1632) already proves; reusing it keeps one identity contract. Rule: a window is attributed to the agent that asked for it, never to the latest started.
- **One finder, parametrized by verb.** `find_self` in `context.py` takes the verb (`context` default, `cost`) in its pattern and, for cost, searches only subagent transcripts (the main transcript is the conductor, not an orchestrator). `cost.py` imports it lazily, because `context` already imports `cost`.
- **The found transcript is the `descendants_of` root.** Its agent id feeds the existing `scoped`, so rows, `agents` and `overBudget` are computed on the same set; this also fixes the overBudget omission seen with the wrong window.
- **Refusals:** no match -> `se-self-not-found`, two equally newest -> `se-self-ambiguous`, both exit 2.

## Alternatives Considered

- **`--agent <id>`**: rejected, the orchestrator does not reliably know its own agentId from inside its Bash; the marker is something it writes itself.
- **`--since` clock window**: rejected, it is what the `--latest-orchestrator` verb replaced and it still mixes interleaved orchestrators.
- **Keep "latest" and serialize orchestrators**: rejected, parallel epics are the supported mode.

## Open Decisions

- none — the flag name `--self` and its marker contract follow `session context --self`; the proposal fixes the shape.

## Risks

- A marker reused by two live orchestrators makes the call ambiguous: it refuses (`se-self-ambiguous`) and the orchestrator reports the cost as `not measured`; the marker already carries the epic or first spec id, which are distinct per orchestrator.
- The orchestrator.md is edited by another run (epic 1835): ACCEPTED — merge origin/main right before touching it; the edit is one line.
- Mirror drift: mitigated by regenerating with the scripts and declaring the mirrors in `files:`.
