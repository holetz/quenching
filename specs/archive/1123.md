## Problem

`README.md:85` promete "add this marketplace and enable the plugin the usual way" e aponta para o README do plugin, cujo `## Install` (`:388-402`, 807 chars) só mostra `claude --plugin-dir ./plugins/quenching`; `grep -rn "marketplace add\|plugin install"` no repositório retorna zero. Nenhum ponto de entrada verifica pré-requisitos: `shutil.which` aparece 2 vezes em todo o `cq` (impeccable, typst); `gh`, `az`, `uv`, `zensical` e a versão do Python não são checados, e o plugin usa `tomllib` (3.11+) sem declarar piso; num 3.10 o usuário recebe `ModuleNotFoundError` no meio de um doctor. Não há comando que escreva o `.claude/quenching.json` inicial; `docs/how-to/adopt-quenching.md:88` devolve isso ao humano. Não há caminho de desinstalação ou reversão documentado. 35% do README do plugin (21.800 de 62.519 chars) é changelog inline sob `## Upgrade`; não existe `CHANGELOG.md`; a entrada 6.x cita `assets/checks/conclude-order-check.sh`, que não existe; `versioning-release.md` diz "four artifacts" no título e lista seis na tabela.

## Proposal

- Instalação por marketplace documentada nos dois READMEs, com o `--plugin-dir` marcado como caminho de desenvolvimento.
- `cq doctor` de topo: piso de Python e presença de `gh`, `az`, `uv` e `zensical` conforme o backend e o profile declarados, com recusa nomeada antes da primeira sessão investida.
- Primeiro uso: um caminho (no `/align` ou num comando próprio, decisão em `## Open Decisions`) que oferece escrever um `.claude/quenching.json` mínimo com backend e profile detectados.
- `CHANGELOG.md` extraído do README, ligado do nav e do README; `cq specs release` recusa sem entrada para a versão nova; reconciliar quatro-versus-seis no standard.
- Seção de desinstalação e reversão.

## Out of Scope

- Não publicar automaticamente um release nem criar tag durante instalação.
- Não tornar ferramentas externas obrigatórias quando o profile ou backend não as usa.
- Não apagar changelog histórico; ele será extraído mantendo links e referências.

- cq doctor retorna exit 2 com remédio quando falta dependência necessária e 0 quando o perfil está satisfeito.
- release recusa versão sem heading no changelog e mantém lockstep dos artefatos.
- README do plugin fica abaixo de 40 KB e zensical strict retorna 0.
## Design

Os READMEs terão dois caminhos visíveis: instalação via marketplace para adoção e --plugin-dir somente para desenvolvimento local. Um doctor de topo verificará o piso de Python antes do carregamento e as ferramentas conforme provider/profile, retornando recusa nomeada quando faltar pré-requisito.

O primeiro uso oferecerá um config namespaced mínimo somente após detectar provider e fronts; a escrita será confirmada e seguirá o mesmo envelope que os adapters leem. A documentação de desinstalação/reversão explicará remover a entrada do plugin e preservar o bundle do alvo.

CHANGELOG.md será a fonte de entradas de release. specs release exigirá uma heading da versão nova e atualizará exatamente o conjunto real de artefatos, com o standard reconciliado.

## Alternatives Considered

| Forma | Custo | Benefício | O que fecha | Decisão |
| --- | --- | --- | --- | --- |
| Manter --plugin-dir como instalação principal | zero | curto para desenvolvimento | não explica adoção e upgrade | rejeitada |
| Colocar pré-requisitos somente no README | baixo | nenhuma mudança de CLI | falha tarde e inconsistente | rejeitada |
| Doctor precoce, caminho de primeiro uso e changelog obrigatório | moderado | onboarding verificável e release rastreável | exige docs/CLI/testes | escolhida |

## Open Decisions

- O comando de primeiro uso será o verbo existente que já conduz align se ele puder oferecer a escrita sem novo estado; caso contrário será um doctor/setup mínimo, decidido pela superfície atual e coberto por teste.
- O changelog conservará somente versões publicadas; alterações de plans arquivadas sem release não recebem entrada.
## Risks

- Verificação de ferramenta pode rejeitar um alvo que usa somente parte dos fronts; mitigação: derivar por backend/profile e reportar applicability.
- Exigir changelog pode bloquear release legítimo; mitigação: refusal antes de escrever, com heading esperada e remédio.
- Extração de README pode quebrar nav/links; mitigação: build strict e links relativos testados.
