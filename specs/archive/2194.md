## Problem

`tc-runtime-drift` reduces every declaration to its first number and compares them for equality, so `requires-python = ">=3.11"` beside a `.python-version` of `3.13` is reported as drift although the pin satisfies the floor. The toolchain-front standard also promises the check covers "manifest, CI, pin file or container declaration", while the code reads only manifests and the two language pin files.

## Proposal

Keep "what the project accepts" apart from "what it runs": a manifest value led by `>=` or `>` is a floor, anything else stays an exact declaration as today. Drift is two exact values that differ, two floors that differ, or an exact value below the highest floor. The standard's row for `tc-runtime-drift` is narrowed to the sources the check actually reads.

## Out of Scope

- Reading CI workflows or container files for runtime versions (that would be a new feature on a reduced-maintenance front).
- Interpreting `^`, `~`, `~=` or ranges with an upper bound; they keep today's exact reading.
- `delivery-runtime-drift`, which compares workflows among themselves.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/toolchain/checks.py` — `_version`, `_runtime`, `check_runtime_drift`
- `quenching/tests/test_toolchain.py` — the floor-satisfied and floor-violated cases
- `docs/standards/architecture/toolchain-front.md` — the `tc-runtime-drift` row names the sources it reads

## Validation

`python3 -m unittest discover -s quenching/tests -p test_toolchain.py` passes with `>=3.11` + `3.13` silent and `>=3.11` + `3.10` still `tc-runtime-drift`; `bash scripts/verify_repo.sh` shows no new failure.

## Design

- `_runtime` yields `(path, version, kind)` with `kind` `floor` for a manifest value whose stripped text starts with `>=` or `>`, else `exact`; pin files are always `exact`.
- Versions compare as integer tuples of the `major[.minor]` the existing regex already extracts.
- The finding message keeps its `source=value` rendering, a floor rendered as `>=value`.
- Precedent: equin keeps the wanted version (`latest`/floor) apart from the locked one (`mise.toml` vs `mise.lock`, `plugins/toolchain/CLAUDE.md`).

## Alternatives Considered

- Treat every manifest value as a floor: would hide a real disagreement such as `engines.node = "18"` beside `.nvmrc` `20`. Rejected.
- Full PEP 440 / semver range evaluation: correct but a new dependency or parser on a reduced-maintenance front for no reported case. Rejected.

## Open Decisions

- none — the floor operators are the two the reported false positive and the standard's own wording need.

## Risks

- A target relying on today's stricter equality loses a finding where a pin is above a floor; that finding was the defect.
