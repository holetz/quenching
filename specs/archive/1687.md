## Problem

`cq knowledge` quebra o contrato de saída em dois pontos: as recusas do `nav` saem 1 (achado) em vez de 2 (recusa), e o carregador de config morre com traceback diante de um arquivo não-UTF-8 ou de um JSON que não é objeto.

Evidência:

- `plugins/quenching/assets/bin/quenching/knowledge/cli.py:374-379` (`nav-no-bundle`) e `:382-387` (`nav-config-unreadable`) imprimem o payload à mão e retornam `FINDINGS` (1).
- `plugins/quenching/assets/bin/quenching/common/output.py:30` fixa `REFUSAL = 2` e `:85-94` oferece o helper compartilhado `refuse()`; o módulo declara que uma recusa não é um achado.
- `plugins/quenching/commands/knowledge/documentation/build.md:278` e `plugins/quenching/commands/knowledge/align.md:284` rodam `cq knowledge nav docs --check` e leem 1 como "nav desatualizado" — um bundle ausente ou uma config ilegível vira um falso achado de navegação.
- `plugins/quenching/assets/bin/quenching/knowledge/config.py:35-40` captura só `OSError`/`json.JSONDecodeError`: um arquivo não-UTF-8 levanta `UnicodeDecodeError`, e um arquivo `[]` ou `null` levanta `AttributeError` em `data.get` — `cq knowledge validate` morre com traceback.

Consequência: os corpos de knowledge tomam uma recusa por estado a corrigir e tentam "consertar" o nav; uma config malformada derruba o validate sem código de saída do contrato.

Escopo: as duas recusas do `nav` passam pelo `refuse()` compartilhado e saem 2; `_load_config` tolera arquivo não-UTF-8 e JSON não-objeto (cai nos defaults ou recusa com 2, nunca traceback); um teste para cada gatilho (bundle ausente, config ilegível, não-UTF-8, `[]`, `null`).

## Proposal

- `cq knowledge nav` exits 2 (refusal) through the shared `refuse()` for a missing bundle (`nav-no-bundle`) and an unreadable config (`nav-config-unreadable`), never 1.
- A non-UTF-8 nav config is an `nav-config-unreadable` refusal, not a traceback.
- `_load_config` falls back to the defaults for a hooks config that is non-UTF-8 or whose JSON is not an object (or whose `okfValidate` is not an object); `cq knowledge validate` never dies with a traceback on them.
- One test per trigger: missing bundle, unreadable config, non-UTF-8, `[]`, `null`.

## Out of Scope

- Rewording `build.md:278` / `align.md:284`: once nav exits 2 on refusal, their reading of 1 as "stale nav" becomes correct; no body edit is needed.
- Other `cq knowledge` verbs' exit codes: not reported broken.

## Design

- A refusal leaves by `quenching.common.output.refuse()` (exit 2, stderr rendering without `--json`); the payload keeps the codes `nav-no-bundle` and `nav-config-unreadable`.
- `_load_config` is a best-effort loader: any unreadable or wrongly-shaped file is skipped and the defaults stand (it already skips on `OSError`/`JSONDecodeError`). It catches `UnicodeDecodeError` too and ignores a non-dict document or non-dict `okfValidate`. Chosen over refusing with 2 because the loader serves hooks and validate where a broken local override must not block the gate, and it matches its current skip behaviour.
- `nav._read` catches `UnicodeDecodeError` beside `OSError` and returns `""`, which the nav verb already turns into `nav-config-unreadable`.

## Alternatives Considered

- Refusing with exit 2 from `_load_config` on malformed config: rejected, it changes a tolerant loader into a gate and every caller would need a refusal path.

## Open Decisions

## Risks

- A malformed local override is now silently ignored: ACCEPTED — it matches how invalid JSON is already treated.
- Callers that read nav exit 1 for these refusals: only the two knowledge bodies cited, which read 1 as stale and are corrected by this change.
