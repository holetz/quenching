## Problem

Evidência (scout ses_de7f04b5, 2026-11-26): `cq config schema --key nope --json` → {ok:true, keys:[]}; `--category bogus` recusa com cq-config-category-unknown e remedy. Consequência: typo de chave passa calado para portal e agentes; os dois filtros do 559 divergem. Proposta: --key sem nenhuma correspondência recusa (exit 2) com código e remedy sugerindo as chaves mais próximas; teste em config/schema.

## Proposal

`cq config schema --key <prefix>` sem nenhuma chave correspondente recusa (exit 2) com `cq-config-key-unknown` e um `remedy` que sugere as chaves mais próximas, no mesmo formato da recusa de `--category`. O portal (`/api/settings?key=`) herda a recusa pelo mesmo `config.schema_payload`.

## Out of Scope

- none — a recusa de `--category` e o formato do payload não mudam; nenhuma mudança de grant, hook, CI ou allowed-tools.

## Impact

### Standards this spec will write into docs/standards/

- `docs/standards/workflows/plugin-configuration.md` — `--key` sem correspondência é recusado

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/config/__init__.py` — `schema_payload` recusa o prefixo sem correspondência
- `quenching/tests/test_config_schema.py` — teste da recusa

### Process surface this spec expects to touch

- none — apenas código do pilar config e seu espelho implantado.

## Validation

- `python3 -m unittest quenching.tests.test_config_schema` verde, com o teste novo.
- `cq config schema --key nope --json` devolve exit 2 e `cq-config-key-unknown`.

## Design

Em `schema_payload`, depois da checagem de categoria, se `prefix` não casa nenhuma chave do registro (restrito à categoria, quando dada), devolve `(None, refusal)` com `code: cq-config-key-unknown`, `key`, `message` e `remedy: "closest keys: …"` via `difflib.get_close_matches` sobre as chaves do registro (cai para os prefixos de topo se não houver proximidade).

- 2026-11-26 — decisão do épico 594: recusa consistente com `--category`.

### Assumptions

- O portal repassa o 404 (`cq-config-key-unknown`) como já faz para a categoria; a aba Configuração não envia `key` inexistente (Impact → portal_settings).

## Alternatives Considered

- Manter `ok:true` com lista vazia — rejeitada: typo passa calado, divergindo de `--category`.

## Open Decisions

- none — decidido pelo épico 594.

## Risks

- Um consumidor que dependia de lista vazia para um prefixo inexistente passa a receber exit 2; busca no repositório não achou nenhum além do portal, que só envia chaves do próprio registro.
