## Problem

A verificação de literais não-web examina apenas /.design/media/, embora a produção real possa ocorrer em outros caminhos declarados pelo projeto. Sem escopo configurável, cópias de tokens em bibliotecas e artefatos de produção passam sem diagnóstico.

## Proposal

- Accept an optional list of root-relative non-web literal globs from tokens.json or production.md.
- Scan the configured paths as well as the existing default media scope, with deterministic deduplication and stable findings.
- Preserve the current default when no scope is declared and reject unsafe absolute or escaping patterns.

## Out of Scope

- Scanning web CSS/HTML/JSON, generated build output, binary files, or repository paths outside the declared scope.
- Inferring a project's production folders from its package manager or framework.
- Removing or rewriting duplicated literals automatically.

## Impact

- `plugins/quenching/assets/bin/quenching/design/doctor.py` — configured scope parsing and scanning.
- `plugins/quenching/assets/bin/quenching/design/model.py` — source extension validation for globs.
- `plugins/quenching/tests/test_design.py` — default/configured scope coverage.
- `docs/standards/code/file-relative-path-resolution.md` — safe root-relative resolution.
- `docs/standards/quality/parse-honesty.md` — malformed declarations must not be treated as absence.

## Validation

- With no configuration, the existing `.design/media/` behavior and findings are byte-compatible.
- A token extension glob such as `src/**/*.typ` finds a repeated literal outside `.design/media/`.
- A production document section declaring the same scope is supported and unioned without duplicate findings.
- Absolute and `../` patterns yield a source error; malformed declarations are not silently ignored.

## Design

- Source configuration is `$extensions.org.quenching.doctor.nonWebLiteralGlobs`, an array of root-relative POSIX globs. Production may additionally declare bullets under `## Non-web literal scope`; the union is used, with the default `.design/media/**` only when the union is empty.
- Globs must be non-empty strings, relative, and contain no `..` segment. Matching is rooted at the repository root and uses `Path.match`/explicit directory expansion without following symlink escapes.
- CSS, HTML, HTM, JSON, generated `.design/build/`, unreadable text, and binary content retain the current exclusions.
- The payload includes the effective sorted scope so a doctor consumer can distinguish default from configured scans.
- Dependency map (2026-08-30): `model.py` validates source-level configuration → `doctor.py` merges source and production declarations and scans → `test_design.py` covers default, external, malformed, and deduped cases.

## Alternatives Considered

- Scanning the entire repository recursively: rejected because it creates false positives in dependencies, generated artifacts, and unrelated fixtures.
- Replacing the default with configured globs: rejected because adding a scope should not silently remove the existing safety net.
- Keeping configuration only in production.md: rejected because machine-readable source configuration is needed for tools that do not load prose.

## Open Decisions

- none — storage locations, union/default semantics, safe pattern boundary, and exclusions are fixed.

## Risks

- A glob can miss a dynamically generated artifact; documentation must name the actual production path.
- A large configured tree increases doctor cost; the payload makes scope visible and the caller can keep globs narrow.
- Production prose is a second input format; malformed declarations must create findings rather than disappear.
