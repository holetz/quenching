## Problem

Target repositories want a subset of the plugin's verticals — only the spec cycle, or everything except
`design` — and today the unit of installation is the whole plugin: 58 commands, 6 agents and one `cq` with
twelve subpackages. Install profiles do not answer this: `shared.profiles.installed` narrows what `/align`
conducts, while every command outside the profile stays installed (`install-profiles.md` §The seven local
fronts and the non-conducted axes). Epic 1627 therefore wants the plugin split into separately installable
modules, on the condition that the full set enabled together loses nothing against today.

Three host mechanisms make that uncertain, and none has been measured with several quenching plugins enabled
at once:

- **Namespace.** The plugin name is the command prefix; a plugin `quenching-specs` replaces
  `/quenching:specs:*` in 57 command files (350 literals), in the `Not for:` cross-routes of 53 descriptions,
  in the 6 agent ids (`quenching:orchestrator` …), in the manual and in the Codex translation.
- **`${CLAUDE_PLUGIN_ROOT}`.** It resolves only inside the plugin that loads the file (`plugin-layout.md`
  §A mold cites nothing it does not also install). `align/tool-resolution.md` alone is cited by 33 command
  files across 9 fronts; 7 of the 21 reference directories are cited by more than one front.
- **`bin/` on `PATH`.** The host appends the `bin/` of every enabled plugin; two `cq` shadow each other, which
  is why the reader's binary is named `cq-specs-read`.

The baseline to preserve: the model-invocable commands add 7,261 characters of resident description (specs
1,481, git 1,408, knowledge 2,693, components 1,250); the rest are `disable-model-invocation`. Import edges
outside `common`: `git → specs` (7), `proof → ops` (2), `components → session` (1).

**Why now.** The demand is installation, not context: the non-core fronts already cost zero resident tokens.
Waiting costs twice — every command the other waves of epic 1627 add widens the surface a later rename has to
sweep, and wave 3 (S7, S8) plus the layout of S10 cannot start without the verdict.

## Proposal

- A decision record exists under `docs/decisions/` that says **go or no-go** on splitting the plugin, and for
  a go: how many modules, which module owns `cq` on `PATH`, the command naming scheme, and the migration path
  for installed targets.
- The verdict follows one stated rule. **Go** only if a split form (a) holds parity with all modules enabled
  and (b) delivers something measured that the single plugin with a front-hiding profile does not.
  Parity is: resident description cost at most 5% above the baseline (7,624 characters); and, with no
  tolerance, every routing probe that passes on the baseline passes on the split, exactly one `cq` resolves on
  `PATH`, every reference citation resolves, and `scripts/verify_repo.sh` and the functional checks stay green.
- Three forms are measured against the same baseline, not argued: **A** a generated shared core per module,
  **B** a base plugin plus dependents through the host's dependency mechanism, **C** the single plugin with a
  profile that hides fronts.
- Renaming the commands is an accepted outcome: it is priced in the record as a cost, never as a veto.
- Every number in the record carries the command that produced it, so the measurement can be repeated.
- A no-go abandons wave 3 of epic 1627 with the evidence, and names the profile extension as the alternative
  where form C delivered the benefit.

## Design

**D1 — Host facts before prototypes.** Five facts are settled by live test first, because one of them can
kill a form before a session is spent prototyping it: the manifest's dependency field and what auto-install
and `claude plugin prune` do with it; the `PATH` order when two enabled plugins ship the same binary name;
whether `${CLAUDE_PLUGIN_ROOT}` in a file of one plugin resolves when cited from another; the command id of a
nested (`commands/specs/develop.md`) and of a flat (`commands/develop.md`) file in a plugin named
`quenching-specs`; and the id under which another plugin invokes its agents. A form a fact kills is recorded
as killed and not built.

**D2 — Three tiers, eight modules.** The partition is the one the installation demand asks for: a **specs**
module (specs, git, the six agents, `handoff`), an **alignment core** (knowledge, components, the root
`align`), and **one module per optional front** (design, ops, proof, toolchain, delivery, security). Code
coupling decides what travels together: `git` imports `specs`; `proof` imports `ops`, so the proof module
carries or requires ops; and `session` travels with **specs**, not with components, because the
`orchestrator` agent calls `cq components session cost`. Per-front splitting of the core was weighed and
lost: `components → knowledge` carries 15 cross-routes and they share the two `knowledge-*` reference
directories.

**D3 — One measurement, three kinds of evidence.** Resident cost is counted statically from the frontmatter
of the model-invocable commands and confirmed once per arrangement in a fresh session. `cq` and citation
resolution are asserted on what the process did — an exit code, a file read — never on what the model said
(`surface-verification.md` §Assert on what the process did, never on what it said). Routing uses a fixed
probe set: the five ids `functional-checks.sh` already asserts plus one per new module, three repetitions
each, baseline taken the same day on the same model. A probe regresses only where the baseline passed all
three and the split failed any.

**D4 — Arrangements.** Specs alone; specs plus the alignment core; everything minus design; everything.
Routing probes run only on "everything" per form and on the baseline; the other arrangements are measured by
the static count and the process assertions.

**D5 — Nothing touches the installed plugins.** Form B needs `claude plugin install` from a local
marketplace, which `--plugin-dir` does not exercise. Every session of the spike runs under a throwaway
`CLAUDE_CONFIG_DIR`, and the prototypes are generated into `.quenching/spike-1628/` by a script that reads
`plugins/quenching` and writes nowhere else (`ephemeral-writes.md`).

**D6 — The record is the working file.** Each task appends its table to the record and commits it, so a
stopped spike leaves the measurements it already paid for.

Binding contracts the spike must not contradict: `plugin-layout.md` §References are cited by absolute path,
never relatively; `command-surface.md` §The surface invariant, and clean renames; `specs-reader-plugin.md`
§What is hand-owned and what is generated; `surface-verification.md` §The five preconditions a check must
satisfy.

## Alternatives Considered

- **Do not measure; split on the epic's D2.** Lost: `plugin-layout.md` already rejected a split once on
  reasoning, and a citation that stops resolving reads as prose with no validator to catch it. Deciding this
  without a fresh-session measurement repeats the argument instead of settling it.
- **Measure form A alone, B as fallback.** Lost: the host turned out to carry a dependency mechanism
  (`claude plugin prune` removes auto-installed dependencies), so B is not hypothetical, and without C a go is
  decided against nothing.
- **Two modules, as the epic first drew it** (spec cycle × alignment). Lost: it cannot express "everything
  except design", which is the stated demand.
- **One module per front, ten modules.** Lost for the prototype: the heaviest coupling in the tree sits
  between `components` and `knowledge`, and `git` cannot ship without `specs`. The three-tier cut keeps those
  together and still makes every optional front droppable.

## Open Decisions

- RESOLVED — **Naming:** nested module prefixes, proven by the host naming probe and 39/39 mapped routing/load observations; the clean rename is an accepted breaking migration cost recorded in ADR 0013.
- RESOLVED — **cq owner:** specs ships the sole PATH shim; all four measured arrangements resolve exactly one executable.
- RESOLVED — **Root align / handoff:** alignment owns root align, specs owns handoff; the registries and full native conductor check support those owners, and extraction must explicitly skip absent optional modules.
- RESOLVED — **Probe model:** all native result model keys are claude-opus-5-5; baseline and split routing were measured against the same source-day and model.
## Risks

- **Routing is measured through a non-deterministic process**, and a single run can pass or fail by chance.
  Mitigation: three repetitions, a same-day baseline, and the regression rule in D3.
- **Fresh sessions cost money and the matrix multiplies.** Mitigation: routing probes run on one arrangement
  per form; the spike stops and reports at 120 sessions, measured or not.
- **A prototype generated by script is not the real extraction**, so a parity it shows can still fail in S8.
  Mitigation: parity with everything enabled stays an acceptance criterion of S8; the record is the go to
  start, never the proof it worked.
- **A host fact changes with the next Claude Code release.** Mitigation: the record carries the host version
  (2.1.296 on the day of the sweep) beside every fact.
- **The spike's sessions leak into the real installation.** Mitigation: D5 — a throwaway `CLAUDE_CONFIG_DIR`,
  and the working tree is checked for stray changes under `plugins/` before each commit.
- ACCEPTED — the benefit comparison against form C rests on a prototype of a profile nobody has built; the
  record says so, and a C that wins becomes a spec with its own measurement.
