## Problem

`plugins/quenching/assets/references/specs-execute/execution.md:139-143` and `plugins/quenching/agents/spec-runner.md:45-47`
(merged in #1493, spec 1476) tell the worker to create a worktree of the base, copy the test there and run `git apply -R`
of the production diff. The base does not contain the fix, so the reverse patch cannot apply. Reproduced in a scratch repo:
`git apply -R ../fix.diff` in the base worktree gives `error: prod.py: patch does not apply` (rc=1), while the copied test
already fails there with no apply at all. A worker that follows the text stops on an error and improvises, which is the
path to `git stash` the rule meant to close. The `RED: … (git apply -R, base worktree)` evidence line also describes a
step that cannot have run. Keep one coherent method: the copied test in a base worktree, OR `git apply -R` on a copy of
the branch tip.

## Proposal

- The RED method in `execution.md` and `spec-runner.md` is one coherent step: add a worktree of the base, copy the regression test into it, run it there and see it fail, with no apply of any diff.
- The evidence line reads `RED: <test> fails without <fix> (copied test, base worktree)`, a step that can actually have run.
- The contract test asserts the copied-test method and that `git apply -R` no longer appears.

## Out of Scope

- The `git apply -R` on a copy of the branch tip variant: ruled out, the copied test in a base worktree needs no patch and the base lacks the fix by construction.
- Any change to a grant, hook, CI, allowed-tools or an agent's `tools:`: only prose changes.
- Regenerating any mirror: the Codex mirror no longer exists.

## Design

- Decision: the RED proof is the test copied into a worktree of the base. The base never holds the fix, so the test fails there with no patch; a reverse patch of the production diff cannot apply to a tree that lacks it (reproduced: `error: prod.py: patch does not apply`, rc=1).
- Rule: the evidence line names the method actually run, `(copied test, base worktree)`.
- The test keeps asserting the worktree-of-the-base wording and the `RED:` line, and now asserts the absence of `git apply -R`.
- Contract: no stash, checkout or reset, as before.

## Alternatives Considered

- `git apply -R` on a copy of the branch tip: works but needs a second checkout and a patch step for no gain over the copied test.
- Dropping the RED evidence line: loses the cheap proof that a regression test can fail.

## Open Decisions

## Risks

- A test depending on files the fix adds cannot run in the base worktree; the worker then reports the RED as not measurable instead of improvising. ACCEPTED — rare, and honest reporting beats a stash.
