## Problem

The `shared.codex` defaults in `codex/config.py` turn Codex on wherever a repository says nothing: `crossReview` is `auto` and `executor.enabled` is `true`, and `cq config init --write` seeds that same block into every newly aligned target. The human asked for Codex to be disabled by default for new projects, so a target only runs the Codex review or executor when it declares them.

## Proposal

Flip the two `shared.codex` defaults owned by `quenching/assets/bin/quenching/codex/config.py`: `crossReview` becomes `"off"` and `executor.enabled` becomes `false`. Because the seed (`config/seed.py`) and the key registry (`config/schema.py`) are built from those constants, `cq config init --write` seeds the disabled block into new targets and `cq config show --effective` / the settings page report the new defaults with no further code. A repository that declares `crossReview: "auto"` or `executor.enabled: true` keeps Codex on; only the absent-key case changes. The tests whose fixtures leaned on the old defaults declare the opt-in explicitly, and every reference, README section and standard that states the default is rewritten to say Codex is opt-in.

## Out of Scope

- Changing any target repository's `.agents/quenching.json` — including this repository's own, which carries an uncommitted change owned by another session; a repo that wants Codex declares it.
- Removing or renaming any `shared.codex` key, or changing the other leaves' defaults (quota ceilings, models, timeout).
- The `after_specs_execute_task` Codex hook, which is already opt-in.
- Release, version bump and changelog — owned by conclude/release, not by this spec.

## Validation

- `cq codex probe --json` in a repository without `shared.codex` reports `unavailable` with `shared.codex.crossReview is off`.
- `cq config show --effective` lists `shared.codex.crossReview = off` and `shared.codex.executor.enabled = false` with source `default`.
- `cq config init` seeds `crossReview: "off"` and `executor.enabled: false`.
- A repository declaring `crossReview: "auto"` and `executor.enabled: true` still gets both.
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` exits 0.

## Design

The constants in `codex/config.py` are the single source: `seed.py` copies `DEFAULTS` into the seed and `schema.py` reads `CODEX["crossReview"]` / `CODEX["executor"]["enabled"]` as the registry defaults, so the flip propagates to `cq config init`, `cq config show --effective`, `cq config schema` and the OpenCode settings page with no other code change. The probe already short-circuits on `crossReview: "off"` (`unavailable`), so the conclude and autopilot Codex reviews fall back to the Claude review alone and report `Codex: fallback`; `cq codex eligible` already refuses with `shared.codex.executor.enabled is false`, so execute's step 5b records `Codex: skipped`. The warning for a malformed `crossReview` names the default from `DEFAULTS` instead of a hard-coded `'auto'`.

### Assumptions

- "New projects" means every repository whose `.agents/quenching.json` does not declare the keys — the seed and the absent-block default both change (Proposal).
- An already-aligned target that has the old seeded block written out keeps Codex on, because the declared value wins (Out of Scope).

## Alternatives Considered

- Change only the seed (`cq config init`) and keep the code defaults on: rejected — a repository with no `shared.codex` block would still run Codex, which is not "disabled by default".
- A new top-level `shared.codex.enabled` master switch: rejected — two existing switches already express it; a third key widens the schema for no gain.

## Open Decisions

- none — the request names the behaviour and the code has one source for the default.

## Risks

- Targets that relied on the implicit default silently stop running the Codex review and executor after upgrading; mitigated by naming the change and the opt-in in the CHANGELOG at release time.
- This repository's committed `.agents/quenching.json` declares no `shared.codex`, so its own runs also lose Codex until it opts in; that file is out of scope here.
