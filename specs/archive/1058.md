## Problem

The plugin owns where **durable** knowledge lives — the OKF bundle — and says nothing about the
step below it. Measured on `main` at `0caec597`: `grep -rn "scratchpad\|ephemeral"` over `docs/`
and `plugins/quenching/assets/knowledge/` returns **zero hits**. There is no contract, so the
default wins by silence, and the default is the Claude Code system prompt's own instruction to
write working files into a **per-session** scratchpad that is discarded when the session ends.

That default is wrong for one specific and common class of file: work that is **irreproducible but
unfit for git** — the extract of a query that no longer runs the same way, the notebook that proved
a number in a meeting, a dump too large or too sensitive to track. Git's `.gitignore` treats
"reproducible in two minutes" (`node_modules/`, build output) and "cannot be made again" (a dated
parquet) as one category. Nothing downstream distinguishes them either, so the second class is
routinely written into a scratchpad and destroyed on session end, or into a worktree and destroyed
with the worktree.

The plugin makes this worse than the ambient default rather than better. `assets/references/git/isolation.md`
recommends the worktree form **unconditionally** ("The worktree is the preferred form"), states the
cost in the offer itself ("a fresh checkout carries only what git tracks — no installed
dependencies, no `.env`, no venv, no build output"), and then offers no remedy but a `worktreeSetup`
command the target must author alone. Combined with `/quenching:specs:execute-queue` and the fan-out,
the plugin is an active producer of parallel checkouts with no shared, surviving workspace.

## Proposal

Publish **one standard** naming the three destinations an agent may write to and the single test
that sorts a file between them, then give that standard the one property it needs to actually
govern: **presence in session context before the first write**.

The test is one question — *if I lose this, can I make it again?*

| Condition | Destination | Why |
| --- | --- | --- |
| another person must read it from a clean clone | versioned, in the tree | it is reviewed and it survives the machine |
| it cannot be reproduced identically (a dated extract, the notebook behind a number) | the target's declared durable-ignored area | irreproducible, but too large or too sensitive for git |
| it can be remade in minutes (a ten-line column check) | the session scratchpad | it may die with the session at no cost |

The standard goes into the embedded bundle at `assets/knowledge/standards/agents/`, beside
`communication.md` — the home that already answers *how an agent behaves here*, whose candidate
list currently holds `communication` alone. "Where an agent writes" is the sibling of "what
language an agent writes in".

**The second half is what makes it binding.** `commands/components/harness/align.md:98-100`
already carries one named exception to its own MOVE-everything-to-`/docs/` routing: *"The language
declaration line is always KEEP"*, preserved verbatim in the root harness because it must be in
context at session start to cost zero tool calls. This contract has the identical property for an
identical reason — a pointer read only once an agent already went looking arrives after the write
it was meant to redirect. So `harness-routing.md` gains a second KEEP line of the same shape, value
plus citation:

```
Ephemeral writes: <path> — the contract is /docs/standards/agents/ephemeral-writes.md
```

A target that declares no durable-ignored area writes no line and loses nothing: absent means the
ambient default, exactly as an undeclared language tag means no declaration.

## Design

### Why a standard and not a rule inside the harness

A rule restated in `CLAUDE.md` is exactly the drift `/quenching:components:harness:align` exists to
remove. The split this repo already uses — the *value* and a *citation* in the harness, the *rule*
in the bundle — is what lets the contract be long enough to be correct while the harness line stays
one line. The language declaration is the precedent, and copying its shape means one mechanism
covers both rather than two mechanisms covering one each.

### Why the sorting test is a question, not a taxonomy

Three named categories invite argument at the boundary. One question — *can I make it again?* —
decides a file in the moment of writing it, which is the only moment the answer is cheap. The
categories are the answers to that question, not a list to be matched against.

### Why `standards/agents/` and not `standards/workflows/`

`workflows/` owns the job/task/schema framework — how work is defined, scheduled and orchestrated,
by its own `index.md` boundary statement. This is not about how work runs; it is about how an agent
behaves. `agents/` is the home whose subject is exactly that, and whose only current occupant is
the other half of the same question.

## Alternatives Considered

- **Fix the two commands that instruct the loss and stop there.** The original plan's approach:
  find each body saying "write to the session scratchpad" and rewrite the path. It works once, for
  the bodies that exist, and does nothing for the next body anyone writes, in this repo or a target.
  A contract generalises where a patch does not.
- **A pointer in the harness rather than a verbatim line.** Cheaper by one line, and it fails at the
  exact moment it must work: the agent has already written to the scratchpad by the time anything
  sends it to `/docs/`. The language line lost this same argument for the same reason.
- **Name the area in the standard rather than per target.** One fixed path would be greppable across
  repos, which is the bundle's usual argument. It loses to policy: a corporation's rule about where
  irreproducible or sensitive data may rest is not the plugin's to fix, and a fixed path in a
  standard is a fixed path in every audit.

## Open Decisions

- **The standard's slug** — `ephemeral-writes` reads well beside `communication` but is arguably the
  wrong noun, since the point is precisely that the second category is *not* ephemeral. `workspace`
  and `write-destinations` are the alternatives. Decide before the file is created; renaming a
  bundle path after citers exist costs a sweep.
- **The harness line's key spelling** — `Ephemeral writes:` inherits the same objection. Whatever
  the standard is called, the key and the slug should agree.
- **Whether the line names a path or only cites the contract.** Naming the path makes the harness
  line self-sufficient and duplicates a value that also lives in `.claude/quenching.json`
  (`sharedPaths`, in the sibling spec). Citing alone keeps one source of truth and costs a read.

## Risks

- **The load-bearing assumption is unproved: that a root harness line actually overrides the system
  prompt's own scratchpad instruction, in practice, without being restated in the user's turn.** If
  it does not, the standard is decorative and the mechanism has to be something else entirely — a
  hook, an output style, a per-command line. Everything else in this spec rests on it, and it is
  cheap to test. That is why the demonstration is now the FIRST task rather than the last: a
  disproof changes the shape of the work rather than merely failing its gate.
- **A contract with no mechanism is advice.** Until the sibling spec ships `sharedPaths`, the
  declared area survives the session but not the worktree. Stated plainly in the standard, or the
  first worktree that eats a declared-safe file discredits the contract.
- **Naming the second category badly teaches the wrong sort.** If it reads as "temp", agents will
  file reproducible junk there and it becomes a garbage heap nobody trusts; if it reads as
  "important", they will file conclusions there that belonged in the tree. The sorting question is
  the mitigation, and it has to be in the harness line's citation, not only deep in the standard.
- **A second always-KEEP line invites a third.** The exception list is the kind that grows until it
  is the rule. The membership test — *does it have to be in context before the first tool call?* —
  goes into `harness-routing.md` beside the line itself, so the next candidate is argued rather
  than appended.
- **The harness byte budget is shared and finite.** `MAX_BYTES` is half a frozen baseline, and every
  future declaration competes for the same 4274 bytes. This line spends a few dozen of the 2259
  remaining; the next one has less room, which is a second reason the membership test is written
  down rather than left to judgement.
