## Problem

Nenhum comando ou agente consegue saber quanto contexto a própria execução já acumulou.
`cq components session cost` lê só os subagentes de uma sessão, depois que retornam; `list` e `digest` olham
comandos, não o tamanho da janela. Por isso todo orçamento do plugin é uma promessa em prosa, e a única forma
de um modelo "medir" é lembrar da própria sessão — o que `session-evidence.md` §The rule a counted claim must
obey proíbe.

A transcrição é legível enquanto a sessão roda (só o turno em voo falta), e o harness expõe
`CLAUDE_CODE_SESSION_ID` ao Bash de um subagente. Falta o verbo: dado um id de sessão ou de agente, devolver em
`--json` o pico de contexto, o número de turnos, a integral, o orçamento aplicável (de S2, por papel: sessão
principal, worker, condutor) e a distância até ele, com exit `0` dentro, `1` acima do orçamento e `2` quando a
transcrição não pôde ser lida — nunca um zero silencioso (`parse-honesty.md`). É o trilho que S4, S5 e S6
usam; sem ele continuam sendo prosa.

## Proposal

Add `cq components session context` to measure one live Claude transcript or agent using recorded usage, and report its context peak, request turns, exposure integral, applicable role budget and remaining distance as JSON. It provides a read-only rail for later boundary enforcement.
## Out of Scope

- Enforcement, automatic respawning and checkpoint cadence belong to dependent specs.
- Native Codex token telemetry is not measured: unsupported records refuse rather than receive invented counts.
- No changes to existing `cost`, `list` or `digest` semantics; no cross-model monetary totals.

## Design

The verb accepts `[transcript|session-id]`, optional `--agent ID`, and `--json`. With no positional selector it requires `CLAUDE_CODE_SESSION_ID`; it never chooses a live session by mtime. A session selector resolves through the existing transcript resolver, then `--agent` selects that session's `subagents/agent-ID.jsonl`. Explicit agent paths also work.
One streaming pass stores final assistant usage by `message.id`, preserving request identity across streamed records. Input exposure is the sum of the three input/cache fields, turns is the number of requests, and integral is summed exposure. The peak uses maximum `type: message` executor iteration input where available; missing iteration coverage yields `peakContext: null`, with the request aggregate reported separately as `peakUpperBound` and an exit-2 verdict. Partial/malformed/unreadable usage cannot produce a green budget verdict: exit 2 with anomalies. Empty and unsupported transcripts also exit 2.
Role is main for a session transcript; agent role comes only from sibling metadata (`spec-runner` → worker, `orchestrator`/`autopilot` → conductor). Missing/new agent types remain unknown and refuse a budget verdict. Budgets are 200000/100000/150000 input-context tokens from spec 1629. For a complete iteration measurement, remaining is signed `budget - peakContext`, exceeded is strict `peakContext > budget`; both are null for inconclusive input, and the request currently in flight is explicitly excluded. JSON returns `peakContext`, `peakUpperBound`, `turns`, `integral`, `role`, `budget`, `remaining`, `exceeded`, `iterationCoverage`, `anomalies`, `transcript`, and `resolvedBy`. Exit 0 is within budget, 1 is above, and 2 is an inconclusive measurement.
