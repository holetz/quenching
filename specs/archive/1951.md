## Problem

Achado do revisor do épico 1945 (main 17270600), reproduzido. A 1944 tirou o `-s read-only` do review Codex (`review.py:41`: `["exec", BYPASS, "--ignore-user-config", ...]`), mas dois docs ainda dizem o contrário:

- `docs/standards/architecture/surface-translation.md:75-76`: "That review runs only as read-only `codex exec` with `-s read-only --ignore-user-config`".
- `docs/standards/architecture/index.md:19`: a linha do `codex-pillar.md` ainda descreve "an independent, read-only reviewer" com "a fixed `-s read-only --ignore-user-config` argv". O commit 4f8547385 atualizou a linha em `docs/standards/index.md` e esqueceu esta.

O gate passa assim mesmo (`bash scripts/verify_repo.sh`: "Repository verification passed."). Consequência: quem lê o standard roteia o Codex achando que existe um sandbox read-only que não existe mais.

## Proposal

Corrigir os dois docs que ainda descrevem o review Codex com `-s read-only`: a frase em `surface-translation.md` passa a dizer que o review roda como `codex exec` sob o bypass com `--ignore-user-config`, sem sandbox nativo, com a prova de que nada mudou dada pelo git guard; e a linha do `codex-pillar.md` em `docs/standards/architecture/index.md` passa a espelhar a `description` atual do próprio `codex-pillar.md`.

## Out of Scope

- Qualquer mudança em `review.py` ou no comportamento do review: o código já está certo (1944).
- Reescrever `codex-pillar.md` ou a linha de `docs/standards/index.md`, que já estão atualizadas.

- `docs/standards/architecture/index.md` — a linha do codex-pillar espelha a description atual

## Design

Duas edições de prosa. A frase nova de `surface-translation.md` segue o que `codex-pillar.md` já afirma (sandbox nativo nunca pedido, bypass limitado pelo git guard que prova a árvore intacta). A linha do índice copia a `description` de `codex-pillar.md` verbatim, como já faz `docs/standards/index.md:81`.
