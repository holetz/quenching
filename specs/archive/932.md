## Overview

Depois desta spec, os dois pontos onde a doutrina hoje instrui coletar evidência bruta
(`grep`/`gh`/`cq`) ou ler uma reference/`/.docs/` inteira para obedecer poucas seções passam a
apontar para uma doutrina compartilhada nova — extrair o agregado compacto no próprio shell (ou
delegar ao sub-agente já estabelecido) em vez de colar a saída crua, e endereçar a leitura por
seção via `cq components read --sections`, mecanismo que já funciona em qualquer markdown,
incluindo `/.docs/`. O ponto medido (`/quenching:specs:develop`, sessão
`2d9e0398-6872-4ddb-bac3-631899fc34a0`) é o primeiro a citar essa doutrina; nada na superfície muda
de comportamento observável — só o que cada leitura paga em contexto.

## Problem

Um comando desta superfície paga contexto cheio por informação que usa em pedaço: despeja a saída
bruta de um `grep`/`gh`/`cq` para extrair um agregado de poucas linhas, e lê uma reference inteira
para obedecer duas seções dela.

Medido na sessão `2d9e0398-6872-4ddb-bac3-631899fc34a0` — `/quenching:specs:develop` sobre
`renomear-docs-para-knowledge`, backend `github`. Dos ~58k tokens ingeridos, **36,6%** foram
evidência bruta e **20,2%** foram references; um único `grep` devolveu 14.252 chars para produzir
uma tabela de oito linhas, outro devolveu 9.475. A sessão terminou com **149.886 tokens** vivos, o
que deixa a passada seguinte sem margem no mesmo contexto.

A comparação é o que ordena o alvo: a duplicação plano↔escrita que a mesma sessão exibe (o corpo
redigido no plano e reemitido no heredoc, 55% das linhas literalmente repetidas) custou 3-4% — e é
a única das três que a doutrina hoje discute, em `commands/specs/develop.md:199`.

## Proposal

Duas causas, uma doutrina compartilhada nova, citada nos dois pontos que a sessão medida prova:

1. **Evidência bruta em vez de agregado compacto.** Quando um passo só precisa de um agregado
   pequeno (uma tabela de N linhas, uma contagem, uma lista de nomes), a saída crua de
   `grep`/`gh`/`cq` não deveria entrar no contexto — o agregado deve ser produzido no próprio
   shell (flags compactas, `awk`/`cut`/`sort | uniq -c`, ou um script de uma linha que já devolve
   a forma final) ou delegado ao sub-agente somente-leitura que
   `specs-develop/questions.md` §Gathering the evidence já estabelece para os banks adversarial e
   gate — hoje restrito a duas perguntas fixas sobre `/.docs/`, nunca à leitura do próprio código
   que o bank shape faz ("read it, do not theorize").

2. **Reference inteira lida para obedecer poucas seções.** `cq components read --sections` já
   resolve qualquer markdown, não só `assets/references/**` — testado nesta mesma passada contra
   `.docs/standards/agents/communication.md`, que devolveu o índice de seções e aceitou
   `--sections` normalmente. Mas a doutrina que instrui ler `/.docs/standards/` e
   `/.docs/knowledge/glossary.md` (specs-develop/questions.md, doctrine "Read `/.docs/` before
   writing") usa a ferramenta `Read` genérica, que só sabe ler o arquivo inteiro — pagando o
   arquivo inteiro onde duas regras bastam.

A proposta: um novo reference compartilhado,
`assets/references/align/evidence-doctrine.md` — home natural ao lado de `sweep-doctrine.md` e
`tool-resolution.md`, front-neutro, citado por caminho absoluto — declarando as duas regras
(extrair o agregado, nunca colar a saída crua; endereçar por seção qualquer leitura, incluindo
`/.docs/` do alvo), e citado a partir do ponto onde o custo foi medido:
`specs-develop/questions.md` §Gathering the evidence, estendida para cobrir também o bank shape
(hoje sem qualquer orientação de economia) e para instruir `cq components read --sections` em vez
de `Read` nas leituras de `/.docs/`.

## Design

Um arquivo novo, duas regras, nomeadas:

**Regra 1 — extrair, nunca colar.** Onde um passo só precisa de um agregado pequeno a partir de
`grep`/`gh`/`cq`, o agregado é produzido no shell (flags compactas — `-c`, `-l`, `-o`,
`--json | jq`/`python3 -c`, `sort | uniq -c`) antes de entrar no contexto; onde a varredura é
ampla e o pedido é uma tabela pequena, o padrão de delegação já estabelecido
(`specs-develop/questions.md` §Gathering the evidence — sub-agente `Read, Grep, Glob`, retorna uma
tabela compacta) é a alternativa, nunca colar a saída crua para depois resumir.

**Regra 2 — endereçar por seção, sempre que o arquivo aceitar.**
`cq components read <path> --sections "§X"` funciona em qualquer markdown (testado contra um
standard OKF nesta mesma passada); nenhuma leitura de `/.docs/standards/` ou
`/.docs/knowledge/glossary.md` usa a ferramenta `Read` genérica quando só uma ou duas seções
decidem a pergunta.

Aplicação no ponto medido: `specs-develop/questions.md` §Gathering the evidence passa a (a) citar
`evidence-doctrine.md` em vez de restatar, (b) estender as duas regras para o bank shape — hoje só
"leia o código, não teorize", sem orientação de economia — e (c) trocar a instrução de leitura de
`/.docs/` de `Read` para `cq components read --sections`.

## Alternatives Considered

| Abordagem | Custo | Ganho | O que fecha |
| --- | --- | --- | --- |
| A — só o ponto medido (editar `questions.md` sozinho, sem novo reference) | mínimo, 1 arquivo | corrige a sessão medida | fecha a reutilização — o próximo comando com o mesmo problema reinventa a regra |
| **B — doutrina compartilhada + aplicação no ponto medido (recomendada)** | baixo, 1 arquivo novo + 2 editados | corrige o ponto medido E dá aos próximos comandos uma regra citável, sem reescrevê-los agora | nada — é aditiva |
| C — auditoria exaustiva de toda a superfície (`conclude.md`, `command/new.md`, `agent/new.md`, `align.md` incluídos) | alto, complexity subiria para medium/high | cobertura máxima nesta passada | desproporcional à complexidade `low` já declarada na captura; os candidatos fora do ponto medido não têm evidência de desperdício, só suspeita |

B recomendada: prova pelo caso medido, doutrina fica pronta para os próximos casos sem forçar uma
reescrita não evidenciada agora.

## Risks

- **Regra nova, sem imposição automática.** Como toda doutrina deste plugin, `evidence-doctrine.md`
  é prosa — nada barra um comando futuro de colar uma saída crua de novo. Mitigação: nenhuma além
  da citação; é o mesmo risco que toda reference já corre.
- **N=1.** A proporção 36,6%/20,2% vem de uma única sessão medida. Mitigação: a regra proposta é
  boa prática independente do número exato (extrair é sempre mais barato que colar; endereçar por
  seção é sempre mais barato que ler tudo), então não depende da métrica se sustentar identicamente
  em toda sessão futura.
- **Escopo raso.** Os quatro outros pontos candidatos (`conclude.md`, `command/new.md`,
  `agent/new.md`, `align.md`) continuam pagando o mesmo padrão até alguém os varrer — parqueado
  como Discovery, não como risco não mitigado desta spec.
