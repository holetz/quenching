## Problem

Reproduzido pela revisão de correção do épico 1582 (2026-10-12), em `main` 0fac8801. A sonda `secret-ignore-coverage`
(`plugins/quenching/assets/bin/quenching/security/probe.py`) decide a cobertura comparando texto, e não pela
semântica do `.gitignore`. Em três casos ela responde `present` enquanto `git check-ignore .env` mostra que o
arquivo **não** está ignorado:

1. **(média, regressão da #1585)** `.env/` e `**/.env/`: a linha 100 tira a `/` final antes de comparar, mas no
   `.gitignore` uma `/` final casa só diretórios, e `.env/` é um nome comum de virtualenv Python. Com
   `.gitignore = ".env/\n*.pem\nsecrets/"`, a sonda responde `present` com `environment-files: ['.env/']`.
2. **(média, já existia)** Um padrão que começa com `.env.` conta como cobrindo `.env` (linha 101,
   `value.startswith(".env.")`). Com `.env.example`, `.env.local` ou `.env.*`, a sonda responde `present`, e o git não
   ignora `.env`.
3. **(baixa, já existia)** Um `!` posterior que anula a regra é ignorado (linha 126): com `.env` seguido de `!.env`,
   a sonda responde `present`.

Consequência: a auditoria de segurança declara cobertos arquivos de segredo que o git vai versionar, e um repo pode
commitar o `.env` com o relatório verde. A correção usa a semântica do próprio git, por exemplo
`git check-ignore --no-index` sobre um nome representativo de cada classe, em vez de comparar texto. Os testes de
regressão cobrem os três casos com o git como oráculo.

## Proposal

Decidir a cobertura de `secret-ignore-coverage` perguntando ao próprio git: copiar o `.gitignore` para um repositório temporário e rodar `git check-ignore --no-index` sobre nomes representativos de cada classe; a classe só conta como coberta se o git ignora algum desses nomes.

## Out of Scope

- Mudar o conjunto de estados (`present`/`missing`/`refused`) ou o comando `/quenching:security:status`.
- Considerar `.gitignore` aninhados, `.git/info/exclude` ou o excludesFile global do usuário.

## Design

Nomes representativos: `.env`; `server.pem`, `server.key`, `id_rsa`; `credentials.json`, `secrets.json`, `token.json`, mais os padrões literais (sem curinga) das classes não-env. O texto continua escolhendo candidatos por classe; o git decide. Ambiente isolado (`GIT_CONFIG_GLOBAL=/dev/null`, `core.excludesFile=` vazio). Se o git não responde, estado `refused`.

### Mapa de dependências (2026-10-12)

- `probe.py` é o único produtor; consumidores: `test_security.py` e `commands/security/status.md` (estados inalterados).

## Alternatives Considered

- Normalizar o texto mais um pouco: rejeitado, é o que gerou os três falsos `present`.
- Implementar a semântica de gitignore em Python: rejeitado, duplica o git.
