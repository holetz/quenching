## Problem

Achado reproduzido pela revisão de segurança do épico 404 (2026-11-24). `git_preflight` está em `_rows("git", "read", …)` (`quenching/assets/bin/quenching/mcp/catalog.py:60-61`), e a classe `read` leva `readOnlyHint: true, openWorldHint: false` (`catalog.py:227-228`). Desde a 406, o check `claims` cria e apaga uma ref de prova no origin (`quenching/assets/bin/quenching/git/preflight.py:6,102,110,297`), com `Claims.Store.swap` em escopo remoto rodando `git push --force-with-lease … <remote> <new>:refs/quenching/claims/<probe>` (`specs/claims.py:177-179`). Se o delete falhar, a ref de prova fica no remoto (`preflight.py:118-119`). A regra do próprio catálogo é "The class is what a sub-agent grant is given by" (`catalog.py:12-13`).

**Consequência:** um sub-agente com grant só de leitura passa a poder escrever no origin, e as dicas MCP mentem ao host (sem `openWorld`, sem efeito colateral).

## Proposal

Tirar o probe de escrita do caminho de leitura: ou `git_preflight` sobe para a classe de escrita remota, com as dicas certas, ou o check `claims` vira opt-in (`--probe-claims`) e o preflight padrão continua só de leitura. Um teste do catálogo confere que nenhuma ferramenta `read` alcança push.

## Out of Scope

- Moving `git_preflight` to the `external` class — rejected: the other four checks (`store`, `push`, `ghAuth`, `ci`) are `--dry-run` or read-only, so the tool as a whole is a read; only the claims probe writes.
- Editing `quenching/skills/quenching-specs/references/autopilot.md` so the autopilot passes `--probe-claims` — deferred: that front body belongs to spec 417's parallel change; parked as a discovery.
- The `openWorldHint: false` of the read class, though the dry-run pushes reach the remote — not touched here.

## Impact

- The repository gate at conclude.

## Design

- **Decision: opt-in flag, not a class change.** `claims` is the only check that writes; the rest stay read. Making the write opt-in keeps the class rule ("the class is what a sub-agent grant is given by") true without demoting a tool the autopilot and agents call as a read. Conductor decision, epic 415.
- **Decision: the flag is CLI-only.** An opt-in a read grant could pass would still be a write through a read tool, so the catalog row hides `probe_claims`; the schema is `additionalProperties: false`, so the MCP call refuses it.
- **Contract:** default output keeps six checks in the same order; `claims` reads `skipped` with the message naming the flag, never `ok`.

## Alternatives Considered

- Raise `git_preflight` to the `external` class with `openWorldHint: true` — rejected: it would make every read-only preflight an external grant for a sub-agent, to cover one optional probe.
- Expose `--probe-claims` on the MCP tool and rely on the caller — rejected: a read-class grant would reach a push.
