## Problem

Depois da 1695 (PR #1700), `plugins/quenching/agents/spec-runner.md:48` e `plugins/quenching/assets/references/specs-execute/execution.md:146` mandam o worker "delete the copied test inside it" e então rodar `git worktree remove .quenching/red` sem `--force`, seguido de `rmdir .quenching` "if empty". A revisão de correção da rodada 4 do autopilot de 2026-10-15 reproduziu, num repositório de brinquedo, o caso mais comum: o teste de regressão vai num arquivo que **já existe** na base.

```
git worktree add --detach .quenching/red main; cp tests/test_x.py .quenching/red/tests/
pytest → 1 failed, 1 passed; rm .quenching/red/tests/test_x.py
git worktree remove .quenching/red
→ fatal: '.quenching/red' contains modified or untracked files, use --force to delete it   (exit 128)
rmdir .quenching → Diretório não vazio
```

Apagar o arquivo copiado deixa uma deleção rastreada, e a remoção sem `--force` recusa. O worker volta `blocked` ou deixa a RED para trás, e a worktree da spec fica presa no `retire`. A instrução precisa devolver o arquivo ao conteúdo da base dentro de `.quenching/red`. A lista Forbidden do worker proíbe `checkout` e `restore`, então o caminho tem de respeitá-la (por exemplo, reescrever o arquivo a partir de `git -C .quenching/red show HEAD:<file>`), e o teste de prosa tem de cobrir o caso do arquivo existente. Nada de `--force`, nada de grant novo.

## Proposal

- The RED-worktree cleanup instruction tells the worker to rewrite a tracked file the copied test overwrote from `git -C .quenching/red show HEAD:<file>`, and to delete only a file the copy created, so `git worktree remove .quenching/red` succeeds without `--force`.
- Both carriers (`spec-runner.md` and `execution.md`) say the same thing, and a prose test pins the existing-file case.

## Out of Scope

- Using `--force`, `checkout` or `restore` for the cleanup: forbidden by the worker's Forbidden list and by the 1695 contract.
- Changing any grant, hook, script or allowed-tools.

## Impact

- `plugins/quenching/assets/references/specs-execute/execution.md` — the "Remove the RED worktree" paragraph

## Validation

- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: restore a tracked file by rewriting it from `git -C .quenching/red show HEAD:<file>` (allowed: not checkout/restore/reset); a file the copy created is deleted. Rule: the worktree must be byte-identical to HEAD before `worktree remove`.
- Assumption: the copied test replaces a file already in the base; `show` output redirect restores content and the mode is unchanged by cp over an existing file.

## Alternatives Considered

- `git worktree remove --force`: rejected, hides real leftovers and is barred by 1695.
- `git restore`/`checkout -- file`: rejected, forbidden for the worker.
