## Problem

Substitui a 1483. Nada confere se um diff rebaixa a régua: o `cq git audit` só olha grants (`plugins/quenching/assets/bin/quenching/git/audit.py:677-690`) e o verifier termina no check 9 (`plugins/quenching/agents/verifier.md:65`). Um worker autônomo pode chegar ao verde afrouxando o gate, e o verifier aceita.

**Decisão do humano (2026-10-11): acusar em níveis.**
- **FAIL (`needs-human:`)** para: teste apagado; teste que perdeu todos os seus `assert`; passo removido de `scripts/verify_repo.sh` ou de `plugins/quenching/assets/checks/**`; e `verify:` de task enfraquecido.
- **Aviso no relatório, sem bloquear**, para: `noqa`, `type: ignore` e `skip`/`skipIf`/`xfail` novos.
- **Exceção:** quando a própria spec declara a remoção como objetivo (como o épico 1473 fez com o espelho Codex), o FAIL cita essa declaração para o condutor decidir; ela não o dispensa sozinha.

O mecanismo é determinístico, no payload do `cq git audit`, e vira um check 10 no verifier.

## Proposal

- `cq git audit` payload gains a `lowered` list: entries `{path, severity: "fail"|"warn", kind, detail}` read from the base..tip diff.
- `severity: fail` for: a deleted test file (`test-deleted`); a test file that had `assert`s at the base and has none at the tip (`test-lost-asserts`); a deleted file, or a removed non-comment line with no matching added line, in `scripts/verify_repo.sh` or `plugins/quenching/assets/checks/**` (`gate-shrunk`).
- `severity: warn` for added lines carrying `noqa`, `type: ignore`, `skip`, `skipIf`, `skipUnless`, `xfail` in code files (`suppression-added`).
- The verifier gains check 10 `ruler`: any `fail` entry is FAIL with `needs-human:` quoting path and detail; `warn` entries are listed in the report without blocking. When the spec itself declares the removal as its objective, the FAIL cites that declaration for the conductor and is not dispensed by the verifier.

## Out of Scope

- `verify:` of a task weakened: the spec store is the `quenching` branch, absent from the worktree diff, so the audit cannot read before/after deterministically. Recorded in `## Open Decisions`; ruled out of this change rather than faked.
- Judging whether a removal is justified: the verifier reports, the conductor decides.
- Any change to the orchestrator's escalation text (1520 owns it) and any grant, hook or executable-surface widening.

## Impact

### Standards this spec will write into docs/standards/

- none — the audit and verifier contracts live in the verifier body and the audit module docstring; no standard is promised.

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/git/audit.py` — the `lowered` read
- `plugins/quenching/agents/verifier.md` — check 10 and the return-format line
- `plugins/quenching/tests/test_git.py` — fixtures for each kind and level

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p 'test_git.py'` exits 0, covering: deleted test and assert-less test give `fail`; a shrunk gate gives `fail`; a new `noqa`/`skip` gives `warn` only; an unchanged or growing gate and an assert-preserving test edit give an empty `lowered`.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Rule: the audit reports facts, never verdicts on justification; `lowered` is read with the same fixed argv (`SAFE`, `--no-ext-diff --no-textconv --text`) as `grants`, over `base...tip`, and executes nothing from the branch.
- Test files are recognised by path: a segment `tests`/`test`, or a name `test_*`, `*_test.*`, `*.test.*`, `*.spec.*`. An assert is `\bassert\w*\b` or `\bexpect\s*\(`. Lost asserts compare the count at base (>0) with the tip (0).
- Gate files: `scripts/verify_repo.sh` and `plugins/quenching/assets/checks/**`. A removed line counts as a lost step when it is non-blank, not a comment, and absent from that file's added lines; a reworded step therefore reads as shrunk and goes to the conductor, which is the declared exception route.
- Alternatives per decision: a count of lines per file (rejected: flags pure growth-with-reformat noise less but misses a swapped step); per-spec allowlist in the audit (rejected: the exception belongs to the conductor, not a flag the worker could set).

### Mapa de dependências

- `audit.py` payload is consumed only by `plugins/quenching/agents/verifier.md` and `plugins/quenching/tests/test_git.py`; `grants` key and the `gate` absence assertion are untouched. Adding a key breaks no consumer.

## Alternatives Considered

- Warn for everything, block nothing: rejected by the human's 2026-10-11 decision; a deleted test is the one lowering no review catches.
- FAIL for `noqa`/`skip` too: rejected by the same decision; legitimate uses are common and would stall autonomous runs.
- A judging sub-agent for lowering: rejected; the mechanism is deterministic by decision.

## Open Decisions

- Weakened `verify:` of a task: decided by whether a deterministic before/after exists; the spec store is a separate branch, so it is parked as a discovery for a follow-up that reads the `quenching` branch history.

## Risks

- A reworded gate step reads as shrunk and raises a false FAIL; the conductor settles it (ACCEPTED — fail-closed on the safety side, human-decided).
- Path-based test detection misses tests under unconventional names (ACCEPTED — the audit is no sandbox, as its docstring already declares).
- `skip` matched as a word may hit unrelated code lines; it is only a warn, so ACCEPTED.

## Outcome

Entregue (done). `cq git audit` ganhou a leitura `lowered` (`plugins/quenching/assets/bin/quenching/git/audit.py`): sobre `base...tip`, acusa com `severity: fail` um arquivo de teste apagado (`test-deleted`), um teste que tinha assert na base e não tem mais (`test-lost-asserts`) e um passo removido de `scripts/verify_repo.sh` ou `plugins/quenching/assets/checks/**` sem linha equivalente acrescentada (`gate-shrunk`); com `severity: warn`, um `noqa`, `type: ignore`, `skip`/`skipIf`/`skipUnless` ou `xfail` novo em arquivo de código (`suppression-added`). Os quatro casos estão cobertos em `plugins/quenching/tests/test_git.py`. O `verifier` (`plugins/quenching/agents/verifier.md`) ganhou o check 10 `ruler`: qualquer `fail` é FAIL com `needs-human: régua rebaixada`, citando a declaração do `## Problem`/`## Proposal` quando a remoção é o objetivo da spec, sem dispensar o FAIL; `warn` só entra na evidência.

Todo arquivo alterado pela branch está no `files:` de uma task (1.1: `audit.py`, `test_git.py`; 2.1: `verifier.md`). O merge de `origin/main` trazido no fechamento (1521, `quenching-hud`) não é mudança desta spec.

Lacunas conhecidas, deixadas fora:
- **`verify:` enfraquecido não é detectado.** O `verify:` de uma task vive no store de specs (o branch `quenching`), que não está no diff do worktree; um follow-up teria de ler o histórico desse branch.
- **Passo do gate reescrito lê como encolhido.** `gate-shrunk` compara linhas exatas: um passo reformulado (mesma checagem, texto diferente) aparece como removido e dá FAIL; quem desfaz o falso positivo é o condutor, ao ler o `detail`.
