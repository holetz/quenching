## Problem

Sub-spec da 262 (gate local verde no Windows): specs, portal, sessão, deploy e conhecimento. Depende da sub-spec de fundação (`.gitattributes` e helpers de teste). Medido em 2026-11-23 no slot 3 (main `efd26cfe2`, Windows 11, Python 3.12, `pytest -n auto`); cada sintoma se reproduz com `python -m pytest quenching/tests/<módulo>`.

**Módulos e sintomas:**
- `test_specs_mcp` (14): `sp-provider-unknown` — "no recognized repository provider" no repositório temporário; `KeyError: 'candidates'`/`'view'`.
- `test_specs_epic_members` (13): store entre dois repositórios; `cache\quenching\mirrors` inexistente (`[WinError 3]`), conjuntos de membros diferentes.
- `test_deploy` (9): symlink de `.agents/skills` (`[WinError 1314]`), caminho `C:/…` contra `C:\…`, regras de ignorados normalizadas.
- `test_portal_registry` (7), `test_specs_portal` (4): registro vazio (`[] != [{'name': 'main', …}]`), `0 != 2`, arquivo do registro ausente.
- `test_session_cache` (4), `test_session_cost` (4), `test_session_pricing` (2): caminhos POSIX literais nos testes (`/repo` vira `C:\repo`), `KeyError: 'rows'/'gaps'/'skillListing'`, `FileExistsError [WinError 183]` em `work`.
- `test_opensource_front` (4): `os-template-drift` nos modelos fixados (provável CRLF) e mensagens com `\` em vez de `/` (`.claude-plugin\marketplace.json`).
- `test_specs_estimate` (2), `test_quenching_mcp_resources`, `test_specs_artifacts` (`'from a file\n' != 'from a file\n\n'`), `test_specs_backends`, `test_specs_build_cost_contract` (`substring not found`), `test_components_bridge` (bit executável), `test_leak_scan` (`test_scratchpad_root_home_and_slug_get_their_relative_form`, que falha igual no main), `test_leak_scrub` (`~/repo/notes.md` não normalizado).

**A pergunta em cada caso:** é o teste que supõe POSIX (caminho literal, bit `x`, symlink) ou é o produto que se comporta errado no Windows (normalização de caminho do leak scan, mensagens com `\`, provedor não reconhecido)? O segundo se corrige no código, com teste.

**Pronto quando** esses módulos passam no Windows sem PYTHONUTF8 e continuam verdes no Linux. Regra do humano: corrigir teste e código, nunca esconder falha; `skipIf(os.name == "nt")` só quando o comportamento não existe no Windows, com o motivo escrito.

## Proposal

Corrigir, módulo a módulo, cada falha que o `## Problem` lista, decidindo em cada uma se é o produto ou o teste:

- **Produto** (correção no código + teste que falha sem ela):
  - `common/config.find_repo_root` devolve a raiz na forma nativa (`os.path.normpath`) e guarda o topo que o git encontrou para cada diretório durante o processo. No Windows, `git rev-parse` imprime `C:/x`. Com isso a mesma raiz virava duas chaves no cache de backends (`sp-provider-unknown` em `test_specs_mcp`/`test_specs_portal`), e cada resolução pagava um `git` de ~50 ms (`test_specs_backends`).
  - `specs/members._TAIL_RE` passa a aceitar `\` como separador: um remoto local no Windows (`C:\stores\owner\repo.git`) não tinha `owner/repo` (`test_specs_epic_members`).
  - `common/io.write_text` grava o texto como foi dado (`newline=""`) e `proof/readme.write_readme` grava LF. Em modo texto no Windows, cada `\n` virava `\r\n` e cada `\r\n` virava `\r\r\n` (`test_specs_artifacts`; o `cq proof readme --write` gravando CRLF).
  - `common/leak.normalize_paths` reconhece a raiz como foi dada e como o `abspath` a escreve, com `/` ou `\` (`test_leak_scan`, `test_leak_scrub`).
- **Teste que supunha POSIX** (o comportamento do produto está certo):
  - HOME sem USERPROFILE: o registro do portal ia para o home real.
  - `read_text()` sem encoding (cp1252).
  - Pasta de transcrição montada à mão em vez de `encode_cwd`.
  - Diretórios OpenCode literais `/repo`.
  - Lançador shebang executado direto (`WinError 193`).
  - `os.symlink` (`WinError 1314`) trocado por junção, que o `realpath` também resolve.
  - Bit `x`, que o Windows não tem, verificado só em POSIX, com o motivo escrito.
  - `write_text` CRLF no fixture do deploy.
- **Ambiente**: as falhas de `test_opensource_front` (`os-template-drift`) vinham de um slot reaproveitado. A cópia de trabalho guardava CRLF de antes do `.gitattributes` da 264 (1551 arquivos `i/lf w/crlf`). Num checkout novo da base o módulo passa (24/24). A cópia do slot 7 foi reescrita com os bytes do índice, sem diff.

## Design

### Assumptions

- O CI Linux é a referência do "continuam verdes no Linux": as mudanças de produto são no-op em POSIX (`normpath` de um caminho git já normal, regex que só ganha `\`, `newline=""` sem `\r`, raiz já com `/`). `## Tasks` 1.x depende disso.
- Um diretório não muda de topo git durante um processo (`_TOPLEVEL` só guarda o topo encontrado; um diretório fora de git é perguntado de novo). Tarefa 1.1.

### Causas medidas (2026-11-23, slot 7, base `d80ee3025`, Python 3.12, `pytest -n auto`)

| Módulo | Causa | Lado |
| --- | --- | --- |
| test_specs_mcp, test_specs_portal (Publish) | `find_repo_root` devolve `C:/…`; o cache de backends está em `C:\…` | produto |
| test_specs_backends (tempo) | um `git rev-parse` por resolução (~50 ms no Windows) | produto |
| test_specs_epic_members | `_TAIL_RE` só aceita `/` e `:` | produto |
| test_specs_artifacts, `cq proof readme --write` | escrita em modo texto traduz `\n` | produto |

## Alternatives Considered

| Abordagem | Custo | Ganho | Fecha |
| --- | --- | --- | --- |
| `skipIf(os.name == "nt")` nos módulos | mínimo | gate local verde | esconde três defeitos reais do produto; contraria a regra do humano |
| Normalizar só nos testes (ex.: chave do cache com `/`) | baixo | testes passam | o produto continua com duas raízes e CRLF no Windows |
| Corrigir no produto o que ele faz errado e no teste o que supõe POSIX (escolhida) | médio | o produto se comporta igual no Windows, e os testes provam isso | nada |

## Open Decisions

- none: cada falha tem a causa medida e o lado decidido pela evidência na tabela de `## Design`.

## Risks

- `_TOPLEVEL` é um cache por processo: um processo longo (MCP, portal) que veja um repositório ser movido continua com o topo antigo. Mitigação: só guarda topo encontrado, e um diretório movido é um caminho novo.
- `write_text` sem tradução muda o que se grava no Windows (passa a ser LF). É a intenção do `.gitattributes` da 264. Um chamador que dependia de CRLF não foi achado.

## Handoff

- Estado: 11/11 tarefas commitadas em `plan/267-testes-windows-specs-portal-sessao-deploy` (slot 7); falta o `conclude` (gate, revis?o, PR).
- Medir no Windows sempre num checkout com LF: um slot reaproveitado guarda CRLF de antes do `.gitattributes` (`git ls-files --eol | grep w/crlf`) e reprova `test_opensource_front` sem culpa do produto.
- No PowerShell, `[Console]::OutputEncoding` UTF-8 antes de reenviar ao `cq` qualquer sa?da dele (subject, corpo de se??o).
