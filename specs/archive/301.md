## Problem

Achado reproduzido pelo quenching-spec-reviewer na revisão da rodada 1 (merges bcabc2258..350ed3c91, spec 244, PR #294).

`mojibake_words` recebe um corpo com dois code spans de crase dupla (``` a?b ``` e ``` c?d ```) e devolve `['a?b', 'c?d']`. São duas palavras, o que atinge `MOJIBAKE_THRESHOLD = 2`, e por isso `cq specs section --write` e `cq specs new` saem com `sp-write-mojibake` sem gravar nada. Uma cerca de 4 crases com uma linha de 3 crases dentro, usada como controle, deu `[]`.

**Onde:** `quenching/assets/bin/quenching/specs/parse/edit.py:155`. Ali, `_CODE_SPAN = re.compile(r"`[^`\n]*`")` só casa span de crase simples. Isso contradiz a docstring em `edit.py:163` ("code spans ... are not read") e a mensagem de recusa em `quenching/assets/bin/quenching/specs/commands/granular.py:203` ("a `?` that is meant goes in a code span").

**Consequência:** quem segue o remédio da recusa e põe em code span de crase dupla um `?` legítimo, como um trecho com crase dentro, é recusado de novo.

Minimal fix proposed: casar code span de N crases (abertura e fechamento com a mesma contagem, CommonMark) em `_CODE_SPAN`, com um teste para crase dupla.

## Proposal

- `mojibake_words` deixa de ler o conteúdo de um code span de N crases (abertura e fechamento com a mesma contagem, como no CommonMark), não só o de crase simples.
- Um corpo com ``` ``a?b`` ``` e ``` ``c?d`` ``` em code spans de crase dupla é aceito por `cq specs section --write` e `cq specs new`.
- Um teste cobre o code span de crase dupla e o de três crases na mesma linha.

## Out of Scope

- Mudar `MOJIBAKE_THRESHOLD` ou a mensagem de recusa em `granular.py`: a mensagem já está certa, é o detector que não a cumpre.
- Code span que atravessa linhas: o detector já lê linha a linha e o CommonMark permite, mas nenhum caso real o pede; fica como está.

## Impact

### Standards this spec will write into docs/standards/

- none — a correção alinha o código com a docstring e a mensagem que já existem.

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/specs/parse/edit.py` — `_CODE_SPAN`
- `quenching/tests/test_specs_section_write.py` — o teste de crase dupla

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_specs_section_write.py` sai 0, com o teste novo falhando antes da correção.
- `mojibake_words("``a?b`` e ``c?d``")` devolve `[]`; `descri??o` fora de code span continua devolvendo a palavra.

## Design

Decisão: `_CODE_SPAN` passa a casar uma corrida de N crases, o conteúdo mínimo e uma corrida de exatamente N crases (`(?<!`)(`+)(?!`).+?(?<!`)\1(?!`)`), por linha. Alternativa pesada: um parser CommonMark completo, descartado por custo sem ganho para um detector heurístico. Contrato: docstring de `mojibake_words` e mensagem de `refuse_mojibake`.

### Assumptions

- O span nunca cruza linha, porque o detector processa linha a linha (`## Out of Scope`).

### Mapa de dependências

(varredura inline: executor sem Task, 2025-11-25) `_CODE_SPAN` só é usado em `edit.py` (`mojibake_words`); `mojibake_words` é chamado por `granular.py` e `create.py`, que não mudam.

## Alternatives Considered

- Parser CommonMark completo para code spans: mais código e dependência para o mesmo efeito.
- Documentar "use cerca" na mensagem: contradiz a regra que a própria mensagem dá.

## Open Decisions

- none — a regex e o teste estão decididos pela evidência do achado.

## Risks

- Regex que case demais e esconda um `descri??o` real: mitigado exigindo contagem igual de crases e o teste que mantém a palavra fora de span sendo detectada.
