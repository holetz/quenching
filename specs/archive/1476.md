## Problem

O execute e o spec-runner pedem um teste de regressão "que falha sem o fix", mas não dizem como provar esse RED, e um worker que tenta medi-lo recorre a `git stash`, que apaga trabalho de outros subagentes no mesmo checkout. A prova precisa ser medida aplicando `git apply -R` do diff de produção numa worktree da base, nunca com stash, e registrada como evidência.

Evidência: `grep "RED:|fails without|git apply -R"` é vazio em `plugins/quenching/assets/references/specs-execute/`, `plugins/quenching/agents/spec-runner.md` e `plugins/quenching/commands/specs/execute.md`.

## Proposal

- The execution contract (`execution.md` §The validation loop) states how a regression test's RED is proved: `git apply -R` of the task's production diff in a worktree of the base, never `git stash`, `checkout` or `reset`.
- The proof is recorded as evidence: one `RED: <test> fails without <fix> (git apply -R, base worktree)` line in the task's report.
- `spec-runner.md` carries the same method beside its Forbidden list, so a worker that wants to measure RED finds the permitted route there.

## Out of Scope

- Changing any grant, hook, CI, `allowed-tools` or agent `tools:` — the method uses only git commands the worker already may run; ruled out because it would widen a grant.
- A tool or script that automates the measurement — deferred, prose first.
- Editing `plugins/quenching-codex/**` or `.agents/**` — the Codex mirror is gone.

## Impact

### Standards this spec will write into docs/standards/

- none — the rule lives in the execution reference, not in a standard.

### Product code this spec expects to touch

- `plugins/quenching/assets/references/specs-execute/execution.md` — the validation loop
- `plugins/quenching/agents/spec-runner.md` — the method beside Forbidden
- `plugins/quenching/tests/test_specs_execute.py` — a check that both cite the method

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p 'test_specs_execute.py'` exits 0, and the new test fails with the two prose edits reverted (`git apply -R` in a base worktree).
- `bash scripts/verify_repo.sh` exits 0 with zero errors.

## Design

- Decision: the method is a durable rule in the validation loop of the execution contract, with a short pointer in the agent. Base worktree plus `git apply -R` isolates the measurement from the shared checkout, so nothing of other subagents is touched.
- Contract: the Forbidden list in `spec-runner.md` stays unchanged; `git worktree add` and `git apply` are not on it. Assumption: the worker's grant already permits them; if a task finds otherwise it stops as blocked rather than widening anything.

### Mapa de dependências

- `execution.md` is cited by `commands/specs/execute.md` and read by `test_specs_execute.py`; an added paragraph under existing rules breaks nothing.
- `spec-runner.md` is read by `test_specs_execute.py` (RUNNER); the verifier agent is not affected.

## Alternatives Considered

- Forbid the question by dropping the "fails without the fix" demand — rejected, it removes the evidence rather than making it safe.
- Measure in the working checkout and restore — rejected, that is the stash failure again.

## Open Decisions

- none — the method and its placement are settled by the Problem; the only assumption (grant allows `git worktree add`) is checked by the task and escalates to blocked if false.

## Risks

- A worker lacks permission for `git worktree add` — mitigated by stopping blocked with `needs-human`, never widening the grant.
- Prose citation drifts — mitigated by the test that pins both mentions.
