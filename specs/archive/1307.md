## Problem

`cq git audit` e `cq git state` ainda executam programa da config: `log`/`reflog show` (`git/audit.py:97,101-103`) rodam `gpg.program` com `log.showSignature=true` (repro `review9/audit/mk.sh`, `PWNED_--keyid-format=long`); `status` desce no submódulo e roda o filtro dele (`_filter_overrides`, `audit.py:54-67`; `state.py:83`; `PWNED_subfilter`).

Consequência: o verifier "só leitura" executa código que qualquer worker pode plantar no `.git/config` comum.

Severidade na fila: alta.

Fonte: revisão de correção opus do épico 1289 (2026-10-08), item S1 da fila `.quenching/autopilot/2026-10-08/round1-queue.md`. Reproduções em `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review9/` (os caminhos `review9/...` deste texto são relativos ao scratchpad). Caminhos curtos: `agents/` e `commands/` sob `plugins/quenching/`; `git/`, `components/` e `specs/` sob `plugins/quenching/assets/bin/quenching/`.
## Proposal

Direção: `-c log.showSignature=false` no `SAFE`, `status --ignore-submodules=all`, e procurar outros executores dirigidos por config.

- A reprodução `review9/audit/mk.sh` deixa de criar `PWNED_--keyid-format=long` e `PWNED_subfilter`; um teste automatizado fixa os dois cenários.

## Out of Scope

- Blanking every config key that can name a program (`core.pager`, `core.sshCommand`, `diff.external`, textconv): the verbs read with a fixed argv, no pager (not a tty) and no diff content (`diff --name-only`), so none of those runs; widening the blocklist without a reproduction is the speculative hardening the audit's design rejects.
- Reporting submodule state in `status`: the verifier reads the superproject branch; a dirty submodule was never part of its facts and is not recovered by running the submodule's own config.
- `git/prune.py`, `git/push.py`, `git/pull.py`, `git/worktree.py`: they do not run through `audit.SAFE` as read verbs and the finding does not reach them.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/git/audit.py` — `SAFE` gains `log.showSignature=false`; its `status` gains `--ignore-submodules=all`; the module docstring states both.
- `plugins/quenching/assets/bin/quenching/git/state.py` — its `status` gains `--ignore-submodules=all`.
- `plugins/quenching/tests/test_git.py` — two fixtures in `Audit` pin the two scenarios.

## Validation

- `cd plugins/quenching && python3 -m unittest discover -s tests -p test_git.py` exits 0 (111 tests), including `test_log_does_not_run_a_configured_gpg_program` and `test_status_does_not_descend_into_a_submodule_filter`.
- Both new tests fail on `origin/main` (marker `PWNED_gpg` and `PWNED_subfilter` are created) and pass with the change.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- `-c log.showSignature=false` goes in `SAFE`, so it covers every verb built through `_run`/`_lines` (`log`, `reflog show`) and `state.py` too; a command-line `-c` outranks the repository config.
- `status --ignore-submodules=all` is the narrowest cut for the submodule filter: git never spawns the child status in the submodule, so the submodule's own `.git/modules/<n>/config` is never consulted. `_filter_overrides` only reads the config of `cwd`, so blanking the submodule's drivers instead would need a recursive config walk and still race with newly added submodules.
- Binding contract: the audit report stays read-only and exit 0 on any facts; submodules are simply absent from `status`.

### Mapa de dependências — 2026-10-08

| `tests/test_git.py` | `Audit`, `State` classes | none |

## Alternatives Considered

- Blanking the submodule's `filter.*` drivers recursively: rejected, needs a config walk per submodule and misses ones added during the read.
- Replacing `SAFE` with `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL=/dev/null` and an empty local config: rejected, the audit needs `safe.directory` and worktree config to resolve at all.

## Open Decisions

- none — the Proposal's direction is binding and every item is answered from the code; the verification policy keeps its default.

## Risks

- A future git verb added to `audit.py` that runs a config program would reopen the hole. Mitigation: both tests assert the marker file, and the module docstring names the two forced settings.
- ACCEPTED — `status` no longer lists a dirty submodule; the verifier never relied on it.
