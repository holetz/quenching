## Problem

Knowledge loads `.claude/hooks/hooks-config.json` from the wrong project and doctor/status ignore `ignoreGlobs`. Independent verification in `../resume-map-verify.json`, item 2, at 719ca3e5 reproduced:

- With target configuration `{"okfValidate":{"ignoreGlobs":["external"]}}` and `docs/external/bad.md` lacking frontmatter, `cq knowledge validate --json` exits 0 without external findings, while doctor/status exit 1 with `no-frontmatter`, `dir-no-index` and `index-orphan` under `external/`.
- With `warnAsError:true` and warnings only, validate exits 1 from the target cwd, but `env -u CLAUDE_PROJECT_DIR cq knowledge validate --root <target>` from another cwd exits 0. `cq --root <target> knowledge validate` behaves the same; ignored-tree findings also return from the other cwd.

Cause: `plugins/quenching/assets/bin/quenching/knowledge/cli.py:267` calls `_load_config(_project_dir())`, resolved by `config.py:52-53` from cwd or `CLAUDE_PROJECT_DIR`; `cli.py:139` invokes `validate_tree(bundle_root)` without `ignore_globs`, unlike line 284. The target-configuration contract is `plugins/quenching/assets/references/specs-align/plugin-configuration.md:54-56`. Consequence: the gate changes with cwd, and specs improvement receives findings from excluded vendor trees.

Scope: load configuration from the resolved target root, preserving the current default, and pass excluded-tree configuration to `_surface_payload`. Files: `plugins/quenching/assets/bin/quenching/knowledge/cli.py`, `config.py` only if needed, and `plugins/quenching/tests/test_knowledge.py`. No new configuration keys or grants.

Acceptance: both reproductions give consistent results from either cwd for either placement of `--root`; doctor/status do not report ignored trees, and unrelated findings remain. New behavioral tests fail on the base. `python3 -m unittest discover -s plugins/quenching/tests -p test_knowledge.py` and `bash scripts/verify_repo.sh` exit 0.

## Proposal

- `cq knowledge validate`, `doctor` and `status` read `.claude/hooks/hooks-config.json` (and `.local`) from the resolved target root, so the result is the same from any cwd and for either placement of `--root` (global or per-verb).
- With no `--root`, the configuration still comes from `CLAUDE_PROJECT_DIR` or the cwd, as today.
- `doctor` and `status` pass `ignoreGlobs` to the tree validation, so excluded trees report nothing while unrelated findings remain.
- Behavioral tests for both reproductions fail on the base and pass after.

## Out of Scope

- New configuration keys, grants or a change to the `warnAsError` semantics: the contract in `specs-align/plugin-configuration.md` already says the checker's settings come from the target's own file.
- `warnAsError` in doctor/status exit codes: the issue asks for `ignoreGlobs` only; doctor/status keep exiting 1 on any finding.
- Other verbs (`project`, `listing`, `nav`, `site-source`) and `config.py` internals, unless the fix proves to need it.

## Design

- Decision: one helper in `cli.py` resolves the config directory as `_project_dir()` when `--root` is the default `.`, else the given root. Assumption: an explicit `--root .` is indistinguishable from the default and takes the same path, which is the current behavior. Alternative weighed: make `--root` default `None` in every declarer; rejected as wider than the bug.
- Decision: `_surface_payload` takes `ignore_globs` and forwards it to `validate_tree`, mirroring `run_cli`; `_density` is left unchanged. Assumption: density counting ignored trees is outside the reported defect.
- Decision: doctor/status refuse with `config-unreadable` on a bad config, as validate does. Assumption: this is the right consistency; it is a new refusal for those two verbs only when a declared config is unreadable.
- Binding: `plugin-configuration.md` lines 54-56 (settings come from the target's own file).

### Mapa de dependências

- `cli.py` `_load_config` callers: only `run_cli` today; `config.py` unchanged.
- `_surface_payload` callers: `_run_doctor`, `_run_status` only; the signature gains an optional argument.
- `validate_tree(..., ignore_globs=)` already exists (used at `run_cli`).

## Alternatives Considered

- Moving config resolution into `config.py` with a root parameter: rejected, the target root is a CLI concern and `_load_config(project_dir)` already takes a directory.
- Making `CLAUDE_PROJECT_DIR` lose to `--root` everywhere including the default: that is what the helper does only for an explicit root; the default keeps the environment variable first.

## Open Decisions

- Whether `warnAsError` should also drive doctor/status exit codes: decided by a separate spec if wanted; this spec leaves exit semantics as is.

## Risks

- A repository whose config was ignored by doctor/status now refuses on an unreadable config. ACCEPTED — it matches validate and the contract.
- A caller relying on CLAUDE_PROJECT_DIR while passing `--root` elsewhere now gets the target's config. ACCEPTED — that is the defect being fixed.
