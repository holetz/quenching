## Problem

Each repository carries its own `quenching.json`, standards and glossary as files, so agents in containers need the whole tree to know the rules. Serve configuration, `/docs/standards/` and the OKF glossary as MCP resources of the quenching specs service, the provider that quenching's configuration reading switches to (quenching S10).

Formerly holetz/tempering#3.

Member S8 of holetz/forge epic 1 (Deliver the self-hosted AI-assisted development platform around Omnigent).

## Proposal

- The specs MCP server (`cq specs mcp`) declares the `resources` capability and answers `resources/list`, `resources/templates/list` and `resources/read`, so an agent in a container reads the repository's rules from the service instead of needing the tree.
- Three families of resource exist: the specs configuration (`quenching://config`), the standards under `docs/standards/` (`quenching://standards`, one resource per file) and the OKF glossary (`quenching://glossary`).
- The configuration resource is the payload of the same `cq specs config` verb, dispatched in-process through the one core, so the backend choice, hooks and profiles it reports are the CLI's.
- A standard or the glossary is never handed over unbounded: a read returns the document's outline, and `?section=<heading>` (standards) or `?term=<term>` (glossary) returns only the named sections or entries; a standard small enough to sit under the document ceiling is returned whole with its outline. Anything above the ceiling is cut with `truncated: true` and a hint, as the tools already do.
- The surface is read-only and closed: a URI resolves only inside `docs/standards/*.md` (no `..`, no symlink out) or to the two fixed names `config` and `glossary`, and the server writes nothing.
- A repository with no `docs/` lists only the configuration; a missing resource is the MCP "resource not found" error, never a crash.
- The plugin README documents the resources, the URI forms and the size policy, and the generated mirrors carry the change. No grant, hook, `allowed-tools` or CI changes.

## Out of Scope

- Swapping `Bash(cq specs ...)` or `Read` grants in agents and commands for these resources: authorized only with the human's review in the PR, and a later member (epic 2096 policy).
- Any grant, `allowed-tools`, `tools:`, hook, script or CI widening (epic 2045).
- Writing configuration, standards or the glossary through the server. Writes of `/docs/` stay with the knowledge commands.
- The effective-configuration view of `cq config show` (layers per key): the resource serves the specs service's own configuration, which is what switching the configuration reading to the service (quenching S10) consumes. Deferred, not rejected.
- Serving the rest of `/docs/` (concepts, decisions, how-to): only standards and the glossary are named by the problem.
- Subscriptions and `resources/list_changed`: the server declares `subscribe: false`, `listChanged: false`.
- The HTTP transport on forge: this is the stdio server only.

## Design

**Decision 1 — resources, not new tools.** The problem names MCP resources, and a resource is the protocol's shape for "context a client may attach": Claude Code lists them and lets the user `@`-mention them. The tool tables stay untouched, which keeps the 2085/2086 golden test of tool names valid and adds no write path.

**Decision 2 — the configuration comes through the core.** `quenching://config` is `run_core(["config"], root)`, the payload of `cq specs config --json`. The server parses no `quenching.json` itself, so a key the CLI learns to read is served the same day. Credentials live outside the repository (2092), and the payload is what the CLI already prints.

**Decision 3 — documents reuse the section rule.** A standard is free markdown, so the server uses `quenching.components.sections.markdown_sections` and `select_sections`, the same rule `cq components read` applies (fences are not headings, a section ends at the next heading of the same or shallower level, an exact name wins then a unique prefix). It is imported lazily: the `quenching-specs-reader` mirror ships no `components` package and never runs this server, so there a read answers "unavailable in this distribution" rather than failing at import.

**Decision 4 — size is a contract, per section.** The epic's rule: no answer carries a whole large document, and every answer sits under about 25,000 tokens. A read of `quenching://standards/<path>` returns the outline (level, heading, characters) always; the full text when the document is at most `DOC_WHOLE = 24_000` characters (about 6,000 tokens, far under the ceiling), otherwise the outline alone with a hint to ask `?section=`. `?section=` takes one or more comma-free headings repeated, resolved by `select_sections`; an unresolved name is a refusal naming it. The glossary is a flat list of `* [Term](...) — definition` and `* **Term** — definition` bullets, so `quenching://glossary` returns the term names only (compact) and `?term=` returns the matching entries (exact, then prefix, case-insensitive). The existing `_guard` ceiling (`MAX_CHARS`) is the last line of defence and applies to every resource text.

**Decision 5 — URIs and containment.** Scheme `quenching://`: `config`, `glossary`, `standards` (the index of files) and `standards/<relative path without .md>`. The relative path matches `[A-Za-z0-9][A-Za-z0-9._/-]*`, has no empty or `..` segment, and its resolved real path must stay inside the real path of `docs/standards`; the file must exist and end in `.md`. The glossary is the fixed file `docs/glossary.md`. Reading never follows a link out of `docs/standards`.

**Decision 6 — frontmatter is metadata.** The listing description carries the document's `title`, `description` and `authority` (`current`, `background`, ...) from its frontmatter, so an agent can prefer `current` standards without opening them. Frontmatter is stripped from the body by the section rule, as for `cq components read`.

**Decision 7 — registration unchanged.** The `.mcp.json` already registers the server; resources appear with it. Declaring a capability is no grant or permission, and the human's permission prompt for the server is untouched.

Binding contracts: the exit-code and `--json` payloads of `cq` stay frozen by the golden fixtures (only the `mcp` help text moves); `docs/standards/code/canonical-set-parsing.md` (the section rule is shared, not forked); `docs/standards/naming` for the file and URI names.

## Alternatives Considered

Reference projects (holetz/forge epic 1, §Reference projects, the "quenching (specs service)" lines), read before this develop:

- **MrLesk/Backlog.md (MIT) — adapts.** Its MCP server also serves project documents beside the work items. We adapt the idea of the server being the one door to the project's context, but serve the repository's governing documents as protocol resources with per-section reads, because Backlog.md has no size contract and the epic requires one.
- **microsoft/azure-devops-mcp (MIT, to confirm) — adapts.** Its read-only toolsets and narrow tool shapes inform the closed, read-only surface; its remote endpoint and Entra auth are not used (stdio, local).
- **automazeio/ccpm (MIT) — rejects for this member.** It targets syncing PRDs and issues into a tracker, the adapters' job (2083 to 2091), not serving rules.
- **`cq specs serve` / `portal.py` (this repository) — reuses the pattern.** The loopback portal already solved containment of what it serves and per-run safety; the same refusal-before-read style applies to URI containment here. The HTTP surface itself is not reused.
- **SVAR Gantt / frappe/gantt — not applicable** (rendering, not context serving).

Whole-shape alternatives rejected:

- **New tools (`docs_read`, `glossary_lookup`).** Rejected: the problem asks for resources, tools would widen the tool table the golden test freezes, and a tool is a model-invoked action while a rule file is context.
- **Mount the whole `docs/` tree as resources.** Rejected: unbounded listing, and concepts and decisions are not what a container needs to follow the rules.
- **Return every standard whole, relying on the final guard.** Rejected: the guard cuts at 60,000 characters and would silently drop the tail of a large standard; the outline plus per-section reads is the epic's per-section rule.
- **Parse `quenching.json` inside the server.** Rejected: a second reading path that can drift from the CLI, the failure Decision 1 of 2085 already ruled out.

## Open Decisions

- none — every item was decided from the evidence. The 1:1 swap of `Bash(cq specs ...)`/`Read` grants for these resources is deliberately a later member with human review before merge.

## Risks

- A repository standard can be large and still be named whole by a careless client; mitigation: the outline-only answer above `DOC_WHOLE` and the final `MAX_CHARS` guard, both tested.
- A symlink or crafted URI escaping `docs/standards`; mitigation: the real-path containment check and the character whitelist, tested with a link out and `..` forms.
- A glossary entry format the term parser does not recognise is invisible to `?term=`; mitigation: the parser matches both bullet forms the glossary standard defines, and an unmatched term answers a refusal that points at `quenching://glossary`.
- The reader distribution lacks `components`; mitigation: lazy import with an explicit "unavailable" answer, and the reader never registers this server.
- Serving rules to agents lets a stale or `background` standard be read as binding; mitigation: the listing carries each document's `authority`.
