## Problem

`plugins/quenching/tests/test_check_codex_upgrade.py::test_forced_auto_gc_packs_loose_objects_without_the_source_config` falha com `'2002' != '0'` nos runners de CI com git 2.56.0 (ubuntu-26.04) e passa com git 2.55.0. O controle positivo `FORCED_GC` (`gc.auto=1`, `maintenance.strategy=geometric`) deixou de empacotar os loose objects no 2.56. A `main` falha igual desde o PR #31 (run 40557510096) e a falha bloqueia o merge do PR #32 (quenching#2110). Origem: spec 2032.

## Proposal

Ajustar o ambiente forçado (`FORCED_GC` e a forma como `commit_many` o aplica) para que o git 2.56, o 2.55 e o 2.43 empacotem os loose objects no controle positivo, mantendo a asserção intacta: sem rebaixar a régua e sem `skip`. O teste negativo (`test_source_config_keeps_every_loose_object_under_forced_auto_gc`) continua exigindo 2002 loose objects e 0 em pack com a `SOURCE_GIT_CONFIG`.

## Out of Scope

- Rebaixar a asserção, `skip` ou portão por versão do git: ocultariam o controle positivo, que existe para provar que o ambiente forçado apaga os loose objects.
- Mexer em `SOURCE_GIT_CONFIG` ou no código de produção de `check_codex_upgrade`: o teste negativo continua verde nas três versões.

## Impact

### Standards this spec will write into docs/standards/

- none — a correção é do ambiente de um teste e não cria regra durável.

### Product code this spec expects to touch

- `plugins/quenching/tests/test_check_codex_upgrade.py` — `FORCED_GC`.

## Validation

- CI verde no PR desta spec (Gate 3.11 e 3.13).
- `bash scripts/verify_repo.sh` com exit 0.
- Git 2.56 local isolado, se disponível, rodando os dois testes de `test_check_codex_upgrade.py`.

## Design

- Causa (git 2.56.0, `odb/source-files.c`, estratégia `ODB_OPTIMIZE_GEOMETRIC`): o limiar de loose objects da estratégia geometric passou a vir de `maintenance.geometric-repack.auto` (padrão 6700), e não mais de `gc.auto`. Com `gc.auto=1` apenas, 2002 loose objects ficam abaixo de 6700 e o auto-gc não empacota. Regra durável: o ambiente forçado define os dois limiares.
- Decisão: acrescentar `maintenance.geometric-repack.auto=1` a `FORCED_GC`. Chaves de config desconhecidas são ignoradas pelo 2.43 e 2.55, que seguem lendo `gc.auto`.
- Prova: git 2.56.0 compilado do tarball em `.quenching/g256` (fora do PATH global); os dois testes passam com 2.56.0 e com 2.43.0.

## Alternatives Considered

- Subir o número de arquivos criados acima de 6700: lento e mexe na régua do teste.
- Portão por versão: proibido pelo escopo.

## Open Decisions

- none — a causa foi reproduzida e a correção provada em 2.56.0 e 2.43.0; o 2.55 só pode ser confirmado pela CI do PR.

## Risks

- O 2.55 não foi rodado localmente. Mitigação: chave desconhecida é inerte e `gc.auto=1` permanece; a CI do PR confirma.
- Outra renomeação de limiar em versão futura do git. ACCEPTED — o teste vermelho a denuncia, que é o papel dele.
