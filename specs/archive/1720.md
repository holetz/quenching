## Problem

Knowledge status reports the payload controls block without collecting that payload. Independent verification in `../resume-map-prose-verify.json`, item 4, at 719ca3e5: `plugins/quenching/commands/knowledge/status.md:104` cites controls, but collection at lines 54-55 only runs validate, which returns a findings array. `cq knowledge status docs --json` exits 0 with keys `applicable,controls,density,errors,findingCodes,findings,ok,root,state,warnings`. Commit `2850be5f` (1638 task 2.5) changed the CLI and status text without adding collection.

Consequence: the controls report lacks a measured source and is filled by inference.

Scope, delegated owner decision: collect `cq knowledge status docs --json`, a superset of validate output, retaining `--activity` and the cheap-by-construction collection budget. Preserve the current Glob-based density method; the density payload is not adopted as its replacement. Files: `plugins/quenching/commands/knowledge/status.md` and `plugins/quenching/tests/test_align_contract.py`. No grants or protocol redesign. Dependency: S9 (1718), which changes both shared files.

Acceptance: collection obtains the status payload before reporting controls; controls derive only from that payload; density still uses Glob and activity is retained. Update the prose contract test meaningfully. `python3 -m unittest discover -s plugins/quenching/tests -p test_align_contract.py` and `bash scripts/verify_repo.sh` exit 0.

## Proposal

Replace the validate collection in `/quenching:knowledge:status` step 2 with `cq knowledge status docs --json` (a superset of validate: `controls`, `findings`, `density`, `ok`), keep `--activity` through `validate docs --activity --json` (status has no `--activity` flag), and keep Glob-based density. Step 4 item 6 derives controls only from that payload. A contract test pins it.

## Out of Scope

- The density count including ignored trees (known from 1712).
- Any change to the CLI, protocol 1694, permissions, hooks or CI.
