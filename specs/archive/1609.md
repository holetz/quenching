## Problem

Reproduzido pela revisão de correção do épico 1607 (2026-10-12), em `main` 41502a11, na prosa que a #1608 (spec 1606)
acrescentou. `plugins/quenching/commands/proof/align.md:102-106` diz: "When `--raise` exits non-zero (…), the floor was
not raised", e manda nunca chamar o piso de elevado. Só que, no código, o `--raise` anota `pf-no-floor` e mesmo assim
põe a raiz em `next_floors` (`plugins/quenching/assets/bin/quenching/proof/ratchet.py:258-262`). Como `pf-no-floor`
fica fora do conjunto `blocking` (`:279`), o arquivo de piso é gravado (`:280-283`), e o retorno é
`1 if findings else 0` (`:292`), repassado por `cli.py:163-166`.

Consequência: `align.md:71` manda o `pf-no-floor` (structural) justamente para o `--raise`. Nesse caso, que é o da
primeira elevação, o comando sai com 1 e `ok:false` mas grava o piso. Seguindo a prosa, o agente relata "piso não
elevado" e deixa um arquivo de piso novo no working tree sem aparecer no relatório. A correção, só de prosa, distingue
os casos: saída 2 (recusa) ou `findings` com `pf-floor-regressed`/`pf-floor-unmeasured` (bloqueado, nada gravado)
contra uma saída 1 só com `pf-no-floor` (piso gravado para as raízes novas, que se relata como elevado).

## Proposal

- `proof/align.md` separates the three outcomes of `proof ratchet --raise`: exit 2 (refusal), exit 1 with `pf-floor-regressed` or `pf-floor-unmeasured` (blocked, nothing written), and exit 1 with only `pf-no-floor` (floor written for the new roots).
- The agent reports the third case as raised, naming the floor file, and never as "not raised".

## Out of Scope

- Any change to `ratchet.py` or `cli.py`: the code is the reference, the prose follows it.
- `gate-contract.md`: its "Either blocking finding or any refusal leaves the floor file unwritten" is already true and does not claim `pf-no-floor` blocks.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/commands/proof/align.md` — the paragraph after the `--raise` command.

## Validation

- `grep -n "only .pf-no-floor" plugins/quenching/commands/proof/align.md` finds the new case.
- `bash scripts/verify_repo.sh` exits 0.

## Design

Durable rule: the floor file is written by `--raise` unless a refusal (exit 2) happens or a `pf-floor-regressed`/`pf-floor-unmeasured` finding is present (`ratchet.py:279-283`). `pf-no-floor` is not blocking; it adds the root to `next_floors` in raise mode (`:258-262`) and only makes the exit 1 with `ok:false` (`:292`, `cli.py:163-166`). The prose therefore decides by the codes in `findings`, not by the exit code alone.

## Alternatives Considered

- Make `--raise` exit 0 when only `pf-no-floor` fires: rejected, a code change outside this prose-only fix.

## Open Decisions

- none — the epic 1610 Design fixed the three-case wording.

## Risks

- The agent still reads a non-zero exit as failure: mitigated by naming the codes that decide each case.
