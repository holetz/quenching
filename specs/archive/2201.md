## Problem

The leak patterns derive from `$HOME`: the home-slug is the HOME path with each slash turned into a dash, matched with a boundary only on its right. On a host whose HOME is the root user's home (a root container, a CI runner, a cloud agent session) the slug is the five characters dash-r-o-o-t, so the repository's own leak gate reports 644 findings on a clean tree (every double-dash "root" CLI flag), and the spec store's write sanitizer silently rewrites any word ending in dash-r-o-o-t into a project placeholder — it corrupted "temp" + dash-r-o-o-t in spec 2197 and a flag spelled in a discovery of spec 2193. Found while building specs 2193–2198 in such a session.

## Proposal

- With `$HOME` set to the root user's home, the `home-slug` leak pattern no longer matches a double-dash CLI flag or a word that merely ends in the slug.
- The store sanitizer (`normalize_paths`) no longer rewrites such words into the project placeholder.
- A genuine Claude Code project slug (after a slash, a quote, a space or at line start) is still detected and normalized, for any `$HOME`.

## Out of Scope

- Changing the `home-path` pattern: the home directory itself is matched with a right boundary by design, and the report concerns only the slug.
- Reworking how the slug is derived from `$HOME`: the derivation mirrors Claude Code's own encoding.
- Any new command step or gate: the fix fits in the pattern.

## Design

The slug is a path-segment prefix: Claude Code writes it right after a slash, so it never legitimately follows a word character, a dot or a dash. Both regexes get a left boundary, a negative lookbehind for a word character, a dot or a dash, mirroring the right-hand boundary already there. A one-pattern change, with no new code path.

### Assumptions

- Real slugs always begin the token (after `/`, a quote, a space or at line start) — the Impact test covers it.

## Alternatives Considered

- Skip the slug pattern when the slug is shorter than N characters: rejected, an arbitrary threshold that hides short real homes.
- Skip the slug when HOME is root: rejected, hides real leaks on that host and special-cases one user.

## Open Decisions

- none — the boundary choice is settled by the evidence above.

## Risks

- A real slug glued to a word character would stop matching. ACCEPTED — Claude Code always places it after a path separator.
