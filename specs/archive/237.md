## Problem

`cq deploy` installs `quenching/skills/quenching-knowledge/references/knowledge-documentation/architecture.md` (and siblings) into a target's `.agents/skills/` and, through the bridge, `.claude/skills/`, but these references are written in Portuguese while the deployed surface is otherwise English. In an English-only target that guards commits with a private, case-insensitive leak denylist, a common Portuguese word in line 197 ("## Registro de capacidades" paragraph) matched a denylist pattern and blocked the commit of a fresh deployment; the target had to hand-edit the generated file in both copies, a local deviation the next `cq deploy --write` will overwrite.

The deployed references should carry English prose (the canonical agent-facing surface), so a deployment never forces a target to edit generated files or weaken its own leak gate; other deployed references with Portuguese prose (for example `specs-create/plan-mapping.md`) likely share the defect.

## Proposal

- The deployed `knowledge-documentation/architecture.md` and `knowledge-documentation/validation.md` carry English prose in every paragraph, table cell and heading; the Portuguese sections are translated with their meaning unchanged.
- `specs-create/plan-mapping.md` keeps its Portuguese tokens (`Contexto`, `fora de escopo`, `Decisões`, `a decidir`, `Riscos`, `Etapas`) as quoted examples of the headings a native plan may use; the Design records why.
- A deploy of the source into a target leaves no Portuguese prose outside quoted examples in these references, so the target's leak gate and the next `cq deploy --write` agree.

## Out of Scope

- `specs-execute/execution.md` and `specs-develop/artifacts.md`: owned by spec 286 (epic 288 decision of 2026-11-23); translating them here would collide.
- Other deployed references the spec does not cite: the epic limits the translation to the references this spec names.
- A repository-wide Portuguese-prose gate: a heuristic check over a bilingual repository is a separate spec.
- `Diátaxis`: a proper noun, kept as is.

## Impact

### Standards this spec will write into docs/standards/

- none — a prose translation of two references, no standard changes.

### Product code this spec expects to touch

- none — no code changes.

### Process surface this spec expects to touch

- `quenching/skills/quenching-knowledge/references/knowledge-documentation/validation.md` — translate the catalog, capability, operational-artifact and scale-baseline paragraphs

## Validation

- A `python3 -c` regex check over each translated source finds none of the Portuguese markers (`catálogo`, `capacidade`, `Registro`, `Recorte`, `Baseline de escala`, ` não `, ` deve `, ` uma `, ` fora `); it exits non-zero on the untouched tree and 0 after the translation.
- `.agents/quenching/bin/cq components read` on each translated file still lists its headings, so the section addresses resolve.
- `bash scripts/verify_repo.sh` raises no finding from the `deployed surface lockstep` check; a Windows platform-red elsewhere is inconclusive and CI proves the merge.

## Design

- **Translate in place, keep structure.** Same section order, tables, `source gap:` tokens and code blocks. Headings become English: `## Catalog contract outside the site`, `## Capability registry`, `## Incremental cut and handoff`, `### Catalog scale baseline`. A grep over the tree finds no other file citing those headings by their Portuguese text, so no citation changes.
- **Plan-mapping stays.** Its Portuguese tokens are literal inputs the mapper must recognise (the file says: match on meaning, never on the literal string), not agent-facing prose; translating them would remove the examples the rule needs. Rule: foreign-language input examples are quoted data; the prose around them is English.
- **Generated mirrors are regenerated, never hand-edited:** `python3 quenching/assets/bin/cq deploy --target . --write` rewrites `.agents/skills/**`, `.claude/skills/**` and the manifests.
- decision: translate only the references the spec cites — `architecture.md` and its sibling `validation.md`, which carries the same defect — not `execution.md` or `artifacts.md`: epic 288 Design, 2026-11-23.
- decision: keep the Portuguese tokens in `plan-mapping.md` as quoted input examples — the mapping rule matches meaning across languages and needs them.
- decision: `Diátaxis` keeps its accent — a proper noun used the same way across the repository.

## Alternatives Considered

- **Translate the `plan-mapping.md` tokens too.** Rejected: it removes the examples that tell the mapper a plan may be in another language.
- **A repository gate that rejects Portuguese prose in `quenching/**`.** Rejected here: a heuristic gate is its own spec.
- **Each target allowlists the words in its denylist.** Rejected: pushes a local deviation to every target, which is the defect this spec removes.

## Open Decisions

## Risks

- A translation that drifts from the meaning of a contract: mitigated by keeping table structure and field names (`capability`, `enabled`, `disabled`, `source gap:`) verbatim and reading the diff line by line.
- A generated mirror left stale: mitigated by redeploying and running the lockstep check in the same task.
- ACCEPTED — `plan-mapping.md` still contains Portuguese tokens a very strict denylist could match; they are quoted examples and the Design says so.
