## Overview

Root `CLAUDE.md`'s "Operating this repo" verify block is missing one check that
`docs/standards/ci-cd/versioning-release.md` §Verifying already documents:
`python3 assets/bin/session.py --version`. This spec inserts that single line so the two blocks
agree, and following `CLAUDE.md` literally catches the lockstep drift `versioning-release.md`
describes.

## Problem

Root `CLAUDE.md`'s "Operating this repo" verify block runs `VERSION` plus the three shipped tool
scripts' `--version` (`specs.py`, `skills.py`, `okf-validate.py`), but omits
`python3 assets/bin/session.py --version`. `docs/standards/ci-cd/versioning-release.md` §Verifying
already lists that check — `session.py` is one of the seven version-carrying artifacts
`specs.py release` bumps in lockstep — so following root `CLAUDE.md` literally would not catch the
exact drift (e.g. `session.py` at `4.2.0` while the other six read `4.3.0`) that
versioning-release.md's own source note describes.

Surfaced as a `## Discoveries` line while concluding `plan/update-plugin-readme-upgrade-section`
(archived, `done`) — out of scope for that spec, which only touched
`plugins/quenching/README.md` §Upgrade.

## Proposal

- Root `CLAUDE.md`'s verify block includes `python3 assets/bin/session.py --version`, mirroring
  `docs/standards/ci-cd/versioning-release.md` §Verifying exactly — same line position, same inline
  comment.
- Following root `CLAUDE.md`'s "Operating this repo" verify block literally catches the same
  lockstep drift `versioning-release.md` already describes (e.g. `session.py` at a stale version
  while the other six version surfaces agree).

## Out of Scope

- `docs/standards/ci-cd/versioning-release.md` itself — already correct; this spec brings
  `CLAUDE.md` into agreement with it, not the reverse.
- `CLAUDE.md`'s opening paragraph ("...plus three dependency-free stdlib Python tools") — now reads
  as four with `session.py` counted, but that is a separate wording drift, unrelated to the verify
  block. Parked to `## Discoveries`.
- Any change to the tools themselves (`session.py`, `specs.py`, `skills.py`,
  `okf-validate.py`) — this spec only edits `CLAUDE.md` prose.

## Impact

### Standards at `authority: background` this spec may resolve

## Validation

- From `plugins/quenching/`: `python3 assets/bin/session.py --version` exits 0 and prints
  `session <VERSION>`, matching `cat VERSION`.
- `git diff CLAUDE.md` shows exactly one inserted line, in the same position and with the same
  inline comment as `docs/standards/ci-cd/versioning-release.md` §Verifying's block.

## Design

- Insert `python3 assets/bin/session.py --version        # outside the six; nothing else reads it`
  immediately after the `okf-validate.py --version` line in `CLAUDE.md`'s verify block — same order,
  same inline comment as `docs/standards/ci-cd/versioning-release.md` §Verifying, so the two blocks
  stay textually identical instead of diverging in wording.
- Binding contract: `docs/standards/ci-cd/versioning-release.md` §Verifying is the authority for
  what this block must contain; `CLAUDE.md` is brought into agreement with it.

## Alternatives Considered

- Point `CLAUDE.md`'s verify block at `versioning-release.md` by reference instead of restating the
  command inline — rejected: `CLAUDE.md`'s own doctrine keeps its verify block self-contained and
  directly runnable; sending the reader to a second file to find one command contradicts that.
