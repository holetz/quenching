## Problem

`.github/workflows/ci.yml:56-71` roda `python -m unittest discover -s quenching/tests -p <arquivo>` em Python `'3.11'` para os testes que só importam no Windows (grupos de processo, spawn sem cmd.exe, fallback de junction). Reproduzido (scout): `python -m unittest discover -s quenching/tests -p test_does_not_exist.py` → py3.11 exit 0, py3.13 exit 5.

Consequência: renomear ou apagar um dos quatro arquivos deixa o passo verde rodando nada, e nenhum outro job os roda no Windows. Direção: falhar quando a saída diz "Ran 0 tests", trocar `discover -p` por `python -m unittest quenching.tests.<mod>` (falha em módulo ausente), ou subir o job para ≥3.12.

## Proposal

Manter o Python 3.11 no job `windows` do `.github/workflows/ci.yml` e manter `unittest discover -s quenching/tests -p <arquivo>` (a forma do gate: so o `discover -s` poe o diretorio de testes no `sys.path` para o `_paths`), mas fazer cada passo falhar quando a saida diz `Ran 0 tests`. O job ganha `defaults.run.shell: bash` (bash do runner: `-eo pipefail`) e cada passo vira `python -m unittest discover ... 2>&1 | tee "$RUNNER_TEMP/unit.log"` seguido de `! grep -q '^Ran 0 tests' "$RUNNER_TEMP/unit.log"`. Um teste em `quenching/tests/test_surface_listings.py` trava a forma: todo `unittest discover` do job `windows` carrega a guarda.

## Out of Scope

- Subir o job Windows para Python >= 3.12 (mudaria o interpretador provado no Windows; fica o piso 3.11).
- Os jobs `gate` e `lint` e o `scripts/verify_repo.sh`: rodam a suite inteira, nao um arquivo por padrao.
- Qualquer mudanca de `permissions:`, gatilho ou action do workflow.

## Validation

- `python -m unittest discover -s quenching/tests -p test_surface_listings.py` passa com o fix e falha na base (prova RED com o teste copiado num worktree da base).
- Reproducao local da guarda em bash: `python -m unittest discover -s quenching/tests -p test_does_not_exist.py 2>&1 | tee x.log && ! grep -q '^Ran 0 tests' x.log` sai != 0 em Python 3.11, e o mesmo comando com `-p test_windows_links.py` sai 0.
- Prova final: o job `Windows (focused tests, no administrator rights)` verde no CI do PR.

## Design

O `unittest` do 3.11 sai 0 com zero testes; o 3.12+ sai 5. A guarda le a linha `Ran N tests` que o runner imprime em toda versao, entao vale no 3.11 e continua valendo se o job subir de versao. `2>&1` porque o unittest escreve o resumo no stderr; `pipefail` (padrao do `shell: bash` no Actions) preserva a falha real do python atraves do `tee`. O passo de glob `test_toolchain_*.py` ganha a mesma guarda.

Isto so estreita o gate: nenhuma permissao, segredo ou action nova (decisao do condutor no epico 230, 2026-11-22).

### Assumptions

- O Git Bash do `windows-latest` acha o `python` do `setup-python` no PATH (padrao dos runners) — Validation depende disso; o CI do PR prova.

## Alternatives Considered

- `python -m unittest quenching.tests.<mod>`: falha em modulo ausente, mas `quenching/tests` nao e pacote e os testes importam `_paths` como irmao (artifacts.md: so `discover -s` resolve). Rejeitada.
- Subir o job para 3.12/3.13: corrige pelo exit 5, mas tira o piso 3.11 do Windows. Rejeitada.
- Guarda em PowerShell (`pwsh`, shell padrao): possivel, mas `$LASTEXITCODE` e `Select-String` em cinco passos fica mais longo que o bash. Rejeitada.
