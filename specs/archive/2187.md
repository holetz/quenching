## Problem

Three defects of the specs flow, observed on 2026-11-13 in this repository and in the SAFRA target (`databricks-risco-gold`).

1. **Conclude archives before the merge.** `/quenching-specs conclude` step 4 runs `cq specs promote --to archive` before the gate and the PR of step 7 ("Commit the move on the branch"), a rule written when specs lived in the repository tree and the archive move rode inside the PR. With the store on the `quenching` ref the move is visible at once, so a spec reads `archive`/`done` over a PR that may still stall: 1518 here (spec 1544), 1028798 and 1030888 in SAFRA, whose standard `fluxo-pr-autonomo.md` forbids promoting before the merge (SAFRA spec 1030889). The spec-verifier (check 8) and the orchestrator's acceptance require the archive before the PR, so the contradiction is built into the conductor too.
2. **Every spec cuts a fresh worktree, and an on-access antivirus rescans it.** The development machine runs Trend Micro (`vls_agent`/`vls_am`). Measured: ~1.7 ms of scanner CPU per new file and ~1.1 ms per hardlink, against a busy baseline (one sample, noisy). A fresh SAFRA worktree is 8,240 tracked files plus ~50,000 `.venv` entries (uv hardlinks from its cache, ~4,000 `.pyc` written) — ~65–100 s of scanner CPU per cut — while switching an existing checkout to a spec branch rewrote 27 files (0.4 s). Retiring at conclude (PR #101) removes the leak but makes the next spec pay the full rescan again. Worktrees also land in five directory layouts.
3. **The configuration has no editor.** `.agents/quenching.json` carries ~25 keys documented only in prose (`specs-align/plugin-configuration.md`); `cq config` is read-only; the user layer `~/.config/quenching/config.json` loses to the project key by key, so a machine-specific value (how many worktrees this machine keeps) cannot be set per machine.

## Proposal

One spec, three sections, built in this repository and landed in SAFRA by its spec 1030889.

1. **Archive after the merge.** Conclude reviews, writes `## Outcome`, distils, sweeps, proves and opens the PR; the `promote --to archive` and the worktree's release move to a post-merge close, run by a conclude resumed after the merge, by `/quenching-git merge`, by the orchestrator after `cq git pr merge`, and by an automatic reconciliation at the start of `execute`, `orchestrate` and `conclude`. The flow's own prose teaches the order; `cq specs promote --to archive --outcome done` refuses mechanically when the work ref is not an ancestor of `origin/<base>`.
2. **Worktree slots, by default.** A slot is a registered worktree that outlives its spec: acquiring one switches it to the spec's branch and locks it (`git worktree lock --reason`); releasing it detaches it at `origin/<base>` and unlocks it, keeping `.venv` and caches. Two limits: a floor of free slots cleanup keeps, and a ceiling acquire never exceeds; at the ceiling `cq` frees a slot it may free, else the agent waits and tells the human.
3. **A configuration schema and an OpenCode settings page.** One registry of every key (type, default, category, scope, reader, description in English and pt-BR) behind `cq config schema`, `cq config set|unset --layer`, a new local layer, per-key precedence, and a Settings page in the `quenching-vitrine` OpenCode Desktop plugin with tooltips.

## Out of Scope

- A cross-machine or cross-person claim record in the spec store (who is building a spec, on which host): the slot lock answers it on one machine; a record shared through the store waits for a second machine or person (decision D8, 2026-11-13).
- A TUI (terminal) settings surface: Desktop only (D14).
- Editing structured catalogs (`hooks`, `subjects`, `tagCatalog`, `workItemTypes`, `azure*`) in the plugin: read-only there, with "open in editor" (D15).
- OpenCode's own session worktrees (`~/.local/share/opencode/worktree/…`): reported by status, never managed as slots.
- An antivirus exclusion for `~/.cache/uv` and the worktree directories: a corporate security decision, independent of this change.
- Migrating SAFRA's live worktrees: SAFRA spec 1030889 lands the release and migrates there.

## Validation

- Archive order: `cq specs promote --to archive --outcome done` on a spec whose work ref is not in `origin/<base>` exits non-zero with or without `--force`; `--outcome abandoned` still passes; `cq specs reconcile --write` archives a merged spec with `## Outcome` and reports one without it as `needs-human`; a flow-sweep test fails when `promote` precedes the PR step in `conclude.md`.
- Slots, on a scratch repository: 13 concurrent `acquire` calls with `max: 12` yield 12 distinct locked slots and one refusal naming the holders; release of a dirty slot refuses; release then acquire of another spec reuses the same directory and its ignored `.venv`; cleanup keeps `min` free slots; `retire` accepts a tree whose only ignored content is a directory of regenerable paths.
- Configuration: `cq config set --layer local shared.worktreeSlots.max 6` changes `cq config show --effective --json` with provenance `local`; the same on a `project`-scoped key refuses; every other key and the file's order survive a `set`; the table test passes against the registry.
- Plugin: `npm run build` and `tsc --noEmit` in `integrations/opencode-vitrine` pass; in OpenCode Desktop ≥ 2.3 the Settings page lists the eight categories, the tooltip shows on hover and a toggle round-trips through `cq config set` (checked by hand once, recorded in `## Outcome`).
- The whole: `bash scripts/verify_repo.sh` zero errors with the floor enforced; `cq deploy --target . --check --json` reports no changes.

## Design

Decisions taken with the human on 2026-11-13 (two decision sheets in the session that captured this spec).

**Archive after the merge**
- D3: the order is taught by the flow, not only refused: archiving before the merge disappears from every text of the flow (conclude's title and opening, step 4 reduced to writing `## Outcome`, a new post-merge step, the resume and `autonomous` tables, `spec-driven.md`'s lifecycle, spec-verifier check 8, the orchestrator's acceptance, the runner, the README catalogue), a test fails if `promote` reappears before the PR, and the CLI guard is the second barrier. The guard has no bypass for `done`; `abandoned` keeps no guard.
- D4 A: a spec whose PR is merged on the remote and is not archived is closed automatically at the start of `execute`, `orchestrate` and `conclude` (the merge is a fact git checks, the Outcome was written before the PR); `status`/`next` list them too.
- Before the merge the spec-verifier accepts `## Outcome` written with the spec still in `plans/`; the archive is checked after the merge.

**Worktree slots**
- D5: slots are the default for every target — there is one way to work, not two the flow must learn.
- D6/D9: two limits, `shared.worktreeSlots.min` = 4 (cleanup's floor: free slots kept warm) and `max` = 12 (the ceiling). At the ceiling `cq` tries to free a slot; if none can be freed it returns a refusal naming who holds each slot, and the agent waits (`cq git worktree acquire --wait`, a retry every 30 s up to a configurable timeout, default 30 min) after telling the human the limit was reached; the timeout becomes `needs-human`. The orchestrator does not wait inside a worker: it does not launch the next one.
- D10 A: only slots count toward the ceiling; legacy and OpenCode worktrees are reported, not counted.
- D11 A: `cq` frees only an unlocked slot or one whose spec is already merged (running the post-merge close); a slot locked by another session is never taken — switching it would move a live agent onto another branch. Stale locks are shown with the release command.
- D7 B (SAFRA): fresh slots are cut; the four merged, clean worktrees are retired; live ones are untouched until they close.
- Acquire is atomic, using `git worktree lock` as the mutex. Release refuses a dirty tree or unrecognized ignored content, so nothing of one spec leaks into the next. A paused spec with a dirty tree keeps its slot; nothing is committed automatically to free it. `worktreeSetup` runs on every acquire and must be idempotent (documented; `doctor` warns). Slot paths are `../<repo>-slot-<n>`; the lock reason is `quenching: <id> · <session> · <host> · <iso date>`.

**Configuration**
- D12 A: a new local layer `.agents/quenching.local.json`, git-ignored, this repository on this machine; `~/.config/quenching/config.json` keeps working for every repository, below the project.
- D13 A: each key declares a scope — `project` (team contract; local cannot override, shown locked), `machine` (local wins: slot limits, `workHost`, context budgets), `either` (project wins, local fills gaps, as today).
- One Python registry is the single source: `cq config schema --json` for the plugin, `cq config set|unset --layer project|local` (validated, preserving every other key) as the only writer, and a gate check of `plugin-configuration.md`'s table against it.
- D14 A: the page lives in `quenching-vitrine` (OpenCode Desktop GUI part) as a `SettingsPage`, reusing its `cq` resolution and RPC.
- D15 A: scalars, enums, booleans, numbers, path lists and the git-convention prose are editable; structured catalogs are read-only with "open in editor".
- Layout: categories by task — Worktrees and isolation · Autonomy and orchestration · Specs and cards · Git and PR · Review (Codex) · Proof and tests · Operations · Knowledge. Each row: title, one short line, a tooltip with the full description, default and reader, a layer badge (Project / Local / Default) and "restore default"; Settings search reveals each key; copy in English and pt-BR.

**Settled at develop (facts found by the dependency sweep)**
- The post-merge close is one verb: `cq specs reconcile [--write] [--json]` lists every spec whose work ref is an ancestor of `origin/<base>` (or whose recorded PR is merged) and whose phase is not `archive`; `--write` archives those carrying `## Outcome` and releases their slot, and reports one without `## Outcome` as `needs-human` instead of archiving it. Conclude resumed after the merge, `/quenching-git merge`, the orchestrator and the reconcile at the open of `execute`/`orchestrate`/`conclude` all call it — one implementation, four callers.
- The local layer stays out of git through `.git/info/exclude`, written by `cq config set --layer local` on first write — no tracked `.gitignore` edit, since `cq deploy` writes no `.gitignore` today.
- The GUI SDK pinned today (`@opencode/plugin` 2.2.5) has `SettingsPage`, `Switch`, `Tooltip`, `TextInput`, `Menu` and `Button`, but not `SettingsLayout`/`SettingsSection`/`SettingsRow`; 2.3.0 adds those three. Neither version has a `ui.Select` component, so an enum is a `ui.Menu`. The vitrine moves its pin to 2.3.0; on an older host the page is not registered and the plugin's other parts keep working (the OpenCode installed on the development machine is 2.2.5, so the page shows after its upgrade).
- Nothing in the gate builds the vitrine today: the gate gains a `tsc --noEmit` step for it that reports `SKIPPED` when `integrations/opencode-vitrine/node_modules` is absent.
- The `plugin-configuration.md` table check is a unit test against the registry, so it runs in every gate tier.
## Alternatives Considered

- **A worktree per session** (the human's first idea): bounds nothing under the orchestrator (each runner is a session) and ties work to a directory whose owner ends before the spec does; the slot keeps the reuse and drops the coupling.
- **A shared `.venv` across worktrees** (SAFRA's W2): each hardlink is still scanned (~1.1 ms), and SAFRA's test wrapper refuses a package from another tree; a slot keeps its own venv.
- **Changing SAFRA's standard instead of conclude**: the archive-before-PR order was correct only for an in-tree store; three incidents in two repositories.
- **Slots opt-in** (`shared.worktreeSlots` absent = today): two ways of working for the flow to learn; no harm of the default was found that the release refusals do not cover.
- **An overflow ephemeral worktree at the ceiling**: replaced by the two limits and waiting.

## Open Decisions

- none — the fifteen decisions were answered on 2026-11-13 (`## Design`).

## Risks

- The archive order is a contract change for every installed target: an agent on an older deployed surface keeps archiving before the PR until the target is redeployed (tag `breaking`).
- A non-idempotent `worktreeSetup` in some target breaks on the second acquire.
- A slot reused across specs may carry ignored build output a target never declared regenerable; release refuses it, which may surface as more `needs-human` at first.
- The OpenCode GUI plugin API is experimental (`./gui-experimental`) and may change between releases.
- Scanner cost was measured once against a busy baseline; the gain is re-measured in SAFRA after the migration.

## Handoff

- **Order of build:** section 1 first — it alone fixes the incident and can ship even if the rest slips; section 2 next, since `reconcile --write` releases a slot only once slots exist (until then it calls `retire`); section 3 last.
- **Do not touch** the uncommitted `.agents/quenching.json` in the main checkout (Codex cross-review off, the human's local choice); cut the worktree from `origin/main`.
- **Gate while building:** `env -u OPENCODE_SESSION_ID QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh`.
- **After the merge:** `/release`, then SAFRA spec 1030889 deploys it and migrates SAFRA's worktrees (D7 B); spec 1544 is closed as a duplicate of this one.

## Outcome

Shipped, reviewed and distilled, ready for merge:

- **Archive after the merge, never before.** `cq specs promote --to archive --outcome done` refuses `sp-not-merged` (no `--force` bypass) until the work is provably merged: the tip is an ancestor of `origin/<base>`, a `merge:` record names a strategy, or the `pr:` record reads MERGED (squash). The new `cq specs reconcile [--write]` is the one post-merge verb: it fetches once, finds every merged spec still in `plans/`, archives each one carrying `## Outcome`, reports `needs-human` for the rest, and releases the spec's worktree slot. `cq specs next --front` surfaces `mergedNotArchived`. `conclude` now writes `## Outcome` before the PR and archives in step 8, after the merge; `merge`, `execute`, `orchestrate`, the verifier, the orchestrator and `plan-git-record.md` teach the same order.
- **Worktree slots.** `cq git worktree acquire | release | slots` keep reusable worktrees at `../<repo>-slot-<n>`, so a spec switches a warm tree (its `.venv` kept) instead of making the antivirus rescan a fresh one. `git worktree lock` is the mutex (reason: spec · session · host · date) and slot creation is serialised by a lockfile, so concurrent takers never share a slot or pass the ceiling. `shared.worktreeSlots.max` (12) is the ceiling: `acquire` refuses naming each holder, or `--wait`s and then needs a human. `min` (4) is the floor `cq git stale`/`prune` keep warm. Release refuses a dirty tree or unrecognised ignored content; only slots count, legacy worktrees are listed and never taken. `worktreeSetup` runs on every acquire and must be idempotent (`sp-config-setup-idempotence`, silenced by `shared.worktreeSlots.setupIdempotent`). An empty-directory skeleton of regenerable caches no longer blocks a release or retire.
- **Configuration you can edit.** One key registry (`config/schema.py`, printed by `cq config schema [--values]`) with type, default, category, scope and copy in English and pt-BR, held equal to `plugin-configuration.md` and the seed by tests. A local layer `.agents/quenching.local.json` (kept out of git through `.git/info/exclude`) applies leaf by leaf by scope: `machine` wins, `either` fills gaps, `project` is ignored and flagged; `show --effective` names the `local` source. `cq config set|unset --layer project|local` is the only writer. The OpenCode vitrine (pin 2.3.0) adds a **quenching** Settings page with task categories, tooltips, layer badges, restore default and search; it registers only on hosts with `SettingsLayout`. The gate typechecks the vitrine, `SKIPPED` without `node_modules`.

Left out: adopting existing worktrees as slots (targets cut fresh slots and retire the old ones, per D7 B); editing structured catalogs from the page (they open in the editor); a slot-aware `/quenching-git cleanup` beyond the floor.
