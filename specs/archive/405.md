## Problem

Pedido do humano em 2026-11-24: rodar `/quenching-specs autopilot --until-dry` em máquinas diferentes sobre o mesmo repositório sem que duas peguem a mesma spec, e sem que a reserva trave uma spec quando ninguém a desmarca, ou por eventos que não deveriam segurá-la (ex.: um humano desenvolve a spec e pede a outra pessoa para executar).

Hoje nada marca uma spec como tomada de forma que outra máquina veja (mapa do scout, 2026-11-24): os records de `specs/schema.py:53-90` não têm dono nem validade; `executing` é derivado de uma tarefa marcada (`schema.py:144-146`), então a spec só parece tomada depois da primeira tarefa; `branch` é write-once (`schema.py:67`); o único teste de "tomada em outro lugar" é `plan/<id>` em outro `git worktree list` (`execute.md:62-73`) e o lock de slot (`git/slots.py:34,90-104`), ambos locais à máquina; as escritas do store git ficam locais até um sync (`specs/backends/git.py:862-872`); o passo 2 do autopilot (`autopilot.md:129-141`) e `cq specs next` não consultam dono nenhum.

**Consequência:** duas máquinas no mesmo épico ou na mesma fila constroem a mesma spec em paralelo, gastam o dobro de tokens e abrem dois PRs conflitantes; a primeira a mergear torna o trabalho da outra lixo.

## Proposal

Uma reserva (lease) por spec, guardada no `origin` como a ref `refs/quenching/claims/<id>`, criada e trocada por push com `--force-with-lease` (comparação e troca no servidor — provado no `origin` deste repositório em 2026-11-24: criar com `<ref>:` vazio é recusado `stale info` quando a ref existe, e trocar com o sha esperado passa). O commit da ref carrega o lease em JSON: `spec`, `holder` (id de máquina aleatório em `git config quenching.machineId` + id de sessão; nunca hostname nem email, que iriam para o remoto), `label` opcional, `stage: execute`, `acquired`, `renewed`, `expires` (UTC). Verbo novo `cq specs claim acquire|renew|release|list|take <id>` (`--json`, exit 0 ok · 1 tomada por outro · 2 recusa), puro git, sem depender do backend de specs. Validade padrão de 45 min, `shared.autonomy.claimMinutes` a substitui; tolerância de relógio de 2 min antes de tratar um lease como expirado.

## Out of Scope

- A leitura das reservas em `cq specs next`, `list --lean`, `status --json` e o check `claims` do `cq git preflight` — spec 406.
- A ligação no fluxo (execute adquire/renova, conclude/runner/autopilot liberam, reconcile apaga leases de specs terminais), os grants `Bash(cq specs claim:*)`, a linha `claimMinutes` em `plugin-configuration.md`, o padrão em `/docs/standards/` e o glossário — spec 407.
- A linha do catálogo MCP (`quenching/mcp/catalog.py`) para `specs claim`: só é exigida quando um corpo cita o verbo, o que acontece em 407.

## Validation

Dois clones do mesmo bare remoto disputam `acquire` da mesma spec em paralelo (processos): exatamente um vence, o outro sai 1 com o holder vencedor. `renew` por quem não é o holder sai 1. Lease expirado é tomado por outro com troca do sha esperado; dois tomadores do mesmo lease expirado: um vence. `release` só apaga com o sha esperado. Spec terminal (done/abandoned/merged) tem lease ignorado. Sem remoto (NO-REMOTE), a ref é local e o verbo diz `scope: local`.

## Design

### Assumptions

- O lease é um commit sem pai cuja árvore tem um único `lease.json`; autor e committer são fixos (`quenching <quenching@localhost>`) para que nenhuma identidade pessoal vá ao remoto — depende `## Tasks` 1.2.
- "Meu" é o mesmo `machineId`, não o mesmo holder inteiro: um runner re-spawnado na mesma máquina tem outra sessão e precisa renovar/liberar o lease da anterior; dentro da máquina o lock de slot já serializa — depende `## Tasks` 1.2.
- `machineId` é gravado no config local do clone (`git config quenching.machineId`), compartilhado por todos os worktrees do clone, nunca no global — depende `## Tasks` 1.2.

### Protocolo (decidido no épico 404, aplicado aqui)

- Ref `refs/quenching/claims/<id>` no `origin`; leitura via `git ls-remote` + `git fetch origin +<ref>:refs/quenching/remote-claims/<id>` (o mesmo espaço que 406 lê).
- `acquire`: ausente → push com `--force-with-lease=<ref>:` (exige ausência); presente e meu → renova; presente e expirado (agora > `expires` + 2 min) ou spec terminal → troca com o sha esperado; vivo de outro → exit 1 com `holder`, `label`, `expires`.
- `renew`: só o dono; outro ou ausente → exit 1. `release`: só o dono, apaga com o sha esperado; ausente → exit 0 `released: false`. `take`: troca um lease vivo de outro com o sha esperado e devolve `taken` (o holder anterior) — uso humano, a regra de quem pode chamar é de 407.
- `list`: todos os leases com `live`, `mine`, `expired`, `terminal`.
- CAS perdido (push recusado `stale info`/`fetch first`/rejected) → exit 1 com o lease vencedor relido.
- Sem `origin` (NO-REMOTE): a mesma ref, local, por `git update-ref <ref> <new> <old>`; o payload diz `scope: local`.
- Spec terminal = fase `archive`, ou record `outcome` ou `merge` presente, lido pelo backend de specs na camada do comando; backend que não abre → não terminal. O módulo `claims.py` não importa o backend.
- Saída: `--json`, exit 0 ok · 1 tomada por outro / CAS perdido · 2 recusa (id inválido, git falhou).

## Alternatives Considered

- Record `claim` no store de specs — descartado no épico 404: escrita local até o sync, CAS só no backend git, conflito de documento inteiro.
- `assignee` — descartado no épico 404: campo humano, sem validade e sem CAS no GitHub.
- Holder exato (máquina + sessão) como dono — descartado: um re-spawn do runner na mesma máquina ficaria preso no próprio lease até expirar.

## Open Decisions

- none — o protocolo foi decidido no `## Design` do épico 404 e as escolhas restantes estão em `### Assumptions`.

## Risks

- Relógios divergentes entre máquinas: mitigado pela tolerância de 2 min e pela validade de 45 min.
- Um push recusado por motivo que não é CAS (rede, permissão) lido como "tomada por outro": o verbo distingue a recusa de lease (exit 1) de falha de git (exit 2, mensagem do git citada).
- O GitHub poderia recusar refs fora de `heads/tags` no futuro: o épico provou que aceita em 2026-11-24; uma recusa sai exit 2, nunca uma reserva silenciosamente ausente.
