## Problem

Achado pelo autopilot 2026-11-21 rodada 8 (scout read-only sobre origin/main 0574813c1), reproduzido em repositório descartável.

`quenching/assets/hooks/warn-git-add-all.py:31` (`\s-n\b` não casa `-nm`), `:89`, `:38`, `:70`. Reprodução (JSON do evento ao hook): `git commit -nm "x"` → `{}`; `git --no-pager commit -n -m x` → `{}`; `git --git-dir=.git add -A` → `{}`; `git -ccore.hooksPath=/dev/null commit -m x` → `{}`; `git commit -n -m x` avisa.

Por que é do humano: alarga o que um hook instalado detecta (continua só aviso).

## Proposal

- `git commit -nm "x"` and other short clusters carrying `n` (`-anm`) are flagged as a hook bypass, while `-mn` (message `n`) stays silent.
- Global options other than `-C`/`-c` before the subcommand (`--no-pager`, `--git-dir=…`, `--work-tree`, `-P`, …) no longer hide `git add -A` or `commit -n` from the hook.
- `-ccore.hooksPath=…` (attached) and `--config-env=core.hooksPath=…` are flagged like `-c core.hooksPath=…`.
- The hook stays warn-only: no block, no new grant, hook entry or CI step.

## Out of Scope

- Blocking instead of warning — the hook is not a security boundary (module docstring).
- Detecting `git add -fA`-style clusters or hook paths set through variables, aliases or `git config` — the docstring already declares them unseen.

## Impact

### Product code this spec expects to touch

- `quenching/assets/hooks/warn-git-add-all.py` — the parser of global options and commit short clusters
- `quenching/tests/test_hook_warn_git_add_all.py` — the new forms and their lookalikes

## Validation

- `python3 -m pytest -q -p no:cacheprovider quenching/tests/test_hook_warn_git_add_all.py` passes, including every form of the Problem section and the silent lookalikes (`git commit -mn`, `git --no-pager log -n 3`).

## Design

- The parser skips every global option before the subcommand: those taking a separate value (`-C -c --git-dir --work-tree --namespace --super-prefix --config-env`) consume two words, every other `-x`/`--x` one; `-c`/`--config-env` values are collected to test for `core.hooksPath=`.
- A commit short cluster is scanned letter by letter: `n` is the bypass, and a value-taking letter (`mCcFtuS`) ends the cluster, so `-mn` is a message. The value of `-m`/`-F`/… is skipped when it is the next word.
- The regex fast path widens to `\s-[A-Za-z]*n`; it only pre-filters and a hit is confirmed on the parsed command, so lookalikes stay silent. Only an unparseable command keeps the regex verdict.
- Epic 559 `## Design` ("2269 entra") authorizes this: the hook detects more forms (narrowing), nothing else changes.

## Alternatives Considered

- Moving the check to the git hooks themselves: rejected, it cannot see the command a bypass skips.

## Open Decisions

- none — the forms are enumerated in the Problem and each is a test.

## Risks

- A wider regex raises false positives only on commands that do not tokenize; ACCEPTED — the hook only warns.
