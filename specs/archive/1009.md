## Problem

`cq specs record <id> merge --set subject="Merge pull request #1008 from holetz/holetz/zensical"` grava o valor sem quoting num inline mapping, então o `#` abre um comentário YAML e o record volta truncado como `{strategy: merge-commit, subject: Merge pull request` — medido na spec 1003, cujo `merge:` ficou permanentemente corrompido porque o record é write-once e a re-gravação é (corretamente) recusada. O subject padrão de um merge de PR no GitHub é sempre `Merge pull request #<n> from <branch>`, então todo merge por PR nesse backend grava um record quebrado, e o `git log --grep` que o record deveria resolver passa a apontar para uma string que nenhum commit tem.

**Precedente na mesma classe:** a spec 825 (`skills.py silently truncates a description at the first '#'`, arquivada) resolveu exatamente este defeito noutro ponto do código. Vale ler o que ela fez antes de decidir a forma aqui — a correção pode ser a mesma, e o fato de a classe reaparecer noutro escritor sugere que o quoting deveria viver no serializador, não em cada chamador.

## Outcome

- Abandonada a pedido do responsável: esta spec não será construída e nenhuma de suas propostas ou tasks foi adotada.
