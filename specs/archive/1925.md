## Problem

Relatado pelo orchestrator do épico 1914 em 2026-10-17, após a 1879 (#1922): quando o guarda de git de `cq codex implement` acusa violação (exit 2), o que o Codex escreveu fora do `files:` continua na worktree, e o `implement` seguinte recusa com `codex-tree-dirty`, travando o executor no resto da execução sem dizer o que fazer. A regra proposta é parar a tarefa em `needs-human` nomeando os caminhos sujos, já que o Claude não pode limpar com `reset`/`stash` (proibidos) nem descartar o que não declarou.

## Proposal

- `cq codex implement`, on `codex-tree-dirty`, answers with a message that names every dirty path and states the way out: stop the task as `needs-human` listing those paths, because Claude may not clean them (`reset`, `stash`, `checkout` are forbidden) and `files:` never declared them.
- `cq codex implement`, on `codex-git-guard` with paths outside `files:`, states the same way out in its `message`, so the next `implement` is never the first place the human learns the tree is stuck.
- The `codex-tree-dirty` and `codex-git-guard` codes, exit codes and payload keys stay as they are.

## Out of Scope

- Changing how the executor or the orchestrator handle `needs-human` (the reference `execution-delegation.md`, the agents): the epic keeps the scope in `codex/implement.py`; ruled out because the refusal text is enough for the existing `needs-human` route to carry the paths.
- Having `implement` clean the tree itself: it would discard what `files:` never declared, which is the human's call.
- Widening any grant or executing surface, or touching the autonomous protocol.

## Design

- Rule: a refusal that leaves the executor stuck names the paths and the way out in the same message. The way out is the existing `needs-human` route; this spec adds only text, in the one module that already emits both codes.
- The way-out text is one module constant, used by the `codex-tree-dirty` refusal and by the `codex-git-guard` message when `outside` is non-empty, so both read the same.
- Assumption: the orchestrator already surfaces a refusal `message` verbatim in its `needs-human` note; if it does not, that is a follow-up outside this scope.
