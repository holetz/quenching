## Problem

`cq git worktree add --spec` recusa um branch que segue a convenção declarada: com `branchName: "feat/<ticket>-<handle-kebab>."` (o exemplo de `conventions.md:24`), `cq git worktree add --path ../wt --branch feat/PROJ-77-fixture --base main --spec 1 --json` sai exit 2 `git-worktree-spec-head-mismatch` e não cria a worktree; sem `--spec` sai 0, e `cq specs record 1 branch --set …` também (`/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review15/f2`). Onde: `plugins/quenching/assets/bin/quenching/git/worktree.py:155` reaproveita `_spec_vs_head`, que sem `branch.work` exige o nome `(?:.+/)?<id>-` (`plugins/quenching/assets/bin/quenching/git/pull.py:203`); `plugins/quenching/commands/git/branch.md:81-83` manda passar `--spec`. Consequência: num alvo cuja convenção não começa com `<id>-`, o passo `branch` para e o run autônomo morre antes da worktree. Direção: com `--spec`, só exigir que a spec exista e não tenha `branch.work` diferente.

Origem: item C1 (média, regressão da 1424) da fila da rodada 7 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round7-queue.md`), da revisão de correção opus da rodada 6 (épico 1418).

## Proposal

- `cq git worktree add --spec <id>` cuts the worktree for a branch whose name follows the declared convention even when it does not start with `<id>-`, as long as the spec exists and its `branch.work` record, if any, names that branch.
- A spec whose `branch.work` names a different branch still refuses `git-worktree-spec-head-mismatch`, and an unknown spec still refuses `git-worktree-spec-unknown`.
- `cq git pr record` and `cq git pr create` keep the name-carries-the-id rule exactly as it is.

## Out of Scope

- Changing the `pr` verbs' ownership rule: a PR is opened after the branch record exists, so the name fallback stays there.
- Rewriting `/quenching:git:branch` step 4: it already passes `--spec`, and the verb now accepts it.
- Making `branch.work` mandatory before `worktree add`: the verb itself stamps it after the cut.

## Design

- Rule: `--spec` on `worktree add` proves that the spec exists and that no other branch is recorded as its `branch.work`; the branch name carries no proof, because the verb stamps the record only after the cut and the convention (`conventions.md`) does not require the id in the name.
- Shape: `_spec_vs_head(spec, head, *, by_name=True)`; with `by_name=False` the no-record case is owned. `pr` callers keep the default. Alternative of a second function was rejected: it duplicates the spec lookup.

## Alternatives Considered

- Require the convention to start with `<id>-`: rejected, it contradicts the declared `branchName` examples.
- Drop `--spec` from `/quenching:git:branch`: rejected, it loses the atomic `branch` stamp the 1424 spec introduced.

## Risks

- A typo in `--branch` is no longer caught by the id check when no record exists. ACCEPTED: the verb stamps `branch.work` with exactly the name it cut, and later `pr` verbs still check ownership.
