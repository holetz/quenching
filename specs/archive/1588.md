## Problem

Encontrado pelo mapa da rodada 11 do autopilot (2026-10-12) e reproduzido pelo condutor em `main` 0fac8801. Num repo
descartável com `.github/workflows/ci.yml` que tem `on:\n  - push` e um job `test`, `cq delivery doctor --json` emite
`delivery-trigger-unreachable`: "workflow does not expose a trigger-to-job path". `delivery/inventory.py:295-296` só
coleta mapeamentos `_CHILD`, então o gatilho em forma de lista (`on:\n  - push` no GitHub, `trigger:\n- main`, a forma
usual do Azure) vira `()`. No sentido oposto, `trigger: none` vira `("none",)` e conta como gatilho.

Consequência: um falso "o workflow não tem caminho do gatilho ao job" em pipelines válidas, e um pipeline desligado
contado como acionável. A correção aceita linhas de lista no bloco e trata `none` como ausência de gatilho.

## Proposal

- `cq delivery doctor` reads a trigger written as a list (`on:\n  - push`, `trigger:\n- main`) as a trigger, so a valid pipeline no longer raises `delivery-trigger-unreachable`.
- `trigger: none` (inline, or `- none` in a list) reads as no trigger, so a disabled pipeline is no longer counted as triggerable.
- The mapping form (`on:\n  push:`) and the inline forms keep today's result.

## Out of Scope

- GitLab `workflow:`/`rules:` blocks: their `- if:` items are conditions, not triggers, and keep the mapping-only read.
- Judging whether a trigger's branches or paths filter matches anything.

- A repo with `.github/workflows/ci.yml` having `on:\n  - push` and a `test` job gets no `delivery-trigger-unreachable`; one with `trigger: none` gets it.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- `_triggers` keeps the mapping children when present. Only when the block has none, it falls back to list items (`- value`, any indent), because nested `branches:` lists sit below a mapping child and must not count as triggers.
- The list fallback does not run for `gitlab-ci`, whose `rules:` items are conditions.
- A case-insensitive `none` is dropped from the result in every form (inline scalar, inline list, list item), so `trigger: none` yields `()`.
- Binding: the conductor's decision in epic 1590 (list triggers accepted; `trigger: none` is no trigger).

## Alternatives Considered

- Parse the YAML with a library: rejected, the inventory is deliberately a static line reader with no dependency.

## Open Decisions

- none — the epic's Design settled both directions.

## Risks

- A list item inside a nested block counted as a trigger: mitigated by the fallback running only when no mapping child exists.
- ACCEPTED — exotic YAML (flow lists across lines) stays unread, as today.
