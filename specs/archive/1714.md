## Problem

`cq knowledge nav --write` emits invalid TOML for a title containing quotes; `--check` then reports current. Independent verification in `../resume-map-verify.json`, item 4, at 719ca3e5 used `docs/how-to/index.md` with `title: Guia "avançado"` and a TOML `nav = []` block. Write exited 0 and emitted `{ "Guia "avançado" = [`. `tomllib` raised `TOMLDecodeError: Expected '=' after a key` at line 5, column 12; check reported current (exit 0).

Cause: `plugins/quenching/assets/bin/quenching/knowledge/nav.py:147,150` interpolate titles/paths without escaping; the kept-title regex also misses escaped quotes. Consequence: the Zensical build fails while the navigation check is green.

Scope: escape backslashes and quotes in emitted TOML strings and recognize the escaped form when preserving titles. Files: `plugins/quenching/assets/bin/quenching/knowledge/nav.py` and `plugins/quenching/tests/test_knowledge_site_source.py`. Preserve idempotence. The absent-nav case is intentional (`site-nav-absent` in `commands/knowledge/documentation/build.md:125`, replacement-only behavior at `nav.py:171-175`) and is excluded.

Acceptance: titles containing quotes and backslashes produce TOML that `tomllib` loads with the original titles; a second write changes nothing and check reports current. The regression fails on the base. `python3 -m unittest discover -s plugins/quenching/tests -p test_knowledge_site_source.py` and `bash scripts/verify_repo.sh` exit 0. S3 precedes S5 as a conservative knowledge-front sequence.

## Proposal

- Titles and paths emitted by `render_nav` are TOML basic strings with `\` and `"` escaped, so `tomllib` loads the written config with the original titles.
- `kept_titles` recognizes the escaped form and returns the unescaped title, so a preserved title is re-emitted unchanged.
- A second `--write` changes nothing and `--check` reports current.

## Out of Scope

- The absent-nav case (`site-nav-absent`, replacement-only behavior in `replace_nav`): intentional, excluded.
- Titles containing `[` or `]` in `replace_nav`'s bracket counting: not part of this report; parked as a discovery if confirmed.

## Design

- Decision: one `_toml_str` helper escapes `\` first, then `"`, and is used for both section titles and page paths; `kept_titles` uses a regex matching `(?:[^"\\]|\\.)+` and unescapes with the inverse mapping. Alternative: serialize via a TOML library — rejected, the file is a human's and is edited in place (`replace_nav` docstring).
- Durable rule: every string the generator interpolates into TOML passes through the escaper, and every string it reads back passes through the inverse.
- Binding contracts: the absent-nav behavior and the bracket-counted in-place replacement stay as they are.

## Alternatives Considered

- Refuse (exit non-zero) on titles with quotes instead of escaping: rejected, a legitimate title would block the build.

## Open Decisions

- none — the escape set (backslash and double quote) is what the TOML basic string requires for printable titles; control characters are not produced by `derive_title` from single-line headings.

## Risks

- Existing configs with an unescaped-but-valid title stay identical, since escaping is the identity without `\` or `"`. Mitigated by the idempotence test.
- A title with a newline would still be invalid TOML: ACCEPTED — titles are single-line front matter values.
