## Problem

Reproduzido pela revisão de correção do épico 1554 (2026-10-11), em `main` 71f8f356, no detector de teste movido
de `plugins/quenching/assets/bin/quenching/git/audit.py` (chamando `_lowered` direto):

1. **(média) Um teste movido para fora da pasta que o gate descobre passa sem achado.**
   `plugins/q/tests/test_m.py` → `plugins/q/attic/test_m.py` (ou → `docs/test_m.py`), com o mesmo conteúdo, dá `[]`,
   porque o `TEST_PATH` aceita como destino qualquer arquivo `test_*` (`audit.py:688-695`). Como o gate roda
   `unittest discover -s plugins/quenching/tests` (`scripts/verify_repo.sh:34,42`), o teste sai do gate em silêncio.
2. **(baixa) Renomear um teste dentro de `tests/`, com o mesmo conteúdo, dá falso positivo.**
   `tests/test_m.py` → `tests/test_n.py` dá `test-deleted fail`, porque o pareamento exige o mesmo nome de arquivo.
   Consequência: um refactor comum para a fila autônoma com `needs-human`.
3. **(baixa) O pareamento destino↔deleção é guloso.** Apagar `tests/a/test_x.py` (1 assert) e `tests/b/test_x.py`
   (3), e adicionar `tests/c/test_x.py` (3) e `tests/d/test_x.py` (1), dá `tests/d/test_x.py fail test-lost-asserts`:
   o "a" consome o "c" e o "b" fica sem par (`audit.py:693`).

O condutor descartou, como evasão deliberada (o audit não é sandbox): asserts falsos em docstring ou string, e
`exit 0` prefixado no gate. Descartou também, por estar latente hoje, o arquivo não-teste sob `tests/` casado pelo
regex cru.

## Proposal

- A test deleted from the gate's discovery directory whose only same-content target sits outside a `tests`-style directory (`attic/`, `docs/`) is reported `test-deleted`.
- A test renamed inside `tests/` with the same content is accepted, no longer requiring the same file name.
- The deletion-to-target pairing is one-to-one and optimal (no greedy consumption), so reordering never yields a false `test-lost-asserts`.

## Out of Scope

- Asserts faked in docstrings or strings, and an `exit 0` prefixed to the gate: deliberate evasion; the audit is no sandbox (epic 1560 decision).
- A non-test file under `tests/` matched by the raw regex: latent today.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/git/audit.py` — `_lowered` moved-test pairing
- `plugins/quenching/tests/test_git.py` — regression tests

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p 'test_git.py'` exits 0, including the three new tests.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Targets are only added files under a `tests?|__tests__` directory, which is what the gate discovers; a target elsewhere never absolves a deletion.
- Pairing ignores file names: a bipartite matching (augmenting paths) assigns each deleted test one target holding at least its asserts.
- An unmatched deletion with an unclaimed same-name target under tests/ is `test-lost-asserts`; otherwise `test-deleted`.
- The reader mirror does not carry audit.py, so no mirror changes.

## Alternatives Considered

- Keep greedy pairing sorted by assert count: rejected, still order-fragile; matching is as small.

## Open Decisions

- none — the epic's Design settles scope.

## Risks

- A rename into a different `tests` directory of a different test with more asserts could absolve a deletion: ACCEPTED — the audit measures asserts, not intent.
