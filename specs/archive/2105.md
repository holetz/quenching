## Problem

A 2046 mapeou todo `Bash(cq …)` da fonte para `"cq *": allow` (`scripts/sync_opencode_plugin.py:181-182`). Com isso, os agentes OpenCode que são só de leitura (reviewer, verifier, scout) passaram a rodar sem perguntar os verbos de escrita do `cq`: `cq git push`, `cq git pr merge`, `cq specs promote` e `cq specs record`. A revisão da rodada 5 achou isso em 2026-10-25.

O OpenCode checa cada subcomando separadamente, porque `packages/core/src/shell/parse.ts` percorre os nós `command` do tree-sitter. Por isso o padrão por prefixo é seguro contra encadeamento com `;`, `&&` e `$(…)`.

**Decisão do humano (2026-10-25): por agente, como na fonte.** Cada `Bash(cq <verbos>:*)` do `tools:` de um agente fonte vira `"cq <verbos> *": allow` no agente OpenCode correspondente, e o resto fica em `"*": ask`. Exemplo: o reviewer recebe `"cq git history *": allow` e nada mais. Um agente fonte sem `tools:` escopado, ou com `Bash` inteiro, mantém o que a 2046 gerou. O padrão `surface-translation.md` registra a regra no lugar da exceção `cq *`.

Done when: o gerador emite os padrões por agente, um teste trava os seis agentes OpenCode contra os `tools:` da fonte, `surface-translation.md` foi atualizado, os espelhos são regenerados e o gate passa. Essa spec muda grants, com a autorização acima.

## Proposal

- Each scoped `Bash(cq <verbs>:*)` in a source agent's `tools:` becomes one `"cq <verbs> *": allow` pattern in the matching OpenCode agent, in source order, followed by `"*": ask`; nothing else is allowed.
- A source agent with unrestricted `Bash` keeps `bash: allow`; one with `Bash(...)` grants and no `cq` keeps `bash: ask`; no `Bash` keeps `bash: deny` (all as generated today).
- The reviewer carries `"cq git history *": allow` and no other `cq` pattern, and the read-only agents (verifier, scout) lose `cq git push`, `cq git pr merge`, `cq specs promote` and `cq specs record` from their silent grants.
- A test locks every OpenCode agent's `bash` map against its source `tools:`, so a new or widened `cq` grant fails the gate until the source says so.
- `surface-translation.md` records the per-agent rule in place of the `cq *` exception, and the generated README describes the same rule.
- The generated OpenCode tree is regenerated and the repository gate passes.

## Out of Scope

- Per-command or session-level permissions (`opencode.json` snippet in the README keeps `"cq *": allow`): commands carry no permission of their own and the decision of 2026-10-25 covers agents only.
- Mapping non-`cq` grants (`git ls-files`, `gh pr view`, `bash scripts/verify_repo.sh`): stays `"*": ask`, a human decision.
- The rule order inside the emitted map (whether OpenCode needs the catch-all first): parked as a discovery, not changed here.
- The Codex and Claude mirrors: they do not change.

## Design

### Decisions

- A source grant `Bash(cq a b:*)` maps to the pattern `cq a b *`, the verbs verbatim; OpenCode checks each parsed command node, so a prefix pattern cannot be chained past with `;`, `&&` or `$(...)`. `Bash(cq:*)` (all of `cq`) maps to `cq *`, which is what the source grants.
- Patterns keep source order and are deduplicated; the catch-all `"*": ask` stays last as today.
- The lock test reads each source agent's `tools:` and derives the expected map independently of `permissions()` (parsing `Bash(cq ...:*)` itself), so the generator cannot agree with itself by construction.

## Alternatives Considered

- Keep `"cq *": allow` and accept the write verbs: rejected, it gives read-only agents `cq git push` without asking.
- Drop `cq` allows entirely (all `ask`): rejected, the OpenCode agents could no longer run their own read verbs unattended.
- Allow only a fixed list of read verbs in the generator: rejected, the decision is to mirror the source, not to invent a second list.

## Open Decisions

- Whether the catch-all `"*": ask` must come first in the map for OpenCode's evaluation order: decided by reading the OpenCode permission docs or source in a later spec; this spec keeps today's order and parks it as a discovery.

## Risks

- A source verb with an unusual shape (a grant like `Bash(cq git pr create:*)`) maps wrongly: the lock test compares every agent against an independent parse, which fails first.
- The grants change for six agents: ACCEPTED, authorized by the human decision of 2026-10-25; the change only narrows what `"cq *"` allowed.
