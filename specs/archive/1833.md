## Problem

**A descoberta de worktrees da 1807 (PR #1826) erra três layouts reais.** Reproduzido em 2026-10-16 (revisão cruzada do épico 1803):

- **`--separate-git-dir`** (`plugins/quenching/assets/bin/quenching/git/worktrees.py:62`): `git init --separate-git-dir=<d>/meta/store.git <d>/repo` → `list_worktrees('<d>/repo')` = `[{'path': '<d>/meta', 'branch': 'master', 'main': True}]`; esperado `<d>/repo`. Usa `dirname(common)`.
- **Ponteiros relativos** (`worktrees.py:76`): no formato que o git ≥ 2.48 grava com `--relative-paths` (`.git/worktrees/w/gitdir` = `../../../../w/.git`), a worktree some com cwd `/` e sai com caminho relativo com cwd no diretório administrativo — `isdir(dirname(pointer))` é resolvido contra o cwd do processo, não contra o diretório que contém `gitdir`. (git local 2.43 não tem a opção; formato simulado à mão.)
- **cwd em subdiretório** (`worktrees.py:39-51`, usado por `session/commands/live.py:21`): `_common_dir` só procura `<cwd>/.git` e não sobe aos pais; `cq components session live --cwd <repo>/plugins` → 0 sessões, com o repo na raiz → 1.

**Consequência.** O painel de sessões e o menu multi-projeto (specs 1812 e 1814) atribuem sessões ao projeto errado ou não acham worktrees.

**Validação.** Testes em repositórios temporários para os três layouts (o relativo por fixture escrita à mão); `list_worktrees` segue batendo com `git worktree list --porcelain` no repo real. Gate exit 0. Precede a 1812.

## Proposal

- `list_worktrees` returns the real main checkout path for a `--separate-git-dir` layout (`<d>/repo`, not `<d>/meta`).
- A linked worktree whose `gitdir` pointer is relative resolves against the directory holding that `gitdir` file, independent of the process cwd.
- A root that is a subdirectory of a repository (for example `<repo>/plugins`) is walked up to the enclosing checkout, so `cq components session live --cwd <repo>/plugins` sees the same sessions as the root.
- `list_worktrees` keeps agreeing with `git worktree list --porcelain` on a regular repository, with no process opened.

## Out of Scope

- Changing `session/commands/live.py` or the portal: the fix lives in the discovery module, and callers inherit it.
- Reporting orphaned or prunable worktrees: that stays `cq git stale`'s.
- Naming the main checkout when a linked worktree of a separate-git-dir repository is the only root and git recorded no `core.worktree`: no file says where it is, so the main row is omitted rather than invented.

## Design

- **Walk up to the checkout.** `_common_dir` starts at the root and climbs parents until a `.git` entry (directory or file) is found; none found returns empty. Rule: a root is resolved to its enclosing checkout before anything else.
- **Main path is not `dirname(common)`.** The main checkout is `dirname(common)` only when the common dir is named `.git`. Otherwise it is the `core.worktree` value in the common `config`, resolved against the common dir when relative; otherwise, when discovery started from a checkout whose `.git` file points at a commondir-less gitdir (the main of a separate-git-dir repo), that checkout; otherwise the main row is omitted. Git 2.43 does not write `core.worktree` for `--separate-git-dir`, hence the start-checkout fallback.
- **Pointers resolve against their own file.** A relative content of `worktrees/<name>/gitdir` is joined to that entry directory and normalized before `dirname` and `isdir`. Rule: a relative path in a git file is relative to the file, never to the cwd.
- Contracts: no process is opened (the existing test mocks `subprocess`), output shape `[{path, branch, main}]` unchanged, main first, linked sorted by path.

## Alternatives Considered

- Shelling out to `git worktree list --porcelain`: rejected, the module exists so a portal GET never spawns `git`.
- Reading `core.worktree` only: rejected, git 2.43 does not write it for `--separate-git-dir`.

## Open Decisions

- none — the omitted main row for a linked-only root without `core.worktree` is settled in Out of Scope.

## Risks

- A repository with a linked worktree and a separate git dir loses its main row when started from the linked one. ACCEPTED — no file records the path; the row is omitted rather than wrong.
- Walking up could attribute a subdirectory of an unrelated nested repository to the wrong parent. Mitigation: the nearest `.git` wins, like git.

## Outcome

Entregue: a descoberta de worktrees (`worktrees.py`) agora sobe do subdiretório até o checkout que contém `.git` (`_checkout_root`), devolve o caminho real do checkout principal em `--separate-git-dir` (`_main_path`, via pai de `.git`, `core.worktree` ou o checkout de partida) e resolve ponteiros `gitdir` relativos contra o próprio arquivo. Testes cobrem `<repo>/sub/dir`, `<d>/repo` e fixture relativa a partir de cwd `/` e do diretório administrativo; o espelho codex foi regenerado.
