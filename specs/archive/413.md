## Problem

Na spec 407 (2026-11-24, execute autônomo) o develop declarou o padrão novo `docs/standards/workflows/spec-claims.md` e a citação de `cq specs claim` em `autopilot.md`, mas nenhum `files:` nomeou `zensical.toml` (nav) nem `quenching/assets/bin/quenching/mcp/catalog.py`. Só o escopo afetado (`python3 -m scripts.toolchain.test --affected`) acusou: `test_surface_listings.py::test_zensical_nav_matches_every_published_markdown_document` (missing=['standards/workflows/spec-claims.md']) e `test_quenching_mcp_coverage.py::test_every_verb_the_skill_agent_and_reference_bodies_cite_has_a_tool` ('skills/quenching-specs/references/autopilot.md: cq specs claim list' …). Como `## Tasks` é append-only depois de `approved`, a correção virou duas tarefas novas (4.2 e 4.3), e as linhas do catálogo regeneram também o `tools:`/`permission:` dos agentes implantados, que nenhum `files:` previa.

Minimal fix proposed: em `specs-develop/artifacts.md` §`## Tasks` (ou §Execution metadata), listar os artefatos derivados de dois gatilhos — doc novo em `docs/` → `zensical.toml`; verbo `cq` novo citado em skill/reference/agent → `mcp/catalog.py` e os espelhos dos agentes.

**Insumos**

- `quenching/skills/quenching-specs/references/specs-develop/artifacts.md` §`## Tasks` §Execution metadata (fonte no checkout do quenching; chega aqui por `cq deploy`)
- `quenching/tests/test_surface_listings.py:159`, `quenching/tests/test_quenching_mcp_coverage.py:24`
- spec 407, tarefas 4.2 e 4.3; specs arquivadas da mesma família: 1901, 2233

## Proposal

- `artifacts.md` §Execution metadata declares two triggers whose derived artifacts a task must name in `files:`: a new published document under `docs/` brings `zensical.toml` (nav); a new `cq` verb cited in a skill, reference or agent body brings `quenching/assets/bin/quenching/mcp/catalog.py`, and the deployed agents' `tools:`/`permission:` mirrors the catalog regenerates.
- A develop pass that composes such a task therefore declares those files up front, so `## Tasks` (append-only after `approved`) never needs a corrective task.

## Out of Scope

- A validator that detects these triggers mechanically — ruled out: the affected-scope tests already catch the drift; this spec only moves the declaration to definition time.
- The `deploy --write` mirrors of a `quenching/` edit — already implicit in the verifier's scope check (§Declare the source, not the mirror); the 465 evidence on that is spec 467's, which follows on this file.

## Design

**Decision: the rule goes in §Execution metadata, beside `files:`'s other authoring rules** (the file the spec cited moved to `quenching/references/specs-develop/artifacts.md`). It is where the author already reads about what `files:` must hold; §`## Tasks` stays about shape.

**Rule, stated durably:** a derived artifact the deploy does not regenerate must be declared. Two such triggers exist: (1) a new document under `docs/` published by the site brings `zensical.toml`, whose nav test refuses an unlisted page; (2) a `cq` verb newly cited in a skill, reference or agent body brings `mcp/catalog.py`, whose coverage test refuses a verb with no tool. The agent mirrors the catalog rewrites follow the existing "source, not mirror" paragraph and are not listed.

**Binding:** `test_surface_listings.py` and `test_quenching_mcp_coverage.py` are the checks that enforce both triggers.
