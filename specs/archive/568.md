## Problem

O portal não aponta para quenching/README.md, docs/index.md, docs/standards/workflows/plugin-configuration.md nem o site (zensical.toml:14). Consequência: o portal não serve de ponto único de navegação. Proposta: aba Docs com links e o catálogo de comandos derivado das descrições das skills instaladas (lido do disco, somente leitura); servir o build do site é opcional e fica fora se exigir rota estática nova.

## Proposal

Uma rota `GET /api/docs` somente leitura e uma aba "Docs" no portal. A rota devolve (a) os links de navegação do repositório alvo — `quenching/README.md` (manual), `docs/index.md`, `docs/standards/workflows/plugin-configuration.md` e a `site_url` do `zensical.toml` — cada um com o caminho e se existe, e (b) o catálogo de comandos derivado das descrições (`description` do frontmatter) das skills instaladas, lidas do disco (`.claude/skills`, `.agents/skills`), com o nome, os fluxos e a descrição. A aba mostra esses links e o catálogo. O código novo mora em `specs/portal_docs.py`, `docs.js` e `docs.css`; `portal.py` e `app.js` ganham só o gancho.

## Out of Scope

- Servir o build do site ou os arquivos `.md` por uma rota estática nova: a spec o deixa fora se exigir rota estática; a aba mostra o caminho e, para o site, o link `http(s)` declarado.
- Qualquer endpoint de escrita ou edição de docs pelo portal (épico 559: só leitura; 569/570 são do épico 560).
- Mudar as descrições das skills ou o `zensical.toml`.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/specs/portal_docs.py` — novo: payload de `/api/docs`
- `quenching/assets/bin/quenching/specs/portal.py` — gancho `docs` em `_get`
- `quenching/assets/portal/docs.js`, `quenching/assets/portal/docs.css` — novos: a aba
- `quenching/assets/portal/app.js`, `quenching/assets/portal/index.html` — link, rota e script
- `quenching/tests/test_specs_portal.py`, `quenching/tests/test_portal_ui.py` — provas
- `docs/standards/architecture/specs-portal.md` — rota e aba

### Deployed surface regenerated

- `.agents/quenching/**` e `.agents/.quenching-deploy.json` — espelho gerado pelo `cq deploy --write`

## Validation

- `python3 -m pytest quenching/tests/test_specs_portal.py quenching/tests/test_portal_ui.py -q -p no:cacheprovider` passa.
- `GET /api/docs` devolve `ok`, `links[]` (rótulo, caminho, `exists`) e `commands[]` (nome, fluxos, descrição) lidos do disco do alvo; `POST` é recusado (`sp-portal-not-found`); sem token, 401.
- O JS da aba não usa `innerHTML`, `fetch(`, POST nem token, e o HTML segue sem script inline nem URL externa.

## Design

- `docs_payload(root)` lê só o disco: os quatro links fixos (existência por `Path.is_file()`; a `site_url` extraída do `zensical.toml` por regex, só se `http(s)`) e o catálogo de `SKILL.md` em `.claude/skills/*` e `.agents/skills/*`, deduplicado por nome, com `parse_frontmatter`. Os fluxos saem do prefixo da descrição ("Run one X flow: a, b."), vazio se a descrição não o segue.
- Rota GET-only sob o token e o Host de toda `/api`; nenhuma escrita, nenhum arquivo servido: a aba mostra caminhos relativos ao alvo, nunca conteúdo de arquivo arbitrário.
- Frontend em `docs.js` (script próprio, CSP `script-src 'self'`), `window.QuenchingDocs.view(ctx)`, sem `innerHTML`, sem token no cliente. O único `<a href>` externo é a `site_url`, com `rel="noopener noreferrer"`.

## Alternatives Considered

- Servir `README.md`/`docs/` por rota estática: rejeitado — rota nova e superfície de leitura de arquivos; a spec manda deixar fora.
- Ler o catálogo de `quenching/skills` da fonte: rejeitado — o pedido é o das skills instaladas no alvo.
- Tudo em `portal.py`/`app.js`: rejeitado pelo Design do 559.

## Open Decisions

- none — o épico 559 fixa somente leitura e módulo próprio; o site é opcional e entra só como link declarado.

## Risks

- Descrição de skill fora do padrão não rende fluxos: ACCEPTED — a aba mostra a descrição inteira e a lista de fluxos vazia.
- O teste que conta `<script>` e os assets do HTML muda para admitir `/docs.js` e `/docs.css`: ACCEPTED — a invariante (sem script inline, só assets locais) segue provada.
- Um `SKILL.md` malformado ou ilegível derruba a rota: MITIGATED — cada skill é lida sob `OSError`/`UnicodeDecodeError` e ignorada.
