## Problem

Per the official sub-agents docs (checked against Claude Code 2.1.296), the `Agent(type)` allowlist applies only to an agent run as main thread with `claude --agent`; in a subagent definition the type list is ignored. `plugins/quenching/agents/orchestrator.md:4` declares `tools: Agent(quenching:spec-runner, quenching:verifier, ...)` and `commands/specs/orchestrate.md` launches it as a subagent, so the orchestrator can spawn any type. Found by spec 1510. The remedy touches a grant (e.g. a `permissions.deny` or running it via `claude --agent`), hence human decision in epic 1481.

`docs/decisions/0007-native-claude-code-features.md:60-61` still states the opposite ("`orchestrator` restricts spawning with `Agent(quenching:spec-runner, ...)`"). It now contradicts `capabilities.md:130`. The conductor did not edit the ADR (it is a historical record); the decision on 1513 should say whether a new ADR supersedes it. Noted by the round-3 correctness review of the 2026-10-11 autopilot.
