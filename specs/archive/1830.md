## Problem

**O check `sk-reference-root` da 1805 (PR #1809) erra nos dois sentidos.** Reproduzido em 2026-10-16 na revisão cruzada do épico 1803 (opus e Codex), sobre a `main` 02b99c23:

- **Falso positivo com URL** (`plugins/quenching/assets/bin/quenching/components/commands/lint.py:798`): `reference_root_findings('[API](https://example.org/references/api.md)', base, {})` → `[('sk-reference-root', 'https://example.org/references/api.md')]`. O ramo `"/references/" in target` roda antes da exclusão de `http`.
- **Falso positivo em doc do usuário**: um `.claude/commands/foo.md` com `[the API](../../docs/references/api.md)` faz `cmd_lint(Namespace(path=None, json=True), <tmp>/.claude)` sair com rc 1 e erro `sk-reference-root` — o check vale para qualquer superfície, não só para as references do plugin.
- **Falso negativo com aspas** (`lint.py:778`): `reference_root_findings('cq components read "assets/references/a.md"', base, where)` → nenhum achado (com aspas simples também); sem aspas → `sk-reference-root`. A classe `[^\s`"'<>-]` exclui a aspa como primeiro caractere.

**Consequência.** O lint quebra (rc 1) superfícies `.claude/` legítimas de usuários, e a regressão que a 1805 deveria impedir (citação sem raiz do plugin, spec 1781) volta se vier entre aspas.

**Validação.** Testes para os três casos em `plugins/quenching/tests/test_components_lint.py`; o check só considera alvos locais que resolvem para `assets/references/**` do plugin; gate exit 0.

## Proposal

- `reference_root_findings` ignores any target with a URL scheme (`http:`, `https:`, `mailto:`, `//`), so `[API](https://example.org/references/api.md)` yields no finding.
- A local link whose path merely contains a `references/` directory (`../../docs/references/api.md`) is no finding; only a target naming `assets/references/` (or a bare path resolving into the plugin's reference tree) is judged.
- `cq components read "assets/references/a.md"` and the single-quoted form yield `sk-reference-root`, as the unquoted form already does.
- `plugins/quenching/tests/test_components_lint.py` covers the three cases and the generated mirrors of `lint.py` are regenerated.

## Out of Scope

- Redesigning the check to resolve targets against the filesystem when no reference tree is present: the existing tests rely on the no-tree behaviour, so a target naming `assets/references/` stays an error without a tree.
- Other lint checks and the `verify:` lint, owned by epic 1893.

## Validation

- `bash scripts/verify_repo.sh` exits 0.

## Design

- Rule: a target is judged only if it is local (no URL scheme) and names `assets/references/`; a generic `/references/` directory says nothing about the plugin.
- Rule: the quote is optional before a `components read` target, and never part of it.
- The bare-form branch (a path resolving into the reference tree) is unchanged.
- Evidence: the user-doc false positive came from the `"/references/" in target` clause alone; dropping it fixes the case without a new heuristic.

## Alternatives Considered

- Resolve every target against the filesystem and flag only those landing in the plugin's reference tree: rejected, it breaks the tests that run with no tree and widens the change.
- Skip the check when the surface is not the plugin: rejected, a `.claude/` surface can legitimately cite plugin references.

## Open Decisions

- none — the design is closed by the existing tests and the reported reproductions.

## Risks

- A user-surface link naming `assets/references/` outside the plugin still errors. ACCEPTED — it is indistinguishable from the real defect without a tree, and rare.
- Shares `lint.py` with epic 1893's work: merge origin/main before each commit.
