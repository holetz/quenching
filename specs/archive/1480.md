## Problem

`plugins/quenching/assets/references/components-command-new/capabilities.md` afirma fatos sobre o Claude Code sem citar a fonte oficial nem a versão em que cada fato vale (o arquivo tem 0 ocorrências de `https://`). Quando o Claude Code muda, ninguém sabe qual fato conferir nem contra o quê.

## Proposal

- Cada seção de `capabilities.md` que afirma um fato sobre o Claude Code cita a página oficial que o sustenta (`https://code.claude.com/docs/en/skills`, `.../sub-agents`, `.../hooks`).
- Onde a página oficial declara a versão mínima do fato (por exemplo `background` em v2.1.218), o arquivo a repete; onde não declara, o arquivo registra "conferido em 2026-10-11 contra Claude Code 2.1.296" e nunca inventa uma versão.
- O fato que a fonte oficial contradiz é corrigido no mesmo arquivo (`memory: true` → escopos `user`, `project` ou `local`).

## Out of Scope

- Revisar o mérito da doutrina de custo (tabela de onde cada byte pesa): é julgamento do repo, sem fonte oficial a citar.
- Citar fontes nos outros arquivos de `assets/references/`: spec própria, se valer.
- Editar `plugins/quenching-codex/**` ou `.agents/**`: o espelho Codex não existe mais.

## Impact

### Standards this spec will write into docs/standards/

- none — a spec só cita fontes em uma reference; nenhum standard novo.

### Product code this spec expects to touch

- `plugins/quenching/assets/references/components-command-new/capabilities.md` — o único arquivo editado.

## Validation

- `grep -c 'https://code.claude.com/docs/en/' plugins/quenching/assets/references/components-command-new/capabilities.md` imprime pelo menos 6 (hoje 0) e `grep -c 'memory: true'` imprime 0.
- `bash scripts/verify_repo.sh` sai com 0.

## Design

- Regra durável: cada fato sobre o Claude Code vale com fonte e versão; a linha `Fonte:` fica logo sob o título da seção, antes do corpo, para o `--sections` carregá-la junto.
- Versão: só a que a página oficial lê (lida em 2026-10-11: `background` exige v2.1.218; `omitClaudeMd` exige v2.1.271). Sem declaração, vale a data de conferência e a versão instalada (2.1.296). Alternativa de pesquisar o changelog por fato foi pesada e descartada: custo alto e a fonte oficial seria a mesma.
- Marcadores `<!-- rules -->` e `<!-- rationale -->` ficam onde estão; a linha de fonte entra antes do marcador.
- Mapa de dependências: `capabilities.md` é citado por `docs/standards/automation/{hooks,skills,agents}.md`, `README.md`, `docs/glossary.md` e pelos comandos `components/*/new.md`, `align.md` e `documentation/build.md`; só adicionamos linhas e corrigimos um valor, então nada quebra.

## Alternatives Considered

- Uma tabela única de fontes no fim do arquivo: perdida porque `cq components read --sections` carrega a seção sem o rodapé, e o fato chegaria sem fonte.
- Citar sem versão: perdida porque a queixa do Problem é justamente não saber contra o quê conferir.

## Open Decisions

- none — a versão por fato é decidida pela regra do Design (a da página, senão a data de conferência).

## Risks

- A página oficial muda e a citação envelhece: ACCEPTED — a data de conferência na linha de fonte é o sinal de que conferir de novo é a ação.
- `spawned-agents` não aparece como campo de frontmatter nas páginas lidas: não se afirma versão para ele, e fica como discovery para decisão separada.
