## Problem

Os templates de gênero não conseguem referenciar o logotipo e outros assets registrados na frente de design, obrigando caminhos manuais fora do sistema. O renderer deve resolver referências de assets apenas dentro de /.design/assets/ e produzir caminhos adequados a cada mídia.

## Proposal

- Resolve the asset.<path> placeholder against files below .design/assets/ for every supported medium.
- Emit a target-relative URL for HTML and a target-relative Typst path.
- Refuse traversal, absolute paths, directories, missing assets, and references outside the design asset root.

## Out of Scope

- Copying assets to output directories, optimizing images, changing SVG contents, or embedding every HTML asset as base64.
- Resolving arbitrary repository files or URLs from templates.
- Modifying DESIGN_COMPONENT_PROPERTIES.

## Impact

- plugins/quenching/assets/bin/quenching/design/genre.py — placeholder resolution and path safety.
- plugins/quenching/assets/bin/quenching/design/doctor.py — recognize asset placeholders as references.
- plugins/quenching/tests/test_design.py — nested asset, traversal, and media output tests.
- docs/standards/code/file-relative-path-resolution.md — paths resolve from named roots with assertions.
- docs/standards/architecture/design-front.md — assets remain under the portable design boundary.

## Validation

- A template containing {{asset.lockup.svg}} resolves to a usable relative HTML URL and a usable relative Typst path.
- A nested asset resolves identically from any output directory under the repository.
- ../, absolute, missing, and directory references refuse with a stable design error; an asset outside .design/assets/ is never opened.
- The existing orphan check treats a valid asset placeholder as a citation, and all prior design tests remain green.

## Design

- The placeholder grammar is {{asset.<path>}}, where <path> is a non-empty POSIX path relative to .design/assets/. Backslashes, absolute paths, empty components, and .. are refused.
- The resolver calls Path.resolve() and asserts the result remains under the resolved asset root before reading or formatting it. Symlink escapes are refused.
- HTML receives a URL-quoted relative path from the output file's parent to the asset. The first contract is a path and does not duplicate bytes.
- Typst receives a POSIX relative path from the generated .typ or temporary PDF source to the asset. The asset remains in place.
- Doctor's searchable sources include the raw placeholder path and the asset-relative path, so citation remains declarative and no renderer execution is needed.
- Dependency map (2026-08-30): genre.py owns placeholder parsing and root assertion → doctor.py consumes template text for orphan classification → test_design.py proves media and safety behavior; the manifest work in spec 1039 adds semantics without changing resolution.

## Alternatives Considered

- Allowing {{asset}} to read any repository path: rejected because it breaks the portable boundary and makes templates an arbitrary file reader.
- Copying every asset beside every output: rejected because it changes the output contract and duplicates licensed or binary assets.
- Embedding every file as a data URI: rejected because it inflates artifacts and is not valid for Typst.

## Open Decisions

- none — placeholder grammar, root boundary, path formatting, and refusal behavior are fixed.

## Risks

- Relative URLs depend on the output location; the renderer computes them from the actual target every time and tests nested targets.
- An asset may be licensed for a restricted use; the resolver only addresses the file and does not grant rights.
- A symlink can change after validation; the path is resolved immediately before formatting and no file contents are copied.
