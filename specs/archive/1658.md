## Problem

Branches created by spec workflows remain in target repositories after the work has finished, and one project accumulated about 150 branches that required manual intervention. The development should include an automatic cleanup flow or explicit guidance for removing these branches so repositories do not keep accumulating them.

## Proposal

- `cq git stale --json` classifies every local non-base branch: the ones that may be deleted stay in `staleBranches` (merged or gone, no open PR, not checked out in a worktree); the ones that must stay are listed in a new `keptBranches` list, each with its reasons (`open-pr`, `worktree`, `unmerged-commits`).
- A merged branch that carries `open-pr` or `worktree` leaves `staleBranches`, so `cq git prune` refuses it as not reported.
- `/quenching:git:cleanup` shows the kept branches with their reasons as information (never selectable), and `/quenching:specs:conclude` names `/quenching:git:cleanup` as the guidance for removing finished work branches after the handoff.
- No new deletion path: every removal still needs the human's confirmation through `cq git prune`.

## Out of Scope

- Automatic deletion of any branch or worktree: ruled out by the owner decision (guidance-first).
- Detecting "retained evidence" beyond a checked-out worktree (recorded task subjects of a squash-merged branch): deferred, parked in Discoveries.
- Remote branch classification: the `remoteBranches` list keeps its shape and behaviour.
- Changing `/quenching:git:merge` behaviour: its branch-deletion offer already stays a separate, informed offer.

## Design

- **Decision:** classification lives in `cq git stale` (deterministic, read-only), the one source `cq git prune` already re-reads; commands only present it. Rule: a report is facts, the command asks.
- **Open PR lookup** uses `gh pr list --state open --json headRefName` when `gh` exists and the repo has a remote; any failure reads as lookup unavailable and adds no `open-pr` reason (the report carries `prLookup: "unavailable"`). The `gh` call is isolated in one function so tests stub it.
- **Worktree reason:** a branch checked out in any registered worktree (from `git worktree list --porcelain`) is kept, because git would refuse the delete anyway.
- **Unmerged-commits:** a non-merged, non-gone local branch has commits not reachable from base; it is kept with that reason.
- **Compatibility:** `staleBranches` keeps its element shape; `keptBranches` is additive.

## Alternatives Considered

- **Automatic deletion at conclude/merge:** rejected by the owner decision; deleting a branch can orphan recorded task subjects.
- **A new command for classification:** rejected; `cq git stale` already is that report and `cleanup` already consumes it.

## Open Decisions

- Decidido em 2026-10-14 pelo autopilot, como owner delegado: **guidance-first**. A entrega é uma
  classificação determinística e somente leitura das branches e worktrees de trabalho de spec, que separa
  as **removíveis** (mergeadas na base, sem PR aberto, sem evidência retida) das **mantidas**, cada uma com
  o motivo (PR aberto, evidência retida, commits não mergeados). A oferta de limpeza que o conclude já faz
  (`plugins/quenching/commands/specs/conclude.md:348`, `plugins/quenching/assets/references/git/merge.md:65-105`)
  passa a usar essa classificação. Nenhuma deleção automática nova sem a confirmação do humano.

## Risks

- A `gh` lookup that fails silently could list a branch with an open PR as removable: mitigated because `cq git prune` still uses `branch -d`, which refuses an unmerged branch, and the report says `prLookup: "unavailable"`. ACCEPTED — merged branches with an open PR are rare.
- Listing all non-base local branches as kept could be noisy: mitigated by showing them compactly in cleanup as information.
