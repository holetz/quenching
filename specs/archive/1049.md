## Problem

`cq proof doctor` grades a verification surface and acts on nothing. Without an align, the front's
eleven codes are a report a human reads and closes by hand, and the front has no row in the
aligned-front column.

The convergence this front owes is unusually asymmetric, and that asymmetry is the whole difficulty.
Some findings close with an edit nobody needs to think about: registering a marker, deleting
`--maxfail=1` from `addopts`, writing a floor equal to what the suite already achieves. Others close
with an edit whose consequence is large and immediate — and one of them is a trap.

**Adding a source root to the measured surface changes the number everyone trusts.** On the measured
target, coverage reads 63% over `src/safra`. `bundle/` is the product: 1,772 modules, 124,085 lines,
unmeasured. Adding it is the correct fix for `pf-unmeasured-surface`, and the reported figure will
collapse — not because anything got worse, but because the question finally matches the repository.
If the align does that quietly, under the same OK that authorized registering three markers, it will
have handed somebody a red dashboard and no explanation. If it also sets the ratchet floor to the
new number in the same pass, it will have locked in a floor derived from a run nobody expected.

An align that cannot tell those two kinds of change apart should not be given a write.

## Proposal

Mint the front's two bodies, on the same three-band model the `ops` align uses, with this front's
own assignment.

**`/quenching:proof:align`** — probe with `cq proof doctor --json`, branch on the exit code, and stop
free when clean. Findings become one plan in three bands, one OK:

| Band | Findings | How it closes |
| --- | --- | --- |
| **Mechanical** | `pf-unmarked`, `pf-stop-first` | applied; no per-item question |
| **Structural** | `pf-loose-fixture`, `pf-fat-conftest`, `pf-no-floor`, `pf-order-unproven` | applied under the one OK, one edit each |
| **Judgement** | `pf-unlayered`, `pf-empty-layer`, `pf-unmeasured-surface`, `pf-no-ci`, `pf-untested-entrypoint` | **reported with the command that closes it, never driven** |

And one rule that overrides the bands: **the align never sets a floor in the same run that changes
the measured surface.** `pf-no-floor` is structural and closes by writing the floor at the achieved
value — but only over a surface the run did not touch. Where `pf-unmeasured-surface` is also open,
the floor is deferred, the report says so, and the human closes the surface first and runs the align
again.

**`/quenching:proof:status`** — read and report, writing nothing: declared layers with their reach,
budget and test counts; the fixture library's health; the measured roots with their floors and last
achieved values; the CI definitions found and what each invokes; and findings by code and band. It
states plainly what it did not measure — the suite was not run, so no pass/fail claim is made — and
it never calls an absent thing healthy.

## Out of Scope

- **Any change to `cq proof`.** A defect found in a check is recorded and fixed in its own spec.
- **Minting layers.** `/quenching:proof:layer:new` and the generated `tests/README.md` are the next
  spec's.
- **Running the suite.** Neither body runs the target's tests, and `status` says so rather than
  implying a green suite.
- **Writing tests.** The align converges shape and gates. A layer with no tests is reported, never
  filled.
- **Installing CI.** `pf-no-ci` is judgement: reported with the command that closes it.
- **Wiring `proof` into `/quenching:align`.** The integration spec owns it.

## Design

**Why the floor-deferral rule exists as its own rule.** Bands answer *who decides*; they do not
answer *in what order*. Two findings can each be safely closed and still be unsafe closed together,
and this front has exactly one such pair. A floor is a promise about a measurement; changing what is
measured in the same run makes the promise about something else. Stating the rule separately, in
`bands.md`, keeps it from being read as a property of either band.

**Why `pf-unmeasured-surface` is judgement.** Its fix is one line in `pyproject.toml` and its
consequence is that the number the team reports drops by a large, unpredictable amount. Nothing about
that is mechanical. The report carries the size of the change it would cause — the unmeasured roots
and their line counts — so the human decides with the consequence in front of them rather than after.

**Why `pf-unmarked` is mechanical but `pf-unlayered` is judgement.** Registering a marker the
collection hook already derives is bookkeeping with one right answer. Deciding which layer an
unlayered test belongs to is a taxonomy judgement about what that test proves — and on the measured
target it would be asked 1,495 times. The align reports the count and the affected paths; a human
declares layers once, and the derived markers follow.

**Why `pf-no-ci` is judgement rather than a scaffold the align installs.** Installing CI means
choosing a provider, a trigger, a runner and a secret model. A plausible default here is a file
somebody has to unpick. The report names the finding, the four providers the verifier can recognize,
and the command that closes it.

**Why `status` must state what it did not measure.** The front's whole design rests on never running
the suite, which means `status` can report a perfectly shaped verification surface for a repository
whose tests all fail. Saying so is not a caveat, it is the report's meaning:
`/docs/standards/quality/unproven-capability-warning.md` already binds this class of claim, and this
is the clearest instance the plugin has.

**What the align may write.** `pyproject.toml`'s pytest and coverage keys, `conftest.py` files under
the proof root, fixture modules under the library, and the ratchet file — the last only under the
deferral rule. Nothing outside the proof root except the gate configuration, and no log of its own
run.

## Alternatives Considered

- **Put `pf-unmeasured-surface` in the structural band and print a warning.** Rejected: a warning
  printed beside a change already made is not a decision the human got to take. The finding's
  consequence is the reason it is judgement.
- **Let the align declare layers by inferring them from the existing directory names.** Rejected: on
  the measured target that would invent 24 layers across three incompatible mirror axes and call the
  result a taxonomy. Inference here produces a confident wrong answer.
- **Set the floor to a fixed conservative value (say, achieved minus five points) so the deferral
  rule is unnecessary.** Rejected: it replaces one arbitrary number with another and still promises
  something about a measurement that is about to change.
- **One body with a `--report-only` flag.** Rejected for the same reason as on the `ops` front: it is
  the retired `align-and-update` shape and it makes a read-only question route to a convergence
  description.
- **Have `status` run the suite so it can report pass/fail.** Rejected: it is the constraint the
  whole pillar is built around, and it would make the cheap read the most expensive command in the
  plugin.

## Open Decisions

- **Whether `pf-order-unproven` is structural or judgement.** Adding a randomizing pass to an
  existing CI invocation is a one-line edit; it can also turn a green pipeline red the same day.
  Resolved at task 1 against whether the align can add the pass as a **non-blocking** invocation —
  if it can, structural; if the only honest form blocks, judgement.
- **Whether the align offers to converge a target that declares no layers at all.** Every layered
  rule is then vacuous and the front's report reduces to the gate contract. Resolved at task 1
  against `sweep-doctrine.md`'s handling of a partially-configured front.
- **Whether `status` reports the last achieved coverage when the artifact is stale or absent.**
  Reporting a number from an unknown run is worse than reporting none. Resolved at task 2 against
  `/docs/standards/quality/empty-response-honesty.md`, with the bias toward naming the artifact's age
  or its absence.

## Risks

- **The floor-deferral rule makes a two-run convergence normal.** Users may read the second run as
  the align having failed. *Mitigation:* the report states the deferral as a deliberate sequencing
  decision and names the exact next step, and `bands.md` carries the reason so the body does not have
  to argue it inline.
- **The judgement band is large on this front — five of eleven codes.** An align that mostly reports
  can read as inert. *Mitigation:* it is the honest split, and the mechanical and structural bands
  still close the six findings that make the gate mean something; the report leads with what it did
  before what it deferred.
- **Editing `pyproject.toml` touches a file the repository's packaging owns.** *Mitigation:* the
  align writes only the pytest and coverage keys, names each key it changed in the report, and the
  edits are inside the one OK that authorized the plan.
- **`status` stating "the suite was not run" every time can become noise people skim past.**
  *Mitigation:* it is one line in a band-structured report, and the alternative — a report that
  implies a green suite — is the failure this front exists to avoid.
