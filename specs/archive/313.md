## Problem

`deploy/tree.py:228-245` gera `.agents/quenching/bin/cq`; no Windows ele faz `subprocess.call([sys.executable, REAL, …])` (`tree.py:245`), mantendo dois interpretadores vivos por chamada, cada um analisado pelo antivírus do alvo (feedback de usuário: Trend analisa todos os processos). `quenching_launch.py:7-11` já mostra a forma no mesmo processo (`sys.path.insert(0, bin)` e `runpy.run_path(cq)["main"]`).

**Consequência:** cada chamada CLI no Windows paga um processo Python a mais (estimado 50–100 ms mais a varredura do antivírus).

Proposta: o lançador Windows insere o `bin` real em `sys.path` e chama `main(argv)` no mesmo processo, preservando o exit code e o argv com espaços; teste do lançador gerado cobre isso.

## Proposal

O ramo `nt` do lançador gerado deixa de chamar `subprocess.call([sys.executable, REAL, …])`. Ele insere `assets/bin` em `sys.path`, carrega o `cq` real com `runpy.run_path(REAL)["main"]` e sai com `sys.exit(main(sys.argv[1:]))`. O ramo POSIX (`os.execv`) não muda.

## Out of Scope

- Unix: o lançador POSIX já usa os.execv (um processo).

## Impact

- `quenching/assets/bin/quenching/deploy/tree.py` — o `_VENDOR_SH` e o docstring do lançador.
- `quenching/tests/test_deploy.py` — teste do lançador Windows gerado.

### Standards this spec will write into docs/standards/

- none — o comportamento está no docstring do lançador gerado.

## Validation

- `python3 -m unittest quenching.tests.test_deploy.TargetLauncher` passa e cobre: o texto do lançador gerado, no ramo `nt`, não contém `subprocess`, insere `assets/bin` em `sys.path` e chama `main`; o ramo `nt` executado com `os.name` simulado devolve a saída e o exit code do `cq` real, e preserva um argumento com espaço.
- `bash scripts/verify_repo.sh` termina com zero erros.

## Design

- O `cq` real alcança o pacote `quenching` por `sys.path`; inserir `assets/bin` no início reproduz o `sys.path[0]` que o Python montaria ao rodar o script, como faz `quenching_launch.py`.
- `main` devolve o exit code (0/1/2); o lançador o repassa com `sys.exit`, sem reinterpretar.
- Os argumentos passam como lista, sem junção por espaço: um argumento com espaço chega inteiro.
- decision: o ramo POSIX fica com `os.execv`, já em um único processo.

## Alternatives Considered

| Forma | Custo | Por que perdeu |
|---|---|---|
| Manter `subprocess.call` | zero | dois interpretadores por chamada, cada um varrido pelo antivírus |
| `os.execv` também no Windows | zero | no Windows junta os argumentos sem aspas e parte o que tem espaço |

## Open Decisions

- none — a proposta e o desenho decidem tudo; nenhuma decisão fica para o humano.

## Risks

- **Estado do processo compartilhado entre o lançador e o `cq`.** ACCEPTED: o lançador não guarda estado e `quenching_launch.py` já usa a mesma forma.
- **`__name__` do script real deixa de ser `__main__`.** Mitigação: a chamada de `main` é explícita, então o bloco `__main__` do `cq` não é necessário.

## Handoff

- none — spec pequena, uma tarefa.

## Outcome

Shipped: the Windows branch of the generated `cq` launcher (`_VENDOR_SH` in `quenching/assets/bin/quenching/deploy/tree.py`) no longer spawns a second interpreter through `subprocess`. It puts `assets/bin` on `sys.path` and calls `main` of the real `cq` in the same process via `runpy.run_path`, returning cq's own exit code (0/1/2). The POSIX branch (`os.execv`) is unchanged. A new test, `TargetLauncher.test_the_windows_branch_runs_cq_in_the_same_process`, checks the `nt` branch holds no `subprocess` and, run as if on Windows, matches the real `cq` on exit code, stdout and stderr (including an argument with a space). This repository's deployed surface (`.agents/quenching/bin/cq`, the vendored `tree.py`, the deploy manifest) was regenerated from the new launcher.

Caveat the next reader needs: the Windows path was exercised only on Linux. The test forces the `nt` branch by rewriting `os.name == "nt"` to `True`; it has not run on a real Windows host, so the antivirus-rescan benefit and `runpy` behaviour there are unverified.

Left out: no change to `cq.cmd`, the POSIX launcher or any command body. Reviewed, distilled (nothing crossed into /docs/), ready for merge.
