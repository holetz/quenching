## Problem

Achado pelo autopilot 2026-11-21 rodada 8 (scout read-only sobre origin/main 0574813c1), reproduzido em repositório descartável.

`quenching/assets/bin/quenching/git/base.py:29` faz `rsplit("/", 1)[-1]`; o mesmo em `:58`, `:68` (nome vindo de gh/az) e em `quenching/assets/bin/quenching/specs/commands/release.py:59`. `codex/guard.py:103` faz certo (tira o prefixo inteiro). Reprodução: `origin/HEAD` → `refs/remotes/origin/team/main`; `cq git base --json` → `"base": "main"`; `cq git stale --json` → `"base": "main", "staleBranches": []`, ok true.

Consequência: stale, preflight e refresh calculam contra um `main` que não existe e respondem "nada velho" com exit 0; `/release` recusa o primário certo com `sp-release-wrong-branch`.

Arquivos prováveis: `git/base.py`, `specs/commands/release.py`, `quenching/tests/test_git.py`.

## Proposal

- `cq git base` devolve o nome inteiro do branch padrão quando `origin/HEAD` aponta para um branch com barra (`refs/remotes/origin/team/main` → `team/main`), e por isso `stale`, `preflight` e `refresh`, que leem `resolve_base`, calculam contra o branch que existe.
- `_is_host_default` compara o nome inteiro que gh (`defaultBranchRef.name`) e az (`refs/heads/<nome>`) devolvem, sem cortar no último `/`.
- `cq specs release` resolve o primário pelo mesmo leitor de `origin/HEAD` e deixa de recusar com `sp-release-wrong-branch` o checkout que está no primário com barra.
- Um único leitor de `origin/HEAD` em `common/git.py` substitui as duas cópias (base.py e release.py).

## Out of Scope

- `codex/guard.py:_primary` — já tira o prefixo inteiro e devolve um ref `refs/heads/…`, contrato diferente; fica como está.
- Um remote diferente de `origin` — toda a cadeia (`infer_base_branch`) assume `origin`; generalizar é outra spec.
- Os outros `rsplit("/", 1)[-1]` do código (cq_calls, delivery/checks, audit, inventory, azure, estimate) cortam caminhos ou palavras, não nomes de branch.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/common/git.py` — leitor único de `origin/HEAD` e o corte de `refs/heads/`
- `quenching/assets/bin/quenching/git/base.py` — `_origin_head_branch` e `_is_host_default` deixam de cortar no último `/`
- `quenching/assets/bin/quenching/specs/commands/release.py` — o primário pelo leitor único
- `quenching/tests/test_git.py`, `quenching/tests/test_specs_release.py` — regressões com branch com barra
- `.agents/quenching/assets/bin/quenching/**` e `.agents/.quenching-deploy.json` — espelho gerado pelo `cq deploy --target . --write`

## Validation

- `python3 -m unittest discover -s quenching/tests -p test_git.py` passa, com casos novos: `origin/HEAD` → `refs/remotes/origin/team/main` faz `_origin_head_branch` e `cq git base --json` devolverem `team/main`; gh respondendo `team/main` e az respondendo `refs/heads/team/main` fazem `_is_host_default(..., "team/main")` verdadeiro. Os casos falham na base (prova RED).
- `python3 -m unittest discover -s quenching/tests -p test_specs_release.py` passa, com um caso novo: num repositório descartável no branch `team/main` com `origin/HEAD` apontando para ele, `cmd_release` não recusa com `sp-release-wrong-branch`. Falha na base.
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` sai 0 (inclui o lockstep do espelho implantado).

## Design

- 2026-11-21 — **Tirar o prefixo inteiro, nunca cortar no último `/`.** O nome de um branch pode ter barras; o único corte correto é remover o prefixo conhecido (`refs/remotes/origin/` para `origin/HEAD`, `refs/heads/` para o az), como `codex/guard.py:103` já faz. Decisão do dono no épico 2270 (`## Design`, 2026-11-21, "2263 (base com barra)").
- **Um leitor só.** `common/git.py` ganha `origin_head_branch(cwd)` (o `symbolic-ref` de `refs/remotes/origin/HEAD` sem o prefixo; `None` quando ausente ou fora do prefixo) e `short_branch(name)` (tira `refs/heads/` quando presente). `git/base.py` e `specs/commands/release.py` importam; nenhuma terceira cópia.
- **gh devolve o nome curto** (`defaultBranchRef.name`), então `short_branch` é idempotente nele; **az devolve `refs/heads/<nome>`**, e o mesmo `short_branch` cobre. Um valor sem o prefixo fica intacto.
- Contrato que não muda: `resolve_base` continua devolvendo `(base, isDefault)`, e a cadeia `origin/HEAD → init.defaultBranch → main` de `infer_base_branch` fica igual.

### Assumptions

- O remote do `origin/HEAD` é sempre `origin` (como toda a cadeia já assume) — `## Out of Scope`.

## Alternatives Considered

- Corrigir só `base.py:29` — rejeitado: deixa `release.py` e as respostas de gh/az com o mesmo corte, e o épico pede os quatro pontos.
- Resolver o nome com `git rev-parse --abbrev-ref origin/HEAD` (devolve `origin/team/main`) — ainda exige tirar `origin/`; o `symbolic-ref` com o prefixo literal é o que guard.py já usa e é exato.

## Open Decisions

- none — o épico 2270 fixou o corte do prefixo inteiro nos quatro pontos; o resto segue do código.

## Risks

- Um ref de `origin/HEAD` fora de `refs/remotes/origin/` (configuração manual estranha) passaria a dar `None` em vez de um último segmento — ACCEPTED: `None` faz a cadeia cair para `init.defaultBranch`/`main`, que é o comportamento declarado para "sem origin/HEAD", e é melhor que inventar um nome.
- O espelho implantado ficar defasado — mitigado: a mesma tarefa roda o deploy e o gate tem o lockstep.
