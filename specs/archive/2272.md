## Problem

`cq components session cache` só enxerga, no lado Claude, a conversa principal: as transcrições de subagentes (`~/.claude/projects/<slug>/<sessão>/subagents/agent-*.jsonl`, com o tipo em `agent-*.meta.json`) ficam de fora, e é justamente ali que estão as retomadas frias medidas à mão em 2026-11-21 (spec-runner no Desktop: 54 de 55 retomadas frias, 10,6M tokens reescritos). O relatório também não separa as escritas por TTL (`ephemeral_5m_input_tokens` × `ephemeral_1h_input_tokens`) nem diz o que infla o contexto.

A medição de 2026-11-21 precisou de scripts avulsos para responder três perguntas que se repetem a cada decisão de custo: qual TTL cada papel usa, quanto custaria o outro TTL, e quais leituras pesam. A última mostrou que referências de fluxo lidas inteiras (`execute.md`, `develop.md`, `conclude.md`, `specs-develop/questions.md`, `specs-develop/artifacts.md`) somaram cerca de 132M tokens relidos do cache em 7 dias, ~12% de todas as leituras de cache das sessões OpenCode.

## Proposal

- Ler os subagentes do Claude Code como papéis (`role subagent`, `agent` = `agentType` do meta), com o host (`entrypoint`: claude-desktop, cli, sdk-ts…) como coluna.
- Separar escritas em 5m e 1h por linha e acrescentar o contrafactual do outro TTL (escritas a 1,25× ou 2×, pausas de 5 a 60 min que virariam leitura ou escrita).
- Um modo `--inflow` que soma, por origem, o tamanho do que entrou no contexto e quanto foi relido depois (tamanho × passos restantes): references por arquivo, `cq components read` com e sem `--sections`, leitura de código, shell, MCP.
- Saída `--json` estável para servir de linha de base às specs 2165, 2257 e 2271 e à remedição da 2159.

## Out of Scope

- Pricing the counterfactual in dollars: `--usd` already prices a row; the TTL block stays in input-token equivalents so no price table decides a TTL change.
- Changing any TTL, hook or role budget: this verb measures; specs 2165, 2257 and 2271 decide.
- A per-message breakdown of what is inside a tool result: `--inflow` takes sizes, tool names and paths only, never content.
- OpenCode's legacy `message`/`part` tables: `--inflow` reads the v2 `session_message` rows, the store the sessions under measure use.
- Splitting OpenCode cache writes by TTL: its store records one `cache.write` number, so those rows keep `write5m`/`write1h` at 0.

## Design

**Most of the proposal already ran.** On this base `cache.py` reads subagent transcripts as `role subagent` with `agent` from `agent-*.meta.json`, and already splits `write5m`/`write1h` per row. What was missing, and is built here, is the host column, the other-TTL counterfactual and `--inflow`.

- **Host is a row key.** `host` is the `entrypoint` of the transcript (first record that carries one) and `opencode` for the OpenCode store; a transcript that names none is the empty string. Two hosts of the same agent are two rows, never one.
- **The counterfactual is in input-token equivalents.** `ttl.writeNow`, `ttl.writeAll5m`, `ttl.writeAll1h` use the table's `cacheWrite` multipliers (1.25 and 2); a write the record did not split prices at 5 minutes, as `request_usd` already does. Pauses are the two numbers a TTL change turns over: `readAfterGap5m` (tokens read after a pause of 5 minutes or more, which a 5-minute TTL would have missed) and `missedAfterGap5to60` (tokens written or uncached after a pause of 5 to 60 minutes, which a 1-hour TTL would have read).
- **`--inflow` counts a result by what happens after it.** A tool result enters once and is re-read from cache at every later request of its session, so `reread = tokens x requests left`; tokens are characters / 4, the estimate `skillListing` already uses. Origin is `(kind, key)`: `reference`, `code` and `cq-read-whole`/`cq-read-sections` keyed by file; `shell`, `mcp` and `tool` keyed by tool name. A bridged name (`mcp__opencode__read`) classifies as the tool behind it.
- **Content stays unread.** Only sizes, tool names, file paths and the `cq components read` target are kept; the contract of the verb ("message content is never selected") is rewritten to say so.
- **`--json` is the stable shape.** The existing keys do not move; `host`, `ttl`, `readAfterGap5m`, `missedAfterGap5to60` are added to each row, and `--inflow` returns `{ok, scope, unit, unavailable, inflow[], anomalies}`.

### Assumptions

- `--inflow` for OpenCode relies on `session_message` assistant rows carrying `content[]` tool entries with `state.input` and `state.content`; a store without it yields no rows and the same `se-no-usage` refusal. (Validation, tests)

## Alternatives Considered

- A separate `inflow` verb: rejected, it shares scope, `--since`, `--harness` and the transcript readers with `cache`, and a new verb is a new command surface to keep.
- Pricing the TTL counterfactual in dollars by default: rejected, the price table is an estimate and the decision is about token-equivalents and pauses.

## Open Decisions

- none — which TTL each role should use is decided by specs 2165, 2257 and 2271 from this verb's output, not by this spec.

## Risks

- **A new reader parses large transcripts twice (`--inflow` re-reads what `cache` reads).** Mitigation: it runs only on `--inflow`, a verb nobody runs in a hook; the default path is unchanged except one `entrypoint` scan that stops at the first match.
- **Character/4 misprices non-prose results.** ACCEPTED — the unit is stated in the payload and used only to rank origins.
- **Windows path scope.** The existing OpenCode scope tests already fail on Windows on the base (`/repo` resolves to `C:\repo`); the new tests use `--all` so they add none.
