## Problem

The repository gate depends on the checkout directory name. In plugins/quenching/tests/test_ops.py:145-150, AlignCleanPath.test_conformant_fixture_stops_after_two_calls_before_inventory serializes both the Read path and Bash command and asserts that the whole transcript does not contain 'inventory'. The absolute ALIGN_BODY path is legitimate input, not an ops inventory call.

During spec 1679, bash scripts/verify_repo.sh exited 1 with 1370 tests, one failure and one skipped in ~/Projetos/quenching-1679-delivery-inventory. The failure was:
AssertionError: 'inventory' unexpectedly found in '~/Projetos/quenching-1679-delivery-inventory/plugins/quenching/commands/ops/align.md cq --root "$TARGET_ROOT" ops doctor --json'

Focused reproduction from such a checkout:
PYTHONPATH=plugins/quenching/tests python3 -m unittest test_ops.AlignCleanPath.test_conformant_fixture_stops_after_two_calls_before_inventory

A read-only scout confirmed the path/command conflation and no duplicate open spec. The failure blocks correct changes solely because of the worktree name. Spec 1679 recorded the discovery and preserved its implementation without changing this unrelated test.

## Proposal

Keep the two-call and body-read assertions. Check absence of the actual ops inventory invocation only in Bash events, rather than searching absolute Read paths. Add meaningful coverage using a body path containing inventory. Scope is plugins/quenching/tests/test_ops.py; do not remove assertions, weaken the gate, add skips or change production behavior.

## Out of Scope

- Changing production behavior of `ops align` or `cq ops` — the fault is in the test only.
- Removing, skipping or weakening any assertion, or touching the gate — ruled out by the Proposal.
- Auditing other tests for path-dependence — parked as a discovery if found, not done here.

## Design

- Rule: a transcript assertion about a forbidden command inspects only Bash events (the command text), never Read paths, which are input and may legitimately contain any directory name.
- The two-call count and the body-read/branch-ordering assertions stay unchanged.
- Coverage: a small transcript built from a Read path containing `inventory` (e.g. `/x/inventory/plugins/.../align.md`) plus the doctor probe must satisfy the Bash-only check; a transcript with an `ops inventory` Bash call must fail it. Assumption: a local helper in the test module is enough; no shared fixture needed.

### Mapa de dependências

- `plugins/quenching/tests/test_ops.py` — sole file touched; nothing imports the changed assertion. Dependency sweep done by direct reading (2026-10-15), no sub-agent.

## Alternatives Considered

- Drop the `inventory` assertion — rejected: loses the guard that the clean path stops before inventory.
- Skip when the path contains `inventory` — rejected: a skip hides the gate and the Proposal forbids it.
