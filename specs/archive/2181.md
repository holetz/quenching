## Problem

On 2026-11-06 the development machine (Linux; Samsung PM9B1 256 GB DRAM-less NVMe; ext4 on LVM on
dm-crypt; `/tmp` on the same disk, no tmpfs) went into I/O halt: the NVMe passed 80 °C (high limit
82.8 °C, one sensor at 94.8 °C), the disk sat at 100% util with `w_await` near 2000 ms while writing
only ~1.3 MB/s, and I/O PSI read `some` 77–92% / `full` ~50%. The top writer was
`bash scripts/verify_repo.sh` run as a gate from worktree `quenching-2178` — `pytest -n auto --cov`
with 12 workers parked in state D on `filename_create`, `filename_rmdir` and
`jbd2_log_wait_commit` — while another worktree's gate (`quenching-2179`) and another project's
tests ran at the same time (about 10 worktrees are active). Two monitoring loops born in the
deploy/gate flow had been running for two days: `du -sm /tmp` every 5 s into
`.quenching/deploy-mon.log` and `free -m` every 3 s into `.quenching/gate-mon.log`.

The bottleneck is not volume but metadata and journal traffic: the suite (161 files, ~2,760 tests)
creates and deletes ~14,000 temp entries per run through 265 `tempfile.TemporaryDirectory`, 29
`mkdtemp` and 7 `gettempdir` call sites (17 `tmp_path`), runs 28 `git init` plus config/commit/
worktree per test and 235 `subprocess.run`, and the measured run writes **~690 MB per gate** through
the ext4 journal and dm-crypt. Parallelism (`-n auto`) and concurrent gates from several worktrees
multiply it, and nothing bounds either. The same suite must also run on Windows without WSL, where
process and file creation are far more expensive and today only three `test_windows_*` modules run
in CI.

## Proposal

Cover the whole flow — suite, gate, worktrees and the deploy loop — in independent slices, each with
a before/after measured by the same instrument. Gate helpers live in a `scripts/toolchain/` package,
run as `python -m scripts.toolchain.<module>` (the structure the SAFRA repository uses for
`toolchain/afetados.py` and `toolchain/test.py`), and the gate-tamper audit watches that package.

1. **One temp root, in RAM when available.** `scripts.toolchain.tmproot` picks the root once; the
   gate exports `TMPDIR`/`TEMP`/`TMP` before pytest starts, so every `tempfile` call, every xdist
   worker and every `git` child inherits it with no test edited. `quenching/tests/_paths.py` applies
   the same resolver when the gate did not (direct runs, the CI 3.13 cell). A per-gate directory is
   removed by a trap; falling back to disk prints a loud `NOTICE` in the style of the gate's
   `SKIPPED` lines. `QUENCHING_TEST_WORKERS` sets the worker count (default `auto`).
2. **A lint guard** that forbids hard-coded temp paths and writes to `tempfile.tempdir` in tests, so
   the single root cannot regress.
3. **Isolated, fsync-free git in tests**: `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM` plus
   `GIT_CONFIG_COUNT` pairs (`core.fsync=none`, `gc.auto=0`, `init.defaultBranch=main`, identity)
   set by `_paths.py` for the test process only — never the user's global config.
4. **A template repository per process**: one `git init` + commit cached per process, copied per
   test (`shutil.copytree`), replacing repeated init/config/commit in the slowest git modules.
5. **Layers and affected-test selection, heavy tests only at the close.** An `integration` marker
   on git/subprocess-heavy modules. `scripts.toolchain.affected` selects the tests a diff reaches
   (explicit source→test rules plus the tests' direct imports read by AST, fail-open to the whole
   suite on any doubt), and `scripts.toolchain.test --affected` runs that selection without the
   `integration` layer unless `--with-integration` is given. **The whole suite runs in CI when CI
   exists**: a task's `verify:` and the session's loop run affected, non-integration tests; the
   local close runs `verify_repo.sh` with `QUENCHING_TEST_SCOPE=affected` (every non-suite check
   stays whole); the PR's CI run of the unchanged whole gate is the close's full gate, and the merge
   waits for it green. With no CI (another repo, CI down, `QUENCHING_FULL_GATE=1`) the local gate
   runs whole, under the RAM root and the worker budget.
6. **A machine-wide worker budget**: `scripts.toolchain.slots`, loaded as a pytest plugin
   (`-p scripts.toolchain.slots`, no `conftest.py`), takes slot locks (`fcntl.flock` on POSIX,
   `msvcrt.locking` on Windows) under the user cache dir and returns the granted count from
   `pytest_xdist_auto_num_workers`; waiting is printed with a timeout, and locks die with the
   process.
7. **Monitor hygiene**: no loop may outlive the command that started it — a measurement is an
   in-process thread or a child in its own process group killed in a trap/`finally`; the rule lands
   in the ephemeral-writes standard and its shipped twin.
8. **Coverage**: confirm the `sysmon` core is in effect (Python 3.14 + coverage 7.17 make it the
   default), measure the `--cov` overhead under xdist, and prove worker data never lands in the
   per-gate temp dir.
9. **Windows, this spec's share**: the resolver and the slot locks are stdlib Python, and the
   Windows CI job runs their tests. Moving the gate itself to Python is a follow-up spec (see
   `## Discoveries`).
## Out of Scope

- Changing system configuration (`/etc/fstab`, `tmp.mount`, the user's git config, Defender
  exclusions, `LongPathsEnabled`, dm-crypt flags): documented only, as optional steps in
  `docs/how-to/`.
- Any dependency that needs admin on the default path; RAM-disk drivers on Windows.
- Weakening the randomized-order evidence (`pytest-randomly`) or the coverage floor
  (`cq proof ratchet`): both stay in the whole gate, which CI runs on every PR (and the local gate
  whenever no CI exists); `QUENCHING_TEST_SCOPE` defaults to `full`, so CI and `/release` are
  unchanged.
- Moving the gate to `scripts/verify_repo.py` and running the full suite on Windows: no immediate
  gain (the incident is Linux; no Windows gate run exists today; the Windows CI job runs focused
  tests) against a wide blast radius — the release skill's and three agents' grants are pinned to
  `bash scripts/verify_repo.sh`, `scripts/check_claude_harness.py:25` requires that string, and
  three tests read the `.sh`. Parked as a follow-up in `## Discoveries`.
- `pytest-testmon`: the affected selector is rule- and import-based and needs no coverage database.
- A mass migration of the 265 `TemporaryDirectory` call sites to `tmp_path` (see Alternatives).

## Validation

- Every slice records before/after with `python -m scripts.toolchain.measure_io` (same seed, idle
  disk, PSI printed) in `## Discoveries`.
- Slice 1: on Linux with a RAM root, `-n auto` writes < 10 MB through the test tree (baseline
  688.8 MB) and the disk sees ≥ 90% fewer write ops; forcing the fallback prints the `NOTICE` and the
  suite still passes; no `quenching-gate-*` directory survives a gate, including one killed by
  SIGINT; the coverage artifact and ratchet are unchanged.
- `bash scripts/verify_repo.sh` stays zero errors, with the same randomized-order evidence and the
  ratchet floor unchanged.
- Slice 5: `scripts.toolchain.test --affected` falls back to the whole suite for every global file
  and for a source path no rule covers; a task-sized diff runs in a fraction of the whole suite's
  wall time (recorded).
- Slice 6: two gates started together never run more workers in total than the budget; a gate
  whose process is killed releases its slots.
- `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` runs every non-suite check whole,
  the affected suite, and prints `SKIPPED` for the coverage floor; unset, the gate is byte-for-byte
  today's behaviour.
- A spec here is merged only after the PR's CI gate is green; a conclude that would merge locally
  first is caught and recorded.
- The audit flags a change under `scripts/toolchain/` as a gate change.
## Design

**Baseline (measured 2026-11-06, seed 12345, 12 CPUs, Python 3.14.3, coverage 7.17.0, pytest
9.2.0, xdist 3.8.0, git 2.43.0).** Disk counters are the physical `nvme0n1` under dm-crypt/LVM,
machine-wide; "tree written" is `getrusage(RUSAGE_CHILDREN)` blocks written by the suite's own
process tree. Runs: `.quenching/measure/20261106T111709-base-ocioso-disco` and
`.quenching/measure/20261106T112314-base-ocioso-shm`.

| Run | Temp root | Wall (s) | Temp peak (MB / entries) | Tree written (MB) | Disk write ops | Disk flushes | Disk write ms |
|---|---|---|---|---|---|---|---|
| `-n auto` | `/tmp` (ext4) | 56.6 | 77.4 / 13,853 | 688.8 | 54,631 | 988 | 717,517 |
| `-n 4` | `/tmp` (ext4) | 72.9 | 37.8 / 6,764 | 687.9 | 33,835 | 1,252 | 27,646 |
| serial | `/tmp` (ext4) | 235.9 | 37.8 / 6,788 | 687.6 | 38,877 | 1,484 | 411,146 |
| `-n auto` | `/dev/shm` | 46.6 | 91.6 / 17,485 | 2.3 | 2,267 | 103 | 19,447 |
| `-n 4` | `/dev/shm` | 70.2 | 42.3 / 7,515 | 1.5 | 1,376 | 118 | 1,819 |
| serial | `/dev/shm` | 204.1 | 42.3 / 7,579 | 1.1 | 6,235 | 278 | 117,036 |

The same `-n auto` suite under contention (another worktree's gate, the orphan loops) took 399 s,
`-n 4` 227 s, and the whole gate on an idle disk 57 s: **contention, not the suite alone, turns a
one-minute gate into a seven-minute one.** Moving the temp root to RAM alone removes ~99.7% of the
tree's writes, ~96% of the disk write ops and ~90% of the flushes, and saves ~18% wall time with no
test edited; the temp peak stays under 100 MB. The 30 slowest tests (serial, contended run) are 28
"git/subprocess" (189 s) and 2 "filesystem" (3.5 s), led by `test_deploy.py` (28 s, 27 s, 9 s,
7.5 s), `test_specs_epics.py` (21 s, 12 s, 10.5 s, 8 s) and `test_run_evals.py` (11.7 s, 6.4 s).
Every run had 4 failures in `test_session_context.py` when the host exports `OPENCODE_SESSION_ID`
(spec 2179); the idle runs unset it.

**Temp-root matrix** (the resolver tries in order; an explicit `QUENCHING_TEST_TMPDIR` wins):

| Environment | Preferred | Fallback |
|---|---|---|
| Linux, no admin | `$XDG_RUNTIME_DIR` (tmpfs, per-user 0700, capped by logind `RuntimeDirectorySize`, 10% of RAM) then `/dev/shm` | system temp dir, with `NOTICE` |
| Linux, admin | `/tmp` itself when `tmp.mount` makes it tmpfs (Debian 13 default; optional how-to step with a `size=` cap) | same |
| Windows, no admin | an existing Dev Drive (`fsutil devdrv query`), else `%LOCALAPPDATA%` outside synced folders | `%TEMP%`, with `NOTICE` |
| Windows, admin | Dev Drive (+ Defender performance mode, automatic on a trusted Dev Drive) | RAM disk is not recommended |

A RAM candidate is accepted only if it is a tmpfs (`/proc/mounts`), writable, and has ≥ 512 MB free
(measured peak 92 MB; ×5 margin); otherwise the next candidate. The gate creates
`quenching-gate-<pid>-XXXX` (0700, `mkdtemp`) under the root and removes it in an `EXIT` trap, so a
killed gate leaves nothing in RAM. `COVERAGE_FILE` stays at `.quenching/coverage/.coverage`: the
trap would otherwise delete the worker data before it is combined, and `cq proof ratchet` reads the
artifact the gate passes with `--artifact` (`proof/ratchet.py:27-30`).

**Why the environment and not 265 edits.** `tempfile.gettempdir()` resolves `TMPDIR`, `TEMP`, `TMP`
in that order and caches the result per process; xdist workers and `git` children inherit the
environment, and `_paths.py` is imported first by every test module, before `tempfile` caches.
152 of the 161 test files are `unittest.TestCase`, which has no `tmp_path` at all. The lint guard
forbids the two ways to escape the root (a literal `/tmp`/`%TEMP%` path used as a location, an
assignment to `tempfile.tempdir`); `/tmp` literals used as data (`test_specs_portal.py:595`,
`test_leak_scan.py:88`, `test_run_evals.py:260-264`, `test_portal_serve.py:237`,
`test_session_live.py:47`) are allow-listed by the guard's rule, not by path.

**Where the helpers live.** `scripts/` is not shipped (`deploy/tree.py:340-350`), so the toolchain
package changes no target. The gate-tamper audit's `GATE_PATH` (`git/audit.py:722`) watches only
`scripts/verify_repo.sh` and `quenching/assets/checks/`; it is extended to `scripts/toolchain/`, so
a PR that weakens a helper the gate calls is flagged like one that edits the gate.

**Git.** The default `core.fsync` (`committed,-loose-object`) already skips loose objects, so the
fsync gain from `core.fsync=none` is expected to be small; the larger gains are isolation
(`GIT_CONFIG_GLOBAL` → `os.devnull`, `GIT_CONFIG_NOSYSTEM=1`, `gc.auto=0`) and fewer processes.
Today only `test_codex_guard.py:23-24` isolates the global config; the rest set identity per repo
(`-c user.*`, `git config user.*`, `GIT_AUTHOR_*`), so no test relies on a global `user.name`, but
none is shielded from global hooks, `commit.gpgsign` or `init.defaultBranch`. `GIT_CONFIG_COUNT`
needs git ≥ 2.31 and `core.fsync` ≥ 2.36; older git ignores the unknown key. Slice 3 confirms with
`strace -f -c -e trace=fsync,fdatasync` which processes still sync.

**Template repository.** `cq proof doctor` refuses fixtures in `conftest.py` (`pf-fat-conftest`,
`proof/checks.py:59-66`) and the suite is `TestCase`-based, so the template is a per-process cache
in a helper module (built on first use under the temp root, copied per test), not a session
fixture. Under xdist each worker builds it once.

**Affected tests and the three tiers.** The selector follows SAFRA's `scripts/toolchain/afetados.py`:
a `RULES` table maps each source surface (`quenching/assets/bin/quenching/<area>/`,
`quenching/skills/`, `quenching/references/`, `scripts/`) to the tests that cover it; each test's
direct imports (AST) are added, catching cross-module use; the diff is `merge-base` + working tree
+ untracked. **Any doubt runs the whole suite**: a global file (`pyproject.toml`, `uv.lock`,
`quenching/tests/_paths.py`, any `quenching/tests/_*.py` helper, `scripts/toolchain/`), a path with
no rule, an unresolvable base, an empty selection with source changed. The heavy layer
(`integration`) is skipped by `--affected` unless `--with-integration`, and the count skipped is
printed. **The whole suite runs in CI when CI exists.** The repository is public (free Actions
minutes), and the last five `ci.yml` runs took 108–163 s; the 3.11 cell already runs the unchanged
`bash scripts/verify_repo.sh` with randomized order, coverage and the ratchet, and the Windows job
runs there too. So the tiers are: task `verify:` and session loop → affected, non-integration;
local close → `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` (ruff, docs, lockstep and
the other checks whole; the suite affected; the floor `SKIPPED`, because a partial run cannot
measure it); remote close → the PR's CI gate, and the merge waits for it green
(`/quenching-git pr-status`); no CI → the whole local gate. "Single gate" holds: it is the same
script, run where the machine is not the bottleneck. The price is feedback latency — a heavy
failure shows 2–3 min after the push and costs another push — and no full gate offline. Today
`/quenching-specs conclude` runs `## Validation` on the work branch and `/quenching-git merge` is a
local `git merge`; the PR route ("Merge pull request #91") is what this repository uses, and task 5.5
makes `## Validation` name the CI check so a local merge before CI is green is refused.

**Worker budget.** On an idle disk `-n auto` beats `-n 4` (56.6 s vs 72.9 s); under contention
`-n 4` beat `-n auto` (227 s vs 399 s). A fixed lower N is wrong alone and right in company: the
answer is a budget shared across gates. Slots are `<user cache>/quenching/gate-slots/slot-<i>.lock`,
N = physical cores; the plugin takes free slots non-blocking up to its share, waits (printing the
holders' pids) up to a timeout when none is free, and returns the slot count to xdist. Kernel-held
locks are released when the process dies, so no slot leaks. Loading it with `-p` keeps
`quenching/tests/` free of a `conftest.py`, and the `unittest` fallback path simply runs without a
budget.

## Alternatives Considered

- **Migrate all 265 `TemporaryDirectory` to `tmp_path` first.** Dropped as the first move: the
  environment relocates them all at once with the same measured I/O gain, 152 of 161 files are
  `TestCase` without `tmp_path`, and `tmp_path` adds on-disk retention. Call sites migrate
  opportunistically; the lint guard keeps the root single.
- **`eatmydata` around the gate.** Linux-only (LD_PRELOAD), misses static binaries, does nothing for
  metadata ops; kept only as a one-off diagnostic.
- **`/tmp` on tmpfs via `tmp.mount`.** Needs admin and changes the whole system; documented as an
  optional how-to step, never required.
- **A fixed `-n 4`.** Measured slower alone (72.9 s vs 56.6 s) and faster under contention; a shared
  budget gets both.
- **A single global gate lock (one gate at a time).** Simpler but serializes worktrees even when
  cores are idle; the slot budget degrades to it when the slots are taken.
- **RAM disks and Defender exclusions on Windows.** Need admin/driver, blocked by Tamper Protection
  on managed machines; Dev Drive is the supported path.
- **`py-filelock` dependency.** The stdlib (`fcntl`, `msvcrt`) covers both locks and keeps the
  toolchain dependency-free.
- **Shared `.venv` across worktrees (`UV_PROJECT_ENVIRONMENT`).** Drifts when locks diverge between
  branches; the per-worktree `.venv` (136 MB) is not on the hot path of the incident.
- **Helpers in `quenching/tests/_*.py`** (no audit change). Rejected for SAFRA's
  `scripts/toolchain/` structure (D3), which keeps tooling apart from tests and is watched once the
  audit is extended.
- **Helpers inline in bash.** Linux-only and hard to unit-test.
- **Move the gate to Python now (D1-B).** Deferred: no immediate gain against the pinned grants,
  the audit and three tests; follow-up spec.
- **Heavy tests also per session (D2 variant).** Rejected by the human.
- **Whole gate locally at conclude (D5-B).** Immediate feedback and offline, but every spec still
  pays a whole suite on the shared disk — the incident's load.
- **Whole gate locally and in CI (D5-C).** Safest, and the most local disk; CI already carries the
  same evidence.
- **`pytest-testmon` for selection.** Needs a coverage database per worktree and conflicts with the
  `sysmon` core for per-test data; the rule + import selector needs neither.

## Risks

- **Late detection of heavy failures**: a task's integration tests run in the PR's CI, so a break
  in git/deploy code surfaces after the push and costs another push; bounded by the printed skip
  count and `--with-integration` for a task that knows it touches that code.
- **A merge before CI is green** would put the heavy run after the merge on `main`; task 5.5 makes
  `## Validation` name the CI check and checks that conclude/merge honours it.
- **CI unavailable or offline**: the local gate falls back to whole (`QUENCHING_FULL_GATE=1`, or no
  CI declared), so a spec can always close.
- **A wrong affected selection passes a task that breaks an unselected test**: fail-open on every
  global file and unmapped path, AST imports on top of the rules, and the whole gate at conclude.
- **RAM pressure**: the root competes with memory and can go to swap; mitigated by the 512 MB free
  check, the per-gate directory and the trap (measured peak < 100 MB; ~10 concurrent worktrees
  ≈ 1 GB against `$XDG_RUNTIME_DIR`'s 3.2 GB here).
- **`/dev/shm` is shared and world-writable**: tried after `$XDG_RUNTIME_DIR` (0700), and the
  per-gate directory is `mkdtemp` (0700).
- **tmpfs hides a disk-only filesystem bug**: CI keeps running on disk-backed runners.
- **A test that depends on the developer's git config** fails once isolation lands; fixed in slice
  3 as a test bug.
- **Slot locks on network filesystems** are unreliable; the slot dir lives under the local user
  cache.
- **The audit change ships** to every target through `git/audit.py`; it only widens what is
  watched, and `test_git.py` pins both the old and the new paths.
