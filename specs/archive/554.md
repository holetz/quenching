## Problem

A 7.18.0 publica as skills geradas só em `.claude/skills` com o harness `claude`, mas as citações `.agents/skills/<skill>/…` do texto fonte seguem intactas: num alvo real (riscos-plataforma, 26/11/2026) 89 caminhos em 39 arquivos apontavam para arquivos inexistentes, e `cq components read .agents/skills/quenching-specs/references/create.md` recusava `sk-read-no-file` — todo fluxo roteado quebrava, no Claude Code e no OpenCode, inclusive no self-host deste repo. Além disso, com `shared.mcp.mount: specs`, o `cq deploy --check` do runtime vendorizado acusava drift permanente nos cinco agentes: o payload guarda os agentes traduzidos sem mount, e a re-tradução sob o mount só acrescentava tools, nunca retirava as que o mount esconde.

## Proposal

`deploy/tree.py` reescreve `.agents/skills/<skill gerada>/` para o diretório publicado; `deploy/translate.py` retira, na re-tradução, as tools MCP fora do mount declarado. Um teste para cada, vermelho sem a correção.

## Validation

- `quenching/tests/test_deploy_skills.py` e `quenching/tests/test_deploy_mcp_mount.py` passam, e falham sem a correção.
- `bash scripts/verify_repo.sh` sai 0.
