## Problem

`cq config schema [--values]` (config/__init__.py:293) sai plano: não filtra por categoria (schema.py:29) nem prefixo, e não diz de qual dos 4 arquivos (common/config.py:19,23,27,268) veio cada valor efetivo. Consequência: achar e entender uma chave exige ler docs/standards/workflows/plugin-configuration.md inteiro. Proposta: --category, --key <prefixo> e, com --values, a camada e o caminho de origem; mesma fonte JSON que o portal e a vitrine leem. Somente leitura.

## Proposal

`cq config schema` ganha `--category <id>` e `--key <prefixo>` (filtram chaves, categorias e, com `--values`, os valores) e, com `--values`, cada valor traz `path`: o arquivo que o forneceu (`null` no default). A mesma carga JSON serve o portal (565) e a vitrine. Somente leitura.

## Out of Scope

- Escrita de configuração (`cq config set` já existe) e qualquer rota/aba do portal (565).
- Mudar o schema, as chaves ou os escopos.

## Impact

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/config/__init__.py` — filtros e `path` em `cmd_schema`
- `quenching/tests/test_config_schema.py` — prova dos filtros e do `path`
- `docs/standards/workflows/plugin-configuration.md` — documenta os flags e o campo

## Validation

- `python3 -m pytest quenching/tests/test_config_schema.py -q -p no:cacheprovider` passa.
- `cq config schema --values --category autonomy --key shared.autonomy` lista só as chaves de `shared.autonomy*`, cada uma com valor, camada e arquivo; `--category zz` sai 2 com `cq-config-category-unknown`.

## Design

- Filtro aplicado sobre o registro antes de montar `values`, para a mesma carga alimentar todos os leitores. `--key` é prefixo literal de string (`shared.autonomy.max` casa `maxWorkers` e `maxLaunches`).
- Categoria desconhecida é recusa (exit 2), não lista vazia: erro de digitação não pode parecer "nenhuma chave".
- `path` por linha vem das camadas que `effective()` já lê (user, repository, local, branch); `default` não tem arquivo.
- Campos antigos (`value`, `source`, `layerPaths`) ficam; `path` é aditivo.

### Assumptions

- Prefixo literal basta; glob não é pedido (depende: Proposal).

## Alternatives Considered

- Filtrar no consumidor (portal/vitrine): rejeitado, repete a lógica em cada leitor e o `cq` no terminal continuaria plano.

## Open Decisions

- none — o desenho cabe no que o código já lê.

## Risks

- Consumidor que compara `values[k]` por igualdade com `{value, source}` quebra com o campo novo: ACCEPTED — o único leitor no repo (o teste) foi ajustado; aditivo para JSON.
