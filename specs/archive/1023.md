## Problem

As skills Codex referenciam o payload em assets/zensical, mas o tradutor não copia esse diretório para o plugin Codex. O espelho também está com o manifesto de origem em drift e o CSS usado no site dogfooded diverge do CSS entregue pelo payload.
## Proposal

- Fazer o tradutor Claude→Codex copiar o payload assets/zensical para o caminho assets/zensical do plugin Codex, pois as skills traduzidas já referenciam esse caminho.
- Regenerar o espelho Codex e fazer sync --check voltar a ser verde, sem editar manualmente arquivos gerados.
- Alinhar a folha de estilos usada pelo site dogfooded com a folha entregue pelo payload, ou registrar em teste qualquer diferença intencional; nesta decomposição, a cópia do payload é a fonte de verdade.
- Ampliar os testes do tradutor para proteger o conjunto de arquivos e a resolução dos caminhos.

## Out of Scope

- Traduzir novamente conteúdo do repositório alvo ou alterar a superfície .agents deste checkout.
- Mudar o contrato de que plugins/quenching é a única fonte editável.
- Alterar a semântica visual do CSS além de restaurar a paridade.

## Design

O diretório assets/zensical é payload inerte e deve preservar seu prefixo no espelho Codex, ao contrário de assets/checks e assets/knowledge, que são superfícies ativas e continuam mapeadas para checks e knowledge. A exceção será declarada no tradutor e coberta por teste, evitando que a convenção genérica produza um caminho que nenhuma skill consegue resolver.

A regeneração usa o tradutor oficial com --write. A folha de estilos local é substituída pela cópia payload, mantendo uma única fonte visual para o contrato que o dogfooding pretende exercer. O manifesto continua sendo derivado pelo próprio tradutor.

## Alternatives Considered

- Alterar as skills Codex para apontarem para zensical na raiz — rejeitado porque esconderia a distinção documentada entre payload inerte e superfície ativa.
- Copiar assets/zensical em dois caminhos — rejeitado porque cria duplicidade e um novo ponto de drift.
- Atualizar apenas .generated-from.json — rejeitado porque o payload ausente continuaria sem ser distribuível.

## Open Decisions

- none — o caminho Codex assets/zensical e o CSS payload são a paridade adotada nesta spec.

## Risks

- A regeneração pode mudar outros arquivos traduzidos — mitigado por sync --check, manifesto e revisão do diff limitado ao gerado.
- CSS pode depender de classes que a configuração local não usa — mitigado pelo build dogfooded e pelo checker visual/HTML das specs irmãs.
- O payload crescer e aumentar o custo do plugin — mitigado mantendo apenas os arquivos já declarados como site layer.
