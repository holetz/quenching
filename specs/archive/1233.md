## Problem

A consulta de estado de PR do épico (1186 #1207, 1213 #1223) lê o repositório errado e a trava de arquivamento a ignora:

- `pr_states` em `plugins/quenching/assets/bin/quenching/specs/commands/epic.py:30-44` roda `gh pr view <número>` sem `cwd=root` e sem a `pr.url` gravada, enquanto `main` resolve `root` por `--root`. Reproduzido em 2026-10-08 com um `gh` falso no PATH: rodando `cq specs --root <repo> status --epic` de outro checkout, a chamada sai do cwd do processo e lê o PR #N do outro repositório (`MERGED`).
- `open_items`, a trava de arquivamento do épico, chama `derive_epic` sem consultar o estado do PR (a 1213 deixou de fora de propósito), então um épico ainda pode ser arquivado como `done` com um membro cujo PR não entrou.

Consequência: um membro não mergeado aparece como `done`, libera dependentes e deixa arquivar o épico — o falso `done` que 1186 e 1213 existiam para fechar.

## Proposal

- A PR-state lookup for an epic member runs from the repository named by `--root`, and uses the recorded `pr.url` when it is a URL, so it can never read another repository's PR.
- The epic archive gate (`promote --outcome done`) counts a member whose PR is not `MERGED`, or whose state could not be read, as open, exactly as `status --epic` does.

## Out of Scope

- Changing `derive_epic` or `member_state`: the derivation is pure and already marks `unmerged`/`unverified`; only the callers were wrong.
- Reading PR state for non-archived members: they are open by definition.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/specs/commands/epic.py` — `pr_states` takes `root`, targets `pr.url` else the number.
- `plugins/quenching/assets/bin/quenching/specs/parse/epics.py` — `open_items` accepts the PR lookup.
- `plugins/quenching/assets/bin/quenching/specs/commands/promote.py` — passes the lookup to `open_items`.
- `plugins/quenching/tests/test_specs_epics.py` — covers the cwd, the URL target and the gate.

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p test_specs_epics.py` exits 0.
- `bash scripts/verify_repo.sh` exits 0.
- A fake `gh` on PATH sees the `--root` directory as its cwd; an epic with a member whose PR is `OPEN` refuses `promote --outcome done` with `sp-open-tasks`.

## Design

- Decision: `pr_states(members, root, timeout)` passes `cwd=root` to `gh`, and prefers the recorded `pr.url` (it names the repository itself) over the bare number. Alternative: always the number with `cwd` only — rejected, a url is unambiguous even if root's remote differs.
- Decision: `open_items(info, members, pr_state=None)` forwards the lookup to the pure `derive_epic`; the caller (`promote`) performs the lookup, keeping the derivation pure. Default `None` keeps every other caller unchanged.
- Rule: a PR-state lookup always runs against the repository the command was pointed at, never the process cwd.

### Mapa de dependências

Dated 2026-10-08, from the working tree: `pr_states` is used by `load_epic` (status/next/add in `epic.py`) and now `promote.py`; `open_items` is used only by `promote.py`; no other file calls either.

## Alternatives Considered

- Moving the PR lookup inside `open_items`: rejected, it would make the parse layer shell out and break its purity.

## Open Decisions

## Risks

- A `pr.url` that is not http(s) falls back to the number with `cwd=root`; ACCEPTED — that is the pre-existing behaviour, now rooted.
- `promote` of an epic now calls `gh` once per archived member with a `pr:` record; a failed lookup keeps the epic from archiving as `done` (needs `--force`). ACCEPTED — that is the intended gate.
