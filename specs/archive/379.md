## Problem

Achado reproduzido pela revisão de correção do épico 358 (2026-11-24, PR #375, spec 370): `cd integrations/opencode-vitrine && node --experimental-strip-types -e 'import("./src/warnings.ts").then(m=>m.localWarnings("/nonexistent")).then(console.log,e=>console.log("ERR",e.name,e.message))'` imprime `ERR ReferenceError first is not defined`. O merge 493e0dfc3 apagou `async function first(paths: string[])`, e `integrations/opencode-vitrine/src/warnings.ts:106` ainda faz `const project = await first([join(root, "opencode.json"), join(root, "opencode.jsonc")])`; o chamador `integrations/opencode-vitrine/src/quenching.ts:107` (`warnings: installed ? await localWarnings(root) : []`) não tem try/catch. O typecheck do gate pegaria, mas sai `SKIPPED` sem `node_modules` (`scripts/verify_repo.sh:336`), e `bench/warnings.check.mjs` só testa `configWarnings`.

**Consequência:** em todo repositório com quenching instalado, a chamada de status do plugin OpenCode quebra — o painel e os avisos da 234 somem; bloqueia o release 7.16.0.

Proposta: restaurar o helper (ou usar o leitor que a 370 introduziu) e cobrir `localWarnings` no bench com um projeto real; considerar que o gate rode o typecheck quando o diff toca `integrations/opencode-vitrine/` e `node_modules` falta (instalar com `npm ci` ou falhar em vez de SKIPPED).

## Proposal

- `localWarnings(root)` volta a devolver a lista de avisos sem lançar: a chamada de status do plugin OpenCode deixa de quebrar com `ReferenceError: first is not defined` em todo repositório com quenching instalado.
- O bench `integrations/opencode-vitrine/bench/warnings.check.mjs` passa a exercer `localWarnings` sobre um projeto real em disco (diretório temporário com `opencode.jsonc`, `XDG_CONFIG_HOME` e `OPENCODE_CONFIG` isolados), não só `configWarnings`.
- O gate `scripts/verify_repo.sh` roda esse bench com `node --experimental-strip-types` sempre que `node` está no PATH e o escopo inclui `integrations/` — sem depender de `node_modules`, de modo que a mesma regressão sai vermelha mesmo quando o typecheck sai `SKIPPED`.

## Out of Scope

- Fazer o gate instalar dependências (`npm ci`) ou falhar quando `node_modules` falta: muda a política do gate (rede, tempo, CI) para todos os contribuidores; fica como `## Discoveries` para uma spec própria. O bench sem dependências cobre a classe de regressão desta spec.
- Mudar `configWarnings`, os nomes globais (`GLOBAL_NAMES`) ou a ordem de leitura que a 370 fixou.
- Envolver a chamada de `quenching.ts:107` em try/catch: esconderia a próxima regressão em vez de prová-la.

## Validation

- `cd integrations/opencode-vitrine && node --experimental-strip-types -e 'import("./src/warnings.ts").then(m=>m.localWarnings("/nonexistent")).then(console.log,e=>console.log("ERR",e.name,e.message))'` imprime um array de avisos (dois avisos para um projeto inexistente sem global configurado), nunca `ERR ReferenceError`.
- `node --experimental-strip-types integrations/opencode-vitrine/bench/warnings.check.mjs` imprime `ok` e sai 0; contra a árvore de base (sem o helper) sai não-zero.
- Com `npm ci` em `integrations/opencode-vitrine`, `npx tsc --noEmit -p integrations/opencode-vitrine` sai 0.
- O gate (`QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh`) mostra o passo `opencode-vitrine warnings bench` verde.

## Design

- **Restaurar `first(paths)` como estava antes do #375** (devolve o primeiro arquivo JSONC legível): é a forma mínima, e a ordem do projeto (`opencode.json` antes de `opencode.jsonc`) fica a que o deploy e a 370 já assumem. `globalConfigs()` continua como a 370 deixou.
- **O bench prova o caminho de I/O, não só a função pura**: cria um diretório temporário com `opencode.jsonc` (comentário + vírgula final), aponta `XDG_CONFIG_HOME` para um diretório vazio e apaga `OPENCODE_CONFIG` antes de importar, e afirma que `localWarnings` resolve para zero avisos no projeto configurado e dois no diretório vazio. Variáveis de ambiente são lidas por chamada, então ajustá-las no processo do bench basta.
- **O gate roda o bench pela condição de integrações** (`RUN_INTEGRATIONS`, a mesma dos outros plugins) e por `command -v node`; sem `node`, o pulo é declarado como no typecheck. O bench não usa `node_modules`, então não herda o `SKIPPED` do typecheck — é isso que fecha o buraco que deixou o #375 passar.
- Contrato que não pode ser contradito: `docs/standards/workflows/task-execution.md` (prova pela superfície real) e a política do épico 378 (2026-11-24: develop autônomo, PR sem merge por este runner).

### Assumptions

- `node >= 22.6` (strip-types) está disponível onde o gate roda o passo; sem ele o passo é pulado com motivo — afeta `## Validation` e a task 1.2.

## Alternatives Considered

- **Reescrever `localWarnings` com `read()` direto sobre `opencode.json` e depois `opencode.jsonc`, sem helper**: equivalente em comportamento, mas duplica a lógica de "primeiro legível"; restaurar o helper é o diff menor e o que existia antes.
- **Só exigir o typecheck no gate (npm ci)**: pegaria o erro, mas depende de rede e de instalar electron/vite; rejeitado nesta spec (ver `## Out of Scope`).

## Open Decisions

- none — o reparo e a cobertura são determinados pelo `## Problem`; a política de `npm ci` no gate está fora de escopo e parqueada em `## Discoveries`.

## Risks

- O passo novo do gate falhar em máquinas sem `node` 22.6+ — mitigação: o passo só roda com `node` no PATH e o bench usa só `node:` built-ins; versões sem strip-types falham visivelmente, não silenciosamente. ACCEPTED — o repositório já exige node 22 para a vitrine.
- O bench vazar o ambiente do desenvolvedor (ler o `~/.config/opencode` real) — mitigação: o bench fixa `XDG_CONFIG_HOME` e remove `OPENCODE_CONFIG` antes das chamadas.

## Outcome

Entregue: `localWarnings` voltou a ler o `opencode.json(c)` do projeto pelo helper `first()` que o merge do #375 apagou, então a chamada de status do plugin OpenCode não lança mais `ReferenceError`. O bench `integrations/opencode-vitrine/bench/warnings.check.mjs` agora exerce `localWarnings` sobre um projeto real em disco (com ambiente global isolado), e `scripts/verify_repo.sh` roda esse bench sem `node_modules` sempre que há `node` com strip-types — a classe de regressão que passou pelo typecheck `SKIPPED` agora fica vermelha no gate.
