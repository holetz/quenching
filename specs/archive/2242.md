## Problem

Evidência reproduzida em repositório descartável (scout da rodada 6 do autopilot 2026-11-21, origin/main 7bb9bc8ef):

1. `quenching/assets/bin/quenching/git/stale.py:32-34` usa `for-each-ref --merged <base>` sem exigir commits próprios. Uma branch `plan/9-fresh` criada em main com `git branch`, sem commits, sai como `branch plan/9-fresh candidate ['merged']`, e `cq git prune --branch plan/9-fresh` imprime `pruned branch plan/9-fresh`, exit 0. O mesmo vale para remotas em `stale.py:57` (`origin/plan/7-remote-fresh` → `candidate ['merged']`).
2. `stale.py:391` adiciona o motivo `gone`, e o guarda `unmerged-commits` (`stale.py:403`) só se aplica quando não há motivo nenhum. `plan/8-gone`, com um commit fora de main e remota apagada, sai `candidate ['gone']`; `cq git prune --branch plan/8-gone` falha com exit 1: "the branch 'plan/8-gone' is not fully merged".

Consequência: (1) uma branch recém-cortada para uma spec, registrada em `branch.work` mas ainda sem commits, é oferecida como segura e apagada (com `gh` disponível, `recommended` vira True) — o mesmo erro "ancestral = mesclada" que 2235 corrigiu no reconcile; (2) toda branch squash-mesclada ou abandonada aparece em toda limpeza como candidata que o prune recusa. 1721 trata da base comparada, não disto.

## Proposal

- `cq git stale` só lista uma branch local como candidata `merged` quando ela é ancestral da base **e** tem commits próprios; uma branch sem commits próprios (recém-cortada) sai em `keptBranches` com o motivo `no-own-commits`, e `cq git prune --branch` a recusa com `git-prune-not-reported` (exit 2).
- Uma branch `gone` com commits fora da base sai em `keptBranches` com `["gone", "unmerged-commits"]`, nunca como candidata; `gone` continua sendo motivo adicional de uma candidata já mesclada (`["gone", "merged"]`).
- Uma branch remota (`origin/<b>`) cujo ponto está na cadeia de primeiro pai da base e que não tem branch local homônima com commits próprios deixa de ser listada em `remoteBranches`.
- O que já era candidato legítimo (branch com commits próprios mesclada por merge commit ou por fast-forward local) continua candidato.

## Out of Scope

- A base comparada (`origin/<base>` versus `<base>` local) — é da spec 1721.
- A avaliação de worktrees e slots (`_assess_worktrees`, `heldSlots`): um slot livre na ponta da base é elegível por desenho, e a reivindicação de slot já exige trabalho próprio (`slots._merged_holder`).
- Uma lista `keptRemoteBranches` para remotas preservadas: remotas não mescladas já não são listadas hoje; acrescentar a lista muda o contrato do payload sem pedido.
- Detectar squash-merge (pela PR mesclada no host): a branch squash-mesclada passa a ser preservada com motivo honesto; oferecê-la exigiria `branch -D`, que o prune proíbe.

## Design

### Regra: "mesclada" exige commits próprios

Uma branch é candidata a apagar só quando é ancestral da base **e** há evidência de que carregou trabalho próprio. Ancestralidade sozinha não basta: uma branch recém-cortada é um commit da própria base, ancestral como uma mesclada. É a mesma regra que 2235 aplicou ao `merge_evidence` do reconcile e que `slots._merged_holder` aplica à reivindicação de slot.

### Evidência de commits próprios

- **Branch local:** o reflog de `refs/heads/<b>` mostra que a ponta saiu do commit da criação (entrada mais antiga ≠ ponta), como em 2235. Sem reflog, ou reflog que não se moveu, vale o critério do grafo: a ponta **não** está na cadeia de primeiro pai da base (`git rev-list --first-parent <base>`). Uma branch mesclada por merge commit tem a ponta como segundo pai, fora dessa cadeia; uma recém-cortada está nela.
- **Branch remota:** o reflog de um ref remoto começa num fetch/push que já trazia a ponta, então não distingue. Vale o critério do grafo, ou a branch local homônima com commits próprios (cobre o fast-forward local seguido de push da base).
- O conjunto do primeiro pai é lido uma vez por relatório.

### Regra: `gone` não torna candidata

`gone` (upstream apagado) é motivo adicional, nunca suficiente: o prune usa `branch -d`, que recusa uma branch não mesclada, e oferecer o que o prune recusa é ruído em toda limpeza. Uma branch `gone` não mesclada é preservada com `["gone", "unmerged-commits"]`; `gone` sem commits próprios fica `["gone", "no-own-commits"]`.

### Motivos de preservação

`unmerged-commits` (não ancestral da base), `no-own-commits` (ancestral sem evidência de trabalho próprio), `open-pr`, `worktree`. O payload não muda de forma: só a classificação.

### Assumptions

- A cadeia de primeiro pai da base cabe numa leitura por relatório (milhares de commits) — `## Risks`.

## Alternatives Considered

- **Só o reflog, como 2235, inclusive para remotas** — rejeitada: o reflog de um ref remoto começa já na ponta empurrada, e um reflog local expirado deixaria toda branch antiga mesclada como `no-own-commits` para sempre.
- **Só o primeiro pai** — rejeitada: um fast-forward local põe a ponta na cadeia do primeiro pai e a branch mesclada nunca mais seria oferecida; o reflog cobre esse caso.
- **Detectar squash-merge pela PR mesclada no host e apagar com `-D`** — rejeitada: `prune` só usa as formas seguras por contrato.

## Open Decisions

- none — as decisões de forma saíram do código e da regra de 2235; nada depende de apetite humano.

## Risks

- Uma branch mesclada por fast-forward local cujo reflog expirou passa a ser preservada como `no-own-commits`. ACCEPTED — o erro é do lado seguro (preserva em vez de apagar) e `git branch -d` manual continua possível.
- Uma remota mesclada por fast-forward local sem branch local homônima deixa de ser oferecida. ACCEPTED — mesmo lado seguro; o fluxo deste repositório mescla PRs com merge commit.
- Custo de `rev-list --first-parent` em histórico longo. Mitigação: uma leitura por relatório, em conjunto.

## Outcome

Entregue: `cq git stale` passa a exigir commits próprios para chamar de `merged` uma branch ancestral da base — reflog que saiu do commit de criação ou, sem ele, ponta fora da cadeia de primeiro pai da base. Uma branch recém-cortada sai em `keptBranches` com `no-own-commits` e o `cq git prune --branch` a recusa (`git-prune-not-reported`). Uma branch `gone` com commits fora da base fica em `keptBranches` com `["gone", "unmerged-commits"]`; `gone` segue como motivo adicional de candidata mesclada. `remoteBranches` deixa de listar a remota cuja ponta está na cadeia de primeiro pai sem branch local homônima com commits próprios. Código em `quenching/assets/bin/quenching/git/stale.py` (espelho deployado em dia), testes em `quenching/tests/test_git.py` e `test_git_cleanup.py` (fixtures de branch "mesclada" passaram a ter commit próprio + merge `--no-ff`).

Fora: o critério não reaproveita `has_own_work` de `quenching/git/slots.py`; para remotas o reflog de remote-tracking não prova nada, então só a branch local homônima ou a ponta fora da cadeia contam. `keptBranches` agora lista todos os motivos verdadeiros (ex.: `["no-own-commits", "worktree"]`).
