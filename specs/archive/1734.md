## Problem

`test_red_cleanup_restores_checkout_bytes_and_removes_worktree` (`plugins/quenching/tests/test_specs_execute.py:72`, at origin/main d32cf79b) flaked on CI. Run 38787921159 attempt 1, job Gate Python 3.13, subtest `carrier=execution.md mode=attributes`, failed with `OSError: [Errno 39] Directory not empty: '.../.git'` raised by the `tempfile.TemporaryDirectory()` cleanup opened at line 84. Attempt 2 passed. The runner had git 2.55.0. It does not reproduce locally: git 2.43, 40 of 40 runs pass.

Probable cause (hypothesis, not confirmed): git 2.47 and later run auto maintenance detached after `commit`, so a background process is still writing under `.git` while `TemporaryDirectory` removes the tree. Consequence: the gate goes red on an unrelated change, and a retry hides it.

Scope: stop background writes in the test's temporary repositories by setting `maintenance.auto false` and `gc.auto 0` after `git init`, or accept the race with `TemporaryDirectory(ignore_cleanup_errors=True)`. Prefer the setting that removes the cause. Apply it to every repository the test file creates under a temporary directory.

## Proposal

- Every temporary git repository created by `plugins/quenching/tests/test_specs_execute.py` has `maintenance.auto` set to `false` and `gc.auto` set to `0` right after `git init`, so no detached background git process can write under `.git` during cleanup.
- `test_red_cleanup_restores_checkout_bytes_and_removes_worktree` no longer fails with `OSError: [Errno 39] Directory not empty` when the runner's git detaches maintenance after `commit`.

## Out of Scope

- `TemporaryDirectory(ignore_cleanup_errors=True)`: hides the race and any real leak instead of removing the cause.
- Pinning or downgrading the CI git version: the runner image is not this repository's to control.
- Other test files: only the three `git init` sites in this file are evidenced; no other file was seen failing.

## Design

- Rule: a test that creates a temporary git repository and later deletes it disables background maintenance in that repository (`git config maintenance.auto false`, `git config gc.auto 0`) immediately after `init`. This removes the cause rather than tolerating the cleanup error.
- Alternative weighed: `ignore_cleanup_errors=True` is rejected (see Out of Scope); a shared helper is not worth it for three two-line sites in one file.
- Assumption named: git 2.47 and later start auto maintenance detached after `commit`, and the runner had 2.55.0; the log confirms the symptom, not the mechanism.
