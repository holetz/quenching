## Problem

`plugins/quenching/agents/verifier.md` declara `Bash(git branch:*)` no `tools:`, e esse prefixo admite `git branch -D` e `git branch -m`, embora o agente seja documentado como somente leitura ("Read-only; never edits or fixes"). A spec 1168 já estreitou os outros verbos de git do verifier para leitura (`git reflog show`, `git merge-base`, `git rev-list`). A revisão de segurança do épico 1163 (spec 1180, decisão 0009) registrou o achado nas Discoveries.

Consequência: um verifier pode apagar ou renomear o branch que está auditando sem pedir permissão, o mesmo tipo de ação destrutiva que o épico 1163 tirou do spec-runner.

## Proposal

- O `tools:` do verifier deixa de conter `Bash(git branch:*)`; nenhum verbo de git que escreva refs fica concedido a ele.
- Todas as verificações documentadas no corpo do verifier continuam possíveis só com os verbos de leitura restantes.

## Out of Scope

- `Bash(git branch:*)` do orchestrator: outro agente, outra superfície; fica como Discovery.
- Os `allowed-tools` de comandos (`git/cleanup`, `git/merge`): esses precisam apagar branches de propósito.

## Impact

### Standards this spec will write into docs/standards/

- none — a mudança estreita uma concessão, sem regra nova.

### Product code this spec expects to touch

- `plugins/quenching/agents/verifier.md` — a linha `tools:` do frontmatter.

## Validation

- `grep -c 'git branch' plugins/quenching/agents/verifier.md` deve imprimir 0 depois da mudança (hoje imprime 1; o corpo não usa o verbo, só a palavra "branch" como argumento de `git log`/`git diff`/`git reflog show`).
- `bash scripts/verify_repo.sh` sai 0.

## Design

- Regra durável: um agente declarado somente leitura recebe só verbos de git de leitura. `git branch:*` admite `-D` e `-m`; o verifier não precisa de listagem, pois recebe o branch ou a worktree como entrada, e `git worktree list` cobre a descoberta.
- Alternativa pesada e descartada: trocar por `Bash(git branch --show-current:*)`. O prefixo ainda admitiria argumentos extras e nenhuma verificação o usa.

### Mapa de dependências (2026-10-07)

- `plugins/quenching/agents/verifier.md` — único arquivo editado; nada o referencia pelo valor de `tools:`.
- `plugins/quenching/tests/` e `plugins/quenching/assets/checks/` — não afirmam sobre o `tools:` do verifier (grep vazio).

## Alternatives Considered

- Manter o prefixo e confiar no texto "somente leitura": perdeu, pois a permissão é o que o harness aplica, não a prosa.

## Open Decisions

- none — o escopo é uma remoção de uma entrada, sem escolha em aberto.

## Risks

- O verifier precisar de `git branch` em alguma checagem: mitigado, o corpo não o usa; o gate e uma releitura do corpo confirmam.
