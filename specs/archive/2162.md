## Problem

Em quenching 7.0.0, cores DTCG com `alpha` diferente de 1 são projetadas em `/.design/build/tokens.typ` como um literal de string (`#let token-... = "rgb(0 0 0 / 0.5)"`) em vez de uma cor Typst, então todo uso do token em um template Typst renderiza o texto da função no lugar da cor. O relator contornou o problema no próprio repositório e pediu que ele fosse corrigido na projeção.

## Proposal

- `/.design/build/tokens.typ` passa a emitir valor de cor Typst para todo token DTCG num espaço que o Typst expressa — `srgb`, `srgb-linear`, `hsl`, `hsv`, `oklab` e `oklch` — com ou sem `alpha`.
- Um token com `alpha < 1` preserva a transparência: `fill:`, `stroke:` e `text(fill:)` aceitam o token e o documento compila. Hoje o token é uma string e o Typst recusa com `expected color, gradient, tiling, or none, found string`.
- Cor `srgb` opaca mantém a saída byte a byte de hoje (`rgb("#RRGGBB")`), então repositórios já instalados não veem churn em `tokens.typ`.
- Espaço que o Typst não expressa (`lab`, `lch`, `hwb`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz-d50`, `xyz-d65`) continua saindo como a string CSS de hoje, e a diferença fica registrada em `## Discoveries`.

## Out of Scope

- Converter `lab`, `lch`, `hwb`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz-d50` e `xyz-d65` para uma cor Typst: o repositório não faz conversão wide-gamut de propósito (`color_to_srgb` recusa e declara a conversão como explícita) e o Typst 0.15 não tem construtor para esses espaços. Fica como follow-up.
- Mexer em `color_to_css` ou em qualquer outra projeção (`tokens.css`, `DESIGN.md`, sidecar, `brand-api.md`): a mudança é local ao adaptador Typst.
- Mexer nos templates `.typ` do brand pack ou no `cq design render`/PDF: eles só consomem o token.
- Fazer o build falhar para espaço sem construtor Typst: quebraria repositórios instalados; a string atual é preservada.

### Decisões

- **A cor é projetada do valor DTCG, não da string CSS.** `_color_to_typst` lê `colorSpace`, `components` e `alpha` e escolhe o construtor; `color_to_css` fica intocado porque cinco consumidores dependem da sintaxe CSS.
- **`srgb` opaca preserva a saída atual.** `rgb("#RRGGBB")`, em maiúsculas, byte a byte: é o único caminho que já funcionava e mudá-lo geraria drift em todo repositório instalado.
- **`srgb` transparente vira `rgb(r, g, b, a%)`.** Componentes arredondados para 0–255 como `color_to_css` já faz; alpha como porcentagem na quarta posição, formato que o Typst 0.15 aceita.
- **Cada espaço usa o construtor nativo:** `color.linear-rgb(c%, c%, c%, a%)`, `color.hsl(hdeg, s%, l%, a%)`, `color.hsv(hdeg, s%, v%, a%)`, `color.oklab(l%, a, b, alpha%)` e `color.oklch(l%, c, hdeg, alpha%)`. Todos compilados com o binário 0.15.0 antes de escrever a spec.
- **Espaço sem construtor mantém a string CSS.** Determinístico e sem quebrar build; a lacuna fica visível em `## Discoveries` e em `## Open Decisions`.
- **`alpha` ausente é 1; `alpha` numérico é limitado a [0, 1].** Componentes já são limitados; o limite evita porcentagem fora da faixa, que o Typst recusaria. `alpha` não numérico é `DesignError`.
- **O helper fica em `build.py`.** Só o adaptador Typst precisa dele; `model.py` é compartilhado por CSS, `DESIGN.md`, sidecar, import e doctor.

### Contratos que o desenho não pode contradizer

- `docs/standards/architecture/design-front.md:50`: adaptadores internos projetam "values from the same DTCG graph at runtime" — a correção faz o adaptador cumprir o contrato, e nenhum texto de padrão muda.
- DTCG 2025.10: `alpha` é opcional, entre 0 e 1; `components` tem três valores.
- O padrão declara a projeção "deliberately lossy"; a string para espaço sem construtor é a perda declarada.

### Assumptions

- O relator usa `srgb` (hex com alpha) ou um espaço que o Typst expressa; `## Open Decisions` cobre a confirmação no issue, e a lacuna de espaço não suportado fica em `## Out of Scope`.

## Alternatives Considered

- **Traduzir a saída de `color_to_css` para sintaxe Typst.** Rejeitada: `rgb(r g b / a)`, `oklch(...)` e `color(...)` não são expressões Typst; converter string em string deixa o adaptador dependente de um formato feito para CSS, e `color_to_css` é compartilhado.
- **Corrigir só `srgb` com alpha.** Rejeitada: resolve o caso hex, mas o mesmo defeito continua em `oklch`/`oklab`/`hsl` com transparência, que é o caso de design systems modernos.
- **Converter todo espaço para sRGB no build e emitir `rgb(...)`.** Rejeitada: contradiz a decisão explícita do repositório de não converter wide-gamut (`color_to_srgb`), acrescenta colorimetria ao build e muda a saída de cores que hoje são string sem que ninguém tenha pedido.

## Open Decisions

- **Qual `colorSpace` os tokens transparentes do relator usam.** Decide-se perguntando no issue que originou a spec; se for um dos espaços de `## Out of Scope`, a conversão vira spec própria.

## Risks

- **Expressão Typst inválida só descoberta ao compilar PDF.** Mitigação: o teste fixa a string exata dos seis construtores e um teste condicional compila com o `typst` real quando ele resolve; o Typst não é dependência de CI, então o skip é declarado.
- **Drift em `tokens.typ` de repositórios instalados.** Mitigação: `srgb` opaca mantém a saída byte a byte; `cq design build` regenera o resto.
- **Queda do piso de cobertura (76.5).** Mitigação: o teste novo cobre os seis ramos e roda no gate.
- **`alpha` fora de [0, 1] silenciosamente limitado.** ACCEPTED — o DTCG declara 0–1; limitar mantém o build determinístico e espelha o limite que `color_to_css` já aplica aos componentes sRGB.
