## Problem

A spec 1041662 do databricks-risco-gold está arquivada como `done`, mas a mudança dela no quenching (o `boards_gate` antes do `cq git push` e do `cq git pr create`, `sp-az-unauthenticated`) existe só na branch local `plan/1041662-preflight-login-boards` do checkout `~/Projetos/quenching-1041662`. Ela já foi rebaseada quatro vezes (7.18.0, 7.18.2, 7.18.3, 7.19.0 — `38bf082fc`, self-host `173f29877`, 365 testes do `test_git.py` verdes), e todo deploy feito de uma tag do quenching a apaga. Precisa entrar no holetz/quenching por PR para deixar de depender de rebase manual.

Minimal fix proposed: abrir o PR da branch rebaseada sobre a `main` atual com o gate do quenching verde e, depois do merge, implantar a próxima tag a partir da `main`.

**Insumos**

- `~/Projetos/quenching-1041662`, branch `plan/1041662-preflight-login-boards`
- databricks-risco-gold `docs/project/quenching.md` (histórico dos rebases do lote)
- Spec de origem: 1042262 (databricks-risco-gold, PR 234120), 2026-11-27.

## Proposal

Levar para a `main` do holetz/quenching, por PR, a mudança da branch local `plan/1041662-preflight-login-boards`: `cq git push` e `cq git pr create` leem o Boards do projeto resolvido (um `az rest` GET no audience do Azure DevOps) antes de escrever no remoto e recusam com `sp-az-unauthenticated` e o remédio `az login --allow-no-subscriptions`. A mudança é reaplicada (cherry-pick dos commits `38bf082fc` e `173f29877`) sobre a `main` atual, com a superfície implantada regenerada por `cq deploy --target . --write`. Depois do merge, a próxima tag sai da `main`.

## Out of Scope

- Alterar o comportamento do preflight em relação ao que a branch local já implementa.
- Publicar a tag ou implantar nos repositórios consumidores (é o release, depois do merge).
