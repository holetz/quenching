## Problem

`cq ops doctor` never emits `op-registry-malformed` when the registry file is not valid UTF-8. Evidence at origin/main d32cf79b: `plugins/quenching/assets/bin/quenching/ops/checks.py:68-72` (`_registry_text`) catches `UnicodeDecodeError` together with `OSError` and returns `None`, and `check_registry_stale` (`checks.py:109-111`) treats `None` as "no registry" and returns `[]`. The contract says otherwise: `docs/standards/architecture/ops-front.md:216` defines `op-registry-malformed` as a registry whose generated zone is duplicated or whose file is not valid UTF-8, and `plugins/quenching/assets/references/ops-align/bands.md:60` repeats it.

Reproduction: a MalformedRegistry fixture (`ops.opsRoot=scripts`, router `pyproject.toml`) with `scripts/README.md` holding the bytes `b'\xff\xfe not utf-8\n'`. `cq ops registry` refuses with exit 2, "registry document is not valid UTF-8". `cq ops doctor --json` exits 1 and reports only `op-adhoc-root`, `op-orphan` and `op-undocumented`, with no `op-registry-malformed`. Consequence: doctor points at a regeneration (`op-undocumented`) that `cq ops registry --write` refuses, so the owner gets no finding that names the real defect.

Scope: read the registry through `registry.read_registry`, map `RegistryError` to `op-registry-malformed`, and keep `None` only for a missing file. Add a doctor test for invalid UTF-8 in `plugins/quenching/tests/test_ops.py`.

## Proposal

- `cq ops doctor` emits `op-registry-malformed` (path and refusal message) when the registry file is not valid UTF-8.
- A missing registry file still yields no `op-registry-malformed` and no `op-registry-stale`.
- A doctor test covers invalid UTF-8 in the registry.

## Out of Scope

- Changing `op-undocumented` for an unreadable registry: it keeps firing, as the contract lists it independently.
- Changing `cq ops registry` refusals (exit 2): already correct.
- Other `OSError` causes (permissions): they stay "no registry"; the contract names only duplication and invalid UTF-8.

## Design

- Rule: a registry that exists but cannot be read as UTF-8 is `op-registry-malformed`, the same finding the duplicated-zone case already produces; `registry.read_registry` is the single reader so doctor and `cq ops registry` cannot disagree.
- `check_registry_stale` returns `[]` when the registry path does not exist, otherwise calls `registry.read_registry` and `render_registry_document` inside one `try` that maps `RegistryError` to the finding. `_registry_text` stays for `check_undocumented` (None still means unreadable there).
- Contract: `docs/standards/architecture/ops-front.md:216` and `ops-align/bands.md:60` already describe this behaviour; no doc changes.

## Alternatives Considered

- Make `_registry_text` raise: rejected, it would break `check_undocumented`, which must keep reporting entries as undocumented.

## Open Decisions

- none — behaviour is fixed by the standard cited in Design.

## Risks

- A permission error on the registry still reads as absent: ACCEPTED — outside the contract's two named causes.
