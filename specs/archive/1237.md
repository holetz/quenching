## Problem

A 1199 (#1220) tirou `required=True` de `--spec` em `show` e `parallel` e moveu a exigência para `plugins/quenching/assets/bin/quenching/specs/commands/cli.py:368`, mas o lint de chamadas `cq` (`components/cq_calls.py:198`) só enxerga `a.required`. Reproduzido em 2026-10-08: `cq specs show --task 1.1` e `cq specs parallel --json` dão `[]` no lint, e antes davam `sk-cq-flag`; o teste foi trocado para `specs task` em vez de manter o caso de `show`.

Consequência: um command ou agente que chama `show`/`parallel` sem id passa no `cq components lint` e só falha na execução — a guarda que a 1149 criou para os agentes perdeu esses dois verbos.

## Proposal

- `cq components lint` flags `cq specs show` and `cq specs parallel` called without a spec id (neither positional nor `--spec`) as `sk-cq-flag`, as it did before 1199.
- The verbs that need the id declare it in one place (`add_spec`), so the lint and the runtime guard read the same fact.

## Out of Scope

- Restoring `required=True` on `--spec`: 1199 removed it so the positional form works.
- Checking the id's value or other positional arguments: the lint checks presence only.

## Impact

### Standards this spec will write into docs/standards/

- none — the change is a lint fix, it proves no new rule.

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/specs/commands/cli.py` — `add_spec` stamps a parser default
- `plugins/quenching/assets/bin/quenching/components/cq_calls.py` — `_check` reads it
- `plugins/quenching/tests/test_components_lint.py` — regression cases

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p test_components_lint.py` exits 0, including the new cases.
- A fenced `cq specs show --task 1.1` and `cq specs parallel --json` give `sk-cq-flag`; `cq specs show 12 --task 1.1` and `cq specs status` stay clean.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: `add_spec(sp, required)` calls `sp.set_defaults(id_required=required)`, and `_check` appends `--spec` to `missing` when the parser's `id_required` is true, no positional token was seen and `--spec` was not given. Durable rule: a requirement enforced after parsing must be declared on the parser, or the lint cannot see it.
- Alternative weighed: importing `SPEC_POSITIONAL` from the specs pillar into the lint; rejected because it couples the lint to one pillar and the verb names.
- Inline spans that only name the verb and flags still cite the verb and are not flagged (existing rule), so the regression cases use fenced calls.

## Alternatives Considered

- Reverting 1199's `required=True` removal: rejected, it breaks `cq specs show <id>`.

## Open Decisions

- none — nothing is left undecided.

## Risks

- A command body that cites `cq specs show --task <id>` without an id in a fenced block now fails lint. Mitigation: that call fails at runtime too; the repo gate surfaces it.
