## Problem

No autopilot de 2026-11-20 (épico 2207), o teste `TheCeiling` de `quenching/tests/test_git_worktree_slots.py` (tomadores concorrentes de slot) falhou uma vez sob carga durante os gates da 2179 e da 2158 e passou ao ser rodado de novo, segundo o relatório do orchestrator. A suíte roda paralela e randomizada (xdist, 2121), então um teste de concorrência que depende de tempo deixa o gate local vermelho de forma intermitente — o mesmo padrão da 2208.

**Insumos**

- `quenching/tests/test_git_worktree_slots.py` (classe `TheCeiling`) e `quenching/assets/bin/quenching/git/slots.py`
- relatório do orchestrator do épico 2207, 2026-11-20 (falha nas execuções da 2179 e da 2158, verde na repetição)
- O primeiro passo é reproduzir (ex.: `python3 -m pytest -q quenching/tests/test_git_worktree_slots.py -k TheCeiling -n 8 --count` em laço) antes de qualquer correção; nunca skip nem xfail.

## Proposal

- `TheCeiling::test_concurrent_takers_get_distinct_slots_and_the_extra_one_is_refused` passes deterministically when the host is busy: the loser of the race is refused with `git-worktree-slots-full`, never with a transient fetch error.
- The fix is in `slots.py`, in the fetch retry, with the test unchanged.

## Out of Scope

- Skipping, `xfail`ing or loosening the test: refused by the epic's decision.
- The slot-cleanup behaviour of 2209, which follows this spec on `slots.py`.

## Impact

### Standards this spec will write into docs/standards/

- none — a bug fix with no new rule.

### Product code this spec expects to touch

- `quenching/assets/bin/quenching/git/slots.py` — the retry predicate in `_fetch_base`.

## Validation

- Before: 14 concurrent rounds of `.venv/bin/python -m pytest -n 8 quenching/tests/test_git_worktree_slots.py`, repeated 6 times, failed in 5 of 84 runs, each with `git-worktree-fetch-failed` at test line 149.
- After: the same load, repeated 8 times, passed 112 of 112.
- `python3 -m pytest quenching/tests/test_git_worktree_slots.py` passes.

## Design

- **Cause (diagnosed).** Several takers `git fetch` into one repository while another taker runs `git worktree add`. The fetch's connectivity check reads the sibling worktree's HEAD before git finishes writing it, and fails with `fatal: bad object worktrees/<slot>/HEAD … did not send all necessary objects`. `_fetch_base` retries only a `.lock` error, so this transient failure becomes `git-worktree-fetch-failed` and the test sees it in place of `slots-full`.
- **Fix.** The same bounded retry (5 attempts, growing sleep) also covers `bad object worktrees/` errors. The change is two lines and a comment.
- **Reproduction.** `pytest-repeat` is not installed; load comes from 14 concurrent `pytest -n 8` processes per round.

## Alternatives Considered

- Serialising fetches behind a lock: a larger change to `slots.py`, which 2209 touches next.
- Retrying on any fetch failure: would mask a real unreachable remote behind five sleeps.
- Skipping or `xfail`ing the test: forbidden by the epic.

## Open Decisions

- none — the diagnosis determines the fix.

## Risks

- The retry matches git's message text; ACCEPTED — the existing `.lock` retry does the same, and an unmatched variant degrades to the old behaviour (a clear `git-worktree-fetch-failed`).

Task 1.1 is committed (cc481f5): `_fetch_base` in `slots.py` now also retries `bad object worktrees/`. The execute gate remains; conclude is a separate spawn.
