## Problem

O brand pack promete que fontes licenciadas podem ser versionadas como assets, mas a renderização PDF não as registra no mecanismo tipográfico e cai silenciosamente em fallback quando a família não está instalada. A fonte declarada também não é validada pelo doctor, então um artefato pode sair com tipografia incorreta sem finding.

## Proposal

- Treat fontFamily as a first-class DTCG token and validate its quenching font metadata: source kind, local files or directories, and license declaration.
- Allow typography tokens to reference fontFamily tokens without losing the resolved family during CSS, Typst, DESIGN.md, or brand API projection.
- Pass every safe local font directory declared by the source to Typst PDF compilation, and emit a deterministic doctor error when a referenced family is unavailable from declared assets or the local font resolver.

## Out of Scope

- Reimplementing font installation, licensing, font conversion, or a font manager.
- Downloading webfonts during render or doctor; webfont metadata is descriptive and cannot make an offline build depend on the network.
- Changing the lossy DESIGN_COMPONENT_PROPERTIES projection boundary.

## Impact

- `plugins/quenching/assets/bin/quenching/design/model.py` — DTCG fontFamily metadata and reference validation.
- `plugins/quenching/assets/bin/quenching/design/genre.py` — Typst font-path arguments and family resolution during PDF rendering.
- `plugins/quenching/assets/bin/quenching/design/doctor.py` — font availability findings.
- `plugins/quenching/assets/bin/quenching/design/build.py` — preserve referenced fontFamily values in projections.
- `plugins/quenching/tests/test_design.py` — absent-system-font and PDF compilation coverage.
- `docs/standards/architecture/design-front.md` — binding one-source/multi-output boundary.

## Validation

- `python3 -m unittest plugins/quenching/tests/test_design.py` passes with a fixture whose font is absent from the system but present under `.design/assets/`.
- The fake Typst compiler receives one `--font-path` per declared font directory.
- A missing local family produces a finding with stable code, path, severity, and family name; a webfont-only family does not claim local availability.
- Existing build projections and all pre-existing design tests remain green.

## Design

- A fontFamily token keeps the DTCG `$type: "fontFamily"` value as a string or ordered string list. Quenching metadata lives in `$extensions.org.quenching.font`, with `source` in `local|webfont|licensed`, a non-empty `license`, and optional `files`/ `directories` paths relative to `.design/assets/`.
- Local and licensed entries resolve only inside `.design/assets/`; declared files contribute their parent directories, and declared directories must exist. Paths that escape the asset root are refused.
- A typography token may use a `{fonts.body}` reference in `fontFamily`; projection resolves it before formatting while preserving the token reference in generated CSS where that adapter already preserves references.
- PDF compilation receives `--font-path` arguments after `--root`, in sorted unique order. No system mutation or network access occurs.
- Doctor checks each family against declared local font files and, when an `fc-match` executable exists, the local font resolver. An unavailable family is an error; a webfont-only declaration is reported as intentionally non-local metadata.
- Dependency map (2026-08-30): `model.py` defines token metadata and path safety → `genre.py` consumes resolved font directories for PDF → `doctor.py` consumes the same model for availability findings → `build.py` consumes token values for projections; `test_design.py` covers all four without changing public component properties.

## Alternatives Considered

- Passing a project-wide `fonts/` directory unconditionally: rejected because it hides which assets a token owns and makes unrelated files affect rendering.
- Requiring every font to be installed system-wide: rejected because the promised asset-first workflow must work in a clean build environment.
- Storing font metadata only in generated DESIGN.md: rejected because DESIGN.md is a lossy projection and cannot be authoritative.

## Open Decisions

- none — the metadata keys, path root, fallback behavior, and offline policy are fixed by this design; fixture coverage decides only implementation details that do not change the contract.

## Risks

- A malformed font file may still be rejected by Typst after path resolution; the compiler error remains surfaced verbatim.
- System font discovery can vary by host; declared local assets are authoritative and the resolver is only an additional source, never a reason to ignore a missing declared file.
- Existing typography values may be strings without metadata; they remain valid and use the existing system-font behavior.
