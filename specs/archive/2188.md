## Problem

Three standards present `assets/checks/conclude-order-check.sh` as the living proof of conclude's ordering, and the script is gone from the repository. During spec 2187 (archive after the merge, 2026-11-13) the conclude order changed — `## Outcome` before the PR, the archive in a new step 8 after the merge — and there was no executable check to re-run against the new order; the prose cites a proof nobody can execute. The citation gate does not flag it because the citations sit in inline code inside prose, not as links. Whatever replaces it has to make a conclude-order claim either executable or not claimed.

**Insumos**

- `docs/standards/workflows/plan-git-record.md:392` — "This is proven, not merely agreed. `assets/checks/conclude-order-check.sh`'s `abandoned` arm builds …"
- `docs/standards/quality/surface-verification.md:158` and `:235` — the script named as the pattern for flow-order checks
- `docs/standards/quality/citation-verification.md:173`, `:186`
- `ls quenching/assets/checks/conclude-order-check.sh` → no such file (main at fcbc620ad)
- spec 2187, conclude step 6; the new order lives in `quenching/skills/quenching-specs/references/conclude.md` steps 4, 7 and 8, locked today only by the text tests `quenching/tests/test_specs_conclude_flow_sweep.py` and `test_specs_conclude_retire_worktree.py`

## Proposal

- Remove or rewrite every citation of `assets/checks/conclude-order-check.sh` in the standards, the assets README and the `next.py` docstring, pointing the conclude-order claim at the text tests that lock it today (`quenching/tests/test_specs_conclude_flow_sweep.py`, `test_specs_conclude_retire_worktree.py`), and saying plainly that no executable check proves it.
- No executable script is recreated.

## Out of Scope

- Recreating `conclude-order-check.sh` or any executable end-to-end check: it would be surface that executes, a human decision.
- `docs/decisions/0004-standards-source-lineage.md`: history, left as written.
