## Problem

O servidor `cq mcp` publica uma tool por verbo: 115 tools com o front opensource, 111 no SAFRA e 76 no mount `core`. Só o `tools/list` pesa cerca de 75 KB. Harnesses como o Copilot não conseguem listar esse volume, então perdemos mais do que ganhamos com o MCP. O motivo do MCP era evitar redisparar `cq` em Python a cada chamada, reimportando todos os módulos, e esse ganho vem do processo único, não do número de tools.

## Proposal

Trocar o catálogo de uma tool por verbo por uma tool por pilar e classe de permissão (`<pilar>_read`, `<pilar>_write`, `<pilar>_external`), cada uma com um argumento `verb` que escolhe o verbo. São no máximo 23 tools no total e 8 no mount `core` (specs, git e components). O dispatch em processo, o elicitation e a validação por verbo derivada do argparse ficam como estão.

## Out of Scope

- Redeployar os repositórios alvo (SAFRA e outros): cada um recebe o catálogo novo no próprio upgrade. Skills próprias de um alvo que citem nomes antigos ficam a cargo dele.
- Manter os nomes antigos como alias: manteria as 115 tools no `tools/list`, que é o problema.
- Aplicar no servidor o grant por verbo de cada sub-agente: o servidor não sabe qual agente chama. O recorte passa a ser por pilar e classe (ver `## Risks`).
- Trocar o MCP por um daemon com socket (ver `## Alternatives Considered`).

## Design

- Cada tool agrupada publica `verb` (enum dos verbos da classe, cada um com uma linha de descrição na description da tool), `args` aberto e `root`. A validação continua por verbo, com o schema que `catalog.resolve` deriva do argparse; um argumento inválido devolve o schema do verbo, e `verb="help"` devolve o schema sob demanda.
- As tools manuais de specs (`specs/mcp.py`) entram nas mesmas tools agrupadas, na classe do verbo.
- As anotações passam a valer para a tool inteira: `read` → `readOnlyHint`; `external` → `openWorldHint`; `destructiveHint` ligado na tool cuja classe tem algum verbo destrutivo.
- O nome da tool muda, mas a classe continua nele, então os grants dos sub-agentes (`translate.py`) continuam recortando por pilar e classe.
- A forma de citar nos corpos passa a ser `<pilar>_<classe>(verb="<verbo>", …)`. A reescrita das citações existentes é mecânica, feita por script.

### Decisões de execução

- **Nome lógico interno.** As tabelas atuais (`catalog.CATALOG` e `specs/mcp.py` `TOOLS`/`WRITES`) continuam como estão, chaveadas pelo nome lógico `<pilar>_<verbo>` (`git_state`). Uma camada nova, `mcp/grouped.py`, envolve o `Composite` e publica só as tools agrupadas. Assim o dispatch, a validação, o elicitation e as tabelas ficam intocados, e a mudança fica na borda.
- **Verbo = sufixo do nome lógico.** `verb` é o nome lógico sem o prefixo do pilar (`git_pr_merge` → `git_external(verb="pr_merge")`), então a reescrita é mecânica e o caminho de volta para o CLI continua sendo `_` como quebra de palavra.
- **Argumentos planos.** Os argumentos do verbo vão ao lado de `verb`, não num objeto `args` aninhado: a citação `git_state(root=X)` vira `git_read(verb="state", root=X)`, sem mudar o resto da linha. O schema publicado tem `verb` (obrigatório, enum) e `root`, com `additionalProperties: true`; a recusa de argumento desconhecido continua por verbo.
- **Classe das tools manuais de specs.** `TOOLS` → `read`; `WRITES` → `write`, exceto `specs_push` → `external` (publica no remoto).
- **`components_read` segue como nome.** É o nome agrupado da classe `read` de components, e a citação antiga passa a exigir `verb="read"`. Uma chamada sem `verb` é recusada com a lista de verbos.
- **Grants.** `catalog.tool_names(prefix)` passa a devolver os nomes agrupados que cobrem o prefixo, e `verb_names(prefix)` os nomes lógicos para quem precisa do verbo (coverage, lint, métricas).
- **Métricas de sessão.** `cqcalls` reconstrói o nome lógico a partir de `input.verb`, então os contadores por verbo continuam com a mesma granularidade.

## Alternatives Considered

- Só restringir o mount: o `core` já tem 76 tools, então não resolve.
- Três tools genéricas (`cq_read`, `cq_write`, `cq_external`): seria o mínimo possível, mas perde o recorte por pilar nos grants dos sub-agentes.
- Abandonar o MCP por um daemon com socket, com o `cq` como cliente fino: resolve a reimportação sem lista de tools, mas desfaz a forma de tool e os grants via MCP, a um custo bem maior.

## Open Decisions

- none — as decisões de forma (classes, nome do argumento `verb`, argumentos planos, `specs_push` como `external`) foram tomadas a partir da evidência e estão em `## Design`.

## Risks

- Mudar o nome das tools quebra skills de repositórios alvo que citam os nomes antigos; o redeploy regenera só o que o quenching gera. Mitigação: tag `breaking` e nota no release.
- Com o schema por verbo fora do `tools/list`, o agente pode errar o primeiro argumento; a resposta de erro com o schema do verbo é o que corrige isso.
- ACCEPTED — o grant de um sub-agente alarga de verbo para pilar e classe: o orchestrator, que tem `cq specs record` e `cq git pr merge`, passa a alcançar todo `specs_write` e `git_external` (inclusive `git_prune`). Os agentes só de leitura (scout, verifier, reviewer) continuam só com `*_read`. O corpo de cada agente continua dizendo o que ele faz, e o `destructiveHint` fica ligado na classe que tem verbo destrutivo, então o cliente pede confirmação.

## Outcome

**Entregue.** O servidor MCP `quenching` publica uma tool por pilar e classe (`<pillar>_read`, `<pillar>_write`, `<pillar>_external`), com o argumento obrigatório `verb`.
- **Medição** (2026-11-26): o `tools/list` completo foi de 115 tools e 74.986 bytes para 23 tools e 23.120 bytes; o mount core (specs, git, components) ficou com 8 tools e 11.276 bytes.
- `verb="help"` (opcionalmente com `of=<verb>`) responde os schemas dos verbos. Um argumento errado devolve o `inputSchema` do verbo, e um verbo desconhecido devolve `mcp-unknown-verb`.
- As tabelas internas continuam por nome lógico, e `mcp/grouped.py` é a borda publicada. `specs_push` passou à classe `external`.
- `catalog.tool_names` devolve os nomes publicados (são eles que os grants usam) e `catalog.verb_names` os lógicos (usados pelo coverage, pelo lint e pelas métricas).
- Mudaram junto com a forma agrupada:
  - os grants do deploy;
  - as métricas de sessão, incluindo o transcript do OpenCode, que agora guarda o `verb`;
  - o ledger do vitrine;
  - o lint de citação e o coverage de opções;
  - as 123 bodies, o contrato `tool-resolution.md`, quatro standards e o manual do MCP.

**Fica de fora.** Não há aliases para os nomes por verbo: é uma mudança quebradora para quem chamava `git_state` etc. direto. O ledger do vitrine ainda aceita os nomes antigos, para ler transcripts antigos. O grant passou a ser por pilar e classe; esse alargamento está aceito em `## Risks`.
