## Problem

Reproduzido pela revisão de correção do épico 1554 (2026-10-11), em `main` 71f8f356. A auditoria de tipos de agente
que a spec 1517 criou (`plugins/quenching/agents/orchestrator.md:89`, sobre
`plugins/quenching/assets/bin/quenching/session/commands/cost.py:86-90`) mede a sessão inteira, não os filhos do
orchestrator. `cq components session cost <sessão> --json` devolve linhas `general-purpose`, `quenching:orchestrator`,
`spec-architect` e `scout`, que foram todas lançadas pelo condutor. O `.meta.json` de cada agente traz
`parentAgentId` e `spawnDepth`, e esses têm `spawnDepth:1` sem `parentAgentId`, mas o `aggregate` ignora esses campos.

Consequência: como `quenching:orchestrator` não está no `Agent(...)` de `orchestrator.md:4`, toda execução de
autopilot reporta `AUDIT: unexpected agent type general-purpose; unexpected agent type quenching:orchestrator`, um
alarme falso que treina o condutor a ignorar a auditoria. O custo por orchestrator também soma os filhos de outros
orchestrators da mesma sessão. A correção é restringir a auditoria (e o custo do relatório) aos descendentes do
orchestrator, pelo `parentAgentId`.

Resíduo no mesmo pacote: `session/commands/cli.py:28` diz "outside the six-artifact lockstep", mas
`RELEASE_ARTIFACTS` (`specs/release.py:28-36`) tem 7 entradas.

## Proposal

- `cq components session cost` accepts `--descendants-of <agentId>` and `--nested`: with either, only agents found through `parentAgentId` (transitively from the id, or any agent that has a `parentAgentId`) enter the aggregate; without them, the output is unchanged.
- The orchestrator's AUDIT and its reported cost use that scope, so the orchestrator itself, the conductor's scouts, architects and reviewers no longer raise `AUDIT: unexpected agent type`.
- The `cli.py` header comment says seven artifacts, matching `RELEASE_ARTIFACTS`.

## Out of Scope

- Changing the `Agent(...)` list at `orchestrator.md:4` or the human's decision of spec 1517 (ADR 0012): this corrects the measurement only.
- Changing the default (unscoped) output of `cost`, which the conductor still reads for the whole session.
- Reading the orchestrator's own agent id from the environment: no such variable is documented, so the flag is explicit.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/session/commands/cost.py` — parent filtering in `aggregate`/`cmd_cost`.
- `plugins/quenching/assets/bin/quenching/session/commands/cli.py` — the two flags and the lockstep comment.
- `plugins/quenching/tests/test_session_cost.py` — regression tests.
- `plugins/quenching/agents/orchestrator.md` — telemetry line uses the scoped call.

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p 'test_session_cost.py'` exits 0.
- `bash scripts/verify_repo.sh` exits 0.
- With a fixture holding a root orchestrator, a root scout and two children of the orchestrator, `--descendants-of <orchestrator id> --json` lists only the children's types.

## Design

- Rule: an agent's membership is decided by its `agent-*.meta.json` `parentAgentId`. `--descendants-of ID` takes the transitive closure of children of `ID`, excluding `ID` itself; `--nested` takes every agent with a `parentAgentId`. The flags are mutually exclusive. An empty scope refuses with the existing `se-no-requests`.
- Why `--nested` exists: an orchestrator does not know its own agent id (assumption: no documented env var carries it), and its children are the only agents with a `parentAgentId` in a single-orchestrator session. orchestrator.md passes `--nested` and says the reading is wrong when two orchestrators share a session; the explicit id is the precise form.
- The orchestrator itself has `spawnDepth:1` and no parent, so it falls outside both scopes, which removes the false `quenching:orchestrator` alarm.
- Binding contract: ADR 0012 keeps the list documental and the audit after the fact; no grant widens, the verb is the same read-only one.

## Alternatives Considered

- Filter by `spawnDepth >= 2`: equals `--nested` in effect but hides the parent relation and cannot scope to one orchestrator.
- Add `quenching:orchestrator` and `general-purpose` to the `Agent(...)` list: widens a grant and silences the alarm instead of fixing the measure.

## Open Decisions

- none — the scope flags are decided above; whether the orchestrator can learn its own id is a follow-up only if the harness exposes it.

## Risks

- ACCEPTED — `--nested` over-counts when two orchestrators run in one session; the text in orchestrator.md names this and the precise flag.
- A missing or unreadable meta file counts as no parent, so it is excluded from a scoped run, never invented as a child.

## Outcome

Entregue: o verbo `cq components session cost` ganhou `--nested` e `--descendants-of <agentId>`, que escopam a medição pelo `parentAgentId` dos transcritos; o orchestrator passa a medir custo e auditar tipos de agente só dos workers lançados por subagentes, sem acusar a si mesmo nem os agentes do condutor. Cobertura por testes em `test_session_cost.py`; o comentário do lockstep (seis para sete artefatos) foi corrigido.

Ficou de fora: nenhuma mudança no formato de saída do verbo nem no condutor. A revisão do diff inteiro não achou incoerência; nenhum doc novo em /docs/ nem obrigação de release a assentar. Quem ler depois: com dois orchestrators na mesma sessão, usar `--descendants-of` com o próprio agent id.
