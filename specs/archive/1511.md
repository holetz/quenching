## Problem

After #1507, `capabilities.md:128-131` no longer recognises `spawned-agents`: spawning is controlled by `Agent` in
`tools`. Yet `plugins/quenching/assets/templates/automation/agent.md:15` still offers `# spawned-agents: …`,
`plugins/quenching/commands/components/agent/new.md:66` tells the author to fill it "only with a stated reason" (its
`Done when` demands passing `capabilities.md` §Subagents), and `docs/standards/automation/agents.md:47` and
`assets/templates/automation/agents-standard.md:41` list it as a field. Consequence: an agent minted from the template
carries a field nothing reads. The author believes they restricted spawning by name, while the real control gets no
guidance. Align these with the conclusion of the sibling spec on `Agent(...)`.

## Proposal

- The agent mold no longer offers a `spawned-agents` line.
- `/quenching:components:agent:new` step 4 no longer names `spawned-agents`; it points at `Agent` in `tools` as the spawn control.
- The agents standard and its template list only `skills` and `memory` as deliberately opened fields.

## Out of Scope

- Changing any agent's `tools:` grant; widening or narrowing is not done here.
- Rewriting `capabilities.md` §Subagents, already settled by #1507.

## Impact

### Standards this spec will write into docs/standards/

- `docs/standards/automation/agents.md` — drop `spawned-agents` from the deliberately-opened fields

### Product code this spec expects to touch

- `plugins/quenching/assets/templates/automation/agent.md` — remove the commented `spawned-agents` line
- `plugins/quenching/commands/components/agent/new.md` — step 4 wording
- `plugins/quenching/assets/templates/automation/agents-standard.md` — same bullet as the standard

## Validation

- `grep -rn "spawned-agents" docs plugins` prints nothing.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: delete the field rather than redirect it; nothing reads it, so a pointer would keep a dead name alive. Alternative weighed: replace with an `Agent(...)` comment in the mold, rejected because that belongs to the sibling spec on `Agent(...)`.
- Contract: `capabilities.md` §Subagents says spawning is governed by `Agent` in `tools`; the edited files must not contradict it.

## Alternatives Considered

- Keep the field as a documented no-op: rejected, it misleads authors into believing they restricted spawning.

## Open Decisions

- none — the text to remove is exact and the replacement wording is a one-line pointer to `tools`.

## Risks

- A test or golden may pin the removed text. Mitigation: the repo gate runs them; fix on red.

## Handoff

Nada pendente. Proximo passo: abrir o PR (/quenching:git:pr:create 1511) contra main. Gate: bash scripts/verify_repo.sh.
