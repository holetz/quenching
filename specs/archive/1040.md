## Problem

A definição atual de campos aceita apenas valores escalares e não representa documentos recorrentes com quantidade variável de itens, seções ou slides. Um gênero precisa declarar um campo de lista e repetir seu bloco no template em HTML e Typst.

## Proposal

- Declare scalar or list cardinality for genre fields while preserving the current scalar syntax.
- Support a repeatable template block for every list field, with a stable current-item context and deterministic empty-list behavior.
- Render repeated blocks in both HTML and Typst and validate required list fields as non-empty arrays.

## Out of Scope

- Nested lists, arbitrary template languages, conditional branches, pagination, sorting, or implicit schema generation from data.
- Changing the four existing placeholder families except for adding the explicit repeat block syntax.
- Turning the renderer into a presentation or slide engine.

## Impact

- `plugins/quenching/assets/bin/quenching/design/genre.py` — field cardinality, block expansion, and validation.
- `plugins/quenching/assets/bin/quenching/design/markdown.py` — repeated body items use the same Markdown subset.
- `plugins/quenching/tests/test_design.py` — N-item HTML/Typst coverage.
- `docs/standards/code/canonical-set-parsing.md` — explicit field grammar and deterministic iteration.
- `docs/standards/architecture/design-front.md` — one genre, N destinations without becoming a presentation engine.

## Validation

- A genre declaring `items:required:list:Item` accepts a JSON array and expands `{{#field.items}}...{{/field.items}}` once per item in HTML and Typst.
- Scalar templates continue to render byte-equivalently for the existing fixture.
- Missing or empty required arrays refuse with a useful field-specific error; optional absent arrays expand to no block.
- A block with an unclosed or unknown list field refuses rather than silently dropping content.

## Design

- Field declarations use `name:required|optional:scalar|list[:description]`; omitted cardinality remains scalar for compatibility. The generated genre contract serializes it as `- `name` — required list Description`.
- Repeat blocks are `{{#field.items}}...{{/field.items}}`; inside a block `{{item}}` resolves a scalar item and `{{item.<key>}}` resolves a shallow object key. Outer `field.*` values remain available. Only one nesting level is accepted.
- A list item may be a scalar or object. Items are rendered in JSON order; missing object keys are empty strings and do not alter list length.
- HTML repeats the literal block body for each item; Typst repeats the source block with the same item values. Body fields still pass through the Markdown renderer when named `body`.
- Required list fields need a non-empty JSON array. Optional absent/null lists produce zero iterations. A scalar supplied to a list field is a refusal.
- Dependency map (2026-08-30): `genre.py` parses declarations and expands contexts → `markdown.py` renders body values inside each context → `test_design.py` proves scalar compatibility and repeated output; build projections only carry genre contracts through existing `MEDIUM.md`.

## Alternatives Considered

- Accepting a JSON array and joining it with commas: rejected because a document's repeated structure belongs in the template.
- Supporting arbitrary Jinja-like syntax: rejected because unbounded template execution conflicts with deterministic safety.
- Adding slide-specific concepts: rejected because cardinality must work for reports, catalogs, and any genre without presentation semantics.

## Open Decisions

- none — declaration grammar, block syntax, item context, nesting boundary, and empty behavior are fixed.

## Risks

- A malformed template can repeat unexpected large output; the one-level block and deterministic input keep expansion bounded by data size.
- Object item fields have no declared sub-schema; missing keys are explicit empty values, and consumers can keep list items scalar when no subfields are needed.
- Typst and HTML have different whitespace rules; tests assert semantic repeated blocks rather than byte identity between media.
