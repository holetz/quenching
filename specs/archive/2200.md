## Problem

During the conclude of spec 2199 (2026-11-20), `QUENCHING_TEST_SCOPE=affected bash scripts/verify_repo.sh` failed only on `leak gate (generic patterns)` with 640 `[home-slug]` findings, because the cloud container's `HOME` is `~`: `_home_slug("~")` is `<project>`, and the pattern `<project>(?![\w.])` matches every `-<project>` flag in tests, scripts and `verify_repo.sh` itself. The same gate with `HOME` pointed at a multi-segment directory ran without that failure. The improvement has to make a short or single-segment home slug unable to match ordinary text such as a CLI flag, without losing the real leak it exists to catch.

**Insumos**

- `quenching/assets/bin/quenching/common/leak.py:94-108` — `_home_slug` and the `home-slug` pattern in `path_patterns`
- `scripts/verify_repo.sh:170-171` — `run_check "leak gate (generic patterns)" python3 quenching/assets/bin/cq security leak --all --generic-only`
- output: `scripts/verify_repo.sh:185: [home-slug] python3 quenching/assets/bin/cq -*** quenching components doctor --json` … `leak gate (all): 640 finding(s)` / `FAILED: leak gate (generic patterns)`
- spec 2199, conclude step 7
