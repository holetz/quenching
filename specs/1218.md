## Problem

A spec 1136 (#1208) criou `cq knowledge listing --write`, que regenera a zona GENERATED de um `index.md`, mas o run orquestrado mergeou sem o fechamento do `conclude`, e o trabalho de docs emergentes ficou só nas Discoveries: os corpos de `/quenching:knowledge:add` e `/quenching:knowledge:align` (`plugins/quenching/commands/knowledge/add.md`, `align.md`) não chamam o verbo novo, e `docs/standards/architecture/generated-listings.md` não tem a linha de dono dele.

Consequência: o `validate` continua mandando "regenerate the zone", e quem segue os corpos reescreve a linha à mão, o atrito que a 1136 existia para tirar.

## Proposal

- `/quenching:knowledge:add` step 5 tells the executor to regenerate the `standards/index.md` GENERATED zone with `cq knowledge listing --write` instead of editing rows by hand.
- `/quenching:knowledge:align` regenerates the same zone with `cq knowledge listing --write` and confirms it with `--check`.
- `docs/standards/architecture/generated-listings.md` carries the owner row for the `standards/index.md` GENERATED zone: owner `cq knowledge listing --write` / `--check`, its delimiters and its freshness checks.

## Out of Scope

- Changing the `cq knowledge listing` verb or its checker: it already exists (spec 1136) and works.
- Generating `index.md` files of other folders: the verb owns only the `standards/index.md` zone.

## Impact

### Standards this spec will write into docs/standards/

- `docs/standards/architecture/generated-listings.md` — owner row for the standards index GENERATED zone

### Product code this spec expects to touch

- `plugins/quenching/commands/knowledge/add.md` — step 5
- `plugins/quenching/commands/knowledge/align.md` — the regenerate bullet
- `plugins/quenching/assets/bin/quenching/knowledge/cli.py` — read only, the verb

## Validation

- `grep -c "cq knowledge listing" plugins/quenching/commands/knowledge/add.md plugins/quenching/commands/knowledge/align.md docs/standards/architecture/generated-listings.md` prints a non-zero count for each file (zero today).
- `bash scripts/verify_repo.sh` exits 0.

## Design

- A command body names the verb that owns a generated zone instead of describing how to rebuild it by hand: one writer per zone, per the standard's own "owner is the only writer" rule.
- The standard's table row follows the shape of the existing rows: owner, delimiters (`<!-- BEGIN GENERATED -->` / `<!-- END GENERATED -->`), freshness marker (the `generated-listing-missing` / `generated-listing-drift` findings, since this zone carries no sha marker).
- Regenerated Codex translation (`cq components translate --write`) rides the same change, since command bodies are translated.

## Alternatives Considered

- Leave the bodies describing the manual rebuild: rejected, it is the friction spec 1136 existed to remove.

## Open Decisions

- none — the verb, its flags and its zone are fixed by spec 1136.

## Risks

- The translated Codex surface drifts from the bodies: mitigated by `cq components translate --write` and `--check` in the tasks.
