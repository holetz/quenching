## Problem

At base 48cd728b, `plugins/quenching/assets/bin/quenching/delivery/inventory.py:256-257` scans every job line for a false condition, including step-level `if: false`. A disabled step therefore sets the entire Job.active to false. `delivery/checks.py:89-95` then skips checkout and runtime setup diagnostics for commands in other, active steps.

The same parser at `inventory.py:201-223` stores GitHub Actions `run: |` as commands `('|',)` and Azure Pipelines `bash: |` as `()`, dropping their indented bodies. Runtime and release classification cannot see those commands. Read-only scouts reproduced both cases by calling `_job` and `_workflow_findings` on in-memory lines; the fixture commands were never executed.

## Proposal

Correct the existing delivery parser's condition scope and multiline command extraction, preserving current supported providers and interfaces. Cover active jobs with disabled steps and literal/folded command blocks in the existing `plugins/quenching/tests/test_delivery.py`. Synchronize generated Codex mirrors through the existing generation process. No new execution capability or grants.

## Validation

Use parser-only regression fixtures: disabled step conditions must not disable their parent job; actual disabled job conditions must remain disabled. Multiline GitHub `run` and Azure `bash`/`script`/`pwsh` commands must preserve runtime/release evidence and produce missing checkout/setup diagnostics where applicable. Run the existing delivery tests, mirror verification, and root `bash scripts/verify_repo.sh`. Do not execute fixture commands.

## Risks

A broad indentation rule could consume following steps or unrelated YAML values; bound each block by its owning indentation and cover adjacent steps. Preserve existing single-line and GitLab command behavior.
