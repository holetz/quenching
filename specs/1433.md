## Problem

As standards OKF em pastas `agents/` fora de `docs/` passam por agente no audit: editar o `timestamp` de `plugins/quenching/assets/knowledge/standards/agents/communication.md` e criar `agents/new-standard.md` ali dá `unknown ["timestamp"]`, `tools ["*"]` e `unknown ["timestamp","title","type"]` (`/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review15/f1`). Onde: `plugins/quenching/assets/bin/quenching/git/audit.py:161-162`, exclusão só em `^docs/` (`:169`); atinge também `plugins/quenching-codex/knowledge/standards/agents/`. Consequência: uma spec como a 1058 (que criou `ephemeral-writes.md` ali) ou um bump de `timestamp` leva FAIL `needs-human: alargamento` num run legítimo. Direção: restringir `AGENT`/`FRONTMATTER_GRANT` às raízes que o Claude Code carrega (`.claude/` e a raiz de um plugin), recursivo dentro delas.

Origem: item C2 (média, falso positivo) da fila da rodada 7 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round7-queue.md`), da revisão de correção opus da rodada 6 (épico 1418).

## Proposal

- O audit só trata como agente, comando ou skill o arquivo sob uma raiz que o Claude Code carrega: `.claude/` (em qualquer profundidade do caminho) ou a raiz de um plugin (`plugins/<nome>/` ou a raiz do repo), recursivo dentro de `agents/`, `commands/` e `skills/` dessas raízes.
- Uma standard OKF em `plugins/**/assets/knowledge/standards/agents/` ou `plugins/quenching-codex/knowledge/standards/agents/` deixa de produzir `unknown`/`tools` no audit.
- Os agentes reais (`plugins/*/agents/*.md`, `.claude/agents/**`) continuam auditados como hoje.

## Out of Scope

- Alterar a regra `DOCS` (`^docs/`): segue valendo e é independente.
- Alargar `SURFACE` (settings, hooks, workflows): não toca o falso positivo e seria alargamento.

## Impact

### Standards this spec will write into docs/standards/

- none — o audit já é descrito por standards existentes; a correção não cria regra nova.

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/git/audit.py` — as regexes `FRONTMATTER_GRANT` e `AGENT`
- `plugins/quenching/tests/test_git.py` — testes do verbo audit
- espelho Codex gerado: `plugins/quenching-codex/scripts/bin/quenching/git/audit.py` e os manifestos `.generated-files.json`

## Validation

`python3 -m unittest discover -s plugins/quenching/tests -p test_git.py` sai 0 com os novos casos: standard em `plugins/p/assets/knowledge/standards/agents/x.md` não aparece em `_grants()`; `plugins/p/agents/a.md` com `tools: *` novo continua aparecendo. `bash scripts/verify_repo.sh` sai 0.

## Design

- Decisão: prefixo de raiz explícito nas duas regexes, `^(?:(?:.*/)?\.claude/|(?:.*/)?plugins/[^/]+/)?` seguido do diretório. Alternativa descartada: ler o manifesto do plugin no git (custo de I/O e de modo de falha novo no audit, que falha fechado).
- Regra durável: o audit casa só o que o Claude Code carrega; pasta homônima mais funda em `assets/` é conteúdo.
- Premissa nomeada: raízes de plugin do repo são `plugins/<nome>/` ou a raiz; marketplace aninhado mais fundo não existe hoje.

### Mapa de dependências (2026-10-08)

- `audit.py` e o espelho `plugins/quenching-codex/scripts/bin/quenching/git/audit.py` (gerado); `.generated-files.json` carrega o hash do espelho; `test_git.py` classe `Audit`.

## Alternatives Considered

- Excluir `/assets/knowledge/` por padrão (como `DOCS`): frágil, só cobre dois caminhos conhecidos e deixa outras pastas homônimas.

## Open Decisions

- none — a raiz de plugin aninhada não existe hoje; se surgir, o audit falha fechado só para o que deixar de casar, e o teste de agentes reais o revelaria.

## Risks

- Um agente num caminho de raiz não previsto deixa de ser auditado (afrouxamento). Mitigação: testes fixam `plugins/p/agents/`, `.claude/agents/` aninhado e raiz do repo; ACCEPTED — o Claude Code só carrega essas raízes.
