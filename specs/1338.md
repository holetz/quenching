## Problem

`cq git audit`/`state` ainda executam programa da config: filtro com `=` no nome (`-c filter.a=b.clean=` vira a chave `filter.a`; `plugins/quenching/assets/bin/quenching/git/audit.py:67-80`; `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review10/audit/run.sh` cria `PWNED_eq`), e a busca preguiçosa de partial clone roda `core.sshCommand` no `diff --name-only` (`audit.py:111`; `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review10/audit/lazy.sh` → `PWNED_lazyssh`).

Origem: item R2 da fila da rodada 2 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round2-queue.md`), da revisão de correção opus do épico 1306.

## Proposal

- Um driver `filter.<x>` declarado na config do repositório não roda durante `cq git audit` nem `cq git state`, qualquer que seja o nome `<x>` — incluindo um `<x>` com `=` (`filter.a=b.clean`), que o par `-c chave=valor` não consegue expressar.
- Nenhuma leitura de `cq git audit` ou `cq git state` dispara a busca preguiçosa de um partial clone: `core.sshCommand`, `remote.<n>.uploadpack` e qualquer transporte escolhido pela config não executam — nem no `diff --name-only` (detecção de rename sobre blob ausente), nem na resolução de um `--sha`/`--base` cujo objeto falta.
- Cada vetor tem um teste em `plugins/quenching/tests/test_git.py` que falha no `main` atual e passa depois.

## Out of Scope

- A busca preguiçosa nas outras verbs que importam `audit._commit`/`_run` (`cq git worktree`, `cq git push`, `cq git prune`): `push` precisa de transporte por definição, e as demais não estão no Problem; fica uma linha em `## Discoveries`.
- O `changed: []` silencioso quando o `diff` falha num partial clone sem o blob (antes buscava; agora falha fechado e `_lines` devolve vazio). Reportar a falha como fato é mudança de contrato da saída do verifier, não deste fix; fica como discovery.
- `GIT_CONFIG_PARAMETERS`/`GIT_CONFIG_COUNT` herdados de quem chama: são do chamador, não do repositório auditado; o filtro que declararem é anulado igual, porque a leitura de config os enxerga.

## Design

- **Sobrepor a config por ambiente, não por `-c`.** `git -c a=b.clean=` divide no primeiro `=` e vira a chave `filter.a` com valor `b.clean=`; `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` (git ≥ 2.31) leva chave e valor separados, então aceita qualquer nome de subseção. Os pares são anexados depois de um `GIT_CONFIG_COUNT` que o chamador já tenha, nunca o sobrescrevem.
- **Ler as chaves com `-z`.** `git config -z --name-only --get-regexp` separa por NUL; a lista não depende de o nome caber numa linha.
- **Desligar a busca preguiçosa em dois níveis.** `GIT_NO_LAZY_FETCH=1` impede o fetch onde o git o conhece; `GIT_ALLOW_PROTOCOL=` (vazio) recusa todo transporte — ssh, file, http, helper — antes de rodar qualquer programa, e vence `protocol.<x>.allow` da config. Medido no git 2.43 deste host: cada um sozinho já impede `PWNED_lazyssh`; os dois juntos não dependem da versão.
- **O ambiente vale para toda leitura do audit e do state**, inclusive a resolução de refs (`rev-parse ^{commit}` de um objeto ausente também busca — medido). As outras verbs que importam `_run`/`_commit` continuam sem `env`, com o comportamento de hoje.
- Contrato que não pode ser contrariado: o docstring de `audit.py` (o audit é um REPORT, exit 0 com fatos; nada da config roda durante a leitura) e os testes existentes da classe `Audit`/`State`.

## Alternatives Considered

- **Continuar com `-c` escapando o nome** — a sintaxe de `-c` não tem escape para `=` na chave; inviável.
- **`-c protocol.allow=never`** — perde para um `protocol.ssh.allow=always` da própria config do repositório, e helpers têm nomes arbitrários; não fecha a classe.
- **`diff --no-renames`** — evita ler blobs no `diff`, mas muda a saída (o caminho antigo passa a aparecer) e não cobre `rev-parse` nem `status`; tratar o sintoma em vez do mecanismo.

## Risks

- `GIT_CONFIG_COUNT` exige git ≥ 2.31; num git mais velho a sobreposição é ignorada e o filtro roda. ACCEPTED — 2.31 é de 2021 e o repositório já usa recursos mais novos.
- Num partial clone sem o blob, o `changed` volta vazio em vez de buscar. ACCEPTED — falhar fechado é o objetivo; tornar a falha visível vai como discovery.
- Um `GIT_CONFIG_COUNT` malformado herdado do chamador faz o git recusar; mitigação: um valor não numérico é tratado como 0.
