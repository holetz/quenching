## Problem

O manifesto gerado da tradução Codex segue frágil depois da 1198 (#1214) e da 1202 (#1216):

- **Ainda conflita.** A 1198 tirou o hash agregado do `.generated-from.json`, mas `plugins/quenching-codex/.generated-files.json` conflitou sempre que duas PRs abertas tocavam a árvore Codex: na orquestração do épico 1197 bloqueou o pouso de 1205, 1210, 1211 e 1219, cada um resolvido à mão (`git show :3:`, `translate --write`). Os workers da 1186 e da 1198 resolveram com `git checkout --theirs`, que o runner proíbe e o verifier não vê.
- **Ainda dá traceback.** Em `components/commands/translate.py:552,560`, `reconciliation` roda antes de `write_tree` (também no `--check`) e só protege o `json.loads`: `sha256` em forma de lista ou string sai `AttributeError`. Em `:645`, uma entrada de `files` que é diretório dentro do destino passa a contenção e o `unlink` lança `IsADirectoryError` depois de já ter apagado os stale anteriores. Reproduzido em 2026-10-08; a contenção em si não foi furada.

Consequência: toda onda paralela ainda paga um pouso manual por PR tardia, empurrando workers a uma ação proibida, e o gate de CI morre com traceback num manifesto danificado.

## Proposal

- `cq components translate --write` recovers from a `.generated-files.json` that is not valid JSON (conflict markers left by a parallel merge): it regenerates the tree and rewrites the manifest, with no `git checkout --theirs` and no hand-made `git show :3:`.
- `cq components translate --check` and `--write` never exit with a traceback on a damaged manifest: a `sha256` that is not an object reads as untracked.
- A `files` entry that names a directory inside the destination no longer aborts `--write` with `IsADirectoryError`, and no stale file is deleted before the refusal or skip is decided.
- Every one of these shapes is covered by a test in `plugins/quenching/tests/test_components_translate.py`, and the Codex translation is regenerated.

## Out of Scope

- Removing the per-file `sha256` map or the manifest: the reverse reconciliation (`target-changed`) depends on it, and dropping it would retire a tested feature.
- Opening the containment rule again: it was reproduced intact on 2026-10-08, and the existing refusals for escaping paths and for a manifest without `files` stay as they are.
- A git merge driver or `.gitattributes` rule: it needs local git configuration the plugin cannot ship.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/components/commands/translate.py` — `reconciliation`, `previous_files`, `write_tree`
- `plugins/quenching/tests/test_components_translate.py` — the damaged-manifest cases

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p test_components_translate.py` exits 0, including the new cases.
- With `{"files": [], "sha256": ["x"]}` as the manifest, `cq components translate --check --target <copy>` exits 0 or 1 with no traceback (before the fix: `AttributeError` at translate.py:560).
- With conflict markers as the manifest, `--write` exits 0 and leaves a valid manifest.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- **A manifest that is not JSON is recoverable; a manifest that is JSON of the wrong shape is a refusal.** Conflict markers are the only damage the merge flow produces, and the regenerated tree is the authority. Stale files are then the owned files on disk absent from the tree (the same owned set `differences` already computes), so recovery deletes no more than a valid manifest would.
- **`reconciliation` is total.** A `sha256` that is not a dict is `untracked`; the function never raises, because `--check` runs it before anything is validated.
- **A `files` entry that resolves to a directory is skipped at deletion time** (`is_file()` instead of `exists()`), after the containment check already passed for every entry.
- Binding contract: `docs/standards/architecture/surface-translation.md` (Claude is the authority; freshness is a byte comparison).

## Alternatives Considered

- Drop the hash map from the versioned manifest: fewer conflicts, but kills the reverse path. Rejected.
- Merge driver via `.gitattributes`: needs per-clone git config. Rejected.

## Open Decisions

- none — the recovery rule and the skip rule are decided above.

## Risks

- Recovery from an unparseable manifest could delete an unrelated file under the destination: the owned set is restricted to the same set `differences` already treats as generated (for the `.agents` surface only `AGENTS.md`, `.generated-from.json`, `skills/` and `references/`), so Codex configuration is preserved.
- A test that passes before the fix proves nothing: each new case is run against the unfixed code first.
