## Problem

Sob condutor, o spec-runner devolve formato fixo e sem prosa, e `develop.md:368` já diz que o sub-agente "present[s] nothing". Mesmo assim, `develop.md:374`, `execute.md:356` e `conclude.md:265` leem `plugins/quenching/assets/references/specs-develop/report-mold.md` §The report mold `--rules-only` (11.341 chars) sem condição: até ~34k chars (~8,5k tokens) por spec para uma tela que não é emitida.

Nos logs de sessão dos últimos 14 dias, o spec-runner responde por 83% dos tokens orquestrados (36,1M de 43,3M), e a criação de PR dentro do runner custou em média 372K tokens por run (14 runs), contra 61K e 93K quando o git-steward a fez (2 runs).

Consequência: o maior centro de custo da orquestração carrega leituras e passos que outro agente faz mais barato.

## Proposal

Condicionar a leitura do molde a haver um humano lendo (nenhum condutor); avaliar mover push e PR do runner para o git-steward no fluxo orquestrado, coordenado com o que a 1185 decidir sobre o encadeamento conclude → pr:create.

## Out of Scope

Reescrever os corpos de develop/execute/conclude por inteiro (o corte dos ramos que o low gear não usa fica para outra spec).

## Impact

### Product code this spec expects to touch

- `plugins/quenching/commands/specs/develop.md` — step 8 report read
- `plugins/quenching/commands/specs/execute.md` — step 7 report read
- `plugins/quenching/commands/specs/conclude.md` — step 7 report read
- `plugins/quenching/agents/spec-runner.md` — pass `autonomous` to execute too
- `plugins/quenching-codex/**` — generated translation, regenerated by `cq components translate --write`

## Validation

Num run orquestrado real, o molde não aparece no contexto do runner e os tokens por spec caem (medido nos logs de sessão antes e depois); `bash scripts/verify_repo.sh` sai 0.

## Design

- **Defect proved on main (2026-10-07):** `develop.md:374`, `execute.md:356` and `conclude.md:265` each run `cq components read .../report-mold.md --sections "§The report mold" --rules-only` with no condition, while `develop.md:368` already says a sub-agent under a conductor presents nothing.
- **Durable rule:** the report mold is loaded only by whoever presents a report to a human. The signal that a conductor holds the human is the word `autonomous` in the command's input, the same signal `develop` (step 8) and `conclude` (step 7) already use. When it is present, the command skips the read and returns its content in the fixed shape its caller specified (the spec-runner return format).
- `execute` did not receive `autonomous` from the spec-runner; the agent now passes it to all three commands, so the condition is uniform.
- Moving push and PR from the runner to the git-steward is evaluated, not built here: it depends on what 1185 decides about the conclude -> pr:create chaining (see Open Decisions).

## Alternatives Considered

- **Shrink the mold instead of skipping it:** rejected, the mold is still needed verbatim by every human-facing run, and the cost is the whole read, not its size.
- **A new `conductor` flag distinct from `autonomous`:** rejected, `autonomous` is already the declared signal in develop and conclude; a second word forks the contract.

## Open Decisions

- Whether push and PR creation move from the spec-runner to the git-steward in the orchestrated flow: decided from the 1185 outcome on the conclude -> pr:create chaining, as a separate spec if it moves.
- A conductor that is not autonomous but still presents the report (a human-supervised orchestrator) keeps the read until it declares otherwise; decided when such a flow exists.

## Risks

Depende da 1185 e da 1188 estarem em `main` (mexem no mesmo encadeamento e em `agents/spec-runner.md`).
