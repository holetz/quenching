## Problem

A spec 1186 (#1207) faz `cq specs status --epic` contar como `unmerged` uma spec arquivada cuja PR está explicitamente fora de `MERGED`, mas `member_state` (`plugins/quenching/assets/bin/quenching/specs/parse/epics.py:74-85`) mantém `done` quando o estado da PR não pôde ser lido ("absent or unknown keeps done"); o worker da 1186 deixou a pergunta aberta.

Consequência: uma falha transitória do `gh` (o backend GitHub já mostrou leituras vazias com `ok: true`) volta a fazer o status do épico afirmar uma entrega que não verificou, e o orquestrador pode liberar a onda dependente antes do merge.

## Proposal

- `cq specs status --epic` reports a member whose `pr:` record exists but whose PR state could not be read as `unverified`, never as `done`.
- An `unverified` member holds its dependents (`waiting`) and is listed under `blocked` with the reason "PR #N state could not be read".
- A member with no `pr:` record, or whose PR is `MERGED`, stays `done`; an explicitly non-merged PR stays `unmerged`.

## Out of Scope

- Retrying the `gh` lookup: the status stays a single read-only pass; a retry is the caller's.
- Callers that never look up PR state (`open_items`, the archive guard): they keep today's behaviour, since no lookup was attempted.

## Impact

- `plugins/quenching/assets/bin/quenching/specs/parse/epics.py` — `member_state` and `derive_epic` gain the `unverified` state.
- `plugins/quenching/assets/bin/quenching/specs/commands/epic.py` — `unverified` is listed as blocked with its reason.
- `plugins/quenching/tests/test_specs_epics.py` — the old "unknown keeps done" test is replaced.

### Standards this spec will write into docs/standards/

- none — a derivation fix; no standard is declared.

## Validation

- `python3 -m unittest discover -s plugins/quenching/tests -p test_specs_epics.py` exits 0, including a test where a `pr:` member with an empty lookup is `unverified` and holds its dependent.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Durable rule: a derivation that was handed a lookup result and finds none for a member with a `pr:` record never asserts delivery. `pr_state=None` means "no lookup made" (unchanged `done`); a dict, even empty, means "looked up".
- Alternative weighed: reuse `unmerged` with an unknown state; rejected because the reason text and the remedy differ (retry versus wait for merge).

### Mapa de dependências

- `derive_epic` is called by `load_epic` (with lookup) and `open_items` (without); only the first changes. Status rows are consumed in `epic.py` only; no other file matches `unmerged`.

## Alternatives Considered

- Fail the whole status with exit 2 when any lookup fails: rejected, it hides every other member's state for one transient failure.

## Open Decisions

- none — the unverified status name and its blocking behaviour are decided above.

## Risks

- A persistently failing `gh` (not authenticated) marks every archived PR member `unverified`. ACCEPTED — that is the honest report; the reason text names the cause.

## Handoff

Implemented: unverified member state in epics.py/epic.py; test updated. Next: verify_repo gate, PR, conclude.
