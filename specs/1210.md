## Problem

Na orquestração do épico 1192 (2026-10-07), o hook `after_specs_execute_task` → `/security-review` rodou a partir do checkout base, contra um diff vazio, em 5 das 8 construções, mesmo depois de o orquestrador mandar os workers apontá-lo para a própria worktree; dois workers revisaram o diff à mão. O worker trabalha numa worktree manual fora do diretório do projeto (ex.: `/home/unicred/Projetos/claude-quenching-1185`), e o skill `/security-review` roda `git diff origin/HEAD...` no diretório de trabalho da sessão, que o harness devolve ao checkout principal [hipótese da causa, a confirmar].

Consequência: a revisão de segurança declarada para toda task que toca superfície sensível passa sem olhar a mudança — o hook "roda" e não revisa nada, e a linha `HOOKS:` do worker diz `ran`.

## Proposal

- The step 5g hook invocation in `/quenching:specs:execute` states the work checkout (`git rev-parse --show-toplevel`) and the exact diff to review (`git -C <toplevel> diff origin/HEAD...HEAD`) in the context it passes to the hook.
- When that checkout is not the session's working directory, the context tells the hook to review that diff in place of its default, so a hook such as `/security-review` never reads the base checkout.
- A test pins the clause so the instruction cannot be dropped silently.

## Out of Scope

- Changing the `/security-review` skill itself: it is a harness skill outside this repository.
- Making the harness keep the session cwd on the worktree: not controllable from a command body.
- Making a hook that reviewed an empty diff report `failed`: classification stays ran/failed/unresolved as today.

## Impact

### Standards this spec will write into docs/standards/

### Product code this spec expects to touch

- `bash scripts/verify_repo.sh` exits 0.
- `python3 plugins/quenching/assets/bin/cq --root . components translate --check` exits 0.

## Design

- Decision: the executor passes the worktree path and the explicit diff command as hook context. Durable rule: a hook invoked from a worktree is told which checkout and which diff to review, because the Skill runs in the session cwd, which the harness resets to the base checkout.
- Assumption (the Problem marks the cause as a hypothesis): the skill diffs the session cwd. The fix does not depend on it: it makes the target explicit regardless.
- Contract: step 5g already restores `origin/HEAD`; this adds the target beside it and keeps "executor never evaluates condition".

### Mapa de dependências

- `plugins/quenching/commands/specs/execute.md` -> translated skill in `plugins/quenching-codex/skills/quenching-specs-execute/SKILL.md` (regenerated), `plugins/quenching/tests/test_specs_execute.py` (asserts on 5g text).

## Alternatives Considered

- Rewrite `.claude/quenching.json` hook command to `cd <worktree> && ...`: rejected, the hook is a Skill and the worktree path is per run, not static config.
- Executor reviewing the diff itself: rejected, it replaces the declared hook instead of directing it.

## Open Decisions

- Why now / what would make this not worth doing: the Problem states the cost (5 of 8 builds reviewed an empty diff); no further decision parked.

## Risks

- The skill may ignore the context and still read the base checkout: ACCEPTED, the clause is the strongest lever the command body has; the worker may review the diff by hand as the epic 1192 workers did.
- Wording drift between execute.md and its Codex translation: mitigated by `components translate --check` in the gate.
