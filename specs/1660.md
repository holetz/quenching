## Problem

OpenAI ships an official Claude Code plugin, `openai/codex-plugin-cc` (released 2026-03-30), that lets
a Claude-orchestrated session hand work to the local Codex CLI: `/codex:review` and
`/codex:adversarial-review` (read-only), and the `codex:codex-rescue` subagent, a thin `model: sonnet`
forwarder that makes one `codex-companion.mjs task --write` call (sandbox `workspace-write`) and returns
Codex's stdout verbatim. Its usage is billed against the ChatGPT/Codex quota, not the Claude one, so it
adds capacity and a second-family reviewer that catches what the authoring model does not.

quenching cannot adopt it today on one hard condition from the human: Codex may be used **only while its
quota has room**, and when the quota runs out (before or during a task) the work must continue on Claude
without human intervention. If that condition cannot be met, nothing is implemented. Feasibility was
proven on 2026-10-14 against codex-cli 0.162.1: `codex app-server` answers the JSON-RPC
`account/rateLimits/read` with `ordinaryUsageAllowed`, `rateLimits.primary` / `secondary`
(`usedPercent`, `windowDurationMins` 300 and 10080, `resetsAt`), `rateLimitReachedType` and
`rateLimitResetCredits`; on that run the quota was exhausted (`primary.usedPercent: 100`,
`rateLimitReachedType: rate_limit_reached`), which is exactly the fallback case.

## Proposal

1. An opt-in `shared.codex` block in `.claude/quenching.json` (`review`, `executor`, `ceilings`). Absent, every
   surface behaves exactly as today.
2. A deterministic quota probe, `cq components codex-quota [--json]`: it confirms the `openai-codex` plugin is
   installed, spawns `codex app-server`, reads `account/rateLimits/read`, and exits 0 (quota under the ceilings),
   1 (exhausted or over a ceiling) or 2 (inconclusive: plugin or CLI missing, no login, JSON-RPC error, timeout).
   Exit 2 reuses the frozen refusal code of the `cq` contract.
3. `/quenching:specs:conclude` gains an **advisory** second-family review, run through `cq components codex-review
   --base origin/<base>` only when `review: true` and the probe exits 0. Its findings feed step 2's whole-branch
   review and the report's item 2. It never blocks and never writes.
4. `/quenching:specs:execute`'s per-task executor may be `codex:codex-rescue` (`--wait`) for a task that declares
   `files:` and `verify:` and writes nothing under `knowledge/`, only when `executor: true` and the probe exits 0.
   A failed or empty Codex result falls back to the Claude executor, which continues from the worktree's partial
   diff. The same route is available under the `spec-runner`, which gains `Agent(codex:codex-rescue)`.
5. The model policy and the agents standard gain an explicit clause for an external provider, recorded in an ADR.
## Out of Scope

- Enabling the plugin's `Stop` review gate (`/codex:setup --enable-review-gate`) in any run.
- Consuming `rateLimitResetCredits` (`ConsumeAccountRateLimitResetCredit`). Never automatic.
- A blocking Codex review; the review stays advisory.
- Running a whole `spec-runner`, `develop`, `triage`, any `/docs/standards/` write, the commit or any confirmation on Codex.
- `--background` jobs and `/codex:status` polling.
- The `quenching-codex` mirror restoration that sits uncommitted in the working tree; if it lands first, its regeneration is that work's concern.

## Design

- **Opt-in config, deterministic gate.** `extension-points.md` routes third-party commands through
  `.claude/quenching.json` and never evaluates a hook's `condition`. Here the gate is not prose: the body calls
  the probe and branches on its exit code, so the config only says *whether* Codex is wanted, and `cq` says
  *whether it may run now*.
- **Ceilings.** Available means `ordinaryUsageAllowed` is true and `primary.usedPercent` (300-minute window) and
  `secondary.usedPercent` (10080-minute window) are under `ceilings.primary` / `ceilings.secondary`, defaulting
  to 80 and 90 so a task does not start at the edge of the 5-hour window. Both are configurable.
- **Fail closed.** Anything the probe cannot read is exit 2, and both 1 and 2 route to Claude. The app-server
  method is flagged experimental; a rename degrades to "Claude only", never to an unguarded Codex call.
- **The review goes through `cq`, not `Skill`.** `/codex:adversarial-review` declares
  `disable-model-invocation: true`, so a body cannot invoke it. `cq components codex-review --base <ref>`
  resolves the installed plugin's `scripts/codex-companion.mjs`, runs `adversarial-review --wait --base <ref>`
  with a deadline, and prints its output; conclude keeps its `Bash(cq:*)` grant and never needs `Bash(node:*)`.
- **Executor hand-off.** Before handing a task to Codex the executor records the state of the task's `files:`
  (`git status --porcelain -- <files>`); after a failed or empty result it compares, and the Claude executor
  continues from whatever Codex left, because the spec-runner is forbidden every command that would discard it.
  `cwd` is the spec's worktree. `verify:` runs outside Codex (its sandbox is `workspace-write` with no network).
  The executor still returns the four-item self-review verdict that execution-delegation.md requires.
- **The orchestrator keeps** spec selection, every confirmation, every `cq specs task --check` / `--block`,
  every `discover`, every `/docs/standards/` write and the commit. Codex writes only inside `files:`.
- **Under the spec-runner**, `Agent(codex:codex-rescue)` is the one new grant; the runner itself is the Claude
  fallback. The orchestrator's telemetry records Codex-executed tasks as their own line, since their cost is
  billed to the Codex quota, not to a Claude model tier.
- **Conclude review placement.** Inside step 2 (conclude.md:137-156), before the `reviewed` stamp; a resume
  row and an `## Under autonomous` row (probe ≠ 0 → skip and say so in the report).

## Alternatives Considered

| Approach | Cost | Buys | Forecloses | Verdict |
| --- | --- | --- | --- | --- |
| Config hook (`before_specs_conclude`) under extension-points, announce-only | no code | uses the existing extension point | the quota gate: hook conditions are never evaluated | rejected; the user's condition needs a deterministic gate |
| The plugin's `Stop` review gate | one setup flag | review on every turn | bounded cost: the plugin warns it can loop and drain the quota | rejected |
| React only to failure (no preflight) | less code | simpler | starts work with an exhausted quota and pays the failed attempt every time | rejected |
| Call `codex exec` directly from `cq`, without the plugin | no plugin dependency | full control of sandbox and output | the official path the user asked for; duplicates the companion runtime | rejected |
| Probe as a new `cq codex` pillar | one pillar row plus the pinned-count test | a readable name | nothing, but a pillar for one verb | rejected for `cq components codex-quota` |
| Blocking review | same code | catches more | autonomous waves on a false positive | rejected; advisory |

## Open Decisions

- Default ceilings (80 / 90) are a starting point; the pilot in `## Handoff` confirms or moves them.
- Whether a subagent (`spec-runner`) can spawn `codex:codex-rescue` in the installed Claude Code version: task 3.2 proves it with a live call; if nesting is refused, the runner falls back to Claude and the grant is dropped, recorded as a discovery.
## Risks

- `account/rateLimits/read` is experimental; a Codex update can rename it. Mitigation: fail closed (exit 2).
- The quota can run out between the probe and the end of a long task; the mid-flight fallback covers it, at the cost of the partial attempt.
- Each Codex delegation still costs a sonnet forwarder with two skills loaded, which can erase the saving on small tasks; the pilot measures it.
- The forwarder's `cwd` must be the spec's worktree, or Codex writes into the wrong checkout.
- An uncommitted `quenching-codex` mirror restoration in the working tree; if it lands, the new body text needs translator rules.
- A new subprocess runner in `cq` widens what `Bash(cq:*)` can do: it executes the installed plugin's Node script. The `after_specs_execute_task` security-review hook applies to tasks 1.1 and 1.2.
## Handoff

- Post-merge pilot: with the plugin installed and `shared.codex` enabled, run about 10 eligible tasks and 3 concludes; record verifier PASS rate, the Codex-executed task count, Claude tokens per model (`cq components session cost`) against a sonnet baseline, how many runs the probe routed to Claude, and how many mid-flight fallbacks happened. Confirm or move the default ceilings.
