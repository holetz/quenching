## Problem

OpenAI ships an official Claude Code plugin, `openai/codex-plugin-cc` (released 2026-03-30), that lets
a Claude-orchestrated session hand work to the local Codex CLI: `/codex:review` and
`/codex:adversarial-review` (read-only), and the `codex:codex-rescue` subagent, a thin `model: sonnet`
forwarder that makes one `codex-companion.mjs task --write` call (sandbox `workspace-write`) and returns
Codex's stdout verbatim. Its usage is billed against the ChatGPT/Codex quota, not the Claude one, so it
adds capacity and a second-family reviewer that catches what the authoring model does not.

quenching cannot adopt it today on one hard condition from the human: Codex may be used **only while its
quota has room**, and when the quota runs out (before or during a task) the work must continue on Claude
without human intervention. If that condition cannot be met, nothing is implemented. Feasibility was
proven on 2026-10-14 against codex-cli 0.162.1: `codex app-server` answers the JSON-RPC
`account/rateLimits/read` with `ordinaryUsageAllowed`, `rateLimits.primary` / `secondary`
(`usedPercent`, `windowDurationMins` 300 and 10080, `resetsAt`), `rateLimitReachedType` and
`rateLimitResetCredits`; on that run the quota was exhausted (`primary.usedPercent: 100`,
`rateLimitReachedType: rate_limit_reached`), which is exactly the fallback case.

## Proposal

1. A deterministic, stdlib quota probe in `cq` that asks the local Codex app-server for the rate limits
   and answers with an exit code: 0 available, 1 exhausted, 2 inconclusive.
2. `/quenching:specs:conclude` gains an optional, read-only second-family review
   (`/codex:adversarial-review --base <base>`) that runs only on exit 0 of the probe.
3. A pilot: `/quenching:specs:execute`'s per-task executor may be `codex:codex-rescue` (`--wait`) for a
   task that declares `files:` and `verify:` and writes nothing under `knowledge/`, again only on exit 0;
   any Codex failure mid-task falls back to the Claude executor.
4. The model policy gains an explicit clause for an external provider.

## Out of Scope

- Enabling the plugin's `Stop` review gate (`/codex:setup --enable-review-gate`) in any autonomous run.
- Consuming `rateLimitResetCredits` (`ConsumeAccountRateLimitResetCredit`) — never automatic.
- Running a whole `spec-runner` on Codex, or regenerating the retired `quenching-codex` mirror.
- Delegating `develop`, `triage`, any `/docs/standards/` write, the commit, or any confirmation to Codex.
- `--background` jobs and `/codex:status` polling inside the orchestrated waves.

## Impact

Probable paths, to be confirmed by develop:
- the `cq` tool tree under `plugins/quenching/assets/bin/quenching/` (new quota probe and its CLI wiring) and its tests under `plugins/quenching/tests/`
- `plugins/quenching/commands/specs/conclude.md` and its references (optional review step)
- `plugins/quenching/commands/specs/execute.md` and `plugins/quenching/assets/references/specs-execute/execution-delegation.md` (executor choice and fallback)
- `plugins/quenching/README.md` §Model policy (external-provider clause)

## Validation

- With Codex absent, logged out, or the app-server timing out, the probe exits 2 and conclude/execute behave exactly as today.
- With `ordinaryUsageAllowed: false` or a window above the ceiling, the probe exits 1 and no Codex call is made.
- A Codex task that fails or returns empty output mid-run is finished by the Claude executor from the worktree's partial diff, with no `stash`/`checkout`/`restore`.
- No code path calls `ConsumeAccountRateLimitResetCredit` or enables the review gate.
- Pilot evidence: verifier PASS rate and cost per model (`cq components session cost`) for the Codex-executed tasks against a sonnet baseline.

## Design

- **Preflight, every time.** The probe spawns `codex app-server`, sends `initialize`, `initialized`, then
  `account/rateLimits/read`, and kills the process. Available means `ordinaryUsageAllowed` is true and both
  windows' `usedPercent` are under a ceiling with margin; a task should not start near the edge of the 5-hour
  window. Codex missing, no login, a JSON-RPC error or a timeout is exit 2, and 1 and 2 both route to Claude.
- **Mid-flight fallback.** The forwarder returns nothing when Codex cannot run, so an empty or failed result
  is a fallback signal, not a retry. The Claude executor takes over from the worktree state: it reads the
  partial diff and continues, because the spec-runner is forbidden every command that would discard it.
- **The orchestrator keeps everything it keeps today**: spec selection, every confirmation, every
  `cq specs task --check` / `--block`, every `discover`, every `/docs/standards/` write and the commit. Codex
  writes code inside the task's `files:` and returns.
- **`verify:` runs outside Codex.** The plugin's sandbox is `workspace-write` with no network, so the task's
  own verify step stays with the orchestrator.
- **`--wait` only**, so the dependency waves never poll background jobs.
- **Optional by construction**: without the plugin installed or without quota, the surface is unchanged.

## Open Decisions

- Where the probe lives: a new `cq codex quota` front or a subcommand under an existing front.
- The ceiling values for the 300-minute and 10080-minute windows, and whether `secondary` gates as hard as `primary`.
- Whether the conclude review is advisory (findings reported) or blocking (a finding returns to execute).
- How the executor detects a partial Codex write versus no write at all before handing over to Claude.
- How the bodies name the option, given that spec 1475 deliberately removed Codex mentions from the bodies: one gated reference that bodies cite, or a config switch in `.claude/quenching.json`.

## Risks

- `account/rateLimits/read` is an app-server protocol method flagged experimental; a Codex update can rename it. The probe must fail closed (exit 2), never open.
- The forwarder's `cwd` must be the spec's worktree, or Codex writes into the wrong checkout.
- The quota can run out between the probe and the end of a long task; the mid-flight fallback must cover it.
- Each delegation still costs a sonnet forwarder with two skills loaded, which can erase the saving on small tasks.
- A second-family review that blocks on false positives can stall autonomous runs.
