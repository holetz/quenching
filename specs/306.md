## Problem

Reduzir o custo de operação do quenching por projeto, pedido pelo humano em 2026-11-24: MCP obrigatório no lugar das chamadas recorrentes ao `cq` (um processo Python por chamada), a spec 305 (gates órfãos), o feedback de usuário (503 chamadas ao cq e nenhuma ao MCP; MCP com timeout de 30 s e só specs; 4 hooks `uv run … python` por comando de shell que travam com `.venv` sem `pyvenv.cfg`), gargalos de tempo medidos (preflight 4,8 s, specs list 2,3 s O(n²), specs create 6–8 s) e o reforço do deploy para OpenCode, Claude Code e GitHub Copilot usarem o MCP sem atrapalhar as worktrees.
## Design

- 2026-11-24 — **política de autonomia** (invocação do humano: "Em modo de autopiloto, sem teto, orquestre o desenvolvimento/execução de specs que reduzam o custo de operação do quenching por projeto … Quando finalizar, suba um PR/merge/release"): develop autônomo (approved como orchestrator-forced), execução forçada, push, PR e merge de **todo membro**, folhas incluídas, depois de um PASS do spec-verifier e com CI verde. Sem teto de lançamentos. O release fica com o condutor no fim do épico.
- 2026-11-24 — dirty: 0 path(s); preflight store/push/ghAuth/ci ok, mergesAllowed true; gate inicial verde (1m42s).
- 2026-11-24 — **decisões do humano, não do condutor** (itens 3 e 6 do pedido): juntar os hooks num processo sem `uv run` (307) muda superfície que executa código; registrar o servidor MCP completo e tornar o MCP obrigatório (308, 310); dar aos agentes do OpenCode as grants Bash que a fonte já concede (2240) e liberar `external_directory` só para os slots e o store irmão, mais `experimental.subagent_depth` pelo projeto (314). Esses alargamentos estão autorizados pela invocação; nada fora deles.
- 2026-11-24 — escopo da rodada: só a frente de custo de operação pedida pelo humano; as demais specs soltas do plans (189, 210, 211, 249, 252, …) ficam para outra rodada, sem triagem nesta.
