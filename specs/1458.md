## Problem

O steward pula o carimbo de `branch:`: `plugins/quenching/agents/git-steward.md:40-41` diz "It skips the command's `branch:` stamp", contra `plugins/quenching/commands/git/branch.md` depois da 1424 (passar `--spec` e o verbo carimba). O passo `branch` da 1452 rodou `cq git worktree add` sem `--spec` e a spec ficou sem o registro até o worker carimbar.

## Proposal

- O passo `branch` do steward não afirma mais que pula o carimbo: o comando carimba `branch:` pelo `--spec` do verbo.
- O espelho Codex do steward reflete a mesma frase.

## Out of Scope

- Alargar grants, hooks, CI ou `allowed-tools` do steward: o verbo `cq git worktree add --spec` carimba sozinho, como `cq git pr create --spec` já faz.

## Impact

### Standards this spec will write into docs/standards/

- none — a correção é de prosa do agente.

### Product code this spec expects to touch

- `plugins/quenching/agents/git-steward.md` — frase do passo `branch`
- `plugins/quenching-codex/agents/git-steward.md` — espelho gerado

## Validation

- `grep -c "skips the command" plugins/quenching/agents/git-steward.md plugins/quenching-codex/agents/git-steward.md` retorna 0 em ambos.
- `bash scripts/verify_repo.sh` sai 0.

## Design

A frase velha vem do tempo em que o carimbo ficava com o execute. Depois da 1424 o comando `git/branch.md` passa `--spec <id>` ao verbo, que carimba. O steward roda o comando, então basta tirar a frase e dizer que o carimbo vem do verbo; nenhum grant muda.

## Alternatives Considered

- Adicionar `cq specs record` aos grants do steward: rejeitada, alarga grant e é desnecessária.

## Open Decisions

- none — a direção está dada pelo comando já em vigor.

## Risks

- O steward rodar o verbo sem `--spec` por seguir texto antigo em outro lugar: mitigado pela busca da frase nos dois espelhos.
