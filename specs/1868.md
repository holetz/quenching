## Problem

**O check de escopo do verifier falha em arquivos que o gerador reescreve.** Em 2026-10-17: 1854 (`plugins/quenching-opensource/assets/bin/cq`, cópia byte a byte de `plugins/quenching/assets/bin/cq` feita por `scripts/generate_plugin_modules.py`), 1855 (`plugins/quenching-codex/.generated-files.json`, `scripts/modules.json` do espelho), 1632 e 1818 (`.generated-files.json`), 1635 (138 caminhos), 1807/1808 (`plugins/README.md`, espelho Codex). Cada caso custou um re-spawn ou uma aceitação manual do orchestrator fora do critério literal.

**Proposta mínima.** O verifier (via `cq git audit`) aceita no escopo um arquivo fora dos `files:` quando ele é saída declarada de um gerador do repositório (`scripts/generate_plugin_modules.py`, `scripts/sync_codex_plugin.py`, `cq proof readme`) e a regeneração a partir dos fontes do branch o reproduz byte a byte; arquivo autoral fora do escopo continua FAIL. Testes: gerado reproduzível = ok; gerado editado à mão = FAIL. Gate exit 0.

## Proposal

- `cq git audit` passes a new `generated` field: the subset of `changed` that is a byte-for-byte copy of its source file, per the module manifest of the BASE ref.
- Check 4 (scope) of the `verifier` subtracts `generated` from `changed` before comparing with the union of the tasks' `files:`; an authored file outside `files:` stays FAIL.
- A copy edited by hand (bytes differ from the source) is not in `generated`, so it is FAIL.
- The audit still executes nothing of the audited branch.

## Out of Scope

- Derived outputs that are not copies (`plugins/quenching-codex/**` translations and `.generated-files.json`, `plugins/README.md`, each module's `plugin.json`, `.generated-from.json`): proving them byte for byte needs running a generator, and the audit never runs branch code. They stay FAIL and are parked in `## Discoveries`.
- Running a generator from the base ref inside the audit: a new execution surface, a human decision.
- Changing the gate or CI, which already run `generate_plugin_modules.py --check`.

## Design

**Rule.** The base ref's `plugins/quenching/assets/modules.json` names the modules (published, with `generated` or `owned`) and the source plugin. A changed path `<module.path>/<rel>` is `generated` when `<source>/<rel>` exists at the tip with the same blob id (compared with `rev-parse <tip>:<path>`), or when both are absent at the tip (a deletion mirrored in the source). The generator copies keep `<rel>` unchanged (`copy_files`, `generated_tree`), so same-rel identical blob is exactly the reproduction. The manifest is read from the base, so the branch cannot declare its own outputs. Only git reads with the existing fixed argv; any failed read is an `errors` entry (`complete: false`).

**Limit declared.** An identical blob proves the file equals what the generator would copy; it does not prove the generator would have selected it. The gate (`--check`) and CI certify selection.

## Alternatives Considered

- Run the generators in a temp export and diff: covers derived outputs too, but executes branch code, which the audit's contract forbids.
- Accept any path under a module directory: not byte-for-byte, a real loosening.

## Open Decisions

- Whether to extend to derived outputs by running base-ref generators: decided by a human, in a separate spec.

## Risks

- A hand edit that equals the source is accepted: ACCEPTED — the bytes are then exactly what the generator emits.
- A module path missing from the base manifest is not covered: it stays FAIL, which is the safe side.
