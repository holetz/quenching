## Problem

Um target que ainda guarda as skills no layout `.claude/skills/<nome>/SKILL.md` some para o status e para o doctor.

- `load_surface` e `discover_commands` (`plugins/quenching/assets/bin/quenching/components/surface.py:129,176-177`) só percorrem `commands/`.
- Sem `commands/`, `cmd_status` (`components/commands/cli.py:118-121`) responde `applicable: false, ok: true`, e o doctor responde `sk-no-surface`.
- Nada em `surface.py` ou `cli.py` olha `skills/*/SKILL.md`. O único lugar que descobre `SKILL.md` é o tradutor Codex (`commands/translate.py:507-514`).
- `/quenching-align:components:align` §2 (`plugins/quenching/commands/components/align.md:91`) acha os pares legados com um Glob manual. O §1 admite "the legacy pairs the tool cannot see".

Consequência: uma skill nova adicionada nesse layout nunca tem a descrição checada. O status de um target só com skills diz "não aplicável, ok", enquanto o align teria pares para colapsar. A manutenção contínua não tem sinal de que existe trabalho.

Esperado: a superfície descobre `.claude/skills/*/SKILL.md` e o doctor emite um finding nomeado que aponta para o colapso do align. O status passa a mostrar o target como aplicável e não conforme. Um teste cobre um target só com skills.

Depende de 1985 (a mesma `surface.py`).
