## Problem

`cq ops doctor` never emits `op-registry-malformed` when the registry file is not valid UTF-8. Evidence at origin/main 528de920: `plugins/quenching/assets/bin/quenching/ops/checks.py:68-72` (`_registry_text`) catches `UnicodeDecodeError` together with `OSError` and returns `None`, and `check_registry_stale` (`checks.py:109-111`) treats `None` as "no registry" and returns `[]`. The contract says otherwise: `docs/standards/architecture/ops-front.md:216` defines `op-registry-malformed` as a registry whose generated zone is duplicated or whose file is not valid UTF-8, and `plugins/quenching/assets/references/ops-align/bands.md:60` repeats it.

Reproduction: a MalformedRegistry fixture (`ops.opsRoot=scripts`, router `pyproject.toml`) with `scripts/README.md` holding the bytes `b'\xff\xfe not utf-8\n'`. `cq ops registry` refuses with exit 2, "registry document is not valid UTF-8". `cq ops doctor --json` exits 1 and reports only `op-adhoc-root`, `op-orphan` and `op-undocumented`, with no `op-registry-malformed`. Consequence: doctor points at a regeneration (`op-undocumented`) that `cq ops registry --write` refuses, so the owner gets no finding that names the real defect.

Scope: read the registry through `registry.read_registry`, map `RegistryError` to `op-registry-malformed`, and keep `None` only for a missing file. Add a doctor test for invalid UTF-8 in `plugins/quenching/tests/test_ops.py`.
