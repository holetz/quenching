## Problem

A 1265 (#1273) deu ao verifier, que é só leitura, grants com curinga no meio: `Bash(git -C * status:*)`, `Bash(git -C * stash list:*)` (e os mesmos para `reflog show` e `merge-base`) e `Bash(bash */scripts/verify_repo.sh:*)` (`plugins/quenching/agents/verifier.md:4`). Pela documentação de permissões do Claude Code, `*` casa qualquer texto, inclusive espaços. A re-revisão de 2026-10-08 reproduziu, num repositório descartável, o que o git executa para comandos que casam esses padrões: `git -C repo branch -D victim1 status` apagou a branch; `git -C repo -c core.fsmonitor="touch …" status` executou o comando; `git -C repo diff --output=<arquivo fora> -- status` zerou o arquivo; `git -C repo clean -fdx -- . status` removeu os não rastreados; e `bash -c "touch …" x/scripts/verify_repo.sh` executou código. Os grants antigos `git log:*` e `git diff:*` também admitem `--output=<arquivo>`. E `verifier.md:23-24` ainda manda rodar `bash scripts/verify_repo.sh` sem caminho, contradizendo `:14-18`.

Consequência: o agente de aceite, documentado como só leitura, pode apagar branches e trabalho, truncar arquivos e rodar código — e fica exposto a prompt injection vinda do diff que audita. É uma regressão de segurança introduzida pela própria noite.
