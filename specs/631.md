## Problem

Na spec 625 (2026-11-26), a task 4.1 declarou `verify: python3 quenching/assets/bin/cq components lint --json` para provar uma mudança em `quenching/references/align/tool-resolution.md`. Sem caminho, o lint leu a superfície deployada: o payload respondeu `"root": ".../quenching-slot-3/.agents", "commandCount": 4`. Essa superfície ainda estava sem o redeploy, então o `exit 0` não dizia nada sobre a fonte alterada. Lintar a fonte (`cq components lint quenching --json`) também não serve como verify: devolve exit 1 com 59 erros `sk-reference-root`, idênticos no `main`, porque as bodies citam `.agents/skills/...`, que não existe na árvore-fonte.

O que a melhoria tem de tornar impossível: um `verify:` de corpo ou reference que fica verde sem ler a fonte alterada.

Correção mínima proposta: o lint aceitar a fonte do repositório quenching como superfície (resolver `.agents/skills/<x>` para `quenching/skills/<x>` ali), ou o develop do quenching passar a usar `python3 -m pytest quenching/tests/test_components_lint.py` como verify de corpo.

**Insumos**

- quenching/assets/bin/quenching/components (raiz padrão do `cq components lint`)
- spec 625, task 4.1 e seu `verify:`
- `cq components lint quenching --json` → exit 1, 59 `sk-reference-root` (no `main` também)
- quenching/tests/test_components_lint.py::StrictFrontmatter::test_the_plugin_command_surface_has_no_lint_errors (o teste que de fato lê a fonte)
