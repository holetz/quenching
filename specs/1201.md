## Problem

`plugins/quenching/assets/bin/quenching/components/commands/cost.py:212-219` captura `OSError` e `JSONDecodeError` mas não `UnicodeDecodeError`: `cq components cost --ratchet` com um baseline não UTF-8 imprimiu traceback (reproduzido em 2026-10-07), enquanto o irmão `proof/ratchet.py:216` captura. `design/genre.py:430` (`typst compile`) e `:361` (engine externo) chamam subprocess sem timeout, e todo outro subprocess do pacote passa um; o caminho do typst também não captura `OSError`.

Consequência: o portão de custo morre com stack trace em vez do achado `ct-cost-ratchet` que os consumidores `--json` esperam, e um engine travado trava `cq design build` inteiro.

## Proposal

Capturar `UnicodeDecodeError` como o irmão; dar timeout aos dois subprocessos de design e converter `OSError` e timeout em `DesignError`.

## Out of Scope

Outros verbos sem achado medido.

## Impact

### Standards this spec will write into docs/standards/

- none — a robustness fix in two existing verbs; no standard is declared.

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/components/commands/cost.py` — `_ratchet_finding` catches `UnicodeDecodeError`
- `plugins/quenching/assets/bin/quenching/design/genre.py` — timeout and `OSError` handling at the engine and typst subprocesses
- `plugins/quenching/tests/test_components_cost.py` and `plugins/quenching/tests/test_design.py` — regression tests

## Validation

Teste com baseline `\xff\xfe` dá achado estruturado sem traceback; teste com engine que dorme além do timeout dá `DesignError`; `bash scripts/verify_repo.sh` sai 0.

## Design

- A ratchet baseline that cannot be decoded is the same class of failure as one that cannot be parsed: it yields the structured `ct-cost-ratchet` finding. `UnicodeDecodeError` is caught beside `JSONDecodeError`, as the sibling `proof/ratchet.py` does. Evidence: dependency sweep skipped (two files, one function each); the read of `cost.py:212-219` and `genre.py:361,430` shows both gaps on main.
- Every subprocess in the package passes a timeout (`common/git.py` `COMMAND_TIMEOUT_S = 60`). The two design subprocesses take a module constant `SUBPROCESS_TIMEOUT_S = 60` in `genre.py`, the same value, patchable by tests. `subprocess.TimeoutExpired` becomes `DesignError`; the typst path also converts `OSError`.

## Alternatives Considered

- Importing `COMMAND_TIMEOUT_S` from `common/git.py`: rejected, it couples design to the git module for an unrelated constant; the value is repeated, not shared.
- A configurable per-genre timeout: rejected as scope growth with no measured need.

## Open Decisions

- none — the timeout value is fixed at 60 s to match the package; no unanswered item remains.

## Risks

Um timeout curto demais reprova builds legítimos; usar o mesmo valor que os outros subprocessos do pacote.
