## Problem

`integrations/claude-hud/hooks/register.tsx:21` chama `cq` pelo nome. `cq deploy` instala `.agents/quenching/bin/cq` sem pô-lo no PATH (o próprio vitrine diz isso em `integrations/claude-vitrine/hooks/cq.ts:85` e resolve o lançador com `withLauncher`/`DEPLOYED_CQ`). Reprodução (scout b, round 11): no checkout deste repositório, `command -v cq` → nada, `bash -c 'cq specs status --spec 1037500 --no-fetch --json'` → `cq: comando não encontrado`; o `catch` silencia e a faixa do HUD some em todo branch `plan/`.

Correção natural: o HUD resolver `<toplevel>/.agents/quenching/bin/cq` como o vitrine. Isso faz um hook do Claude Code executar um arquivo que vem do repositório aberto (um repositório hostil pode plantar `.agents/quenching/bin/cq`) — alarga o que um hook executa, por isso é decisão do humano (never-forced). A spec 207 corrige só o README.
