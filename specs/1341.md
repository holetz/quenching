## Problem

A auditoria falha aberta: `_lines` devolve `[]` em qualquer erro (`audit.py:30-32`, `plugins/quenching/assets/bin/quenching/git/state.py:28`). `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review10/audit/failopen.sh` (índice corrompido, `status` sai 128) → `ok: True status: []`; `hang.sh` → filtro morto aos 60 s e exit 0. Consequência: os checks 4 e 5 do verifier e a auditoria por onda passam no vazio.

Origem: item R3 da fila da rodada 2 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round2-queue.md`), da revisão de correção opus do épico 1306.

## Proposal

Erro de git vira fato de erro no payload e o verifier o lê como inconclusivo. Depois do R2.

## Out of Scope

- A timeout that kills grandchildren of a hanging config program: 1338 blanked the `filter.<x>` drivers, so `hang.sh` no longer reaches one; this spec only makes a timeout visible.
- The verifier's other checks (gate, delivery): unchanged.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/git/audit.py` — `_lines` records a failed read; the payload gains `errors` and `complete`
- `plugins/quenching/assets/bin/quenching/git/state.py` — same for `cq git state`
- `plugins/quenching/agents/verifier.md`, `plugins/quenching/agents/orchestrator.md` — read `complete: false` as inconclusive
- `plugins/quenching/tests/test_git.py` — one test per vector

## Validation

- Reproduction (corrupt index, `status` exits 128): before, `ok: True status: []`; after, `complete: false` and `errors` names `status`.
- `python3 -m unittest discover -s plugins/quenching/tests -p test_git.py -k FailClosed` exits 0.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- A git read that fails (non-zero exit, timeout 127, no git) is an entry `{read, code, message}` in the payload's `errors`, and `complete` is `not errors`; the verb still exits 0 (a REPORT). Durable rule: a fact the tool could not read is never rendered as an empty fact.
- `merge-base --is-ancestor` exit 1 is the honest "no"; only exit above 1 is an error.
- The verifier and the orchestrator treat `complete: false` as inconclusive, so FAIL.
- 1338's `audit._inert_env` stays untouched.

## Alternatives Considered

- Exit non-zero on a failed read: rejected, the verb is a REPORT and callers parse the payload on exit 0.
- Raise on failure inside `_lines`: rejected, one failing read would hide the other facts.

## Open Decisions

- none — every item was decided from the evidence above.

## Risks

- A caller that ignores `complete` still reads the empty list: mitigated by the verifier and orchestrator bodies naming it.
- A new field in the payload: additive, no existing key moves.

All three tasks committed; remaining: conclude (gate, PR).
