## Problem

Revisão de correção do épico 2042 (2026-10-24, faixa e49d71126..b5a5873b0), achados reproduzidos sobre o código da 2039:

- `commands/validate.py:311-313` (Claude e Codex): ao remover os nós do primeiro ciclo, a varredura escopada destrói os ciclos que se sobrepõem a ele. Com o store `1→[2]`, `2→[1,3]`, `3→[2]`, `find_cycle` devolve `['1','2','1']`, a remoção deixa `None`, e `validate --spec 3` não acusa o ciclo `2→3→2`.
- `commands/deps.py:40-47` (Claude): o `--remove` de um id ausente ou do próprio id recusa com `sp-dep-missing` ou `sp-dep-self`. Os testes fixam esse comportamento (`test_specs_deps_commands.py:62-66`), e é justamente o reparo que o remedy de `validate.py:298-299` manda fazer pelo único escritor da chave.
- `commands/deps.py:49-51` (Claude): o grafo não filtra self-edges e não se limita à spec editada. Com `{"X":["X"],"Y":[]}`, `find_cycle` devolve `['X','X']`, e qualquer edição de `Y` recusa nomeando um ciclo que não tem relação com ela.
- `parse/deps.py:150-151` e `:169-177` (Claude): uma dependência arquivada como `dropped` entra no máximo do caminho crítico. Com o fixture de `test_specs_deps.py:137`, o resultado é `criticalPath: ['A']` e `B` com `critical: False`.
- `parse/deps.py:145` (Codex): uma dependência aberta sem datas marca `blocked` antes do tratamento de `outcome: done`. Uma spec arquivada como concluída, com `target`, mostra `earliestFinish: null`, enquanto as sucessoras continuam calculadas a partir do `target` dela.
- `parse/deps.py:38` (Codex): `find_cycle` é recursivo. `find_cycle({str(i): [str(i+1)] for i in range(1100)})` levanta `RecursionError`, então `validate` e `schedule` caem num backlog com uma cadeia longa.

Consequência: o `validate`, o `cq specs depends` e o cronograma que o Gantt do portal lê dão respostas erradas, ou recusam e caem, em stores válidos.

## Proposal

- `find_cycle` in `parse/deps.py` walks the graph iteratively: a 1100-node chain (and any longer one) returns `None` instead of raising `RecursionError`, and the cycle it reports for a cyclic graph is the same one as today.
- `cq specs validate --spec <id>` reports every cycle that touches the selection, including cycles that share a node with an earlier one (`1→[2]`, `2→[1,3]`, `3→[2]` reports `1,2,1` and `2,3,2` for `--spec 3`).
- `cq specs depends <id> --remove <dep>` removes an id that is absent from the store or is the spec's own id, which is the repair the `sp-dep-missing` and `sp-dep-self` remedies prescribe; `--add` keeps refusing both.
- `cq specs depends <id>` refuses with `sp-dep-cycle` only for a cycle that passes through the edited spec; self-edges and cycles among other specs never block an edit of an unrelated spec.
- `cq specs schedule` leaves an archived non-`done` (dropped) dependency out of the critical path.
- `cq specs schedule` computes an archived `outcome: done` spec's `earliestFinish` from its own `target` even when one of its own dependencies is open and undated.
- The generated mirrors carry the same code and `docs/standards/workflows/spec-dependencies.md` states the `--remove`, scoped-cycle and dropped-path rules.

## Out of Scope

- Folding `dependsOn` into `cq specs next` ranking: still the follow-up that `spec-dependencies.md` records.
- The recursive `find_cycle` in `parse/epics.py` (epic `after:` edges): it works on one epic's items, not on a whole backlog, and is parked as a discovery.
- A new finding code or a new flag on `cq specs depends`: every fix is a behaviour correction under the existing codes.
- Cross-repository dependency ids: the contract still reads only ids of this store.

## Design

Decisions, stated as rules:

- **Iterative search.** `find_cycle` keeps the DFS order (sorted roots, declaration-order edges, same first cycle) but uses an explicit stack of `(node, iterator)` frames, so depth is bounded by memory, not by the interpreter's recursion limit.
- **Peel the closing edge, not the nodes.** The scoped sweep finds a cycle, records it, deletes only its closing edge (last node to first) and searches again, until the graph is acyclic. Each pass removes one edge, so it terminates, and cycles that overlap an earlier one survive to be found. Cycles are deduplicated by their node set.
- **`--remove` is a repair, not an edit to validate.** Only `--add` ids are checked for `sp-dep-self` and `sp-dep-missing`. Removing an id not in `dependsOn` stays an idempotent no-op with no write.
- **The edit refuses only its own cycle.** A new `find_cycle_through(edges, node)` looks for a path from `node` back to itself (iterative), over edges with self-edges dropped; the reported path is rotated to start at its smallest id so the existing `["1","2","3","1"]` shape holds.
- **A dropped spec is not a schedule input to the critical path.** Archived specs whose outcome is not `done` are excluded from the set that picks the latest finish. They stay in `nodes`.
- **A done-archived spec is fixed by its `target`.** The `blocked` marker applies only to specs that are not archived `done`.

Binding contract: `docs/standards/workflows/spec-dependencies.md` (the verbs, the derivation and the findings) and `docs/standards/workflows/epics.md` (a dropped dependency never satisfies an edge).

## Alternatives Considered

- Raise `sys.setrecursionlimit` instead of an iterative search: rejected, it only moves the cliff and risks a native stack overflow.
- Report one cycle per strongly connected component (Tarjan): rejected, it names a node set, not the path that `sp-dep-cycle` prints.
- Keep refusing `--remove` of an unknown id and add a separate `--prune` flag: rejected, it adds surface for what the existing remedy already asks.

## Open Decisions

- none — every behaviour above is fixed by the cited remedies, the contract and the findings; the `--remove` of an id that is not in the key stays a silent idempotent no-op, decided by the existing idempotence test.

## Risks

- A scoped sweep that peels edges could report more cycles than before on a dense cyclic store: ACCEPTED, each is a real cycle touching the selection, and the findings are deduplicated by node set.
- Hand-editing the mirrors would pass locally and fail the generator check: mitigated by regenerating with the generators only and running the gate.
- Reordering the done-archived branch could change `blocked` for some open specs: mitigated by limiting the change to `phase == archive` with `outcome == done` and a test for the open case.
