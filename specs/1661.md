## Problem

The model policy never downgrades production code: `execution-delegation.md` pins the per-task executor
to the session model and says **never `haiku`**, and the orchestrator routes workers only to sonnet or
opus. The rule is right while nothing can catch a cheap model's mistake, but many execute tasks already
carry a deterministic oracle (`verify:`) and run in a disposable worktree, which is the condition under
which a cheaper executor can be measured without risk.

The economics are not flat and must shape the rule. Pricing checked on 2026-10-14 (Claude API reference,
cached 2026-10-06): Claude Haiku 5.5 has two rate cards chosen by prompt length, $0.10 / $0.50 per MTok
up to a 100K-token prompt and $0.50 / $2.50 above it (5×, applied to the whole prompt); cache reads are
0.1× the input rate and cache writes 1.25× (5 min) or 2× (1 h) of the card in force; its tokenizer counts
about 30% more tokens than Haiku 4.5's. Sonnet 5.5 is $2 / $10 flat to 1M, Opus 5.5 $4 / $20. Below the
cut, haiku is 20× cheaper per token than sonnet; above it, only 4×, and smaller models also degrade in
long context. An agentic executor's prompt grows every turn, so a task that crosses 100K loses most of
the advantage at the moment it is most likely to fail.

## Proposal

Add a `haiku` (`claude-haiku-5-5`) rung below sonnet for the execute executor, admitted only when every
condition holds:

1. a deterministic oracle exists before the task runs: the task's `verify:`, written by a stronger model or a human;
2. the oracle's files are outside the task's `files:`, so the executor cannot edit the test it is judged by;
3. failure is reversible: worktree, no destructive git, nothing under `knowledge/`;
4. the projected peak context of the executor stays at or under ~80K tokens, counted with Haiku 5.5's tokenizer and including the subagent's fixed system prompt, tools and loaded instructions; a task that does not fit goes to sonnet;
5. a short escalation ladder: one haiku attempt, then sonnet, then the human on the second FAIL;
6. a stronger model reviews the diff (reading it, not rewriting it) before the task is checked.

The change is decided in an ADR that amends `README.md` §Model policy, and a pilot measures it.

## Out of Scope

- `/quenching:knowledge:import-memory`: its classifiers and executors stay never-haiku (irreversible deletion, no oracle).
- Haiku for judgment: develop, triage, conclude, the orchestrator, the verifier, any `/docs/standards/` write.
- Tasks without `verify:` or whose oracle lives inside their own `files:`.
- Codex as the cheap rung, which is spec 1660's subject.

## Validation

- A task without `verify:`, with its oracle inside `files:`, or projected above the context ceiling is never routed to haiku.
- A haiku FAIL escalates once to sonnet and then to the human; no haiku retry loop exists.
- Pilot on about 10 tasks of `complexity: low` specs against a sonnet baseline, measured as cost per **completed** task (retries and escalations included), not per request, with `cq components session cost` per model; the verifier PASS rate and the reviewer's rejection rate reported beside it.
- Peak prompt size per haiku executor recorded, and the share of requests that crossed 100K reported; a nonzero share means the projection under-estimates.

## Design

- **The 80K ceiling is a margin, not the cut.** It leaves room for the turns the executor adds while it
  works (tool results, re-reads, the verify output) before the prompt reaches 100K, where every following
  request is billed on the higher card including its cached reads.
- **The projection is declared, not observed.** It sums the subagent's fixed prompt with the sizes of the
  task's `files:` and the files it names as pattern, converted with Haiku 5.5's tokenizer; anything the
  task cannot bound routes to sonnet.
- **Cost per completed task decides.** A cheap request that needs a retry, an escalation and a stronger
  review is not cheaper; the ADR records the pilot's numbers, and the rung stays only if they hold.

## Open Decisions

- How the projection is computed: a deterministic `cq` estimate over the task's declared files, or a judgment step in the executor brief.
- Whether the diff review is done by the orchestrator itself or by a separate stronger subagent, and its own context budget.
- Which effort level the haiku executor runs at (Haiku 5.5's default is `medium`).
- Whether the subscription used in Claude Code weights models in proportion to API prices; if not, the rung's saving must be measured in the subscription's own usage units.

## Risks

- A cheap executor can overfit to the oracle (special-casing the tested inputs); the protected oracle and the stronger review are the only defenses, and neither is proof.
- The fixed prompt of a Claude Code subagent is large; small tasks may already start near the ceiling, which shrinks the eligible set.
- Pricing is a cached reference and may change; the ADR must cite the date it was checked and the pilot must re-read it.
- Multi-model routing forfeits prompt-cache reuse across models.
