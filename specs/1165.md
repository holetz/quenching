## Problem

O PR #1158 do dependabot (zensical 0.0.57 → 0.0.67) está vermelho no CI (run 37641284615, jobs
Gate 3.11 e 3.13): `RuntimeError: error reading page metadata 'decisions/0003-plan-git-record-history.md':
mapping values are not allowed in this context at byte 102 line 3 column 57` → `FAILED: Zensical strict build`.

Medido nesta sessão com `yaml.safe_load` sobre o frontmatter de `docs/**/*.md`: **8 docs** não são
YAML válido. Sete têm `description:` com `: ` sem aspas e um começa o valor com crase:
`docs/decisions/0003-plan-git-record-history.md`, `docs/standards/automation/skill-evaluation.md`,
`docs/standards/workflows/plugin-configuration.md`, `docs/standards/quality/computed-fact-prose-fanout.md`,
`docs/standards/architecture/{bundle-root,type-follows-home,shared-mold-keys}.md`,
`docs/concepts/automation/skills-lint-warning-exit-code.md`. O `cq knowledge validate` (parser
próprio, tolerante) e o zensical 0.0.57 aceitam esses arquivos, então o gate local fica verde.

Além disso, há ~9 links relativos quebrados que o gate não pega:
`docs/standards/workflows/task-execution.md:290,394,415`, `plan-git-record.md` (3) e
`architecture/spec-backend.md` (2) apontam `../decisions/000N-…`, que resolve para
`docs/standards/decisions/` (inexistente); `docs/glossary.md:186` aponta `../standards/…`;
`docs/decisions/0002-task-execution-history.md` linka `plan-git-record.md` no próprio diretório.

Consequência: nenhuma atualização do zensical entra; o dependabot, ligado hoje pela spec 1152, fica
vermelho para sempre nesse ecossistema; um agente que segue o "porquê" (ADR 0002, 0003, 0006) cai num 404.

Default registrado no `## Design` do épico #1163: erro neste repositório; em alvos, o develop decide entre warning e erro (tag `breaking` se for erro).
