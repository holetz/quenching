## Problem

O PR #1158 do dependabot (zensical 0.0.57 → 0.0.67) está vermelho no CI (run 37641284615, jobs
Gate 3.11 e 3.13): `RuntimeError: error reading page metadata 'decisions/0003-plan-git-record-history.md':
mapping values are not allowed in this context at byte 102 line 3 column 57` → `FAILED: Zensical strict build`.

Medido nesta sessão com `yaml.safe_load` sobre o frontmatter de `docs/**/*.md`: **8 docs** não são
YAML válido. Sete têm `description:` com `: ` sem aspas e um começa o valor com crase:
`docs/decisions/0003-plan-git-record-history.md`, `docs/standards/automation/skill-evaluation.md`,
`docs/standards/workflows/plugin-configuration.md`, `docs/standards/quality/computed-fact-prose-fanout.md`,
`docs/standards/architecture/{bundle-root,type-follows-home,shared-mold-keys}.md`,
`docs/concepts/automation/skills-lint-warning-exit-code.md`. O `cq knowledge validate` (parser
próprio, tolerante) e o zensical 0.0.57 aceitam esses arquivos, então o gate local fica verde.

Além disso, há ~9 links relativos quebrados que o gate não pega:
`docs/standards/workflows/task-execution.md:290,394,415`, `plan-git-record.md` (3) e
`architecture/spec-backend.md` (2) apontam `../decisions/000N-…`, que resolve para
`docs/standards/decisions/` (inexistente); `docs/glossary.md:186` aponta `../standards/…`;
`docs/decisions/0002-task-execution-history.md` linka `plan-git-record.md` no próprio diretório.

Consequência: nenhuma atualização do zensical entra; o dependabot, ligado hoje pela spec 1152, fica
vermelho para sempre nesse ecossistema; um agente que segue o "porquê" (ADR 0002, 0003, 0006) cai num 404.

Default registrado no `## Design` do épico #1163: erro neste repositório; em alvos, o develop decide entre warning e erro (tag `breaking` se for erro).

## Proposal

- The 8 `docs/**/*.md` whose frontmatter is not valid YAML parse under `yaml.safe_load` (values quoted), so the zensical 0.0.67 strict build reads them.
- The relative links in `docs/` that resolve to nothing (`../decisions/…` from `standards/`, `../standards/…` from `glossary.md`, the sibling `plan-git-record.md` from `decisions/`) resolve to existing pages.
- `cq knowledge validate` reports a concept doc whose frontmatter has a plain scalar that strict YAML rejects (`: ` inside an unquoted value, or a value opening with a backtick) as the ERROR `frontmatter-not-yaml`.
- `cq knowledge validate` reports a link in any concept doc that points at a `.md` or directory inside the bundle that does not exist, as the WARN `doc-broken-link` (the same rule `index-broken-link` and `glossary-broken-link` already apply).

## Out of Scope

- Bumping zensical in `pyproject.toml`/`uv.lock`: that is dependabot PR #1158; this spec only removes what blocks it.
- Adding PyYAML as a dependency: the plugin is stdlib-only, so the check is a heuristic over the plain-scalar rules, not a full YAML parse.
- Making `doc-broken-link` an ERROR: OKF tells consumers to tolerate broken links; the structure family stays WARN by design.
- Links to files outside the bundle (`../..` climbs, repo-absolute paths): `_resolve_link` already declines them.

## Impact

### Standards this spec will write into docs/standards/

- none — the check refines two existing codes' behaviour under `docs/standards/code/frontmatter-parser.md` and the validate contract; no new standard is declared up front, and anything revealed is a discovery for conclude.

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/knowledge/structure.py` — `doc-broken-link` over concept docs

## Validation

- `uv run --with zensical==0.0.67 zensical build --clean --strict` after regenerating the site source exits 0 (it exits non-zero today with `error reading page metadata`).
- `python3 plugins/quenching/assets/bin/cq knowledge validate docs` prints `0 error(s), 0 warning(s)`.
- On a fixture bundle with a `description: a: b` doc and a doc linking a missing `.md`, the same command exits 1 with `frontmatter-not-yaml` and prints `doc-broken-link`.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- **Durable rule: the validator's parser is tolerant on purpose, so strict-YAML compatibility is a separate check.** The common parser keeps reading `key: a: b`; `frontmatter-not-yaml` is raised beside it, never by tightening the parser, so the specs/skills/components readers do not change behaviour.
- **Heuristic, stdlib-only.** For each top-level `key: value` line whose value is a plain scalar (not starting with a quote, `[`, `{`, `|`, `>`), flag when it contains `: ` (or ends with `:`) or starts with a YAML indicator (a backtick, `@`, `%`, `*`, `&`, `!`). Block-scalar and list bodies are not inspected. Default registered in epic #1163: ERROR in this repository.
- **`doc-broken-link` reuses `_link_targets`/`_resolve_link` in `validate_structure`**, extending `link_checked` to every concept doc instead of adding a second walker; the code is distinct so a prose-link finding is told apart from a dead listing entry.
- `frontmatter-not-yaml` joins `CONCEPT_DOC_CODES` so an unsigned directory is not charged one ERROR per document.
- Fix the data by quoting with double quotes (escaping `"` and `\`), and fix each dead link by correcting its relative path.

### Mapa de dependências

- `knowledge/checks.py` is called only from `knowledge/validate.py`; `schema.CONCEPT_DOC_CODES` is read by `validate_tree`. Nothing else consumes the new codes. The plugin copy under the Codex translation is regenerated by `cq components translate`, run by the gate.

## Alternatives Considered

- Vendor or require PyYAML for an exact parse: rejected, the plugin is stdlib-only and a dependency for one check is out of proportion.
- Tighten `common.frontmatter.parse_frontmatter` to refuse these: rejected, it would change behaviour for every spec/skill reader that today tolerates them.
- Leave only the zensical strict build as the guard: rejected, that is the status quo that let a pinned old version hide the defect.

## Open Decisions

- Whether targets outside this repo get WARN or ERROR for `frontmatter-not-yaml`: decided at conclude from the epic #1163 default; this spec ships ERROR and flags the breaking tag in Risks.

## Risks

- A target bundle with unquoted `: ` values now fails validate: ACCEPTED, those files already break a strict YAML consumer; the message names the key and the fix.
- The heuristic false-positives on a legitimate plain scalar: mitigated by only flagging `: ` and the indicator starts, which strict YAML itself rejects in a plain scalar.
- New WARNs from `doc-broken-link` in other bundles: ACCEPTED, WARN does not fail the gate.
