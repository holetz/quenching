## Problem

A trava de ignorados do `cq git worktree retire` falha aberta quando o `git status` falha: com `git config status.showUntrackedFiles no` e um `.env` ignorado, `git status --porcelain --ignored=matching` sai `fatal: Unsupported combination of ignored and untracked-files arguments`, e `cq git worktree retire --path wt --branch feat --base main --json` devolve `ok: true, worktreeRemoved: true` — o `.env` some (controle sem a config: exit 1, `ignored: [".env"]`) (`/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review12/retire`). Onde: `plugins/quenching/assets/bin/quenching/git/worktree.py:197-198`. Mesma causa em `plugins/quenching/assets/bin/quenching/git/audit.py:248`: sob a config, `status` volta `[]` com arquivo não rastreado, e o check 5 do verifier (`plugins/quenching/agents/verifier.md:42`) passa. Direção: exit ≠ 0 é recusa; as duas leituras passam `--untracked-files=normal`. Depois do V1 (mesmo `audit.py`).

Origem: item V2 (média) da fila da rodada 4 do autopilot de 2026-10-08 (`.quenching/autopilot/2026-10-08/round4-queue.md`), da revisão de correção opus da rodada 3 (épicos 1337 e 1364).

## Proposal

- `cq git worktree retire` recusa (exit 2, código próprio) quando a leitura de ignorados falha, em vez de tratar a falha como "nada ignorado".
- A leitura de ignorados de `retire` e o `status` de `cq git audit` passam `--untracked-files=normal`, então valem sob `status.showUntrackedFiles=no`.
- Um teste reproduz a configuração `status.showUntrackedFiles no` com `.env` ignorado e prova que o worktree fica de pé.

## Out of Scope

- `state.py:33` (mesmo `status` sem a flag): superfície de outro comando, parqueada como discovery.
- Mudar a política de `--discard-ignored`: continua pulando a leitura.

## Design

- Decisão: `_ignored_files` devolve `None` quando `git status` sai ≠ 0; `_retire` converte em `refuse` (exit 2) antes de qualquer escrita. Regra durável: leitura de segurança que falha é recusa, nunca ausência.
- Decisão: `--untracked-files=normal` explícito nas duas leituras, pois `--ignored=matching` é incompatível com `showUntrackedFiles=no`.
- Alternativa pesada: usar `git ls-files --others --ignored --exclude-standard`; descartada, muda a semântica de `matching` (diretórios).
