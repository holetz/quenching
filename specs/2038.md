## Problem

OpenCode is the default harness of the platform, but quenching ships only for Claude Code and, through `quenching-codex` and `scripts/sync_codex_plugin.py`, for Codex. Generate and validate an OpenCode distribution of the commands, agents and `cq` tooling following the Codex sync pattern, so the H1 spike can run quenching on OpenCode with the Flash model.

Member S3 of holetz/forge epic 1 (Deliver the self-hosted AI-assisted development platform around Omnigent).

## Proposal

Add a second generated distribution, `plugins/quenching-opencode/`, laid out as an OpenCode configuration directory, and produce it with a new deterministic generator, `scripts/sync_opencode_plugin.py --write|--check`, that follows the Codex sync pattern (`scripts/sync_codex_plugin.py` → `cq components translate`).

The generator does not re-translate the Claude source from scratch: it builds the Codex tree in memory with the existing translator (`translate.configure(plugins/quenching, plugins/quenching-codex)` + `translate.generated_tree()`), which already removes every Claude-only marker, and re-maps that tree to OpenCode:

```
plugins/quenching/ ──cq components translate (in memory)──> Codex tree
Codex tree ──sync_opencode_plugin.py──> plugins/quenching-opencode/
  skills/<name>/SKILL.md        -> commands/<name>.md   (frontmatter: description; Codex runtime block -> OpenCode runtime block)
  agents/<agent>.md             -> agents/quenching-<agent>.md (mode: subagent; deny-only permissions mapped from the source tools:)
                                   + quenching/agents/<agent>.md (protocol copy)
  references/ templates/ specs/ knowledge/ design/ portal/ -> quenching/<same>/
  scripts/ (cq + bin)           -> quenching/scripts/   (verbatim)
  checks/, .codex-plugin/, skills/*/agents/openai.yaml, README.md -> not carried
  + README.md (install), .generated-from.json, .generated-files.json
```

The bundled `cq` is reached through a per-call wrapper, `cq() { python3 "${QUENCHING_OPENCODE_ROOT:-$HOME/.config/opencode/quenching}/scripts/cq" "$@"; }`, substituted for the Codex wrapper in every bash block; payload paths (`../../references/` and siblings) become `~/.config/opencode/quenching/<dir>/`. Model pins are not carried: commands and agents inherit the session model (Flash in H1), and the source tier is kept as prose. `--check` also validates the generated tree (no Claude or Codex markers, every cq bash block defines the OpenCode wrapper, every command has a description, every agent is `mode: subagent`, command and agent counts equal the source). The check joins `scripts/verify_repo.sh`, and the release regeneration steps run the generator after the Codex one so a version bump keeps the tree in lockstep.

## Out of Scope

- An OpenCode JS/TS plugin, OpenCode hooks or any host event wiring — hooks are never forced in this epic.
- Running the commands on a live OpenCode host and judging quality — that is the H1 spike (holetz/forge#2), fed by the eval runner of #2037.
- Harness-independent Omnigent agents (#2041) and per-model evals.
- A marketplace/registry entry or a `distributions` row in `modules.json` for OpenCode: OpenCode has no plugin catalog for Markdown commands; installing is copying the directory.
- Translating each command's `allowed-tools` into a per-command permission set, and exact allow-patterns for agents' scoped `Bash(...)` grants (see `## Open Decisions`).
- Hand edits to any generated mirror (`quenching-codex`, `quenching-specs`, `quenching-specs-reader`, `quenching-opencode`).

## Design

### Why this shape

The Codex translator already owns the hard part (platform markers, `${CLAUDE_PLUGIN_ROOT}` paths, module-qualified ids → `quenching-<front>-<verb>`, model-tier and telemetry prose, removals). Deriving from its in-memory tree keeps one translation authority and makes the OpenCode generator a thin, testable re-mapping. The Python payload is carried verbatim from the Codex tree: its components surface model reads `.agents/skills/`, which OpenCode also discovers, so `cq` behaves the same on both hosts (assumption named; H1 confirms on a live host).

### Agent permissions (deny-only)

Source `tools:` are mapped so the generated agent is never wider than the source: no `Edit`/`Write`/`NotebookEdit` → `edit: deny` (and write/patch); no `WebFetch` → `webfetch: deny`; no `Bash` at all → `bash: deny`; scoped `Bash(...)` only → `bash: ask`, because the wrapper prefix makes pattern allow-lists unmatchable; unrestricted `Bash` → `bash: allow`. Exact allow-patterns are the human's (never forced: an agent's tools).

## Open Decisions

- Scoped `Bash(...)` agent grants are generated as `bash: ask` (never wider than the source). Whether to replace that with exact allow-patterns (which requires a wrapper-free `cq` call form) is the human's — never forced in this epic; decided after H1 shows whether `ask` stalls a non-interactive `opencode run`.
- Command `allowed-tools` are dropped, as the Codex precedent does: an OpenCode command runs under the session agent's permissions. Whether each command should instead run under a narrowed generated agent is the human's — never forced (widening or reshaping grants).
- Directory names `commands/` and `agents/` (plural) are assumed from the current OpenCode documentation, which also accepts the singular form; H1 confirms on a real install.

## Risks

- **Unverified on a live host.** `opencode` is not installed where this is built; the layout and frontmatter follow the documented OpenCode format but are proved only structurally here. H1 (forge#2) is the first live run. Accepted: the spec's consumer is exactly that run.
- **Permission gap versus Claude.** Commands lose their `allowed-tools` narrowing (same as Codex today) and scoped-Bash agents fall back to `ask`. Accepted for the spike; recorded in `## Open Decisions` for the human.
- **Double derivation.** A change to the Codex translator silently changes the OpenCode tree; mitigated because `--check` in the gate turns every such change into visible drift.
- **Install path baked into prose.** Paths read `~/.config/opencode/quenching/`; a different install root works for `cq` through `QUENCHING_OPENCODE_ROOT` but not for prose paths. Accepted for the spike.
