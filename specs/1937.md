## Problem

Achado reproduzido pelo reviewer `opus` na revisão de correção do épico 1928 (rodada 1 do autopilot de 2026-10-17), sobre o merge `5392dc95` (#1932, spec 1849).

Em `plugins/quenching/assets/bin/quenching/specs/commands/doctor.py:92-94`, o aviso de backend inferido só aparece quando falta o arquivo de config: `inferred = not cfg.get("present", True)`. A inferência não depende de o arquivo existir:
- `common/config.py:168-174` sempre define `provider` a partir do remote.
- `specs/config.py:379` copia esse valor para `"backend": provider`.
- `_read_backend` (`specs/config.py:181-186`) só sobrescreve quando o arquivo declara `"git"`.

Com isso, um `.claude/quenching.json` sem a chave `backend` (só `{"specs": {...}}`) num remote GitHub chega com `backend: github` inferido e `present: true`. O `sp-backend-deprecated` sai sem "inferred" e sem o pedido de declarar `backend: git`, e esse é o caso do título da 1849. O teste `plugins/quenching/tests/test_specs_doctor.py:64-82` faz mock de `load_config` e só exercita `present=False/True` com o backend já resolvido.

**Reprodução:**
- `cq git history show 6e977e0f --path plugins/quenching/assets/bin/quenching/specs/commands/doctor.py`
- `grep -n 'def _read_backend' -A30 plugins/quenching/assets/bin/quenching/specs/config.py`
- `sed -n 360,400p plugins/quenching/assets/bin/quenching/specs/config.py`
- `sed -n 164,175p plugins/quenching/assets/bin/quenching/common/config.py`

**Consequência.** Um projeto que tem config mas nunca escolheu o backend cai no store deprecado sem receber o aviso que a 1849 prometia.
