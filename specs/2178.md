## Problem

When a spec's development exposes that the workflow, skill, structure or automation around it is the real constraint, `develop` still only fills the spec's own sections, so that refinement becomes a second spec or is lost. Asked to refine the process alongside the objective — researching current practice when it helps — `develop` should change workflows, skills and structure under the same spec, held to standards and to automation wherever it fits.

## Proposal

- `develop` recognises an explicit ask to refine the process surface and **plans it as tasks**: no workflow, skill, reference or code file is edited during definition.
- The plan is an ordered group in `## Tasks` — `### 1. Process surface` — whose items edit the surface, followed by the objective's tasks that rely on the new behaviour, and a proof that the flow behaves as declared.
- The spec declares the surface files it expects to touch under a fourth `## Impact` sub-heading; every declared path is named by a task, and every task carries `files:` and `verify:`.
- Without the ask, the pass only **parks** surface opportunities, one `## Discoveries` line each with `path:line` and the consequence; a cost finding — a counted figure (tokens, round trips, whole-file reads) plus the flow it names — is one kind of opportunity. Nothing is lost and nothing is edited.
- Research, when the plan needs current practice, is delegated to a read-only sub-agent that returns a source table — URL, publication date, retrieval date, claim, what it would change — cited in `## Alternatives Considered` or `## Design`.
- The spec also measures the executor↔develop round trips and records the number and its causes; narrowing the executor's pause limits is a follow-up gated on that measurement.
## Out of Scope

- **Direct edits by `develop`.** No grant change and no prose-now path: the pass writes the spec and nothing else. A widened grant would widen every invocation, including the autonomous ones.
- **A new stage, flow or `cq` verb.** The surface refinement rides `develop`'s existing compose/refine and its single edit; a fourth stage reopens the design `plan-gates.md` §Three intermediate forms measured and rejected.
- **A periodic batch cost sweep.** Its home is the existing transcript reader (`command-retro`, `improve --with-session-logs`), not a new skill and not this pass; a 7-day cadence is a scheduler decision, and `.github/workflows/ci.yml` carries no `schedule:` trigger today.
- **Narrowing the executor's pause limits in this spec.** It is its own contract change with its own proof; the measurement here is its trigger, and the follow-up is parked.
- **A new `docs/standards/` document.** The rule amends `plan-lifecycle.md` and `agents.md`; a new standard would add an index row, a validator surface and a second owner for the same rule.
- **Whole-repository improvement.** `/quenching-specs improve` keeps the map and the epic; `/quenching-components align` keeps the whole-surface sweep.
- **Minting a spec at definition time.** Surface opportunities park in `## Discoveries`; only `conclude` mints.

## Design

**Decision 1 — the pass plans; execution builds.** The process surface is the product in this repository and implementation code elsewhere; either way, editing it is building, which is the work `develop` already refuses to do. The alternative — prose now, in the pass's single edit — was weighed and rejected: it widens the grant for every invocation, edits the doctrine the running pass obeys, and leaves the rework loop without a test runner.

**Decision 2 — the refinement is a task group, ordered first.** `### 1. Process surface` is the unit of verification; its tasks land before the objective's tasks that name the new behaviour. The dependency is real and serial, so no `[P]` crosses the group.

**Decision 3 — the proof runs in a fresh process.** A flow change cannot be proved by the session that loaded the old text. The structural test checks the contract's anchors per task; the live probe runs the deployed surface in a throwaway target, once, at `## Validation`.

**Decision 4 — the trigger is explicit.** The input names the surface refinement — the human's own words, or `--with-surface` as the shorthand. It is never inferred from `## Impact`, from a missing section, or from the pass's own judgment, the same discipline `autonomous` follows.

**Decision 5 — notice always, work only when asked.** Every pass may park a surface opportunity as one `## Discoveries` line carrying `path:line` and the consequence, under the same evidence bar as `/quenching-specs improve`. A cost finding is one kind of opportunity, and it carries a counted figure — tokens, round trips, whole-file reads — read from the session tool, never from the pass's recollection. A batch sweep over many sessions is not a pass's job. With the ask, the opportunities in scope are folded into the task group instead of parked.

**Decision 6 — research is delegated and cited.** A read-only sub-agent returns a table: source URL, publication date, retrieval date, claim, what it would change, confidence. It lands in `## Alternatives Considered` or `## Design`. A web source may support an alternative or a rationale; it may not ground a binding rule alone.

**Decision 7 — the fourth `## Impact` sub-heading is unparsed.** Like `### Product code this spec expects to touch`, it declares scope for the reviewer; the one parsed contract remains the standards sub-heading. Automation is the task's `verify:`, not a second validator.

**Decision 8 — the measurement is in, the softening is out.** The round trips are counted and classified here; changing the executor's pause list needs its own spec, because it changes what the executor may decide and must be proved against live runs, not against a plan.

### Assumptions

- The scratch-spec probe can run in a throwaway target from `functional-checks.sh` — `## Validation` and task 2.3 depend on it.
- The session transcripts cover the last 30 days for this repository — the round-trip measurement depends on it; where they do not, the measurement reports the window it actually has.
- The ask arrives in words the pass can recognise — Decision 4 depends on it; `--with-surface` is the fallback when the words are ambiguous.
## Alternatives Considered

- **Direct prose edit in the pass (the first shape weighed).** The pass would edit the declared surface files and land them in its single edit. Rejected: it widens `develop`'s grant, makes the pass rewrite the doctrine it is obeying, and gives the rework loop no runner — the pass cannot execute the flow it just changed.
- **A `surface` stage in the pass.** Rejected: `plan-gates.md` §Three intermediate forms measured and rejected stage-shaped stops, and a fourth stage would re-derive the spec on disk between stages. The pass's stages are fixes; the refinement is work, and work is a task.
- **A companion spec captured and linked.** Rejected: it is the status quo the request names as the problem, and definition-time minting is forbidden by `plan-lifecycle.md` §When a follow-up becomes a spec.
- **Hand the refinement to `/quenching-specs improve`.** Rejected: it maps the whole repository, mints an epic, and returns no spec-local task list; the objective and its instrument would ship apart.
- **A separate periodic cost skill.** Rejected: it would be a third reader of the same transcripts (`command-retro` and `improve --with-session-logs` already read them), a skill cannot schedule itself, and the counted-claim rules of `session-evidence.md` would have to be reimplemented. A batch mode of the existing reader is the smaller shape.
- **A `--with-surface` flag only.** Rejected as the only form: the request arrives in prose ("refine the workflow too"), so the pass must recognise the words; the flag stays as the deterministic shorthand.
## Open Decisions

- **Whether to narrow the executor's human-led pause list to the six real blocks.** Decided by the round-trip measurement in `## Validation`: a non-trivial count and a cause the list creates produce a follow-up spec; a count near zero leaves the list unchanged. This spec records the number and decides nothing.
- **Whether a target carrying only the deployed payload can declare a process surface.** Decided by the first target run. The source of truth is required; a target without it parks the line as a `## Discoveries` entry naming the plugin repository.

## Risks

- **The executing session changes the doctrine it is running under.** Mitigation: the change lands in commits; the session loaded the old text and finishes under it; the proof runs in a fresh process; the report names the old-to-new boundary. Expected, not a defect.
- **Task-group inflation.** Every spec starts declaring surface files. Mitigation: the ask is explicit, the sub-heading is opt-in, a declared path with no task is a review finding, and parked lines carry the evidence bar.
- **A web claim becomes a rule.** Mitigation: research lands only in `## Alternatives Considered`/`## Design`, with URL and dates; a binding rule still needs the repository's own contract, cited beside it.
- **The proof is too expensive per task.** Mitigation: the structural test is cheap and per-task; the live probe is once, in `## Validation`, which is where billed sessions belong.
- **The measurement finds nothing.** Then the follow-up does not exist; the number is recorded and that is a result.
- **Two owners for the surface.** `develop` plans it, `execute` writes it, `components align` still owns the whole-surface sweep. Mitigation: the plan is scoped to the declared paths; the align is named when the change crosses beyond them.
