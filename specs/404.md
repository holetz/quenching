## Problem

Composite da rodada 1 (run 2) do autopilot de 2026-11-24: reserva de specs entre máquinas pedida pelo humano. O problema e a evidência estão em 405; o desenho decidido está em ## Design.
## Design

- 2026-11-24 — **política de autonomia**: o humano invocou o autopilot "sem teto" pedindo explicitamente que o fluxo de specs ganhe uma reserva entre máquinas (duas máquinas em `autopilot --until-dry` no mesmo repositório nunca pegam a mesma spec; a reserva não trava spec por falta de desmarcação nem por eventos que não deveriam segurá-la, como desenvolver e passar a outra pessoa executar). Develop autônomo (approved como orchestrator-forced), forced execution, push, PR and merge of every member depois de um PASS do spec-verifier e com CI verde, autorizados por essa invocação.
- 2026-11-24 — **o desenho do protocolo é pedido do próprio humano**, então não vai ao épico "decidir com o humano"; o condutor escolheu o desenho abaixo como delegado e o relata no relatório final.
- 2026-11-24 — **decisão: lease em ref do `origin`, não record no store.** `refs/quenching/claims/<id>` criada/trocada/apagada por push com `--force-with-lease` é comparação e troca no servidor, igual para os backends git, github e azure (todos têm `origin` git), não entra no histórico do store nem conflita com escritas de documentos. Provado no `origin` deste repositório em 2026-11-24: criar com `<ref>:` recusa `stale info` quando a ref existe; trocar com o sha esperado passa; o GitHub aceita refs fora de `heads/tags`. Alternativas descartadas: record `claim` no store git (escritas são locais até o sync, só o backend git tem CAS, e o sync recusa conflito de mesma spec com o documento inteiro); `assignee` (campo humano, sem validade, sem CAS no GitHub, `github.py:911-919`).
- 2026-11-24 — **decisão: só a construção reserva.** create/develop/triage/status nunca reservam; execute adquire, renova por tarefa, conclude/blocked/failed/fim de rodada liberam; reconcile apaga leases de spec terminal; lease de spec terminal é ignorado. É isso que impede a trava do caso "desenvolvo e peço a outro usuário para executar".
- 2026-11-24 — **decisão: validade, não vigília.** Padrão 45 min (`shared.autonomy.claimMinutes`), tolerância de relógio 2 min; um holder morto libera sozinho ao expirar. Autopilot e orchestrator só tomam lease expirado; tomar lease vivo (`take`) é só do humano e fica registrado.
- 2026-11-24 — **decisão: identidade sem dado pessoal.** `holder` = id de máquina aleatório (`git config quenching.machineId`, gerado uma vez) + id de sessão; nunca hostname nem email, porque a ref vai para o remoto. `label` opcional e declarado pelo usuário.
- 2026-11-24 — **grant**: `Bash(cq specs claim:*)` no `tools:` do spec-orchestrator e do spec-runner, só esse verbo; o alargamento é o próprio pedido do humano, e o reviewer do épico o confere na revisão de segurança.
- 2026-11-24 — ondas: 405 (verbo) → 406 (leitura em next/list/status + preflight) → 407 (fluxo, grants, padrão, glossário). 405 e 401 tocam `specs/` mas arquivos distintos (`specs/claims.py` novo vs `specs/backends/git.py`); sem dependência.

- 2026-11-24 19:3x — **decisão do condutor sobre o checkout base**: às 19:22 o checkout `.` passou para `feat/opencode-vitrine-remote-deploy` com edições não commitadas em `integrations/opencode-vitrine/src/` (reflog: checkout manual, fora deste run). É trabalho do humano em andamento: ninguém o toca, nem stash, nem checkout, nem pull. Todo worktree é cortado de `origin/main`; o merge é remoto (`cq git pr merge`) e o store é a ref `quenching`, independente do HEAD do checkout; o reconcile roda normalmente. Esse estado não é inesperado e não para o run.
- 2026-11-24 — **decisão do condutor sobre o FAIL check 9 da 407 (needs-human: grants)**: a 407 está autorizada a dar ao spec-orchestrator e ao spec-runner `Bash(cq specs claim:*)` **e** as ferramentas MCP equivalentes `mcp__quenching__specs_claim_acquire`, `_renew`, `_release` e `_list` — o mesmo verbo pedido pelo humano, pela via MCP-first. **`specs_claim_take` não entra em nenhum agente** (nem no mapeamento OpenCode, onde hoje sai `allow`): tomar lease vivo é só do humano, como diz o bullet de validade. No Bash, o agente que chamar `cq specs claim take` é proibido pelo corpo do agente; o reviewer confere. Re-spawn da 407 no mesmo branch para estreitar o mapeamento; PR #414 se atualiza; verifier de novo antes do merge.
- 2026-11-24 — **estreitamento do bullet anterior**: no Bash, em vez de `Bash(cq specs claim:*)`, os quatro verbos `Bash(cq specs claim acquire:*)`, `Bash(cq specs claim renew:*)`, `Bash(cq specs claim release:*)` e `Bash(cq specs claim list:*)` (e as formas `cq.cmd` onde o arquivo já as declara), para que nenhum grant de agente alcance `take`.
