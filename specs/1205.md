## Problem

`plugins/quenching/agents/spec-runner.md` concede `Bash, Read, Edit, Write, Grep, Glob, Skill`, mas `develop.md:5` e `execute.md:5` declaram `AskUserQuestion` e `Task`, e o `execute.md` (~linha 146) manda pedir `approved` inline ("Never refuse over it"). O runner não pode perguntar, e nenhuma regra diz o que fazer: a seção Forbidden só cobre git.

Consequência: um runner fora do `autonomous`, ou numa spec `medium` sem `ready`, improvisa uma pergunta para ninguém ou devolve um `blocked` vago; o orquestrador o relança uma vez e o custo dobra.

## Proposal

Uma regra no runner e um ramo "AskUserQuestion indisponível" nos corpos que perguntam: devolver `STATE: blocked` com `NOTE: needs-human: <pergunta>`, e o orquestrador não relança um `needs-human`.

## Out of Scope

A confirmação de PR, que é da 1185, e o gear forçado, que é da 1188.

## Impact

### Product code this spec expects to touch

## Validation

O runner tem a regra; os corpos que perguntam têm o ramo; o orquestrador não relança `needs-human`; `bash scripts/verify_repo.sh` sai 0.

## Design

- **Rule in the runner, one line per asking body.** The runner has no `AskUserQuestion`, so any point where a command would ask the human becomes `STATE: blocked` with `NOTE: needs-human: <question>`. Each asking body gets one sentence naming that outcome, so the command does not improvise a question to nobody.
- **The orchestrator reads the NOTE prefix.** A `blocked` whose NOTE starts with `needs-human:` is escalated to the human with the question and is never re-spawned; the one-re-spawn rule stays for every other failure.
- **Minimal diff in the agent files**: 1204 edits `spec-runner.md` in parallel, so only one bullet is added there.
- Alternative weighed: granting the runner `AskUserQuestion`. Rejected, a sub-agent never talks to the human.

## Alternatives Considered

- Give the runner `AskUserQuestion`: rejected, a sub-agent never talks to the human (develop.md, step 8).
- A new STATE value `needs-human`: rejected, the fixed return format has four states and the verifier parses them.

## Open Decisions

- none — the prefix `needs-human:` in NOTE is fixed by the Proposal.
