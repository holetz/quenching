## Problem

O estreitamento do git-steward da 1279 (#1281) não bloqueia as operações perigosas (reproduzido em 2026-10-08): os bloqueios de `plugins/quenching/agents/git-steward.md:5` são padrões de texto e o argparse do `cq` aceita abreviar flags (`allow_abbrev` ligado), então `cq specs section <id> Outcome --w` foi lido como `--write`; `gh pr merge` aceita `-d`, `-s`, `-r` para `--delete-branch`, `--squash`, `--rebase`, e o glob não os pega; `Bash(git:*)` (`git-steward.md:4`) aceita `git stash`, `reset --hard`, `push --force` e `branch -D`, que a linha 17 proíbe, e `git -c alias.x='!cmd' x` executou um comando. Não está documentado se o Claude Code entende `:*` no meio de um padrão de bloqueio.

Consequência: o steward pode apagar a branch remota, fazer squash, escrever seção de spec ou rodar código pelos próprios grants, apesar da prosa.

## Proposal

**Decidido com o humano em 2026-10-08:** o git-steward passa a agir só por verbos `cq git` de argv fixo, no molde do `cq git audit` (refs resolvidas antes do uso, `--end-of-options`, `SAFE` com `core.fsmonitor` e `core.hooksPath` neutralizados); a lista de bloqueio por texto deixa de ser a defesa.

- Verbos novos para o que os passos do steward fazem (por exemplo push da branch, abertura da PR, merge com `--merge` fixo exigindo o `gh pr checks` verde da 1291, o corte da worktree do passo `branch`). O conjunto exato sai do develop, lendo `commands/git/{branch,commit,merge,pr/create,cleanup}.md`; os corpos que o steward roda passam a chamar esses verbos.
- O `tools:` de `agents/git-steward.md` perde `Bash(git:*)` e os `gh` de escrita; o `disallowedTools` por texto sai ou fica só como redundância.
- Todo parser do `cq` passa a `allow_abbrev=False` (`components/cq_calls.py:158` já lê esse atributo).
- Validação: nenhum grant do steward casa os comandos reproduzidos em `/tmp/claude-1000/-home-unicred-Projetos-claude-quenching/a284eb01-1fc3-4a7f-ae95-abf7651b3d1b/scratchpad/review8/` — `cq specs section <id> Outcome --w`, `gh pr merge -d/-s/-r`, `git -c alias.x='!cmd' x`, `git stash`, `reset --hard`, `push --force`, `branch -D`.

Complexidade alta: worker em opus.

## Out of Scope

- A rota Azure (`az repos pr create`) — continua no corpo de `/quenching:git:pr:create`; o steward não tem grant `az`, então um passo `pr` sob `azure-boards` é `STATE: blocked`, como já é hoje na prática.
- `/quenching:git:merge` (merge local) — o steward nunca o roda; o passo `merge` dele é o merge da PR, que passa a ser `cq git pr merge`.
- Os grants de outros agentes e comandos (`orchestrator`, `verifier`, `commands/specs/improve.md` com `Bash(git:*)`, `.claude/commands/release.md`) — fora do steward; a 1279 e a 1281 já trataram o verifier.
- `commit-incremental`, `sync`, `push`, `revert`, `pr/review`, `pr/status` — o steward não os roda.
- O desencontro entre o grant `Bash(cq …:*)` e a forma resolvida `python3 <path>/cq …` / `cq --root <x> …` — anterior a esta spec e comum a todos os agentes.
- Decidir se o Claude Code entende `:*` no meio de um padrão — a proposta tira a defesa desses padrões, então a pergunta deixa de importar para o steward.

## Design

**O steward age por verbos `cq git` de argv fixo; a lista de bloqueio por texto não é defesa.** Cada verbo monta o argv do git/gh no próprio módulo, no molde de `git/audit.py`: refs e nomes de branch validados (`check-ref-format --branch`, nada começando por `-`) e resolvidos antes do uso, `--end-of-options` onde o git aceita, e o `SAFE` de `audit.py` (`--no-optional-locks`, `core.fsmonitor=false`, `core.hooksPath=/dev/null`) em toda chamada git dos verbos novos. Exit 0 ok · 1 findings · 2 refusal, `--json` em todos.

O conjunto de verbos sai dos cinco corpos que o steward roda:

| Corpo / passo | Hoje | Verbo |
| --- | --- | --- |
| `branch` §1, `commit` §1–2, `pr/create` §1 | `git status --porcelain`, `git branch --show-current`, `git diff --cached --name-only`, `git remote -v` | `cq git state` — branch atual, status porcelain (filtros `filter.<x>` neutralizados como no audit), arquivos staged, remotes |
| `branch` §4 | `git fetch origin <base> && git worktree add <path> -b <branch> --no-track origin/<base>`, depois `cq git worktree link` | `cq git worktree add --path --branch --base [--remote origin]` — faz fetch, corta do `<remote>/<base>` resolvido para sha (sem upstream), cai para o `<base>` local só quando o remote não existe e diz isso, e roda o link na worktree nova |
| `commit` §3 | `git commit -m … && git log -1` | `cq git commit --subject` (já existe; mantém os hooks por contrato) |
| `pr/create` §4 | `git push -u <remote> <branch>` | `cq git push --branch [--remote origin]` — `push -u <remote> refs/heads/<b>:refs/heads/<b>`, nunca force |
| `pr/create` §4 (github) | `gh pr create --base --head --title --body` | `cq git pr create --base --head --title --body` — devolve número e URL |
| passo `merge` do steward | `gh pr checks` + `gh pr merge <url> --merge` | `cq git pr merge --url [--wait SECONDS]` — lê `gh pr checks --json`, mergeia com `--merge` fixo só com todo check verde (pass/skipping); vermelho, pendente ou nenhum check é exit 1 com `reason`; `--wait` re-lê a cada 20s até o limite (≤ 540, abaixo do teto de 10 min de uma chamada Bash), e o steward re-chama até os 30 min da regra da 1291 |
| `cleanup` §3–5 | `git branch -d`, `git worktree remove`, `git push <remote> --delete` | `cq git prune --branch \| --worktree \| --remote-branch [--remote]` — re-lê o relatório de `cq git stale` e só age no item que ele reporta; nunca `-D`/`--force` |

`cq git pr` é só a rota GitHub; a rota Azure fica no corpo. A URL de `pr merge` precisa ter a forma `https://<host>/<owner>/<repo>/pull/<n>`; qualquer outra é recusa.

**Parsers sem abreviação.** `common/output.py` ganha a base `NoAbbrevParser(argparse.ArgumentParser)` com `allow_abbrev=False` por padrão; `CQArgumentParser` passa a derivar dela, e todo `argparse.ArgumentParser(` da árvore `assets/bin` vira `NoAbbrevParser(`. Os subparsers herdam porque `add_subparsers` usa `type(self)` como `parser_class`; o teste percorre a árvore de cada pilar para provar. `components/cq_calls.py:167` já lê o atributo, então o lint dos corpos passa a recusar flag abreviada sem mudança ali.

**Grants do steward.** `tools:` fica `Bash(cq git:*), Bash(cq specs config:*), Bash(cq specs status:*), Bash(cq specs show:*), Bash(cq components read:*), Bash(gh repo view:*), Bash(gh pr view:*), Read, Skill`. Saem `Bash(git:*)`, `gh pr create`, `gh pr merge`, `gh pr checks` (o verbo lê) e `cq specs section` (tem `--write`); a leitura das seções para o corpo da PR passa por `cq specs show --spec <id> --full`, verbo sem flag de escrita, e `pr/create` §2 diz isso para quem não tem o grant de seção. `disallowedTools` fica só como redundância, com padrões de prefixo puro: `Bash(git:*), Bash(gh pr merge:*), Bash(gh pr create:*), Bash(cq specs section:*)`.

Contratos que não podem ser contrariados: `cq git` não aceita `--root` (roda como `cd <wt> && cq git …`); `cq git commit` nunca pula hooks; `cleanup` nunca age fora do relatório de `stale`; o merge de PR é sempre `--merge`.

## Alternatives Considered

- **Manter os grants largos e endurecer a lista de bloqueio** (mais padrões, `-d`, `-s`, `-r`, `stash`, `reset`) — perdeu: um padrão de texto nunca fecha `git -c alias.x='!cmd' x`, abreviações e variações; foi justamente o que a 1279 tentou e a reprodução de 2026-10-08 derrubou.
- **Grants exatos sem curinga** (`Bash(git status --porcelain)`) — perdeu: o steward roda com `git -C <worktree>`, o que exige curinga no meio, a forma que já escapou (memória "Grant de agente com curinga escapa").
- **Um único verbo `cq git step <branch|pr|merge>` que faz o passo inteiro** — perdeu: moveria para código a montagem do título e do corpo da PR, que segue `config.prTitle`/`prBody` e as seções da spec; os corpos continuam donos do julgamento, e os verbos só da execução.

## Open Decisions

- Se o passo `cleanup` do steward continua alcançável com `commands/git/cleanup.md` marcado `disable-model-invocation: true` — decidido na tarefa 3.2 lendo se o `Skill` carrega um corpo com essa flag; se não, a regra do steward diz que `cleanup` é `STATE: blocked` para o humano, e `cq git prune` serve o corpo humano do mesmo jeito.

## Risks

- Desligar a abreviação quebra uma chamada que hoje abrevia (corpo, teste, script) — mitigação: `components lint` valida todas as chamadas `cq` dos corpos contra os parsers, e a suíte inteira roda no gate.
- `core.hooksPath=/dev/null` no `push` e no `worktree add` pula um `pre-push`/`post-checkout` do repositório — ACCEPTED — é o molde que a proposta fixou; o gate é certificado pelo CI antes do merge, e `cq git commit` mantém os hooks de commit.
- Um corpo de PR longo no argv — ACCEPTED — o limite de argv do Linux (~2 MB) está muito acima do corpo que `pr/create` monta.
- O `gh pr checks --json` muda de campos numa versão do gh — mitigação: o verbo lê `bucket` e trata campo ausente como pendente, nunca como verde.
