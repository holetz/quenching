## Problem

No autopilot de 2026-11-20 a 2178 tomou FAIL no check 7 do spec-verifier por um `commit --amend` local de 2026-11-06 nunca publicado. O humano decidiu refazer a branch limpa (`plan/2178-develop-refines-the-workflow-alongside-the-spec-r2`, 13 cherry-picks, `commit:` das 10 tarefas recarimbados, gate verde). Daí em diante o fluxo não tem rota:

- `cq specs record 2178 branch --set work=…-r2` → exit 2 `sp-record-write-once` ("a record that disagrees with reality is a finding to report, never a value to overwrite");
- `cq git pr create --spec 2178 --head …-r2` recusa porque a head não é `branch.work`;
- uma spec sucessora não serve: os subjects dos commits carregam `plan/2178-…`.

O que a melhoria tem de tornar possível: uma reconstrução de branch autorizada (humano ou política do épico) registrar a nova head de forma auditável — ex.: um campo de histórico em `branch` ou um verbo `cq specs record … --supersede` com motivo — sem editar o frontmatter à mão nem afrouxar o check 7.

**Insumos**

- spec 2178, épico 2207 `## Design` (bullet 2026-11-20 sobre o rebuild)
- `quenching/assets/bin/quenching/specs/` (registro write-once de `branch`), `cq git pr create --spec`
- check 7 de `quenching/agents/spec-verifier.md`
