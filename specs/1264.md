## Problem

Em `main` (2026-10-08), o `spec-runner` repassa `autonomous` ao `conclude` (`plugins/quenching/agents/spec-runner.md:20-22`) e devolve `needs-human` onde um command perguntaria (`:28-29`), mas o `conclude` só usa `autonomous` para não encadear o `pr:create` (`commands/specs/conclude.md:12,19,247`): ele ainda pergunta o outcome (`:98-99`, e devolve `needs-human` num sub-agente), pede confirmação em `:142`, `:150`, `:180` e `:194-195`, e `:296` proíbe inferir o outcome. O orquestrador só aceita spec arquivada (`agents/orchestrator.md:43-45`, check 8) e nunca relança um `needs-human` (`:52-53`). Achado da revisão de coerência da sessão condutora; as orquestrações da noite não bateram nisso porque rodaram com os agentes instalados (6.4.0) e instruções no prompt.

Consequência: com os agentes de `main` (depois do próximo release), todo runner autônomo volta `blocked` no conclude, nada é arquivado e nenhum PR é aberto — `--autonomous` vira uma fila de perguntas ao humano.

## Proposal

- `commands/specs/conclude.md` carries one bounded grant for `autonomous`: a table naming every point where the command asks the human (steps 1, 3, 4, 5, 6 and the abandoned branch offer) and the fixed answer it takes instead, so a run under `autonomous` reaches `archive` + `## Outcome` and the named PR handoff without a question.
- The outcome is still never inferred: under `autonomous` it comes only from an explicit `--outcome` in the input; without one the run returns `STATE: blocked` / `NOTE: needs-human:` exactly as today. `--force` is never taken, an exit 2 on `promote` is `needs-human`.
- `agents/spec-runner.md` states the outcome it passes: `--outcome done` only when execute left every task checked; open tasks return `blocked` with `needs-human`, never `--force`, never `abandoned`.
- The Codex translation of both files is regenerated, and a unit test pins the grant.

## Out of Scope

- Changing the orchestrator's acceptance rule (`agents/orchestrator.md` check 8) or its no-re-spawn rule for `needs-human` — they are correct; the contradiction is on the conclude side.
- Letting `autonomous` choose `abandoned` or pass `--force` — that is the inference the doctrine forbids, and the narrowest grant does not need it.
- Releasing a version so installed agents (6.4.0) pick this up — owned by `/release`.
- `/quenching:specs:execute`'s own autonomous handling — it already skips its questions (`commands/specs/execute.md:369`).

## Design

- **Rule: under `autonomous`, conclude asks nothing; every ask has one fixed answer, and the answer is the narrowest that lets the step run.** The grant lives in ONE table in `conclude.md` (a section `## Under autonomous`), and each asking step points at it rather than restating it.
- Fixed answers:
  - Step 1 outcome: taken from the input's `--outcome` only; absent → `blocked` `needs-human`. Spec ambiguity (several ids, no marking) → `blocked` `needs-human`.
  - Step 3 emergent docs and step 5 distillation (`done`): the narrated plan is applied on the work branch without the confirmation — the PR is the human review of those writes. For `abandoned` the offer is declined (nothing written to the base checkout) and candidates are named in the report.
  - Step 4 `## Outcome`: drafted and written without the confirm; an exit 2 from `promote` → `blocked` `needs-human` with the refusal quoted; `--force` never.
  - Step 5 release obligations (`done`): applied as narrated on the work branch with the standard quoted in the report.
  - Step 6: branch behind base, red gate, or inconclusive gate → `blocked` `needs-human` (or `failed` for a red gate) — never a merge/rebase unasked.
  - Abandoned branch-delete offer: keep (the default), recorded in the report.
- The invariant "Never infer the outcome" stays; its wording names the explicit `--outcome` of an `autonomous` caller as the stated word.
- Contracts it must not contradict: `agents/orchestrator.md` check 8 (archive + Outcome) and its rule never to re-spawn a `needs-human`; `agents/spec-runner.md` "never improvise an answer" — the table is not improvisation, it is the command's own answer.

## Alternatives Considered

- **Orchestrator answers conclude's questions** (relay each `needs-human`) — rejected: the orchestrator forbids re-spawning a `needs-human`, and it would turn every autonomous spec into a human round trip.
- **`autonomous` skips the whole close-out (no archive)** — rejected: orchestrator check 8 requires `phase archive` and an `Outcome`.
- **Infer `done` from all tasks checked inside conclude** — rejected: contradicts the doctrine "the outcome is stated, never inferred"; the runner states it instead.

## Open Decisions

- none — the outcome source, the confirmations and the stop cases are each answered by the existing doctrine plus the orchestrator contract.

## Risks

- Docs and release writes applied without confirmation under `autonomous` — ACCEPTED: they land only on the work branch and the human reviews them in the PR before merge.
- Runner states `--outcome done` on a spec whose tasks were descoped — mitigated: only when every task is checked; otherwise `needs-human`, and `--force` is never taken.
- Installed agents (6.4.0) do not carry the runner change until a release — ACCEPTED: out of scope, the release owns it.
