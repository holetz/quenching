## Problem

Three gaps show up when a target installs quenching through `cq deploy` instead of the marketplace:

1. **An upgrade can uninstall the surface.** The documented upgrade is `cq deploy --write` from a
   new release, but `--modules` defaults to `core`. On a target that deployed `--modules all`, the
   second call builds a core tree, sees the other modules' files as "owned minus tree" and deletes
   them. The manifest records the original selection and the command ignores it.
2. **OpenCode receives no subagents.** `--harness opencode` is accepted and validated, but
   `tree.py` only acts on `claude`. OpenCode reads `.opencode/agents/` (not `.claude/agents/`), so a
   target that drops the marketplace plugin loses `quenching-spec-runner`, `quenching-verifier` and
   the rest of the operator agents while keeping the skills.
3. **Nothing checks the installed surface after the first write.** Every other generated tree in
   this repository is verified by the gate (`sync_codex_plugin --check`, `sync_opencode_plugin
   --check`, `generate_plugin_modules --check`); the deploy manifest is the only generated artifact
   whose drift is invisible until someone runs the command by hand.

The self-install depends on all three: the repository is about to run from `.agents/` with no
plugin, so an upgrade that silently removes modules, a missing operator agent or a vendored copy
that no longer matches the source are not acceptable.

## Proposal

- `cq deploy` reads an existing `.agents/.quenching-deploy.json` and reuses its `modules`,
  `harnesses`, `runtime` and `profiles` for any selection flag the caller did not pass. An explicit
  flag still wins; the manifest is a default, never an authority over the plan.
- `--harness opencode` materializes `.opencode/agents/quenching-<name>.md`, translated from the
  source agent: `mode: subagent`, deny-first permissions from the source `tools:` list (with each
  `Bash(cq <verbs>:*)` grant mapped to `.agents/quenching/bin/cq <verbs> *`), and the same body
  translation the Claude bridge receives.
- `scripts/verify_repo.sh` gains a `deployed surface lockstep` check that runs
  `cq deploy --target . --check` with no selection flags, so the installed tree is regenerated or
  the gate is red.

## Out of Scope

- Changing the deploy layout beyond the OpenCode agents directory, or installing hooks.
- Making deploy run a model, align knowledge or choose a provider.
- The gate's suite runner (spec 2121 owns it).

## Impact

- `plugins/quenching/assets/bin/quenching/deploy/cli.py`: manifest defaults when a flag is absent.
- `plugins/quenching/assets/bin/quenching/deploy/tree.py` and `translate.py`: OpenCode agents.
- `plugins/quenching/tests/test_deploy.py`: upgrade-after-all, explicit-flag-wins and OpenCode
  agent proofs.
- `scripts/verify_repo.sh`: the lockstep check.
- `docs/standards/architecture/deploy-mode.md`: the layout table and the upgrade sentence.
- The generated Claude/Codex/OpenCode/Omnigent distributions of the plugin, refreshed because the
  deploy package changed.

## Validation

- `python3 -m unittest ... -p test_deploy.py` green, including: an `all` install upgraded with
  `--write` keeps every module and reports no deletions; `--modules core` still narrows on request;
  `.opencode/agents/quenching-verifier.md` carries `mode: subagent` and the target-local cq grant;
  `--harness claude` alone writes no `.opencode/agents`.
- `cq deploy --target . --check --json` exits 0 on the repository after the self-install, and exits
  1 after a hand edit under `.agents/quenching/`.
- `bash scripts/verify_repo.sh` green with the lockstep check present.

## Design

`cli.py` resolves each selection in one place:

```python
previous = read_manifest(str(target)) or {}
modules = _split(args.modules) or previous.get("modules") or ["core"]
harnesses = _split(args.harness) or previous.get("harnesses") or DEFAULT_HARNESSES
profiles = _split(args.profiles) or previous.get("profiles") or deploy_tree.profiles_for(modules)
runtime = args.runtime or previous.get("runtime") or "vendor"
```

`--runtime` and `--modules` currently carry argparse defaults; they move to `None` so "absent"
is distinguishable from "explicitly core/vendor". The refusal for an unknown harness still runs on
the resolved list, and the manifest written after a successful write records what was resolved.

`translate.opencode_agent_document(raw, name)` mirrors the OpenCode distribution's agent writer
(`scripts/sync_opencode_plugin.py`): `description`, `mode: subagent`, `permission:` with
`edit`/`webfetch`/`bash`/`task` derived from the source `tools:`, `tools: task: false` when the
source denies `Agent`/`Task`, and a body through `transform_platform` with the source model tier
and effort stated as prose. `tree.build_tree` adds the `.opencode/agents/` files when `opencode` is
selected, after the Claude branch, so the manifest owns them and `--check` covers them.

The gate line is one command: `python3 plugins/quenching/assets/bin/cq deploy --target . --check
--json`, placed after the distribution checks. With the manifest defaults it needs no flags and
checks exactly what the repository installed.

## Alternatives Considered

- **Document `--modules all` in the upgrade path**: fixes the one target that remembers, not the
  command; a manifest that records a selection and is then ignored is a trap.
- **Keep the OpenCode agents global** (`~/.opencode/agents`): that is the plugin install the target
  is removing; a target on another machine would still need it.
- **Write `.opencode/commands/` too**: OpenCode V2 exposes skills as `/id` commands, so the skills
  already cover it; commands would be a second surface to keep in sync.
- **Skip the gate check**: drift in the installed tree would be found only when a command misbehaves,
  which is the failure mode every other generated tree in this repository refuses.

## Open Decisions

- none — the manifest is a default (explicit flags win), OpenCode agents are generated only when
  the harness is selected, and the gate check uses the recorded selection.

## Risks

- **A target that wants a narrower re-deploy** must pass the flag explicitly; the manifest keeps the
  old selection otherwise. That is the documented meaning of "upgrade", and the flag remains the
  override.
- **OpenCode permission translation diverges from the distribution's writer.** The mapping is
  copied in form, not imported, because the script lives outside the shipped package; the test pins
  the cq grant and the deny-first shape, and a divergence in an untested key is possible.
- **The lockstep check makes every prose edit a redeploy.** It already is for the Codex/OpenCode/
  Omnigent mirrors; this adds the installed copy, and `cq deploy --write` is a 0.3 s local command.
