## Problem

Na sessão anterior o backend GitHub devolveu vários HTTP 500; toda escrita só passou com nova
tentativa manual. Em `plugins/quenching/assets/bin/quenching/specs/backends/github.py`:

- `_gh_run` repete só leituras: `max_attempts = GH_MAX_ATTEMPTS if reads else 1` (linhas 156-159).
  `_gh_transient` já reconhece 429/500/502/503/504 (linha 94), mas `_gh_is_read` (100-118) classifica
  todo `-X PATCH/PUT/DELETE` como escrita. Quase toda escrita do fluxo é um PATCH idempotente do
  corpo inteiro (`_store`, 863), de estado (`_set_state`, 945), de comentário de continuação (1032),
  ou um `gh issue edit --type` (960). Só o POST de criar issue (907) e de criar comentário (1035)
  não são idempotentes.
- Num 500, o chamador recebe `sp-gh-api-error`, exit 2, `attempts: 1` (245-249). O spec-runner é
  instruído a "ler, nunca repetir às cegas" o exit 2 (`agents/spec-runner.md`, §How you work).
- `cq specs new` faz o POST (907) e depois `_set_type` (921), `_sync_parts` (929), `_set_state` (933).
  Uma falha nesses passos recusa **sem o número da issue já criada**. O retry cego duplica: já
  aconteceu, com 36 issues para 12 specs em 2026-09-02 (memória do projeto). `commands/specs/create.md`
  não traz a regra de buscar pelo título antes de retentar.
- Uma spec com várias partes recebe primeiro o PATCH do head (que declara N partes) e depois os
  comentários (1028-1036). Um 500 no meio deixa o head declarando partes que não existem, e a leitura
  recusa com `sp-gh-parts-missing` e a mensagem falsa "a continuation comment was deleted" (998-1005).
  Com a contagem de partes inalterada, o head novo fica com uma parte velha **sem recusa**.
- `promote --outcome` grava o outcome (`write_spec`) e depois o `move_spec` (PATCH de estado), sem
  avisar que a primeira etapa foi aplicada se a segunda falhar (`specs/commands/promote.py:~125`).

Consequência: cada 500 transitório vira trabalho manual de retry; um retry ingênuo duplica issues;
uma falha no meio de uma escrita multi-parte pode corromper o corpo de uma spec grande.
