## Problem

O `cq knowledge listing --write` da 1136 (#1208) não converge e diverge do validador (`plugins/quenching/assets/bin/quenching/knowledge/structure.py`), reproduzido em 2026-10-08 com fixtures:

- grava a `description` crua na célula (`:334,345`); com `|` na description, `_ROW_CELL_RE`/`GENERATED_ROW_RE` deixam de casar a linha, e três `--write` seguidos dão `changed: True` e três linhas duplicadas, com o `--check` ainda STALE (exit 1);
- resolve o link com `normpath(join(...))` (`:327`), enquanto o validador usa `_resolve_link` (tira `#âncora`, aceita `/docs/…`): uma linha `code/imports.md#rules` cai em `removed` e é recriada;
- `last_row` só registra seções que mantiveram linha (`:354`): renomear o único doc de `code/` deixa `### code/` com tabela vazia e acrescenta um segundo `### code/` no fim.

Consequência: o verbo que deveria zerar `generated-listing-*` faz o índice crescer ou duplicar seções; hoje latente (nenhum doc tem `|` na description), mas qualquer alvo cai nisso.

## Proposal

- `cq knowledge listing --write` converges: a second `--write` over any bundle reports `changed: False`, and `--check` exits 0 right after a `--write`.
- A `|` in a doc's `description` is written escaped (`\|`) and both the generator and the validator read an escaped pipe as part of the cell, so the row neither duplicates nor drifts.
- The generator resolves a row's link through the validator's own `_resolve_link` (strips `#anchor`, accepts `/docs/...`), so a row such as `code/imports.md#rules` is kept, not removed and recreated.
- A subfolder section whose last row is removed keeps its `### <sub>/` table as the insertion point, so a doc added to that folder lands there instead of in a second `### <sub>/` heading at the end.

## Out of Scope

- A second GENERATED zone or a generalised listing: the zone stays a population of one (`standards/architecture/generated-listings.md`).
- Reordering or reformatting rows the generator does not own; prose outside the zone stays untouched.
- Rewriting descriptions that contain a pipe in the docs themselves: the escape lives in the listing only.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/assets/bin/quenching/knowledge/structure.py` - `GENERATED_ROW_RE`, `_ROW_CELL_RE`, `validate_generated_listing`, `regenerate_listing`
- `plugins/quenching/tests/test_knowledge.py` - `RegenerateListing` regression cases

### Standards this spec will write into docs/standards/

- none - the contract is already `standards/architecture/generated-listings.md`; this restores the code to it.

## Validation

- `cd plugins/quenching && python3 -m unittest discover -s tests -p test_knowledge.py` exits 0, including three new cases that fail on main: pipe in description (three consecutive `--write` end `changed: False` and `--check` exits 0), a `code/imports.md#rules` row (not in `removed`), and the only doc of `code/` renamed (exactly one `### code/` heading).
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: escape the pipe as `\|` in the cell, and let both row regexes take the cell as `(?:\\.|[^|\n\\])*`; the validator unescapes `\|` before comparing to the description. Alternatives: replace `|` by another character (lossy, would read as drift against the frontmatter); refuse the doc (blocks the verb on valid input). Rule: a cell is compared by its unescaped text, and the generator and the validator share one cell grammar.
- Decision: the generator calls `_resolve_link(target, subject_root, root)` and keeps the row when the result is an `md` doc present in `docs`; the row text (including its `#anchor`) is preserved. Rule: the generator never resolves a link differently from the validator.
- Decision: `last_row` records every table line (row, header, separator) under a `### ` heading, so a heading that lost all its rows still anchors insertion.
- Contract: `standards/architecture/generated-listings.md`.

### Mapa de dependências (2026-10-08)

## Alternatives Considered

- Make `--write` idempotent by rewriting the whole zone from disk: rejected, it discards the existing row order and subfolder headings the contract keeps.
- Leave the pipe case latent: rejected, any target bundle with `|` in a description duplicates rows on every write.

## Open Decisions

- none - every point is decided by the evidence in `structure.py`.

## Risks

- A cell grammar change could make the validator read a previously unmatched row and raise new WARNs on bundles: ACCEPTED - those rows were already ignored wrongly; the repo's own bundle is checked by `scripts/verify_repo.sh`.
- Unescape on the validator side changes drift for rows that literally contain a backslash before a pipe: ACCEPTED - that sequence was never valid in a cell.
