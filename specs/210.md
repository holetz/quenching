## Problem

`quenching/agents/spec-verifier.md:47` diz que linha de gate ausente ou `not-run` é "INCONCLUSIVE, never FAIL"; `:161` diz "Any fail, inconclusive gate … is FAIL", e o PASS de `:161` exige "every applicable check is ok" enquanto o formato de `:145` dá ao check 3 só "claim only", sem estado `ok` (autopilot round 11, scout c). Consequência: o mesmo relato `GATE_EXIT: not-run` gera PASS num verifier e FAIL noutro; no PASS o orquestrador carimba `verifier=pass` (`spec-orchestrator.md:57`) sobre uma spec cujo gate não rodou e publica; no FAIL gasta um re-spawn. O merge segue protegido pelo CI.

Escolher entre INCONCLUSIVE-não-bloqueia e inconclusivo-é-FAIL muda o contrato de aceitação do fluxo autônomo — decisão do humano (lista never-forced), como a 189.

- 2026-11-26 (autopilot): o mesmo sintoma custou verifiers extras 4× num dia — 518 (FAIL corrigido para PASS no mesmo relatório), 532 (FAIL só pelo item gate 'alegação até a CI'), 597 (FAIL com os 10 itens ok, branch já contendo origin/main), 596 (FAIL só por atraso; ver 606). Cada caso = 1 spawn de verifier a mais. Reforça decidir o contrato do item 3.
