## Problem

Na spec 627 (2026-11-26), o tool MCP `git_commit(subject=..., root="~/Projetos/quenching-slot-4")` respondeu `{"ok":false,"message":"nothing is staged; this verb commits the existing index and never stages"}` enquanto `git -C <slot> status --short` mostrava quatro paths staged (M/A). O mesmo verbo pela CLI, `cd <slot> && python3 quenching/assets/bin/cq git commit --subject ... --json`, commitou (4d36433). A spec 426 (arquivada) deu `root` por chamada justamente para um worker num worktree poder chamar `git_commit`; o `root` deste verbo não chega à leitura do índice (ou o servidor lê o índice do checkout principal). O execute manda usar `git_commit(root=<worktree>)` em todo commit de tarefa, então todo worker em slot cai no fallback.

Minimal fix proposed: fazer o handler MCP de `git_commit` rodar `git diff --cached`/`git commit` com cwd = `root`, com um teste que staged num worktree ligado e commita pelo tool com `root`.

**Insumos**

- `quenching/assets/bin/quenching/mcp/` (handler de `git_commit`) e `quenching/assets/bin/quenching/git/commit.py` (verbo)
- chamada: `git_commit(subject="plan/627-timeout-configuravel-git: 1.1 ...", root="~/Projetos/quenching-slot-4")` → `nothing is staged`
- spec 627, passo execute 5e, tarefa 1.1; fix no checkout do quenching e `cq deploy`
