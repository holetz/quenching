## Proposal

- The disposable marketplace source repository that `scripts/check_codex_upgrade.py` builds disables Git automatic maintenance (`maintenance.auto=false`, `gc.auto=0`) before its first commit, so no detached repack runs while Codex clones it.
- With background auto-gc forced on (`GIT_CONFIG_*` `gc.auto=1`), the check passes 20 of 20 runs locally, where before the fix the same loop failed with the CI error class (`fatal: failed to copy file to .../.git/objects/xx/...: No such file or directory`).
- A unit regression test proves deterministically that a commit in the source repository, made the way the script makes it, leaves its loose objects in place even when the environment asks for auto-gc.

## Out of Scope

- `.github/workflows/ci.yml`, the pinned Codex version, CI permissions and hooks — the epic 2033 design forbids widening; the cause is fixable in the script.
- Moving the scratch directory out of the checkout (`tempfile` outside `.quenching/`) — evidence shows the location is irrelevant to the race (see `## Design`), so it is not changed.
- Retrying the codex upgrade on failure — would mask a race instead of removing it.
- Upgrading the local Git or pinning Git on the runner — outside the script.

## Design

**Root cause (evidence, 2026-10-23).** The script commits the extracted 6.4.0 package (~1200 loose objects) into a fresh source repository, then commits the candidate package and immediately runs `codex plugin marketplace upgrade`, which `git clone`s that repository by local path (via `url.<source>.insteadOf`). A local clone copies `.git/objects` file by file. Since Git 2.54 "git maintenance starts using the geometric strategy by default" (RelNotes 2.54.0), and its `geometric-repack` task fires under `--auto` once there are at least 100 loose objects (`maintenance.geometric-repack.auto`, default 100); auto maintenance after `git commit` detaches by default (`maintenance.autoDetach`). The runner uses Git 2.55.0 (job log), so each commit starts a background repack that packs and deletes loose objects while Codex's clone is enumerating them: the clone sees a loose object, it is gone by the copy, and it dies with ENOENT. Locally (Git 2.43, legacy `gc --auto` threshold 6700) 30 of 30 runs pass; forcing the old path into the same behavior with `gc.auto=1` reproduces the exact CI message in 5 of 20 runs (`.../.staging/marketplace-linux-*/checkout/.git/objects/4e/...: No such file or directory`). Main passes and PR 2030 failed with the same runner image (20261012.334.1) and Git version: the race depends on timing, not on content (PR 2030 changes two Codex files).

**Decision — the disposable repository disables auto maintenance.** It is set in the same config loop that already sets `commit.gpgsign` and `core.hooksPath`: `maintenance.auto=false` (honored by Git ≥2.29 for every auto-maintenance trigger, the geometric strategy included) and `gc.auto=0` (the legacy trigger on older Git). The repository lives for seconds and needs no maintenance. Repository-level config cannot be overridden by the `gc.auto` the stress proof injects through the environment, because `maintenance.auto=false` stops the auto run before any task heuristic is consulted.

**Binding contracts.** `docs/standards/ci-cd/versioning-release.md` §Upgrade acceptance (the check stays a real Git marketplace refresh with no model calls); no user Git config is modified (only the disposable repository's local config).

## Alternatives Considered

- **Scratch outside the checkout (`tempfile.TemporaryDirectory()` with no `dir=`)** — rejected: the race is between the source repository's own background repack and the clone, both inside the scratch tree, wherever it lives.
- **`git clone --no-local`-style or a `file://` URL to force the pack protocol** — rejected: the clone is made by Codex, not by the script; changing its URL form changes what the check exercises.
- **`git gc` / `git repack -ad` synchronously after each commit** — would also close the race (no loose objects left to delete), but runs extra work every time and still leaves the next auto run possible; disabling maintenance removes the cause.
- **Retry the upgrade** — rejected: it hides a real race and makes the gate nondeterministic.
