## Problem

`commands/specs/execute.md:117-118` e `commands/git/branch.md:77-78` oferecem `cq --root <worktree>` como forma de levar o caminho da worktree a cada comando (regra da 1252), mas o pilar `git` não declara `--root`: `cq --root /tmp git base --json` sai com `cq: error: git declares no --root` (medido em 2026-10-08). Os passos atingidos são `cq git commit` (`execute.md:270`, da 1212) e `cq git worktree link` (`branch.md:72`).

Consequência: a cadeia do passo 5e do execute para no commit com o índice já preparado na worktree; e um agente que escreva `git -C <wt> add … && cq git commit` commita o índice vazio do checkout base e falha.

## Proposal

- `execute.md` e `branch.md` deixam de oferecer `cq --root <worktree>` para o pilar `git`: o commit do passo 5e e o `cq git worktree link` passam a rodar como `cd <worktree> && cq git …` na mesma chamada.
- `--root` continua sendo a forma para os pilares que o declaram (`specs`, `knowledge`, …); as duas frases dizem qual pilar fica de fora.

## Out of Scope

- Declarar `--root` no pilar `git` (`assets/bin/cq`, `takes_root`): exigiria código e os agentes instalados são 6.4.0, então a correção não seria exercitável nem alcançável agora. Adiado, não descartado.

## Impact

### Standards this spec will write into docs/standards/

## Validation

- `bash scripts/verify_repo.sh` sai 0 na worktree.
- Medido em main: `cq --root /tmp git base --json` sai com `cq: error: git declares no --root` (`assets/bin/cq:193-194`); após a edição nenhuma linha dos dois comandos manda `--root` para `cq git`.

## Design

- Regra durável: um comando que leva a worktree em cada chamada usa `cq --root <wt>` só para pilares com `takes_root`; para o pilar `git` o cwd da própria chamada (`cd <wt> && cq git …`) é o único portador do caminho.
- Alternativa pesada (declarar `--root` em `git`) rejeitada aqui: ver Out of Scope.

### Mapa de dependências (2026-10-08)

## Alternatives Considered

- Declarar `--root` no pilar `git`: mais correto a longo prazo, mas é código e fora do alcance dos agentes 6.4.0; rejeitada nesta spec.
