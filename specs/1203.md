## Problem

`plugins/quenching-codex/skills/quenching-specs-orchestrate/SKILL.md:15,42` manda ler `plugins/quenching/agents/orchestrator.md` e lançar o agente `quenching:orchestrator`, mas `plugins/quenching-codex/` não tem `agents/` (conferido em 2026-10-07). `cq components translate --check` sai in-sync com 0 achados, e o gate não vê. Outros corpos que lançam os cinco agentes (o `improve` com o scout, o caminho do spec-architect) provavelmente têm a mesma lacuna [unverified].

Consequência: num alvo Codex a skill falha no passo 3, depois de o humano já ter respondido a pergunta do passo 2, e nada no gate acusa.

## Proposal

Decidir entre traduzir os agentes para o equivalente do Codex, marcar como não suportada (com o motivo) a skill que depende de agente, ou dar a ela um protocolo degradado na própria sessão; e acrescentar ao `translate --check` ou ao `validate_codex_plugin.py` um achado para toda citação de `agents/*.md` ou `quenching:<agente>` que não resolve na árvore Codex.

## Out of Scope

O protocolo do orquestrador em si.

## Impact

### Standards this spec will write into docs/standards/

- none — the rule lives in the translator and its gate, not in a standard

### Product code this spec expects to touch

- `scripts/validate_codex_plugin.py` — the new citation check
- `plugins/quenching/tests/test_codex_agent_citations.py` — proof the check accuses and then passes (new)
- `plugins/quenching/assets/bin/quenching/components/commands/translate.py` — ship `agents/` into the Codex tree
- `plugins/quenching/assets/translation/codex-adaptation.json` — rewrite the two launch sentences for Codex
- `plugins/quenching-codex/**` — regenerated, never hand-edited

## Validation

O check novo acusa o estado atual antes da correção e passa depois; nenhuma skill Codex cita agente inexistente; `bash scripts/verify_repo.sh` sai 0.

## Design

- **Decision: degraded protocol in the session.** Codex ships no plugin agents, so the translation carries the six agent definitions as `agents/*.md` in the Codex plugin and the two launching skills (`orchestrate`, `improve`) are rewritten to read the definition and follow it in the current session, keeping its prohibitions (no git stash, checkout, reset, rebase or amend; the orchestrator edits nothing itself). The `tools:` allow-list in the definition is not enforceable in Codex and is stated as such.
- **Durable rule: a Codex skill never cites an agent the Codex tree does not carry.** Two forms are checked in `skills/*/SKILL.md`: a path `plugins/quenching[-codex]/agents/<name>.md` or `../../agents/<name>.md` must exist under the plugin root; a remaining `quenching:<name>` (the Claude agent form; skill names become `quenching-<name>`) must resolve to `agents/<name>.md`.
- Why in `validate_codex_plugin.py`: `translate --check` only compares generated bytes against the source, so a faithful translation of a dangling citation is in sync by construction. The validator already inspects the generated tree.
- The rewrite is done with `replacements` in the adaptation manifest (exact sentences), keeping the Claude command bodies untouched.
- Binding contract: Claude is the source of truth; the Codex tree is only regenerated with `cq components translate --write`.

## Alternatives Considered

- **Translate agents to a Codex-native equivalent**: rejected, the Codex plugin manifest has no agent surface and its sub-agent facility is not verified here.
- **Mark the skill unsupported on Codex**: rejected, it leaves two skills dead on a target that can follow the protocol in-session; the check would still be needed.

## Open Decisions

- Whether a future Codex release offers restricted-tool sub-agents worth mapping to — decided when a Codex agent surface is documented; then the in-session rewrite is replaced by a translation.
- Other bodies that launch the agents (spec-architect path, git-steward, verifier) — decided by the new check: any it flags is fixed in this spec; today it is evidenced only for `orchestrate` and `improve`.

## Risks

O Codex pode não ter subagente com ferramentas restritas; um protocolo degradado precisa manter as proibições de git do runner.
