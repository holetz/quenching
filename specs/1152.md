## Problem

- `cq security status --json`: `secret-ignore-coverage` missing (`.gitignore` sem `.env*`, `*.pem`, `*.key`) e `advisory-dependency-configuration` missing (sem `.github/dependabot.yml`; `.github/` só tem `ISSUE_TEMPLATE` e `workflows`). **Reproduzido.**
- `ci.yml` fixa três actions por SHA, e o `uv.lock` fixa o zensical, sem automação de atualização.
- Consequência: correções de segurança das actions não chegam. Um `.env` criado por um agente pode entrar num `git add` num repositório público de marketplace.

Candidato `C07` do mapa `.quenching/improve/2026-10-07/delivery-security/07-higiene-de-seguranca-dependabot-e-gitignore.md` (efêmero); a proposta, os riscos e a validação estão no epic 1145 e no mapa.

## Proposal

- `.gitignore` ignores the secret classes the repository can plausibly create: `.env*` (with `!.env.example` kept trackable), `*.pem` and `*.key`.
- `.github/dependabot.yml` exists and keeps the pinned GitHub Actions (`github-actions` ecosystem, `/`) and the `uv.lock` dependencies (`uv` ecosystem, `/`) updated on a weekly schedule.
- `cq security status --json` reports `secret-ignore-coverage` and `advisory-dependency-configuration` as `present`.

## Out of Scope

- Secret scanning in CI, push protection or gitleaks hooks: detection is a different control from ignore rules and needs its own decision.
- Auto-merge of Dependabot PRs: updates arrive as ordinary PRs reviewed by a human.
- Ignoring further classes (`*.p12`, `id_rsa*`, credentials JSON): no such file exists in the tree; the three classes the check names are the reproduced gap.
- Changing the existing SHA pins in `ci.yml`: Dependabot keeps SHA pins with the version comment, so the pins stay as they are.

## Impact

### Product code this spec expects to touch

- `.gitignore` — adds the secret-class patterns.
- `.github/dependabot.yml` — new file.

## Validation

- `bash -c 'cd . && plugins/quenching/bin/cq security status --json'` must show `secret-ignore-coverage` and `advisory-dependency-configuration` with `state: "present"`; both are `missing` today.
- `git ls-files | grep -Ei '\.env|\.pem$|\.key$'` stays empty (no tracked file is shadowed by the new rules).
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: one `dependabot.yml` with two ecosystems, `github-actions` and `uv`, both weekly. Rule: every pinned supply-chain input (action SHAs, `uv.lock`) has an update feed. Assumption: `uv` is a supported Dependabot ecosystem for the `uv.lock` at the root (pyproject.toml present).
- Decision: ignore patterns `.env*`, `*.pem`, `*.key` with a `!.env.example` exception, so a template stays committable.
- Binding contract: Dependabot rewrites SHA-pinned `uses:` lines and their `# vX` comments in place, preserving the pin policy of `ci.yml`.

### Mapa de dependências (2026-10-07)

| File | Relation | If it changes |
| --- | --- | --- |
| `.gitignore` | edited | no tracked file matches the new patterns (verified: `git ls-files` empty), so nothing is orphaned |
| `.github/dependabot.yml` | new | read by GitHub only; `cq security status` detects it |
| `.github/workflows/ci.yml` | read-only | its three SHA-pinned actions are what Dependabot will update |
| `uv.lock` / `pyproject.toml` | read-only | the `uv` ecosystem reads them |

## Alternatives Considered

- Renovate instead of Dependabot: rejected, it needs an extra app install and the check recognizes Dependabot configuration.
- Only the `github-actions` ecosystem: rejected, it would leave the zensical pin in `uv.lock` without updates, which the problem names.

## Open Decisions

- Weekly versus monthly cadence — decided at review of the PR by the human; weekly is the default written here because the repository is public and security fixes should arrive promptly.
- Why now / what would make this not worth doing — only a human answers; decided at review of the PR (the epic 1145 carries the stated appetite).

## Risks

- Dependabot PR noise from a weekly cadence: ACCEPTED — bounded to two ecosystems and three actions plus one lockfile.
- `.env*` could hide a legitimately tracked file in future: mitigated by the `!.env.example` exception.
- The `uv` ecosystem not parsing the lockfile: mitigated because the first Dependabot run surfaces an error visible in the Insights tab; revisit then.
