## Problem

O grant `Bash(git branch --list:*)` do agente `orchestrator`, estreitado pela #1227 (spec 1211), ainda admite apagar branches: `git branch --list --no-list -D <branch>` casa o prefixo, e o `--no-list` desfaz o `--list`; medido em 2026-10-08 num repositório descartável, o comando saiu com 0 e apagou a branch (sem `--no-list`, `--list -D` sai com 129). O mesmo vale para `-m`/`-M`/`-c`.

Consequência: o orquestrador, documentado como quem nunca edita nada, segue podendo apagar ou renomear branches pelo próprio grant; a revisão de segurança dos épicos 1192 e 1197 (decisão 0011, spec 1232) registrou isso.

## Proposal

- The `orchestrator` agent's `tools:` no longer carries `Bash(git branch --list:*)`; it carries `Bash(git for-each-ref:*)` in its place, so the orchestrator still reads which branches exist and cannot delete, rename or copy one.
- The Codex translation of the agent carries the same change.

## Out of Scope

- Rewriting `git branch --list` mentions in `execute.md`, `isolation.md` and `execution.md`: those run in workers and the steward, whose grants are not narrowed by this spec.
- Editing decision 0011 (`docs/decisions/`): it records the finding as it stood on 2026-10-08.
- Other agents' grants: not part of the finding.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/agents/orchestrator.md` - the `tools:` line
- `plugins/quenching-codex/agents/orchestrator.md` - regenerated translation

## Validation

- `grep -c 'Bash(git branch' plugins/quenching/agents/orchestrator.md` prints 0 afterwards (1 before).
- `grep -c 'Bash(git for-each-ref:\*)' plugins/quenching/agents/orchestrator.md` prints 1.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Decision: swap the grant for `git for-each-ref`. It has no flag that writes a ref, so no prefix trick such as `--no-list` can turn it into a mutation. Assumption: the orchestrator needs only to list branch names, which `git for-each-ref --format='%(refname:short)' refs/heads/` does.
- Rule: a Bash grant on a subcommand family that mixes read and write flags is narrowed by changing the command, never by a longer prefix, because the prefix match cannot see a later flag that undoes an earlier one.
- Alternative weighed: `Bash(git branch --list plan/:*)`. Rejected: `git branch --list plan/x --no-list -D plan/x` still matches the prefix.
- The Codex translation is regenerated with `cq components translate --write`, never hand-edited.

## Alternatives Considered

- Dropping branch visibility altogether: rejected, the orchestrator checks worker branches through `git worktree list` and `git log` only partially; for-each-ref costs nothing.
- Delegating branch reads to `scout`: rejected, a turn per read for something one grant covers.

## Open Decisions

- none - the one choice (for-each-ref) is settled in Design.

## Risks

- The translation drifts from the source; mitigation: task 1.2 regenerates it and the repository gate checks it.
