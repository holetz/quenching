## Problem

Independent correctness review of accepted spec 2026 commit b1de343c977bbf5d6b6584da972fe1d970addf6a reproduced contradictory scope rules across the owning contracts.

Reproduction: run cq git history show with each argument:
- b1de343c977bbf5d6b6584da972fe1d970addf6a:plugins/quenching/agents/verifier.md
- b1de343c977bbf5d6b6584da972fe1d970addf6a:plugins/quenching/assets/references/specs-execute/execution.md
- b1de343c977bbf5d6b6584da972fe1d970addf6a:plugins/quenching/assets/references/specs-develop/artifacts.md

Output/evidence: verifier.md:46 explicitly approves a nonempty changed set containing only proven generated copies. execution.md:231 still says that anything written under files: [] fails scope. artifacts.md:265-267 says the verifier cannot discount an undeclared derived output. For changed = generated = {proven byte-for-byte copy} and an empty declared files union, the verifier approves while execution requires failure and development denies the discount.

Consequence: developers and verifiers still receive opposite decisions for the same payload despite spec 2026 fixing the local contradiction. Preserve the distinction between proven byte-for-byte copies and derived outputs that are not copies.

Captured for future work only. The owner's current instruction ends the existing-spec execution run without any new improvement round; this spec is not admitted to that run.

## Proposal

- `execution.md` states the scope rule the way `verifier.md` does: a path the audit proved a byte-for-byte copy of its source in a manifest-declared module is discounted from scope; anything else outside the union of `files:` fails.
- `artifacts.md` no longer says the verifier cannot discount a derived output: it says only proven byte-for-byte copies are discounted, and a derived output that is no copy (a manifest, a hash index, a rewritten `plugin.json`, a golden) still needs a `files:` declaration.
- Every generated mirror of those two references is regenerated with the repo's generators and declared in the task's `files:`.

## Out of Scope

- `plugins/quenching/agents/verifier.md`: already the authority for the exemption (spec 2026); not touched.
- Any change to the verifier's audit, grants, hooks or CI: prose in `references/**` only.
- Dropping the instruction to declare generator outputs in `files:`: it stays, because declaring remains the safe default and non-copy outputs still need it.

## Validation

- `bash scripts/verify_repo.sh` exits 0 (generator `--check`, Codex translation and lockstep included).
- `grep -n "cannot regenerate or discount" plugins/quenching/assets/references/specs-develop/artifacts.md` finds nothing, and both references name the byte-for-byte copy exemption and keep non-copy derived outputs in scope.
- For changed = generated = one proven copy and empty `files:`, execution.md, artifacts.md and verifier.md now give the same decision (passes scope).

## Design

- Rule: the three contracts state one scope rule. Proven byte-for-byte copies (the payload's `generated`) are discounted; hand-edited generated files, non-copy derived outputs and authored files are not. execution.md and artifacts.md cite the rule and never restate the audit.
- Keep the `files:` declaration advice: a task that runs generators still declares the outputs it changes; the exemption is a safety net for proven copies, not a licence to omit non-copies.
- Mirrors are never hand-edited: `scripts/generate_plugin_modules.py` and `scripts/sync_codex_plugin.py` regenerate them, and every changed output is declared in the task's `files:`.
