## Problem

- `cq delivery doctor --json` (nesta sessão): `delivery-setup-missing` em `lint` e `functional`, `delivery-runtime-drift` com `python=${{, python=['3.11',`.
- `lint` provisiona com `astral-sh/setup-uv` + `uv sync`; `functional` é só bash. O drift vem do parser quebrar `['3.11', '3.13']` e `${{ matrix.python-version }}` no espaço, e não há divergência com `requires-python >=3.11`.
- Consequência: três erros espúrios no próprio repositório ensinam a ignorar o doctor, e um drift real fica indistinguível do ruído.

Candidato `C06` do mapa `.quenching/improve/2026-10-07/delivery-security/06-falsos-positivos-do-delivery-doctor.md` (efêmero); a proposta, os riscos e a validação estão no epic 1145 e no mapa.

## Proposal

- `cq delivery doctor` no longer emits `delivery-setup-missing` for a job that provisions through `astral-sh/setup-uv` (any `<owner>/setup-*` action) or whose commands never invoke a language runtime (a bash-only job).
- A flow list (`python-version: ['3.11', '3.13']`) is read as a matrix axis and a `${{ ... }}` expression is not read as a version, so the repo's own `ci.yml` yields zero `error` findings.
- A scalar runtime that disagrees with another scalar, or with every version of the matrix, still raises `delivery-runtime-drift`.

## Out of Scope

- New delivery adapters or providers: front not core, defect fix only.
- Parsing the body of block-scalar `run: |` scripts for runtime commands: the inventory records no body lines, so a runtime call hidden there is not measured (conservative: fewer false errors, never a new one).
- Resolving `${{ matrix.x }}` against the matrix: the matrix axis already carries the values.

## Validation

- `plugins/quenching/bin/cq delivery doctor --json` in this repo: zero findings with severity `error`.
- `python3 -m pytest plugins/quenching/tests/test_delivery.py -q` exits 0, including a fixture with real drift (scalar 3.10 vs 3.11) that still reports `delivery-runtime-drift`.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- **Setup provenance is `<owner>/setup-*`** (regex `^(?:[^/@]+/)?setup-`), not only `actions/setup-*`: `astral-sh/setup-uv` provisions the toolchain. Alternative: an allowlist of actions, rejected as it rots.
- **Setup is required only when a command's first word (after env assignments, split on `&&`, `||`, `;`, `|`) is a language runtime or its package tool.** Alternative: exempt by job name, rejected as arbitrary.
- **A matrix axis is recorded as `<lang>:matrix:<v>`** and compared apart from scalars: drift is a scalar conflicting with another scalar or absent from the matrix; a matrix alone never drifts. Expressions (`${{`) are dropped as unresolvable.
- Binding contract: finding codes and bands in `_BANDS` stay unchanged; the golden `delivery-results.json` must keep its code sets.

## Alternatives Considered

- Fix only `ci.yml` to avoid the parser: rejected, it hides the defect for every other repo.
- Drop both checks: rejected, the real drift case would be lost.

## Open Decisions

- none — the criteria for runtime commands and matrix handling are settled in `## Design`.

## Risks

- A runtime command outside the list is not seen, so a missing setup goes unreported (false negative). ACCEPTED — the list covers the supported languages and the check is a hint, not a gate.
- A runtime invoked only inside a `run: |` block is not measured. ACCEPTED — see Out of Scope.
