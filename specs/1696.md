## Problem

A 1687 (PR #1693) fez `knowledge/config.py:38-42` cair nos padrões quando `.claude/hooks/hooks-config.json` não é UTF-8 ou não é um objeto JSON. A revisão de correção da rodada 3 do autopilot de 2026-10-15 reproduziu, com um bundle que só tem WARNs:

- `{"okfValidate":{"warnAsError":true}}` → `cq knowledge validate docs` sai 1 (esperado);
- o mesmo conteúdo com um byte Latin-1 (`"caf\xe9"`) → sai 0, sem nada no stdout nem no stderr;
- `[{"okfValidate":{"warnAsError":true}}]` → sai 0, em silêncio.

Em ea961157 os dois casos falhavam alto (traceback, exit 1). Agora uma config quebrada faz o gate de warnings **passar** em silêncio, em vez de falhar. Um JSON truncado já era silencioso antes. Consequência: quem declarou `warnAsError` perde o gate sem aviso. O contrato pede recusa (exit 2) com uma mensagem que nomeie o arquivo para config ilegível, inválida ou que não seja objeto, nunca o padrão silencioso.
