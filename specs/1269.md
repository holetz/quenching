## Problem

A 1212 (#1230) mudou o execute para commitar cada task por `cq git commit --subject` (`commands/specs/execute.md:262-264,270`, "never reload `/quenching:git:commit` per task"), mas o texto antigo ficou em dois lugares: `plugins/quenching/agents/spec-runner.md:14-15` ("`/quenching:git:commit` for every commit") e `commands/git/commit.md:20-23` ("Commands that build a spec, including `/quenching:specs:execute`, delegate here"). Achado da revisão de coerência de 2026-10-08.

Consequência: um runner que segue a própria definição invoca o Skill a cada task, recarrega o corpo (~2,8k tokens por task, decisão 0010) e sai do caminho que o teste da 1212 fixa.

## Proposal

- `agents/spec-runner.md` no longer tells the runner to invoke `/quenching:git:commit` for every commit: task commits are made by execute through `cq git commit --subject`, and the runner names the Skill only for develop, execute and conclude.
- `commands/git/commit.md` no longer says `/quenching:specs:execute` delegates its per-task commits there; it says execute commits through `cq git commit` and this command serves standalone commits.

## Out of Scope

- Changing `commands/specs/execute.md`: it is already the correct side (lines 262-264, 270).
- Exercising the fix live: installed agents are 6.4.0, so proof is the two cited sides plus the repository gate.

## Impact

### Product code this spec expects to touch

- `plugins/quenching/agents/spec-runner.md` — the "How you work" first bullet.
- `plugins/quenching/commands/git/commit.md` — the intro paragraph.

## Validation

- `grep -n 'git:commit. for every commit' plugins/quenching/agents/spec-runner.md` exits 1 and the new text names `cq git commit`.
- `grep -n 'delegate here' plugins/quenching/commands/git/commit.md` exits 1.
- `bash scripts/verify_repo.sh` exits 0.

## Design

- Rule: a command that already commits per task through `cq git commit` is never described elsewhere as delegating to the Skill; the Skill stays the boundary for standalone commits (decision 0010: ~2.8k tokens per reload).
- The runner's `tools:` keeps `Skill` (develop, execute, conclude need it) and Bash already covers `cq git commit`; no grant widens.

## Alternatives Considered

- Reverting execute to the Skill per task: rejected, it reintroduces the per-task reload cost 1212 removed.

## Open Decisions

- none — the fix follows execute.md, already settled by 1212.

## Risks

- A reworded runner bullet could be read as forbidding the Skill for standalone commits. Mitigation: the text scopes the rule to task commits made inside execute.
